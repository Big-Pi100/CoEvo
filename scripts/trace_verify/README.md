# 痕迹与转义验收（`scripts/trace_verify/`）

## 这个目录现在验什么

**两件事**（都属于「阅读链路的纯 Dart 可验证部分」）：

| 脚本 | 验什么 | 规模 |
|---|---|---|
| `bin/verify_trace_markdown.dart` | **痕迹标记注入** —— 把已查词包成控制字符标记 | 10 组 · 43 项 |
| `bin/verify_unescape.dart` | **Markdown 转义消化** —— 把产出侧多余的 `\X` 还原成字面标点 | 4 组 · 56 项 |

```bash
cd scripts/trace_verify
DART=/d/flutter/bin/cache/dart-sdk/bin/dart.exe    # 官方版 Dart 3.11.0（PATH 里那个是鸿蒙版）

$DART run bin/verify_trace_markdown.dart
$DART run bin/verify_unescape.dart
```

**退出码 0 = 全过；1 = 有失败** → 可挂 CI / pre-commit。

## ① 痕迹标记注入（`verify_trace_markdown.dart`）

### 为什么需要它：这条路上全是**静默**错误

| 往哪插 | 后果 | 会不会报错 |
|---|---|---|
| **围栏代码块**里 | 代码内容被污染（代码块本该原样呈现） | ❌ 不报错 |
| **行内代码**里 | 同上；且控制字符会被当代码显示出来 | ❌ 不报错 |
| **链接 URL** 里 | 🔴 **链接直接失效**（点不开） | ❌ 不报错 |
| 重复调用 | 双层标记 → 多渲染一层 | ❌ 不报错 |

⇒ 这类「不抛异常、肉眼也难发现」的缺陷，只能由断言锁死。

🔑 **本脚本最强的一条是【0】**：**剥掉控制字符后必须与原文完全相同** ——
一句覆盖了「只加不清、不改内容」这整类风险。

### 十组断言

| 组 | 内容 |
|---|---|
| 【0】🔑 **核心不变量** | 剥掉控制字符后与原文**完全相同**（只加不清、不改内容）|
| 【1】基本注入 | 词被包住，且档位正确（fresh / reviewing 用不同控制字符）|
| 【2】🔴 跳过围栏代码块 | ``` / ~~~ 内的词**不得**被标记 |
| 【3】🔴 跳过行内代码 | `` ` `` 内的词**不得**被标记 |
| 【4】🔴🔴 跳过链接 URL | `](…)` 里插字符会让**链接失效** |
| 【5】词边界与大小写 | `\b` 判据（`art` 不标 `start` 里的 art）· 大小写不敏感 |
| 【6】🔑 幂等 | 重复调用不产生双层标记 |
| 【7】边界 | 空输入 / 空词表 / 无命中 / 空词 |
| 【8】🔑 **与渲染端一致** | 注入的标记能被渲染端的 `pattern` 匹配回原文 + 档位 |
| 【9】词表顺序无关 | 词表顺序不同 → 结果相同；控制字符数一致 |

## ② Markdown 转义消化（`verify_unescape.dart`）

### 🔴 这条路上「做宽了」比「做窄了」更危险

消化 = **删反斜杠**。删错会**制造新语法**：

| 删错了 | 后果 |
|---|---|
| `\*text\*` → `*text*` | **开始强调**（内容被改）|
| `\[a\](u)` → `[a](u)` | **变成链接** |
| `1\. item` → `1. item` | **变成列表项** |

而这类错误**不报错**，只是渲染结果变了 ⇒ 只能靠断言锁死。

🔑 **本脚本最强的一条同样是【0】**：**剥掉所有反斜杠后内容必须完全相同**。

### 为什么需要它（根因）

**产出侧按 CommonMark 全量（且过度）转义，消费侧只实现了子集**：

| 侧 | 行为 |
|---|---|
| 产出侧 `dom_smoothie` | 输出 `DELETE\.` · `\"QUERY\"` · `\(66\.4%\)` · `\["IN", "US"\]`（句点/引号/圆括号/方括号**本来都不需要转**）|
| 消费侧 `gpt_markdown` 1.3.0 | 源码原话 `Only \| is unescaped` ⇒ **只反转义 `\|`**，其余原样显示 |

📄 调查报告 → [`docs/review/s4-device-feedback-findings-2026-10-02.md`](../../docs/review/s4-device-feedback-findings-2026-10-02.md) §4
📄 实现 → [`app/lib/services/markdown_unescape.dart`](../../app/lib/services/markdown_unescape.dart)（文件头有完整的设计说明与白名单依据）

### 四组断言

| 组 | 内容 |
|---|---|
| 【0】🔑 **核心不变量** | 剥掉反斜杠后内容完全相同 + 长度不增长 |
| 【1】🔴 白哥报的具体症状 | `DELETE\.` · `\"QUERY\"` · `\{…\}` · `\(66\.4%\)` · `\["IN","US"\]` · 逗号分号冒号 |
| 【2】🔴 **必须保留的** | `\*` `\_` `` \` `` · 行首 `\[` · 含 LaTeX 命令的 `\(…\)` · `\#` `\+` · `\|` · 反斜杠+字母 · `\\` |
| 【3】边界与保护条件 | 围栏/行内代码/URL 不消化 · 行首 `1\.` 保留 · **行内/标题里的 `1\.` 消化** · 小数消化 · `\![` 保留 · `\\[1em]` 不被误判 · 幂等 |
| 【4】🔑 **生产库真实正文** | 两个 fixture（见下）|

### 📁 `fixtures/` —— 用生产库真实正文

| 文件 | 来源 | 特征 |
|---|---|---|
| `http_query_id1444.md` | 生产库 `content_pool.id=1444`（**白哥报的那篇**）| 97 个反斜杠 · 无代码块/LaTeX → 消化后 **0 残留** |
| `benchmarks_id1452.md` | 同上 `id=1452` | 260 个反斜杠 · 含 `\(…\)` LaTeX + `\.` 小数 → **只留该留的** |

🔑 判据：**实测数据要用用户报的那份**（验完能直接说「你报的问题被治好了」）。
⚠️ 这两个文件是 **RSS 抓取的公开正文快照**，仅用于本仓测试断言。

### 全库实测（2026-10-02 · 49 篇含反斜杠的正文）

| 指标 | 结果 |
|---|---|
| 反斜杠总数 | **5487 → 894（消化 83.7%）** |
| 核心不变量 | ✅ **49/49 篇「剥掉反斜杠后内容完全相同」** |
| 长度 | ✅ 全部只减不增 |

## 为什么是「零依赖」脚本

被验的源文件都是**纯 Dart、零 Flutter 依赖**：
· `services/trace_markdown_source.dart`（纯字符串处理）
· `services/markdown_unescape.dart`（纯字符串处理）

所以本目录 `pubspec.yaml` **不拉任何包**。

理由同 `tokens_verify` / `fsrs_verify`：本机 `flutter analyze` 会因 Windows 管道耗尽崩溃
（`CreateFile failed 231`，见 `scripts/static_check/README.md`），
**只有纯 Dart 才能本地独立验证**。

🔑 **这条约束反过来影响了架构**：为了让「痕迹怎么注入」「转义怎么消化」可验证，
它们必须**不碰 Flutter** —— 于是「判定 / 编码 / 渲染」被强制分层。
**可验证性促成了更好的分层。**

## 能力边界（重要）

| 能查 | 不能查 |
|---|---|
| ✅ 标记注入的全部逻辑边界（跳过区 / 幂等 / 词边界）| ❌ **`gpt_markdown` 是否真的把它渲染成带样式的 span**（需 Flutter 环境）|
| ✅ 转义消化的全部保护条件（白名单 / 列表 / 图片 / LaTeX / 代码块）| ❌ **消化后的观感好不好**（需真机）|
| ✅ 「只加/只减、不动其它字符」这一整类不变量 | ❌ **「这样消化是否符合用户期待」**（产品判断）|

⚠️ **两个脚本末尾都会主动打出这些提醒** —— 避免「跑绿了就当没问题」。
另：token 层（三档 × 两态 · 读法递减 · `forReps` 映射）**不在本目录验**，
已并入 `scripts/tokens_verify/`（【4】组「痕迹 token」，断言到具体数值，比这里更严）。

## 历史：`bin/verify_trace.dart` 已于 2026-10-02 删除

S4 之前，痕迹是「**词 → 字符区间 → 逐 span 上色**」，那个脚本验的就是这条路径
（8 组 · 97 项：切分边界 / 确定性 / 不变量 / token / 定位）。

**删除理由（逐组交代，不是整块丢弃）**：

| 原组 | 处置 |
|---|---|
| 【1】切分边界 · 【2】确定性 · 【3】核心不变量 | 🔴 **随死代码作废** —— 测的 `splitTraceSpans` 只在「字符区间」表达下有意义，而 Markdown 渲染后**偏移全变**，这条路径已整体删除 |
| 【8】痕迹定位 | 🔴 同上 —— `locateTraceMarks` 已删 |
| 【4】token 完整性 · 【5】读法递减 · 【6】三档语法 · 【7】`forReps` | ✅ **已被 `tokens_verify`【4】组覆盖且更严**（那里断言到具体数值：墨 `p.right=3`/`r=3`、格线宽 `2.5→1.5`、夜暖度 `r−b` 递减…；而删掉的这几组只验「已显式给出」）|

📌 **判据：删断言前先逐组交代「它的价值去哪了」** ——
是「随被删的实现一起作废」，还是「已被别处覆盖」。
两者都不成立时才叫**真的丢覆盖**，那时不该删。
🔑 顺带清掉的两条**恒真断言**（`check(desc, true, detail)` —— 第二个参数写死 `true`，
实际只是打印信息）：它们永远绿，是「看起来有覆盖」的假象。
