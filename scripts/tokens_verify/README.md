# 视觉 token 验收（`scripts/tokens_verify/`）

## 验证什么

`app/lib/theme/coevo_tokens.dart` 是 `docs/design/design-system-spec-2026-09-25.md`
（视觉的**单一事实源**）的代码化。本脚本把 spec 的**全部数值**写成断言 ——
**「文档改了但代码没改」当场暴露**。

🆕 **【9】接线**（2026-09-27 加）验的是**另一类失效**：
数值全对，但 `app.dart` 还在用旧主题、或有人又手写了一个 `ThemeData` ——
**编译器不报错、界面照旧**，只有结构级断言抓得住。
「三档 token 写好了却没人用」正是 Step 2 最容易翻车的地方。

## 怎么跑

```bash
cd scripts/tokens_verify
dart pub get                       # 零依赖，秒装
dart run bin/verify_tokens.dart
```

- **纯 Dart，零 Flutter 依赖** —— `coevo_tokens.dart` 刻意不 import Flutter
  （本地 Flutter 是鸿蒙定制版、`analyze` 会因 Windows 管道耗尽崩溃），
  所以任何装了 Dart 的机器都能跑，**不需要 iOS 真机**
- **退出码 0 = 通过；1 = 有实现类失败** —— 可直接挂 CI
- 🔑 用**相对路径直接 import app 的源码** → 验证的是**实际要发布的实现**，不是副本

## 三类断言（分工不同，别混）

| 类型 | 方法 | 失败含义 |
|---|---|---|
| 数值核对 | `eq` / `near` / `color` / `listEq` | **实现写错了** |
| 规则不变量 | `check` | **实现违反了 spec 的设计规则** |
| 规格自洽性 | `checkSpec` / `conflict` | **文档有歧义/矛盾** → 改文档，不是改代码 |

🔑 **区分的意义**：`#2` 的对比度断言用 spec **自己声称的实测值**（4.76 / 5.56 / 3.87…）
去反验我们的算法 —— 这**一次同时验了两件事**：token 值对不对 + 对比度实现对不对。
若两者都错但恰好互相抵消，也会被这批断言抓住。

🔴 **一个易踩的坑**：Dart 的 `List == List` 是**引用比较** —— 用它断言会让「值相同」的列表报失败，
且打印的实得/期望**看起来一模一样**。→ 用 `listEq`（本脚本首轮踩过）。

### 🆕【7】的字体验证：专治「写了但没接通」

字体是**最容易静默失效**的一类资源 —— 名字写错 / pubspec 没声明 / 文件不存在，
**运行时都不报错**，只是悄悄回退系统字体。所以【7】做了两层交叉验证：

1. 代码里的 `CoFonts.shippedFamilies` → **逐个在 `app/pubspec.yaml` 里找 `- family: <name>`**
2. pubspec 里声明的 asset 路径 → **逐个确认文件真的存在**（并打印字节数）

> 这对应 `.workbuddy/skills/safe-bulk-deletion` 里那条教训：
> **「在别处验证过」≠「在此处可用」**（声明了依赖却没在 `app/` 内 pub get，就是同类问题）。

## 与 `fsrs_verify` 的关系

同一个方法论：**把「文档里的数字」变成「可执行的断言」，让文档漂移无法静默发生。**

| 脚本 | 锁定什么 |
|---|---|
| `scripts/fsrs_verify/` | FSRS 调度的**行为**（四档单调 / elapsed 敏感 / 预览==提交） |
| `scripts/tokens_verify/` | 视觉系统的**数值与规则**（token 值 / 对比度 / 几何约束 / 层级不变量 / **字体接通**） |

两者都放在**核心层零框架依赖 + 相对路径 import 真源码**的架构上（见
`.workbuddy/skills/verifiable-core-logic`）。
