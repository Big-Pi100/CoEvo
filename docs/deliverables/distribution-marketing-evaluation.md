## 🔴 严重问题（必须修复）

### 1. 未成年人分销合规漏洞

**现状**：§12.6 声称"不向未满 18 岁用户开放分销功能"。

**问题**：CoEvo 的目标用户群是 **K12 学生**（初中/高中生），大量未满 18 岁。如果一刀切屏蔽所有未成年人：
- 失去最大用户群体的传播能力
- 学生才是真正的日活主力，家长/教师 DAU 远低于学生端

**建议**：改为**监护人授权制**——
- 学生注册时 `guardian_declaration` 字段已存在（见 encryption.rs）
- 扩展逻辑：学生发起分享前需确认监护人已同意
- 或：学生分享的佣金由监护人代收/代管
- 或：学生可生成海报（品牌曝光），但不参与佣金结算（降低了驱动力但保留了传播面）

### 2. 冷启动闭环缺失

**现状**：文档假设营销活动已存在、用户已进入系统。

**问题**：MVP 上线第一天——
- 谁来创建第一个营销活动？
- 没有推广员，没有收益，没有团队树
- §9.9 的"连续 2 天未生成海报"提示永远不触发（因为没有用户会打开成就页）

**建议**：设计一条从 0 到 1 的冷启动路径——
- 预置 1-2 条默认活动（代码硬编码，"邀请好友得7天"），上线即生效
- 创始团队前 50 名种子用户手动绑定推广关系（RLHF 式冷启动）
- 首日收益数据 mock（展示"如果你邀请了 3 个朋友，你会获得..."的假设页面）

### 3. 无病毒系数 (K-factor) 目标与优化

**现状**：零提及 K-factor。

**问题**：没有 K-factor 目标，就无法知道"设计了 100 行活动配置，但到底有没有用"。

**K-factor = 每用户邀请人数 × 邀请转化率**

假设当前设计：
- 平均分享 5 次/人（海报保存到朋友圈 + 群聊）
- 海报查看 → 注册转化率 3%
- K = 5 × 0.03 = **0.15**

这远低于可持续增长所需的 K > 1.0。

**要达到 K > 1.0，需要组合拳**：

| 杠杆 | 当前 | 目标 | 策略 |
|:-----|:-----|:-----|:------|
| 邀请人数/人 | 5 | 8 | 多链路曝光（朋友圈+群聊+会话+私聊） |
| 海报点击率 | 3% | 8% | A/B 测试海报样式、文案 |
| 引导注册率 | 30% | 50% | H5 页即时注册（无需下载 APP） |
| **K-factor** | **0.15** | **>1.0** | 上述组合优化 |

**建议**：在 §4 归因规则之后新增 K-factor 一节，定义 MVP 目标 K=0.5，下一阶段 K>1.0，并列出每个优化杠杆的测试计划。

## 🟡 重要问题（强烈建议修复）

### 4. 推广码 UX：12 字符太长

**现状**：格式 `CoEvo_A1B2`（11 字符 + 前缀）。

**对比**：

| 产品 | 推广码格式 | 长度 |
|:-----|:-----------|:-----|
| Uber | `uber123` | 7 |
| Airbnb | `guest1234` | 10 |
| 拼多多 | 6位纯数字 | 6 |
| **CoEvo (当前)** | **CoEvo_A1B2** | **12** |
| **CoEvo (建议)** | **6-8 位大写字母数字** | **6-8** |

- 微信聊天中手动复制长字符串体验差
- `CoEvo_` 前缀是品牌需求但不是用户需求
- 建议改为纯 6-8 位大写字母数字（如 `A1B2C3`），前缀只在展示时加

### 5. 缺失：渠道矩阵与优先级

**现状**：§9 详细设计了微信链路的 H5/海报，但**假设微信是唯一渠道**。

**问题**：

| 渠道 | 当前支持 | 潜力 | 优先级 |
|:-----|:---------|:-----|:-------|
| 微信朋友圈 | ✅ SVG 海报 | ★★★★★ | P0 |
| 微信会话 | ✅ H5 链接卡片 | ★★★★★ | P0 |
| 微信小程序 | ❌ 未设计 | ★★★★ | P1（无公众号，但小程序可内嵌分享） |
| 抖音私信 | ❌ 未设计 | ★★★ | P2 |
| 小红书 | ❌ 未设计 | ★★★ | P2 |
| QQ/QQ空间 | ❌ 未设计 | ★★ | P3 |
| 线下面对面扫码 | ✅ QR 码 | ★★★ | P1 |

**建议**：在 §9 新增渠道矩阵，按以下维度评分：
1. 用户覆盖面（CoEvo 目标人群在哪个渠道活跃）
2. 分享成本（一键 vs 多步）
3. 归因能力（能否追踪到转化）
4. 实现成本

### 6. 缺失：首单分享者的"Aha Moment"设计

**现状**：佣金面板显示"🔒 30天锁定期"，用户分享后要等 30 天才能看到收益。

**问题**：
- 行为心理学：奖励必须在行动后 **立即或短时间** 内出现，才能形成习惯回路
- 等待 30 天 = 90% 的新推广员在第一天放弃
- 只靠"每日生成海报"的成就系统（§9.9）不足以驱动重复分享

**建议**：增加**即刻反馈**机制——

```
用户 A 首次分享后 → 即时反馈流:
  1. ✅ "分享成功！你的推广码已生效"（即时通知）
  2. 🎉 "获得 1 天分享者奖励"（首次分享即送，不依赖对方注册）
  3. 🔮 "当有好友通过你的链接注册时，你还会获得..."
  4. 👀 通知小红点亮起（"有人打开了你的分享链接"）
  
  如果 B 在 10 分钟内点击链接:
    → 💬 推送: "你的朋友正在看你的学习海报！"
    → 用户 A 感受到实时社交反馈，更可能再次分享
```

### 7. LLM 成本缺乏弹性上限

**现状**：§9.10 估算 DAU 1000 时日均 ¥10-20。

**风险**：

| DAU | 日均成本 | 月均成本 |
|:----|:---------|:---------|
| 1,000 | ¥10-20 | ¥300-600 | ✅ 可控 |
| 10,000 | ¥100-200 | ¥3,000-6,000 | ⚠️ 值得关注 |
| 100,000 | ¥1,000-2,000 | ¥30,000-60,000 | 🔴 不可持续 |

在不知道 ARPU / LTV 的情况下，¥30,000/月的生成成本可能吃掉全部利润。

**建议**：
1. 设置**硬性日预算上限**（如 app_config `daily_llm_budget_cents`，超出后降级为默认模板）
2. 海报 + H5 **合并为一次 LLM 调用**（§9.8 说"分开调用"——建议重新评估，可以设计一个 prompt 同时输出 SVG 片段 + HTML 片段）
3. 按**活跃度分层**：只有过去 7 天有学习行为的用户才触发 LLM 生成（避免 DAU 中的僵尸用户浪费成本）
4. 默认模板做 3 种不同风格，A/B 测试发现 LLM 生成 vs 模板的转化率差异，如果差异不显著，直接用模板

### 8. 用户自我归因查询 UX

**现状**：§4.1 说点击后 localStorage 存 `ref_by=A`，B 注册时提交。

**问题**：如果用户清浏览器缓存、换设备、或微信内置浏览器隔离：
- `localStorage` 丢失
- 归因断裂，CPS（按销售付费）归零
- 推广员辛苦白费

**建议**：双重归因——
1. URL 参数 `ref`（**不依赖 localStorage**，注册时直接从 URL 取）
2. localStorage 作为备用（浏览器场景）
3. 推广员生成的海报 QR 码已内含 `ref` 参数，扫码注册直接带参

当前 §4.3 的设计已经部分覆盖（注册时提交 `referral.code`），但需要确保注册 API 的 `referral` 字段在 Web 端从 URL 参数取、在 APP 端从分享链路参数取，**不依赖前端自己存的 localStorage**。

## 🔵 增长优化机会（建议纳入 roadmap）

### 9. 建立增长实验框架

**现状**：零实验设计。

**最低可行实验框架**：

```
每 2 周一个增长实验

实验 #1: 海报样式 A/B 测试
  ├─ 控制组: LLM 生成个性化海报
  ├─ 实验组: 固定模板 + 变量替换（省成本）
  └─ 指标: 点击率 / 注册率 / 每分享成本

实验 #2: 奖励结构 A/B 测试
  ├─ 控制组: 双方各得 7 天会员
  ├─ 实验组A: 邀请者得 14 天 / 被邀请者得 3 天
  ├─ 实验组B: 邀请者得 ¥5 红包（现金感更强）
  └─ 指标: 分享率 / 注册转化率 / 获客成本

实验 #3: 推送时机 A/B 测试
  ├─ 控制组: 注册后立即推送分享活动
  ├─ 实验组A: 学习 3 天后推送（有了数据再分享，海报更有说服力）
  ├─ 实验组B: 完成第一个任务后推送（"成就感"时刻分享）
  └─ 指标: 分享率 / 海报保存率
```

### 10. 推广者留存飞轮

**现状**：分享一次后反馈周期太长（30天解锁）。

**设计留存飞轮**：

```
Day 0  → 首次分享 → ✅ 即时奖励 + 引导语
Day 1  → 有人点击了你的链接 → 💬 通知: "有人看了你的学习海报"
Day 3  → 无人注册 → 💬 提示: "把海报发到家长群试试？"
Day 7  → 累计分享奖励 → 🎁 "连续分享 7 天，送你 7 天会员"
Day 30 → 佣金解锁 → 💰 "¥20 已到账，可以去提现了"
```

这个飞轮每 7 天一个循环，与成就系统（§9.9）联动。

### 11. 非微信渠道的前置优化

**假设**：CoEvo 是 K12 教育产品，学生群体在以下渠道活跃度高于微信会话：

| 渠道 | 学生活跃度 | 分享形式 | 实现难度 |
|:-----|:----------|:---------|:---------|
| QQ 群 | ★★★★★ | 链接卡片 | 低（已有 H5 链接） |
| 班级微信群（家长群）| ★★★★ | 海报 | 低（已有 SVG 海报）|
| 学校 BBS/社区 | ★★★ | 图文 | 中 |
| 小红书 | ★★★ | 图文笔记 | 高（需适配平台风格）|

建议：P0 阶段聚焦**微信链路**（已覆盖），P1 增加 **QQ/QQ空间** 一键分享（国内学生 QQ 使用率仍高于微信）。

### 12. 分级佣金结构优化

**现状**：Fixed 10%（一级）/ 5%（二级）比例。

**问题**：固定比例下，高价值订单（¥1,280 终身）和低价值订单（¥200 月卡）对推广者的激励差异巨大。如果推广者只推大单，小单被忽略。

**建议**：阶梯佣金——

| 推广者月推广量 | 一级佣金 | 二级佣金 |
|:---------------|:---------|:---------|
| 0-2 单 | 10% | 5% |
| 3-5 单 | 12% | 6% |
| 6-10 单 | 15% | 8% |
| 10+ 单 | 18% | 10% |

阶梯结构：
- 激励推广者冲量
- 防止"只推大单，不管小单"的偏科行为
- 与成就系统（§9.9 分享达人/社交之星）联动

调整为 `marketing_campaigns.rewards` JSON 中的阶梯数组支持。

| 能力维度 | 文档表现 | 评分 |
|:---------|:---------|:-----|
| 数据层设计 | 精细、完备、可扩展 | ★★★★★ |

| LLM 创意 | 个性化海报是亮点 | ★★★★ |
