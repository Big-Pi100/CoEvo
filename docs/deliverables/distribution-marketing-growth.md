# CoEvo 增长活动策划

> 版本: v1.0 · 2026-06-19  
> 前置系统: `distribution-marketing-design.md` V2.0（分销基础建设）  
> 设计者: Growth Hacker

---

## 核心理念

> 分销系统是**基础设施**，增长活动是**弹药**。  
> 没有弹药的基础设施，只是一堆空 SQL 表。

这套增长活动的设计逻辑：

1. **病毒资产**：用户每次学习都在生成可分享的内容（学习海报、成就卡、进步报告）
2. **习惯回路**：分享不是一次性动作，而是学习行为的自然延伸
3. **阶梯激励**：从即时满足 → 7天习惯 → 30天持续 → 90天成为推广大使
4. **多阶段冷启动**：从创始人亲自拉到100人，再靠300人裂变到3000人

## 活动一：「创始会员」— 预热期种子计划

**目标**：上线前聚集 100 名种子用户，他们既是首批付费用户，也是第一批推广员。

### 核心机制

| 项目 | 内容 |
|:-----|:------|
| 资格 | 前 100 名注册并完成首次学习对话的用户 |
| 定价 | 终身会员 **五折**（原价 ¥1,280/年 → ¥1280/终身） |
| 条件 | 上线后 7 天内完成激活 |
| 推广特权 | 种子用户的推广佣金 **永久提升至 15%**（基准为 10%） |

> 这是冷启动的核心杠杆。100 个人不是最终目标——这 100 人是**传播节点**，每人最多影响 10 个人就是 1000 人。

### 冷启动执行方案

| 时间 | 动作 | 责任人 |
|:-----|:------|:-------|
| 上线前 30 天 | 创始人在朋友圈/个人社交账号发预告："我在做一款对抗AI焦虑的学习产品，找100个最早体验的人" | 创始人 |
| 上线前 14 天 | 建立微信群"CoEvo 创始会员群"，每天分享开发进度、设计稿 | 创始人 |
| 上线前 7 天 | 群内发起"每日打卡"预热活动（还没产品就先用 Notion/AirTable），培养习惯 | 创始人 |
| 上线日 | 群内首发 + 每人给 5 个亲友邀请码（亲友同样享 7 天免费体验） | 系统发送 |
| 上线后 7 天 | 群内评选"最早完成 100 张卡片"的成员，奖励额外 30 天会员 | 社群运营 |

### 所需系统支持

- 管理端 → 创建活动 `campaign_type: commission`，`rewards` JSON 写 `founder_bonus_rate: 0.15`
- 注册 API → `applicable_campaigns` 字段标记 `is_founder: true`
- 无额外开发，纯配置驱动的活动

## 活动二：「每天进化1%」— 打卡式裂变（核心引擎）

**这是 CoEvo 的增长飞轮。所有其他活动都是这个飞轮的加速器。**

### 飞轮逻辑

```
用户 A 完成每日学习任务
    ↓
系统自动生成今日海报（LLM 个性化）
    ↓
A 看到海报被分享到朋友圈（成就驱动）
    ↓
B 看到海报上的 QR 码（扫码）
    ↓
B 看到 H5 分享页 → 注册 CoEvo → A 获得奖励
    ↓
B 也开始学习 → 第二天 B 也生成海报 → 循环
```

### 活动配置

| 参数 | 值 |
|:-----|:----|
| 活动类型 | `invite_award + commission` |
| 条件 | 每日完成至少 1 轮复习 |
| A 奖励 | B 注册赠 A **3 天会员**（即时，非 30 天锁定） |
| B 奖励 | 注册即得 **7 天免费体验** |
| 额外激励 | A 每月带来 ≥3 人 → 次月佣金率提升至 12% |
| 推送时机 | 用户完成每日学习任务后，弹窗展示海报 |

### Aha Moment 设计（关键）

传统的"分享得奖励"的问题是**延迟反馈**。CoEvo 的解法是靠海报本身的成就感先驱动首次分享：

```
用户 A 完成第 1 次复习 → 弹出海报
  └→ 海报内容："A 今天学习了 8 张卡片，正确率 75%"
  └→ A 的第一反应："这张图挺好看的，发朋友圈吧"
  └→ ✅ 首次分享完成（零门槛，不依赖奖励承诺）
  └→ 系统即时推送小红点："你的朋友 B 正在看你的海报！"
       └→ A 感受到社交认可，驱动第二次分享
```

关键区别：

| 维度 | 传统分销 | CoEvo 策略 |
|:-----|:---------|:-----------|
| 分享驱动力 | "分享能赚钱" | "这张海报好看 + 顺带赚钱" |
| 反馈周期 | 30 天后到账 | 即时海报生成 + 即时点击通知 |
| 分享频率 | 偶尔被激励才分享 | 每天学习自动有内容可分享 |
| 社交背书 | 纯广告链接 | 个人学习成果 = 真实背书 |

### 所需系统支持

- ✅ 海报生成 API（§9.11 已设计）
- ✅ 点击通知（§9.11、user_notifications 表）
- ❌ **待补充**：分享后小红点的实时推送（需要 WebSocket 通知或轮询检测）

## 活动三：「同桌计划」— 强关系裂变

**目标**：由内生增长转向"学习伙伴"式的强关系传播。

### 核心机制

| 概念 | 说明 |
|:-----|:------|
| "同桌" | A 邀请 B，B 接受邀请后二人绑定为同桌 |
| 绑定奖励 | A 和 B 各获得 **5 天会员** |
| 同桌学习 | 二人每天的学习数据互相可见（完成率、卡片数），形成轻度社交 |
| 同桌挑战 | 二人连续 7 天同时完成学习 → 各获得 **7 天会员** |
| 佣金加成 | 如果 B 也成为了推广员，B 邀请的人 A 也能享受 2% 的二级佣金 |

### 为什么"同桌"比"分销员"更有效？

| 维度 | 传统分销 | 同桌模式 |
|:-----|:---------|:---------|
| 身份 | 我是推销员 | 我是学习搭子 |
| 传播动力 | 赚钱 | 一起进步 + 社交压力 |
| 目标对象 | 所有人 | 我认识的具体一个人 |
| 转化率预判 | 3-5% | 15-30%（强关系） |
| 适合场景 | 社交媒体广撒网 | 私聊、班级群、家长群 |

### 操作流程

```
A 点击"找个同桌"
  → 生成邀请链接（带回参）
  → 发给微信好友 B
  → B 注册并接受邀请
  → 二人成功绑定为同桌
  → 各自收到推送："你和 B 成为同桌了！"
  → 每天各自完成学习 → 同桌进度显示
  → 两人都完成当天学习 → 击掌动画 + 额外积分
```

### 所需系统支持

- ❌ **需要新建**：`learning_buddies` 表（buddy_pair_id, user_a, user_b, created_at, streak_days）
- ✅ 现有 referral 系统可复用（邀请链路 → 注册 → 属性标记）
- ❌ 同桌进度展示：前端需要新增"同桌"Tab

## 活动四：「学霸周榜」— 竞争裂变

**目标**：利用排名驱动的焦虑和炫耀心理，刺激高活跃用户分享。

### 核心机制

| 项目 | 说明 |
|:-----|:------|
| 周期 | 每周一凌晨结算 |
| 指标 | 本周完成**复习卡片数**（非制卡数，制卡无门槛） |
| 分组 | 按会员等级分组（免费用户 vs 付费用户） |
| 可视化 | SVG 排名海报（LLM 生成，包含排名变化箭头 △/▽） |
| 分享触发 | 周榜生成后自动推送给 TOP 10% 用户："你的周榜排名来了" |

### 奖励结构

| 排名 | 奖励 |
|:-----|:------|
| 组内第 1 名 | 30 天会员 + 专属"学习王者"勋章 |
| 组内前 10% | 7 天会员 + "学霸"称号 |
| 组内前 30% | 3 天会员 |
| 相比上周进步最大 | 7 天会员 + "进步之星"勋章 |

### 病毒引擎

排名海报本身就具有强传播性：

```
               ┌──────────────────────┐
               │   ✨ 本周学习排行榜     │
               │                      │
               │  🥇 张三 · 428 张卡片  │ ← 第一名（炫耀）
               │  🥈 李四 · 356 张卡片  │
               │  🥉 王五 · 289 张卡片  │
               │                      │
               │  📈 你 · 124 张卡片     │ ← 普通用户（焦虑）
               │  ↑ 上周第 24 名        │
               │                      │
               │ 扫码加入，下周上榜      │
               └──────────────────────┘
```

- **前几名用户**：主动分享炫耀 → 社交背书
- **普通用户**：看到差距产生焦虑 → 激励增加学习 → 或转发给朋友（"你也来，咱们一起学"）
- **未上榜用户**：不分享排名（避免羞辱感），改为推送："下周还差 50 张就上榜了"

### 所需系统支持

- ✅ 已有 achievement_engine（可扩展新成就触发器）
- ✅ 已有 LLM 海报生成（周榜海报是模板化的，不必须 LLM，固定模板更省钱）
- ❌ **待补充**：周榜计算 cron 任务（每周一凌晨 00:30 计算）
- ❌ **待补充**：排行榜 API `/api/leaderboard/weekly`
- ❌ **待补充**：排行榜前端页面

## 活动五：「AI 进化周报」— 内容型裂变（社交资产型）

**目标**：创造用户愿意主动分享的"社交资产"，而非推销链接。

### 机制

每年暑假/寒假前4周和考试前3周打开入口（以第一次进入为准，非一次性）：

```
┌──────────────────────────────┐
│       张三的 AI 进化周报        │
│                              │
│  📚 本周学习 156 张卡片        │
│  🎯 正确率 82% ↑ 5%          │
│  🔥 连续学习 12 天            │
│  💪 薄弱学科: 英语时态         │
│  🏆 本周打败了 87% 的 CoEvo用户 │
│                              │
│  扫码开始你的进化              │
└──────────────────────────────┘
```

核心设计思路：

这个活动的目标是制造"社交货币"，用户分享的不是广告链接，而是**展示自己努力成果的荣誉徽章**。海报上每一行数据都是用户自己的学习成就——看到「本周打败了 87% 的用户」这句话，用户会本能地想："我要让朋友看看我有多努力"。

分享是自我表达，不是推销。

### 技术实现

```python
# 伪代码逻辑
def generate_weekly_report(user_id):
    stats = get_weekly_stats(user_id)  # 卡片数、正确率、连续天数
    percentile = get_user_percentile(stats.total_cards)
    weak_areas = get_weak_subjects(user_id)

    if stats.days_active >= 5:  # 活跃用户 → LLM 个性化生成
        poster = llm_generate_poster(stats, percentile, weak_areas)
    else:  # 非活跃用户 → 模板海报 + 激励文案
        poster = template_poster("下周一起加油！")

    return poster
```

### 所需系统支持

- ✅ LLM 海报生成 API（复用）
- ❌ **待补充**：每周统计聚合 SQL（`card_memory` + `review_sessions` 聚合）
- ❌ **待补充**：用户 percentile 计算（分布统计）

### 实施计划

每周一和周报推送协同——一天里跑一次周榜 API 和一次周报生成，同一天的两次热点算作一次爆发。

## 活动六：「新学年冲刺」— 场景化限时活动

**目标**：结合学期节奏，在关键时间窗口（开学季 / 期末季 / 寒暑假）制造爆发式增长。

### 活动日历（年度）

| 时间 | 活动名 | 核心机制 |
|:-----|:------|:---------|
| 2 月下旬 | 🎒 开学逆袭计划 | 活动期内注册 = 立即激活 14 天体验 + 完成首周任务另送 7 天 |
| 6 月上旬 | 📚 期末冲刺营 | 拼团：3 人成团享 7 折 + 团长额外 7 天 |
| 7-8 月 | ☀️ 暑假弯道超车 | 每日打卡满 30 天送 30 天（买一送一） |
| 9 月 | 🎒 秋季开学 | 老用户邀请新生注册 = 双方各得 14 天 |
| 12 月 | 📚 期末冲刺 | 双人拼团 7 折 + 团长 14 天 |
| 1 月 | 🧨 寒假特训 | 寒假 30 天挑战，完成享额外奖励 |

### 第一个版本 MVP（只实现最有效的一个）

**优先做「3人拼团7折」**，原因：

1. 拼团自带裂变属性（必须 3 人才能成团）
2. 学期冲刺场景真实，K12 家长支付意愿高
3. 技术实现简单（`marketing_campaigns` 加 `campaign_type: ` `team_discount`）
4. 测试期仅需 5 天就能看到数据

### 拼团流程

```
A 看到活动 → 支付全价 ¥200（占位）
  → 生成拼团链接 -> 发给 B 和 C
  → B 和 C 分别支付 ¥200
  → 3 人成团 → 各自退款差额（¥200 → ¥140）
  → 系统推送："你和 A/B/C 的拼团成功了！"
```

**关键设计**：先付全价再退差额，避免拼团失败导致的收入损失。

## 活动七：「老师推荐码」— 教育行业垂直裂变

**目标**：利用教师的影响力，批量获取学生用户。

### 核心机制

| 概念 | 说明 |
|:-----|:------|
| 适用对象 | 英语/语文老师（已有课程知识，能测试产品价值） |
| 推荐码 | 老师生成专属邀请码，发给全班学生 |
| 老师收益 | 学生注册 + 使用 ≥7 天 = 老师得 ¥20/人 |
| 学生收益 | 使用老师的推荐码注册 = 首月半价 |
| 班级看板 | 老师能看到全班的使用数据（匿名统计：完成率、进步情况） |

### 为什么老师是最佳推广节点

| 节点 | 影响力 | 一次影响人数 | 信任度 | 佣金敏感度 |
|:-----|:-------|:------------|:------|:-----------|
| 学生 | 低 | 3-5 人 | 一般 | 高 |
| 家长 | 中 | 1-2 人 | 一般 | 中 |
| **老师** | **极高** | **30-50 人** | **高** | **低** |
| 教育博主 | 高 | 1000+ | 中 | 中 |

1 个老师 = 1 个班 40 人 + 口口相传 = 潜在的 100+ 用户

### 执行要点

- 不主动推广给老师，而是在**现有用户中识别老师身份**（注册时可选"您是老师吗？"）
- 教师端功能（班级看板）是核心钩子，比佣金更有吸引力
- 与「同桌计划」联动：学生之间的绑定自动归属于老师的影响力树

### 所需系统支持

- ❌ **需要新建**：`teacher_classrooms` 表 + 班级看板功能
- ✅ 现有 referral 系统可支持推荐码生成 + 佣金结算

## 增长实验框架

每两周一个增长实验，用数据驱动下一个活动方向。

### 实验 #1: 海报生成方式

| 项目 | 控制组 | 实验组 |
|:-----|:-------|:-------|
| 海报类型 | LLM 个性化生成 | 固定模板（3种风格随机） |
| 指标 | 点击率 / 注册转化率 / 分享率 | 同上 |
| 样本量 | 50% 用户 | 50% 用户 |
| 周期 | 14 天 | 14 天 |

**问题**：个性化 LLM 海报是否值日均 ¥10-20 的成本？
**预期**：实验组（LLM）点击率高 15-30% → 保留 LLM；差异小 → 改用模板，成本归零。

### 实验 #2: 奖励结构

| 项目 | 控制组 | 实验组 |
|:-----|:-------|:-------|
| 奖励 | A +3天 / B +7天 | A +¥5红包 / B +¥5红包 |
| 指标 | 分享率 / 注册转化率 / 获客成本 | 同上 |
| 周期 | 14 天 | 14 天 |

**问题**：虚拟会员 vs 现金红包，哪个激励效果更好？
**预期**：现金红包分享率高 20-40%，但获客成本也高——需计算 LTV/CAC。

### 实验 #3: 推送时机

| 项目 | 控制组 | 实验组 |
|:-----|:-------|:-------|
| 推送时机 | 注册后立即推送分享活动 | 学习 3 天后推送 |
| 指标 | 分享率 / 海报保存率 | 同上 |
| 周期 | 14 天 | 14 天 |

**问题**：是让新用户一进来就分享，还是先体验产品再分享？

### 实验 #4: 同桌 vs 分销

| 项目 | 控制组 | 实验组 |
|:-----|:-------|:-------|
| 邀请机制 | 标准分销（佣金 + 会员奖励） | 同桌模式（社交 + 挑战） |
| 指标 | 邀请转化率 / 留存率（接受邀请方） | 同上 |
| 周期 | 14 天 | 14 天 |

**问题**："一起学" vs "赚佣金"哪个转化率和留存更高？
