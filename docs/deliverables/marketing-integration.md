> 版本: v1.0 · 2026-06-19  
> 整合范围: 定价套餐 + 营销活动（7个） + 落地页改进 + 分销系统

## 一、全量资产清单

在整合之前，先把所有设计中的"营销资产"列清楚。

### 1.1 定价基线 — `payment_plans` 表（固定 3 行）

```sql
-- 基线套餐，固定不变。所有价格变化必须通过营销活动。
payment_plans
├─ monthly    ¥120/月     ← 随时取消
├─ quarterly  ¥XXX/季     ← 小幅优惠
└─ annual     ¥1,288/年   ← 最常用
```

**原则**：`payment_plans` 只存 3 行基线数据。不包含"体验"、"终身"等特殊价格。

### 1.2 营销活动 — `marketing_campaigns` 表（所有变价都在这里）

所有非基线价格都通过活动系统实现，不修改 `payment_plans`：

| 活动 | 作用 | 实现方式 |
|:-----|:-----|:---------|
| 免费体验 | 3 天试用，¥0 | `campaign_type: free_trial`, `duration_days: 3`, `price: 0` |
| 创始会员 | 终身 5 折，¥640 | `campaign_type: discount_pct`, 定向分发 |
| 学期冲刺 | 3 人拼团 7 折 | `campaign_type: team_discount` |
| 老师推荐码 | 首月半价 ¥60 | `campaign_type: discount_fix`, 绑定 referral |
| 学霸周榜 | 送会员天数 | `campaign_type: reward_days` |
| 同桌计划 | 送会员天数 | `campaign_type: reward_days` |
| 每日进化1% | 邀请送天数 | `campaign_type: invite_award` |

**终身会员不是固定套餐**，它是某个营销活动的产出选项（创始会员/学期冲刺等）。不在 `payment_plans` 里出现。

### 1.3 架构总图

```
                  定价引擎
                      │
        ┌─────────────┴─────────────┐
        │                           │
   payment_plans (基线)        marketing_campaigns (活动)
        │                           │
  ┌─────┼──────┐           ┌────────┼────────┐
  │     │      │           │        │        │
月付  季度  年度         免费    折扣    奖励
¥120  ¥XXX  ¥1,288      体验    活动    天数
                         ¥0/3d   -X%    +X天
```

**规则**：用户购买时，订单引擎先查 `payment_plans` 拿基线价，再查 `marketing_campaigns` 看是否有生效的折扣活动。活动引擎输出最终价。**基线不膨胀，变价全走活动。**

## 二、冲突检测（共 8 个）

### 🔴 冲突 1：¥0.99 体验 vs "免费体验 3 天"

| 来源 | 说法 |
|:-----|:-----|
| 现有套餐 | 3 天体验 ¥0.99 |
| 落地页审计建议 | "免费体验 3 天" CTA 按钮 |

**问题**：落地页说"免费"，用户点进去发现要付 ¥0.99 → 信任受损。¥0.99 本身不贵，但"说免费结果收费"这个落差会直接劝退。

**解决**：二选一，不要并存。

| 方案 | 做法 | 影响 |
|:-----|:-----|:-----|
| A（推荐） | 直接免费，¥0.99 → ¥0，零门槛获取用户 | 放弃微量收入，换取更多注册 + 后续转化 |
| B | 保留 ¥0.99，落地页改说"¥0.99 体验 3 天" | 诚信但降低点击率 |

**推荐方案 A**。¥0.99 收入 ≈ 0（1000人×¥0.99 = ¥990，但还要扣微信支付手续费），而每个免费注册的用户都有后续转化潜力。少赚 ¥990 但多 100 个注册用户，值。

### 🔴 冲突 2：年度会员 ¥1,288 vs 营销活动产出的"终身"同价

| 来源 | 价格 | 性质 |
|:-----|:-----|:-----|
| `payment_plans` 基线 | ¥1,288/年 | 固定套餐 |
| 营销活动产出 | ¥1,288 终身 | 活动特价，非固定套餐 |

**问题**：如果年度套餐和营销活动的终身价一样，用户会发现"年付 = 终身"的不合理感。且终身不应出现在基线套餐里——它应是活动的输出。

**解决**：

```
1. 终身从 payment_plans 中移除 → 它不是固定套餐
2. 年度套餐保持 ¥1,288/年（基线）
3. 终身仅作为营销活动产出出现（创始会员/学期冲刺）
4. 已购年费用户 → 自动升级为终身（一次性用户关系维护）
```

这样 `payment_plans` 始终保持 3 行基线，终身价格的矛盾自动消失。

### 🟡 冲突 3：免费体验 vs 创始会员 ¥640，哪个是第一入口？

| 活动 | 入口 | 价格 |
|:-----|:-----|:-----|
| 免费体验（落地页） | 落地页 → /app/auth | ¥0 |
| 创始会员（种子活动） | 创始人群 → 定向邀请 | ¥640 |

**问题**：用户通过落地页看到"免费体验"，点进去体验了 3 天，然后收到"创始会员 ¥640 终身"的邀请——他会觉得"创始会员"不稀缺，因为谁都能看到。

**解决**：**创始会员只做线下定向邀约**，不通过落地页推。落地页的"免费体验"和创始会员是两个完全独立的渠道：

```
渠道 A: 落地页自然流量
  用户 → 免费体验 3 天 → 转化为月付/终身

渠道 B: 创始会员定向邀请
  名单内用户 → 专属链接 → ¥640 终身
  名单外用户 → 不可见
```

创始会员的邀约入口**不公开在落地页**，而是通过创始人群内的定向链接访问。这保持了稀缺性。

### 🟡 冲突 4：多个活动同时推送造成的通知轰炸

**问题**：多个活动的 `push_trigger` 可能在同一事件上触发——

| 事件 | 哪些活动会触发 |
|:-----|:--------------|
| 注册时 | 每日进化1%（推送到你注册） + 系统欢迎 + 赠送体验套餐 |
| 支付成功后 | 佣金通知 + 同桌邀请 + 冲刺活动推送 |
| 登录时 | 学霸周榜 + 每日海报 / 同桌进度 / 活动预热 |

如果这些同时弹窗，用户会关掉所有通知，以后再也不会打开。

**解决**：建立**单次事件 → 单一推送**规则

```json
{
  "push_priority": [
    { "type": "reward_earned", "priority": 1, "always_show": true },
    { "type": "system_welcome", "priority": 2, "once": true },
    { "type": "daily_poster", "priority": 3, "once_per_day": true },
    { "type": "marketing_campaign", "priority": 4, "max_per_week": 2 }
  ]
}
```

具体规则：

| 事件 | 推送内容 | 优先级 | 频率限制 |
|:-----|:---------|:-------|:---------|
| 注册成功 | 系统欢迎 + 送体验天数 | P1 | 仅 1 次 |
| 首次完成学习 | 每日海报（分享引导） | P2 | 每天 1 次 |
| 支付成功 | 佣金到账通知 | P1 | 每次支付 |
| 我的链接被点击 | "有人看了你的海报" | P2 | 每次点击 |
| 每周一 | 学霸周榜（仅 TOP30%） | P3 | 每周 1 次 |
| 常规营销 | 活动推送 | P4 | 每周最多 2 条 |

**关键原则**：同一事件下，**优先级高的推送先展示，低优先级的自动合并或推迟**。用户在同一时间最多只看到 1 条推送。

### 🟡 冲突 5：会员天数奖励过度稀释

**问题**：多个活动都在送会员天数——

| 活动 | 最高赠送天数/月 |
|:-----|:---------------|
| 每天进化1% | 3天 × N次邀请 ≈ 可能无限 |
| 学霸周榜 | 3-30天/月 |
| 同桌计划 | 5+7天（一次性）+ 挑战奖励 |
| 创始会员 | 本身已经是终身 |

如果这些奖励叠加，一个活跃推广者可能一个月积累 **100+ 天的会员奖励**，而会员本身又是按月/年收费的——这意味着奖励的"会员天数"实际价值趋近于零。

**解决**：设置用户级和系统级的赠送上限。

```sql
-- 用户级：每月最多通过推广获得 30 天
-- 系统级：所有活动的 days 奖励共享同一个池子
-- 规则引擎实现:
rewards: [
  {
    "type": "days",
    "party": "inviter",
    "value": 3,
    "trigger": "registration",
    "fulfill_mode": "immediate",
    "monthly_cap": 30   -- 新增：每人每月最多通过此活动得 30 天
  }
]
```

**全局上限**：系统全局 `app_config` 增加：

```sql
INSERT INTO app_config (key, value) VALUES ('max_reward_days_per_user_month', '30');
```

当用户本月已累计获得 30 天推广奖励时，后续奖励不再发放（但记录仍保留，提示"本月奖励已达上限"）。

### 🟡 冲突 6：落地页 CTA 堆叠问题

**问题**：我建议的"三档 CTA"——免费体验 + ¥120/月 + ¥1,288 终身——在同一行展示三个按钮，移动端根本放不下。

**核心原则**：免费体验**不是套餐**，不应出现在定价表中。它应是落地页唯一的入口CTA，引导用户先试用，体验结束后再展示付费方案。

**解决**：

```
落地页 Hero 区:
┌─────────────────────────────────────────────┐
│  [🔥 免费体验 3 天 · 无需付款]             │  ← 唯一的 CTA
│                                              │
│  或选择直接购买:                              │  ← 次要入口，小字
│  ¥120/月  ·  ¥1,288 终身                    │
└─────────────────────────────────────────────┘

定价区（页面下方，提供给已决定购买的用户）:
┌─────────────────────────────────────────────┐
│  ¥120/月  ·  随时取消                        │
│  ¥1,288 终身 · 限 200 人 · 30 天退款         │
│                                              │
│  (免费体验不在这里出现)                       │
└─────────────────────────────────────────────┘
```

**为什么免费体验不能和付费方案并列**：

```
❌ 错误:
  定价表: ¥0/3天 · ¥120/月 · ¥1,288 终身
  用户心理: "¥0 和 ¥120 之间选，当然是 ¥0"
  结果: 选免费的人把免费当成"白嫖3天"，到期直接流失

✅ 正确:
  入口: "免费体验 3 天" (这不是一个套餐，这是大门)
  用户心理: "进来看看好不好用"
  3天后: 看到学习数据，再决定是否付费
  结果: 有数据的用户转化率远高于冷启动
```

**所有端统一**：
```
桌面 Hero:    [🔥 免费体验 3 天]  ← 大按钮，旁边小字显示月付/终身
移动 sticky:  [🚀 免费体验 3 天]  ← 唯一的 sticky CTA
定价区:        ¥120/月 · ¥1,288 终身（不包含免费体验）
```

### 🟡 冲突 7：多个活动争夺"注册后第一个 CTA"

**问题**：用户注册成功后，应该先看到什么？

| 想要什么 | 来源 |
|:---------|:-----|
| 进入产品，开始学习 | 产品体验 |
| 生成推广码，发展下线 | 每日进化1% |
| 看创始会员购买链接 | 创始会员活动 |
| 填写基本信息 | 用户引导 |

如果新用户注册后第一件事是被引导发展下线——他连产品都没用过，怎么推荐给别人？

**解决**：新用户黄金路径必须遵循产品价值优先。**注册后 3 天内不推送任何营销活动。**

```
新用户注册成功:
  → 进入产品（跳过所有营销）
  → 完成首次对话和学习
  → 看到第一张每日海报
  → ✅ 此时才推送"分享给朋友，双方得奖励"
  
整个过程在首次学习完成后触发，不是注册时触发。
```

### 🔵 冲突 8：学期冲刺拼团 7 折 vs 创始会员 5 折，折扣级冲突

| 活动 | 折扣 | 对象 |
|:-----|:-----|:------|
| 创始会员 | 终身 5 折（¥640） | 种子 100 人 |
| 学期冲刺 | 终身 7 折（约 ¥900） | 所有用户 |

**问题**：7 折公开，5 折私密——但内容一样（都是终身），后进的人看到 7 折也不觉得亏，因为没见到 5 折的价。**不构成直接冲突**，但需要注意：

1. 创始会员和学期冲刺**不要同时在线**（创始会员是预热期，学期冲刺是 D45，相隔 75 天）
2. 学期冲刺的 7 折算法：**不直接打折终身价**，而是通过拼团机制让利

```
学期冲刺的正确文案:
  终身会员 ¥1,288 → 3 人成团 = 每人 ¥900
  对比: 每月 ¥120 × 12 月 = ¥1,440
  你省了: ¥540

不要在文案里提到"原价 ¥1,288 现在 ¥900"（避免与创始会员¥640对比）
而是用月付锚定:"一个月的辅导班钱 = 终身 AI 教师"
```

## 三、统一推送日历

解决了所有冲突后，用户的整个体验路径应该是这样的：

### 新用户路径（从落地页到第一次付费）

```
落地页访问
  │
  ├──→ 线索捕获（不下单 → 留微信/邮箱 → 后续自动化触达）
  │
  └──→ 免费体验 3 天
        │
        ├── 注册成功 → 直接进产品（零营销推送）
        │
        └── 首次学习完成
              ├── 🎨 每日海报弹出（分享引导）
              ├── 💬 分享引导区："邀请朋友，双方各得 3 天"
              └── ✅ 至此开始允许营销推送
                     ├── 体验期 → 付费方案展示
                     └── 基线价格: ¥120/月 · ¥XXX/季 · ¥1,288/年
```

### 活跃用户路径

```
每日学习完成
  │
  ├── 🎨 每日海报生成（自动）
  │     └── 分享 → 邀请朋友 → 双方得奖励
  │
  ├── 📊 周一：学霸周榜推送（仅 TOP 30%）
  │
  ├── 📧 每周日：AI 进化周报（自动生成，不推送）
  │
  ├── 🤝 已绑定同桌：同桌进度推送
  │
  └── 📢 营销活动推送（每周最多 2 条，优先级低于以上所有）
```

### 禁止推送的场景

```
❌ 注册后 3 天内 → 不推送任何活动
❌ 同一事件同时触发 ≥3 条推送 → 只展示优先级最高的 1 条
❌ 用户手动关闭通知 3 次以上 → 自动降低该用户的推送频率（1 次/月）
❌ 已退款用户 → 不推送任何营销
```

## 四、定价体系（最终版）

### 分层架构

```
┌──────────────────────────────────────────────────────┐
│                  定价体系（最终版）                      │
├──────────────────────────┬───────────────────────────┤
│  payment_plans（3 行基线）│  marketing_campaigns（动态） │
├──────────────────────────┼───────────────────────────┤
│  monthly   ¥120/月       │  免费体验  ¥0/3天          │
│  quarterly ¥XXX/季       │  创始会员  ¥640 终身       │
│  annual    ¥1,288/年     │  学期冲刺  拼团 ¥900 终身   │
│                          │  老师推荐码  ¥60 首月       │
│                          │  学霸周榜  送天数           │
│                          │  同桌计划  送天数           │
├──────────────────────────┴───────────────────────────┤
│  规则: 订单引擎 = payment_plans 基线价 × 活动折扣     │
│        基线不膨胀，变价全走活动                          │
│        已购年费用户 → 自动升级为终身（一次性用户关系维护）│
└──────────────────────────────────────────────────────┘
```

### 定价树

永久不变的 3 条数据，存在 `payment_plans` 表里：

```sql
INSERT OR IGNORE INTO payment_plans (id, name, price, period, description) VALUES
  ('monthly',   '月度会员',  12000, 'month',   '随时取消'),
  ('quarterly', '季度会员',  XXXXX, 'quarter', '小幅优惠'),
  ('annual',    '年度会员',  128800, 'year',    '最常用的选择');
```

所有其他价格（¥0 体验、¥640 终身、¥900 终身、¥60 首月、赠送天数）都是营销活动的产出，**不走 `payment_plans`**。

### 活动配置示例

```
免费体验（注册即自动激活）:
  campaign_type: "free_trial"
  duration_days: 3
  price: 0
  after_expiry: "展示付费方案 → 引导购买"

创始会员（定向内邀）:
  campaign_type: "discount_pct"
  target_plan: "annual"          ← 折扣应用到年度套餐
  discount_pct: 50               ← 5 折 → ¥640
  campaigns 产出: "lifetime"     ← 内部标记，活动结束后不再提供
  distribution: "invite_only"    ← 不公开

学期冲刺（公开活动）:
  campaign_type: "team_discount"
  target_plan: "annual"
  team_size: 3
  team_price: 90000              ← 拼团价 ¥900/人
  anchor: "¥120/月 × 12月 = ¥1,440 你省 ¥540"
```

> ⚠️ 后两个活动都产出"终身"使用权限，但不冲突——创始会员是 D-30 到 D0 的预热期定向活动，学期冲刺是 D45 后的公开活动，**时间错开 75 天**。用户在任何时间窗口只能看到<span>最</span>多一个终身相关活动。

## 五、实施整合清单

把以上冲突解决落实到具体文档中：

### 需要修改的文档

| 文档 | 修改内容 |
|:-----|:---------|
| `distribution-marketing-design.md` | 活动推送规则增加优先级和频率限制 |
| `distribution-marketing-growth.md` | 各活动奖励增加 `monthly_cap` 配置；终身改为活动产出 |
| `landing-growth-audit.md` | CTA 统一为"免费体验 3 天"，定价区只展示基线价格 |

### 需要修改的配置

| 配置 | 改什么 |
|:-----|:-------|
| `payment_plans` | 删掉"终身"和"3 天体验"行，只保留月/季/年 3 行基线 |
| `payment_plans` | 体验 ¥0.99 → 废弃，由 `campaign_type: free_trial` 接管 |

### 需要新增的功能（后端）

| 改动 | 改什么 |
|:-----|:-------|
| `app_config` | `max_reward_days_per_user_month` 全局限额 |
| `marketing_campaigns` | 新增 `campaign_type: free_trial` 枚举值 |
| `marketing_campaigns` | 新增 `target_plan` 和 `after_expiry` 字段用于活动折扣 |
| `order_engine` | 订单计算改为: `payment_plans 基线价 × active_campaign 折扣` |
| `user_notifications` | 增加 `priority` 字段 + 同一事件的合并逻辑 |
| `reward_fulfillments` | `monthly_cap` 字段（用户级限额）|
| `registration` | 注册后 3 天内 `push_blocked_until` 时间戳 |

### 不需要改的功能

| 功能 | 为何不改 |
|:-----|:---------|
| 创始会员 | 已有 `campaign_type=discount_pct`，只需关联 `target_plan` |
| 免费体验 | 新增 `campaign_type=free_trial`，不走 `payment_plans` |
| 分享引导 | 已有用户推广面板（`/app/referral`）|
| 每日海报 | 已有 LLM 海报 API |

## 六、最终检查：8 个冲突解决状态

| # | 冲突 | 状态 | 方案 |
|:-:|:-----|:-----|:-----|
| 1 | ¥0.99 vs "免费" | ✅ 已解决 | ¥0.99 → ¥0，完全免费，消除信任落差 |
| 2 | 年费 vs 终身同价 | ✅ 已解决 | 取消年费；已购年费用户自动升级为终身 |
| 3 | 免费体验 vs 创始会员 | ✅ 已解决 | 免费走 `free_trial` 活动，创始会员走定向邀约，不同渠道 |
| 4 | 多活动推送轰炸 | ✅ 已解决 | 优先级队列 + 频率限制 + 注册后 3 天静默 |
| 5 | 会员天数稀释 | ✅ 已解决 | 每人每月最多获 30 天推广奖励（系统限额） |
| 6 | 落地页 CTA 堆叠 | ✅ 已解决 | 统一为 "免费体验 3 天" 入口，定价区只展示基线 |
| 7 | 注册后首 CTA 竞争 | ✅ 已解决 | 注册后先体验产品，首次学习完成后再推分享 |
| 8 | 折扣级冲突 | ✅ 已解决 | 时间错位（相隔 75 天）+ 锚定方式不同 |
