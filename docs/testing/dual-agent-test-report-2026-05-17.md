## 三、根因分析

### 3.1 计划过大（高频问题）

LLM 倾向于创建 4-6 阶段、15-25 任务的宏大计划。可在 system prompt 中限制：

```diff
+计划包含 2-3 个阶段，每个阶段 2-3 个任务。总共不超过 6 个任务。
```

### 3.2 教学过于详尽

导师 LLM 每次教学包含"概念→举例→小测"完整循环，一个任务需要 3-5 次 LLM 调用（每次 $0.001）。可在 prompt 中压缩：

```diff
+每次教学保持简洁：概念解释（2-3 句）→ 1 个例子 → 1 个检查问题。
+如果学生回答正确，立即推进到下一任务。
```

### 3.3 测试超时

40 轮 × 每次 2 次 LLM 调用（学生 + 导师）= 80 次 API 调用。每次 ~3-5 秒 = 4-6 分钟。加上编译和 setup，总时间 ~8-10 分钟。刚好达到 Bash 10 分钟限制。

## 四、优化建议

| 优先级 | 改进 | 效果 |
|--------|------|------|
| 🔴 P0 | System prompt 限制计划规模（≤3 阶段 ≤6 任务） | 减少 70% 轮次 |
| 🟡 P1 | 缩短教学循环（1个例子+1个检查→即推进） | 每个任务 3-5 轮 |
| 🟡 P1 | 提高轮次上限至 60，延长超时至 15 分钟 | 覆盖完整生命周期 |
| 🟢 P2 | 学生智能体可主动说"我已经理解了，直接出题吧" | 减少冗余教学 |
