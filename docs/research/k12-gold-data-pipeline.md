## 一、核心理念

课标文件只需要三部分：

```
课标 MD → 清洗 → 拆三段
                    │
    ┌───────────────┼───────────────┐
    ▼               ▼               ▼
课程内容           学业质量          附录
(concepts)         (assessment)     (vocab/refs)
    │               │               │
    ▼               ▼               ▼
  LLM提取概念      分割完整条目      规则/LLM提取词表
  + 交叉验证        (不做概念化)      + LLM生成卡背
    │               │               │
    ▼               ▼               ▼
  去重→逻辑排序    运行时LLM评估     词卡
  → plan                             (含音标/释义/例句)
  → cards关联                        + plan绑定
```

**关键原则（V3 更新）：**
1. **三段各有分工** — 课程内容→概念，学业质量→运行时评估，附录→词表。不互相混淆。
2. **学业质量不做概念提取也不预出题** — 学业质量描述是综合性的能力评估条目（覆盖多个 stage/task），预出题不灵活且不安全。改为运行时 LLM 动态生成试卷 + LLM 判卷。
3. **概念提取用 LLM** — 对清洗后的 `_content.md` 分块，LLM 提取 + 逻辑推演补全。
4. **附录词表用规则 + LLM 补充** — 结构化附录规则提取，非结构化 LLM 提取。词条背面用 LLM 批量填充。
5. **Plan 由概念逻辑排序生成** — 非语言类概念逻辑排序 + LLM 推演补全；语言类按场景×技能组织。
6. **卡片与 Plan 关联** — 每个 task 的 gold_cr_ids 指向对应概念。词卡通过关键词匹配绑 plan_task_id。
7. **大考由后端 crate 处理** — `k12_assessment` 出题框架 + LLM 动态出题 + LLM 判卷 + 考试成绩报告。

### 1.2 Plan 生成核心规则：逻辑推演补全

Plan 生成时不能直接使用提取的概念列表做简单排序。必须由 LLM 进行完整的逻辑推演：

1. **前置知识检查** — 每个 stage/task 需要哪些前置概念？如果缺失 LLM 补充并标记 `prequisite_gap`
2. **概念密度均衡** — stage 内概念 >12 拆分为多个 task；<3 合并或补充
3. **课标缺陷修复** — 课标本身可能跳跃或遗漏关键知识点，LLM 补充并标记 `curriculum_fix`
4. **跨科目补全** — 理科共用数学基础（如物理需要向量知识、化学需要摩尔概念）
5. **来源标记** — 每个概念带 origin 字段：`extracted` / `prequisite_gap` / `curriculum_fix` / `cross_subject`

## 二、三部分分割方案

### 2.1 课程内容（所有科目的主体）

```
每个科目 MD 中从"课程内容"标题开始到"学业质量"标题之间的部分。
包括：
  - 内容要求（带编号的条目）
  - 学业要求（每个主题的评价标准）
  - 教学提示

提取方式：
  1. 按 MD 章节标题定位"课程内容"块
  2. 非语言类：LLM 提取概念列表（学科知识点），去重后逻辑排序
  3. 语言类：按学段/级别/场景组织，不提取孤立概念，保留场景完整性
```

### 2.2 学业质量（评估标准）

```
每个科目 MD 中"学业质量"章节。
包括：
  - 学业质量内涵
  - 学业质量描述（按年级/水平划分）

提取方式：
  1. 按 MD 章节标题定位"学业质量"块
  2. 整块保存为 raw_text
  3. LLM 按质量描述生成试题（未来构建题库时使用）
```

### 2.3 附录（词表/参考书/语法）

```
不同科目的附录差异较大：
  - 英语：词汇表（按字母顺序/级别）、语音表、语法表
  - 语文：生字表、背诵篇目、语法知识
  - 理科：实验器材清单、案例
  - 语言类（俄/日）：词汇表、语音、语法

提取方式：
  1. 按附录标题定位
  2. 结构化提取（表格解析/行级正则/规则提取）
  3. 词汇直接转卡，参考书/语法作为卡背素材
```

## 四、管线流程

### 4.1 清洗阶段

```
输入：OCR 原始 MD
输出：清洗后的三段式 JSON

步骤：
  1. 检测编码（UTF-8/GBK）
  2. 去掉页码标记（===== Page xx =====）
  3. 去 OCR 污染（*、特殊字符、断行合并）
  4. 定位"课程内容"/"学业质量"/"附录"三个章节锚点
  5. 按锚点拆分保存 raw_text
  6. 结构化提取附录（词汇/表格/字表）
```

### 4.2 概念提取阶段（LLM）

```
输入：清洗后的 curriculum_content raw_text
输出：概念列表（每条 1 个知识点）

每条 LLM 请求处理 50 条未分段内容：
  
  prompt: "从以下课标文本中抽取内容要求，每条为一个具体知识点。
           返回 JSON 数组：[{text, module, grade}]"
  
  tokens: ~2000/批
  调用次数: 约 total_items/50
  总成本: ~$0.10/科
```

### 4.3 卡片生成阶段（LLM）

```
输入：概念列表 + 附录词汇
输出：带完整卡背的学习卡片

概念卡：
  prompt: "生成学习卡片。front=概念名，back=完整释义+例句+关联概念"
  批量 20 条/次
  总成本: ~$0.05/科

词汇卡：
  prompt: "为以下词汇生成卡片。front=单词，back=音标+中文释义+例句"
  批量 50 词/次
  总成本: ~$0.02/科（英语）
```

### 4.4 计划生成

```
输入：概念列表（按 module 字段分组）
输出：按认知递进排列的 stage/task 结构

  1. 按 module 分组（集合/函数/几何/...）
  2. 按标准教学顺序排列 module
  3. 每个 module 为一个 stage
  4. stage 内的概念按难易排列
  5. 输出 plans.json
```

### 4.5 题库评估（运行时 LLM 动态出题）

学业质量条目不再预生成试题，改为后端 Rust crate `k12_assessment` 在运行时按出题框架配置动态生成：

```
输入：出题框架配置 + 质量条目 + Plan stage/task
输出：运行时 LLM 生成试卷 → 学生作答 → LLM 判卷

  POST /k12/exam/start   → LLM 按框架 + 质量条目出题
  POST /k12/exam/submit  → LLM 判卷 + 评分汇总

试卷不留前端（安全），每次动态生成
```

详见 `k12-prebuilt-redesign.md §7 大考系统设计`

## 五、与 V1 对比

| 维度 | V1（规则提取） | V2（LLM 提取） |
|:----|:-------------|:--------------|
| 提取方式 | 正则/模板匹配 | LLM 概念提取 |
| 卡背质量 | 规则截断/空背面 | LLM 生成的完整释义+例句 |
| 遗漏率 | 高（规则覆盖不到就漏） | 低（LLM 理解语义） |
| 清洗工作量 | 每个科目写解析器 | 通用三段式分割 |
| 运行成本 | 零 | 每科 ~$0.15 |
| 前期开发工时 | 10h | 2h |
| 可扩展性 | 每增加一科写一个新解析器 | 通用 |

**结论：V2 虽然每次运行有 API 成本，但前期开发成本低、遗漏率低、卡背质量高。**
