# CoEvo 全链路评估框架

> 日期：2026-05-22 · V1
> 目标：量化 AI 教学全链路质量，从「功能通过」到「教学优秀」

---

## 一、概述

当前测试体系（Grade A/B/C/D/F）只回答了 **「功能是否跑通」**。  
这个框架要回答 **「教学好不好」**——覆盖教师、学生、计划、卡片、复习五个维度。

### 五个评估维度

```
                    ┌──────────────────┐
                    │  1. 教师回答质量 │  ← 讲解是否清晰、正确、适合年级
                    └────────┬─────────┘
                             │
              ┌──────────────┼──────────────┐
              │              │              │
              ▼              ▼              ▼
   ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
   │ 2.学生模拟质量│  │ 3.计划执行度  │  │ 4.卡片提取质量│
   │ 自然(犯错/口  │  │ plan_update  │  │ front/back   │
   │ 语化/追问)    │  │ 命令执行率   │  │ domain 准确  │
   └──────────────┘  └──────────────┘  └──────────────┘
              │              │              │
              └──────────────┼──────────────┘
                             │
                             ▼
                    ┌──────────────────┐
                    │  5. 复习全链路   │  ← FSRS 状态更新、review_log
                    └──────────────────┘
```

## 二、维度定义与指标

### 维度 1：教师回答质量（Teacher Quality）

**衡量标准**：AI 教师的教学内容是否清晰、准确、适合学生年级水平。

| 指标 | 测量方式 | 评分 | 数据来源 |
|------|---------|:----:|---------|
| T1. 内容正确性 | LLM 评估教师回答是否存在事实错误 | 0-100 | 第二条 LLM 交叉审查 |
| T2. 年级适配度 | 内容深度是否匹配目标年级（如 g1-2 不用导数） | 0-100 | 第二条 LLM |
| T3. 结构清晰度 | 是否包含讲解→举例→小测→考核的子阶段 | 0-100 | 回答文本分析 |
| T4. 概念覆盖 | 教学回合中提出的关键概念数 | 数值 | 教学对话统计 |
| T5. plan_update 频率 | 是否定期更新学习计划 | 次数/turn | plan_events |

**自动评估 prompt（给第二条 LLM 用）：**
```
你是一位教育评估专家。以下是 AI 教师对{g年级}{科目}学生的教学对话。
请从以下维度评分（每项 0-100）：
1. 内容正确性：有没有知识性错误？
2. 年级适配度：教学内容是否符合{g年级}学生的认知水平？
3. 结构清晰度：教学是否有层次（讲解→举例→小测）？

教学对话：
{对话历史}

输出 JSON：
{"correctness": 85, "grade_fit": 70, "structure": 90, "issues": ["..."]}
```

### 维度 2：学生模拟质量（Student Simulation Quality）

**衡量标准**：模拟的学生是否像真实学生——不总是正确、会犯错、用语口语化、会追问。

| 指标 | 测量方式 | 评分 | 数据来源 |
|------|---------|:----:|---------|
| S1. 错误率 | 学生回答中犯错的占比（真实学生不会全对） | 百分比 | 学生回答 LLM 评估 |
| S2. 语域自然度 | 是否使用口语化表达、短句、填充词（"嗯…""这个…"） | 0-100 | 文本分析 |
| S3. 追问率 | 是否在适当时候追问"为什么""能再举个例子吗" | 次数/回合 | 对话分析 |
| S4. 多样性 | 每次回答的句式和长度是否变化（不重复模板） | 0-100 | N-gram 多样性检测 |
| S5. 理解深度 | 回答是机械复述还是体现了真正的理解 | 0-100 | 第二条 LLM 判断 |

**问题**：当前 K12 测试使用**固定学生回答**（4 句模板），多样性为 0。
需要恢复双 LLM 模式（教师+学生两个 LLM 对话）才能真实评估。

**自动评估 prompt：**
```
以下是一位学生在 AI 教学过程中的回答。请评估：
1. 这个回答是否像真人学生？（考虑口语化、语法错误、不确定语气）
2. 学生是否真实理解了内容，还是机械复述？
3. 学生有没有主动追问或要求更多例子？

学生回答：{回答文本}
输出 JSON：{"naturalness": 分数, "understanding": 分数, "initiative": 布尔}
```

### 维度 3：计划执行度（Plan Command Execution）

**衡量标准**：系统是否正确解析和执行了 LLM 的 plan_update 指令。

| 指标 | 测量方式 | 评分 | 数据来源 |
|------|---------|:----:|---------|
| P1. 命令解析率 | plan_update JSON 被成功解析的占比 | % | plan_handler 日志 |
| P2. stage 推进 | 是否按计划推进了教学阶段 | 布尔 | plan_events |
| P3. task 完成 | current_task_complete 是否被正确触发 | 布尔 | plan_events |
| P4. plan 持久化 | plan_json 是否正确写入数据库 | 布尔 | DB 记录对比 |
| P5. 路由一致性 | plan 中的 domain 与管线加载的 domain 是否一致 | 布尔 | prompt_loader 调用链 |

### 维度 4：卡片提取质量（Card Extraction Quality）

**衡量标准**：从教学对话中提取的复习卡片是否有学习价值。

| 指标 | 测量方式 | 评分 | 数据来源 |
|------|---------|:----:|---------|
| C1. 候选概念数 | 每次教学提取的候选概念数量 | 数值 | extraction.candidates.len() |
| C2. domain 准确率 | 卡片 domain 与管线 domain 一致的比例 | % | 现有 domain_ok |
| C3. front 质量 | 概念名是否正确（不是问句、不是空字符串） | 0-100 | LLM 评估 |
| C4. back 质量 | 释义是否完整、有例句、有结构 | 0-100 | LLM 评估 |
| C5. 去重正确率 | 重复提取是否被有效抑制 | % | 对比 existing_fronts |
| C6. 冗余率 | 提取的概念中有多少是重复/无用的 | % | LLM 评估 |

**自动评估 prompt：**
```
以下是从 AI 教学对话中提取的复习卡片。请评估每张卡片的可用性：
卡片正面：{front}
卡片背面：{back}
所属学科：{domain}

评分标准：
- front 是否是恰当的概念名称（不是问句、不是太宽泛）？
- back 是否包含有学习价值的定义/解释/例子？
- 卡片整体是否值得加入复习队列？

输出 JSON：{"front_quality": 0-100, "back_quality": 0-100, "useful": true/false, "reason": "..."}
```

### 维度 5：复习全链路（Review Flow Quality）

**衡量标准**：从制卡到 FSRS 复习再到 review_log 的完整闭环是否正确。

| 指标 | 测量方式 | 评分 | 数据来源 |
|------|---------|:----:|---------|
| R1. 制卡成功率 | 概念→卡片写入 DB 的成功率 | % | insert_card 结果 |
| R2. FSRS 更新 | submit_review 后 state/stability/due 是否正确变更 | 布尔 | card_memory 查询 |
| R3. review_log | 每次复习是否写入 review_log 表 | 布尔 | select count |
| R4. 验证模式匹配 | card_type 对应的验证策略是否正确激活 | 布尔 | strategy 路由验证 |
| R5. 多轮复习一致性 | 同一卡片多次复习后：reps 递增、lapses 递增、state 迁移 | 布尔 | card_memory 对比 |

## 三、评估自动化分级

| 级别 | 含义 | 自动化占比 | 执行方式 |
|:----:|------|:----------:|---------|
| L1 | **基础设施测量** — 从现有日志提取量化指标 | 100% | 已有（Grade 体系） |
| L2 | **LLM 交叉评估** — 用第二条 LLM 评判教师/学生/卡片质量 | ~80% | 新增评估 pipeline |
| L3 | **人工抽样审查** — 每轮抽取 5-10% 样本人工复核 | 0% | 人工 |

### L1 指标（现有）

涵盖：P1-P5、C1-C2、R1-R5、T5  
→ 直接从 `PhaseResult.metrics` 和 `LifecycleLog` 中提取。

### L2 指标（需新增）

涵盖：T1-T4、S1-S5、C3-C6  
→ 需要跑第二条 LLM 评估任务。每个测试增加约 5 个 LLM 评估调用。

### L3 指标（人工）

涵盖：T1 事实正确性（关键学科如数学/物理必须人工复核）  
→ 从完整保存的 teacher response 中抽样。

## 四、综合评分模型

每个维度的最终得分 = L1 指标加权 + (L2 指标加权 if available)

```
Teacher Quality = T1×30% + T2×20% + T3×20% + T4×15% + T5×15%
Student Quality = S1×25% + S2×25% + S3×20% + S4×15% + S5×15%
Plan Execution   = P1×30% + P2×25% + P3×20% + P4×15% + P5×10%
Card Quality     = C1×15% + C2×15% + C3×25% + C4×25% + C5×10% + C6×10%
Review Flow      = R1×20% + R2×25% + R3×20% + R4×15% + R5×20%
```

最终综合评分 = Teacher×25% + Student×20% + Plan×15% + Card×25% + Review×15%

## 五、实施路线

| 阶段 | 内容 | 依赖 |
|:----:|------|:----:|

## 六、与现有体系的衔接

```
                       Grade（功能级）              Score（质量级）
                        A/B/C/D/F                 0-100 综合评分
                            │                           │
                            ▼                           ▼
                     pipeline-test / k12-runner    evaluation-pipeline
                     (当前已有)                      (待建设)
                            │                           │
                            └──────────┬────────────────┘
                                       ▼
                             统一报告：Grade + Score
```

- **Grade** 决定能否发布（A 级可发布）
- **Score** 指导改进方向（教师 60 分 → 优化教学 prompt）
