### 🔴 三个设计决定（都是为了防「把残缺文本发到公网」）

| # | 决定 | 为什么 |
|---|---|---|
| 1 | 占位符走**命令行参数**，不写进 md | md 是**模板** ⇒ 进 git 的**不含真实姓名/邮箱** |
| 2 | 生成后**校验无 `【待填`**，有则**拒绝上传** | 漏填的后果是「公网可见的法律文本残缺」，比构建失败严重得多 |
| 3 | 部署**幂等** + 改前备份 + `nginx -t` 失败**自动回滚** | nginx 配置坏了会**连累同机所有站点**（这是共享机器）|

### 🔴 三层校验，全部**真跑过**才发现的坑（2026-10-04）

生成脚本现在查**三层**，每层都是踩到之后补的（**不是设计出来的**）：

| 层 | 查什么 | 踩到的实例 |
|---|---|---|
| ① **占位符残留** | `【待填：…】` + `__ 日` | 第一版只查方括号 ⇒ **漏了日期**「10 月 `__` 日」，生成出来是残缺文本 |
| ② **产物里的坏链接** | `href` 指向 `.md` / 含**非 ASCII** | 见下两条 |
| ③ **部署后公网复核** | HTTP 200 + 内容 + 再次查残留 | （见部署脚本 ⑤）|

**② 抓到的两个真 bug**（都是**只在产物层**才暴露的）：

| # | 现象 | 根因 |
|---|---|---|
| 1 | `href="./privacy-policy.md"` —— **死链** | md 里 `[《隐私政策》](./privacy-policy.md)` 在 md 语境下是「同目录文件引用」，**渲染成 HTML 就是死链**（服务器上没 `.md`）|
| 2 | `href="发送邮件至support@…"` —— **坏链接** | 裸邮箱替换后 `发送邮件至support@…` **被 pandoc 当成一个邮箱**（RFC 允许 UTF-8 local part）⇒ 中文被吞进 `mailto:` |

**修法**：① 整段替换成 `[《隐私政策》]({privacy_url})`；② 邮箱替换成 `[邮箱](mailto:邮箱)` ——
pandoc **优先解析 link 语法**，中文不会被吞，且链接**可点**。

> 📌 **核心判据（值得记住）**：
> **「占了位」≠「渲染对了」** —— 占位符替换是**字符串层**的事，
> 而「链接能不能点」是**渲染层**的事。
> ⇒ **产物必须按它自己的形态去验**（查 HTML 的 `href`），
> 只查源 md 的占位符会**假绿**。
> 🔑 同族教训：本项目的「**全绿 ≠ 通过**」（三层验证）·「**检测为 0 要先证检测器有效**」。

## 写作依据（**为什么这么写**）

本政策**只写实际做的事** —— 逐项都核对过代码与数据库：

| 政策里的说法 | 核实来源 |
|---|---|
| 「生词本/复习记录只存设备」| 端侧 `user.db` / `word.db` |
| 「IP 仅用于试用防滥用」| 后端 `trial_ip_log` 表（**确实记录 IP**）|
| 「无第三方埋点/广告」| 全 `app/lib` grep `analytics` / `umeng` / `firebase` **零命中** |
| 「AI 服务在境内」| `DEEPSEEK_API_KEY` + `api.deepseek.com`（境内）|
| 「支付由 Apple 处理」| ✅ **已接入 Apple IAP**（`iap_transactions` + `/api/iap/verify`）；微信支付已移除 |
| 「收集邮箱/密码哈希」| `users` 表 `email` / `password_hash`（**已删实名/手机号 5 列**）|

> 📌 判据：**隐私政策不能写未实现的能力**（会构成虚假陈述），
> 也不能漏写已收集的项（如 IP）。⇒ 逐条对回代码/DB。
