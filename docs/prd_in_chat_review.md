# 复习弹窗 + 弹窗调度器 — PRD

## 1. 项目信息

| 字段 | 值 |
|------|-----|
| **项目名称** | `coevo_review_popup` |
| **语言** | 简体中文 |
| **前端技术栈** | Flutter (Riverpod + GoRouter + Material3) |
| **后端技术栈** | Rust (axum + tokio + rusqlite) |
| **性质** | CoEvo 内部功能升级，非独立项目 |

## 2. 产品目标

1. **消除复习断裂**：到期卡片主动弹出，用户无需主动翻复习 tab
2. **尊重用户意愿**：提供"推迟30分钟"按钮，不打扰正常对话
3. **弹窗不打架**：所有弹窗统一调度，优先级明确，不再卡死

## 3. 用户故事

1. **作为学习者**，我打开对话页时，如果有到期卡片，自动弹窗让我复习，这样我不会积累未复习的卡片
2. **作为学习者**，复习弹窗沿用现有的卡片样式（翻转、输入验证），体验一致
3. **作为学习者**，如果我正忙，可以点"推迟30分钟"，所有到期卡整体延后，不会一会又弹出来
4. **作为学习者**，我不论答对答错，全部答完才能退出
5. **作为学习者**，支付弹窗弹出来时，复习弹窗不会打扰
6. **作为开发者**，新增弹窗只需指定优先级，无需操心冲突逻辑

## 4. 设计决策

### 4.1 复习形式

**弹窗**，不是对话气泡。复用现有 `ReviewScreen` 的卡片样式（翻转动画、输入框、验证策略）。

### 4.2 复习队列

到期卡组成有序队列，弹窗逐一展示。全部答完才关闭弹窗，无论对错。

### 4.3 推迟机制

不改 `card_memory.due`（不破坏 FSRS 间隔曲线）。使用独立的 `defer_queue` 状态：

| 概念 | 说明 |
|------|------|
| FSRS 到期池 | `card_memory.due <= now` 的卡片 |
| 弹窗队列 | 当前被抓取到弹窗中的到期卡 ID 列表 |
| `deferred_until` | 推迟到什么时候才弹（unix ts） |

前端查 `deferred_until` > now → 不弹。点推迟 → 后端设 `deferred_until = now+1800`。

### 4.4 弹窗调度器

所有弹窗走统一 `DialogQueue`（Riverpod Provider），单点 `DialogOverlay` 渲染。

| 优先级 | 弹窗 | 表现 |
|-------|------|------|
| **P0** | 支付套餐 | 不可抢占，其他排队 |
| **P1** | 分享卡片 | 用户主动，不被被动弹窗打断 |
| **P2** | CP1 概念提取 / 成就海报 / 通知中心H5 | 可被 P0/P1 打断，排队等 |
| **P3** | 复习弹窗 | 最低，遇到其他弹窗自动 defer |

### 4.5 出题判断

复用现有验证系统：
- 语言类 → 文本匹配（VerificationType::Spelling）
- 通用类 → LLM Judge（VerifyRequest → JudgeResponse）

## 5. 需求池

### P0 — 必须有

| ID | 需求描述 | 验收标准 |
|----|---------|---------|
| P0-1 | **DialogQueue Provider**：全局弹窗调度器，支持优先级、排队、抢断 | 高优先级弹窗出现时自动暂存低优先级；关闭后恢复 |
| P0-2 | **复习弹窗**：到期卡以弹窗形式弹出，复用现有复习页卡片样式 | 弹窗内卡片翻转、输入、验证均正常工作 |
| P0-3 | **复习队列**：到期卡组成队列逐张复习，全部答完才退出 | 弹窗进度显示"1/N"，所有答完自动关闭 |
| P0-4 | **推迟30分钟按钮**：点推迟 → 所有到期卡整体延后30分钟，不破坏 FSRS due | 推迟后30秒内不弹，前端状态正确 |
| P0-5 | **弹窗触发**：打开对话页 / WS 连接成功时，查 defer 状态 + get_due_cards，有卡则弹 | 对话页打开时自动弹出复习弹窗 |
| P0-6 | **冲突规避**：复习弹窗遇到其他弹窗时自动 defer | CP1/支付/分享/成就/通知H5弹窗出现时复习不弹出 |

### P1 — 应该有

| ID | 需求描述 | 验收标准 |
|----|---------|---------|
| P1-1 | **现有弹窗迁移**：CP1概念提取、分享卡片、成就海报、通知H5 改用 DialogQueue | 各弹窗行为不变，冲突不再发生 |
| P1-2 | **支付弹窗迁移**：支付套餐改用 DialogQueue，P0 优先级 | 支付弹窗不被任何弹窗覆盖 |
| P1-3 | **复习结束后统计摘要**：弹窗关闭时显示"答对 X/Y，下次复习: n天后" | 关闭弹窗前有汇总提示 |

### P2 — 可以有

| ID | 需求描述 | 验收标准 |
|----|---------|---------|
| P2-1 | DialogQueue 支持过渡动画 | 弹窗切换时有平滑过渡 |
| P2-2 | 推迟时长可配置 | 推迟 30/60/120 分钟可选 |

## 6. 开放问题

| # | 问题 | 决定 |
|---|------|------|
| Q1 | 复习判对错后 FSRS 评分映射？ | 复用现有：pass=Good(3), fail=Again(1) |
| Q2 | 对话 LLM 知不知复习结果？ | 不知。关注点分离 |
| Q3 | 到期卡 > 5 张怎么办？ | 全部答完，不留尾巴 |
| Q4 | 弹窗冲突时具体谁让谁？ | 见 4.4 优先级表 |
| Q5 | 推迟 30 分钟后再次触发？ | 是，deferred_until 到期后再弹 |
