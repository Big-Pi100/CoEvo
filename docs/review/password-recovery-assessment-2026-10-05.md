## 二、🔴 一条新核实到的事实：这是**审核风险**，不只是体验缺口

我此前把它归为「用户体验缺口（忘密码就锁死）」。核实后发现**比这严重**：

多家审核前检查清单把「**账号维护功能**」列为一组必交项，原文：

> **Account maintenance features Apple expects**
> If your app has account creation, you must ship **all of these** — missing any one is a **common silent rejection**:
> 1. Account deletion in-app（§5.1.1(v)，2022-06 起强制）— ✅ **我们已完成**
> 2. **Forgot password / reset password flow** — ❌ **缺**
> 3. **Change password in settings** — ❌ **缺**
> 4. Change email（nice to have）— ❌ 缺（**非必需**）

另一来源把「账号创建」的完整成本写得更直白：

> Account creation is not one screen. It is sign-up, sign-in, **password recovery**,
> in-app deletion … **Cost the whole set when you decide, because the store rules
> will not let you ship half of it.**

### ⚠️ 必须如实标注的三点

| # | 说明 |
|---|---|
| 1 | 🔴 **这不是 Apple 明文条款** —— 现行《App Store Review Guidelines》5.1.1(v) 原文**只写了「账号删除」**，没写找回密码。以上是**第三方实务总结**（审核前检查清单类文章），可信度**中高但非一手** |
| 2 | 🟠 该风险的作用机制是「**审核员主动测试账号功能完整性**」，而不是「明文卡你」⇒ 属**概率性**风险，不是必然拒审 |
| 3 | ✅ 但**另一条是确定的**：我们 App **允许不登录使用**（产品原则），所以不触发 5.1.1(v) 的「登录墙」；而「注册了账号却无法找回密码」是**真实的产品缺陷**，与审核无关也该修 |

📌 **判据应用**：这属「**归零型 vs 罚款型**」里偏归零型的一侧吗？—— **不是**。
它最坏是「被拒审 + 补做」，**不影响备案/账号**。但**补做的成本远高于现在做**
（拒审一次 = 至少一个来回 = 数天），且**现在做能同时解决真实用户痛点**。

## 三、🛠️ 方案选项（请白哥定）

### 方案 A ⭐ —— **自助重置（接邮件服务）**

| | 内容 |
|---|---|
| **流程** | 登录页「忘记密码」→ 填邮箱 → 收邮件 → 点链接/输码 → 设新密码 |
| **白哥要做** | ① 腾讯云**实名认证**（个人可用）② 添加发信域名 `keyievolution.fun` 并按提示配 **SPF / DKIM** DNS 记录 ③ 生成 **API 密钥**给我 |
| **我要做** | 后端：重置令牌表 + 3 个端点（申请/校验/重置）+ 邮件发送封装；<br>前端：忘记密码页 + 重置页；断言 + 证伪 |
| **优点** | ✅ **自助**（审核员能完整体验）· ✅ **终局方案**（邮件能力今后可发验证码/通知）· ✅ **数据不出境**（腾讯云国内） |
| **成本** | 白哥约 30–60 分钟（实名若已有则更快）；我 1 批 |
| **🔴 时间敏感** | 腾讯云 SES **自 2026-03-02 起，新开通的个人实名用户不再支持 SMTP 发信**，只能用 **API**（或控制台）<br>⇒ 无影响（我们本来就用 API，`reqwest` 已在）**但别再按老教程找「SMTP 密码」** |
| **额度** | 新发信域名默认信誉度 **1 级 = 单日 500 封** —— 找回密码绰绰有余（升级靠送达质量自动提） |

### 方案 B —— **人工重置（零新依赖）**

| | 内容 |
|---|---|
| **流程** | App 内「忘记密码」给出说明：**发邮件到 `support@keyievolution.fun`**（我们能收）→ 管理员在后台点「重置密码」→ 系统生成临时密码 → 邮件回复用户 |
| **白哥要做** | **零**（`support@` 已配好、已验证） |
| **我要做** | 后端 1 个 admin 端点（生成临时密码 + 写回 bcrypt）；<br>前端：忘记密码**说明页**（不是表单）；断言 |
| **优点** | ✅ **零外部依赖**·✅ **立刻可用**·✅ 成本最低 |
| **缺点** | 🔴 **非自助** —— 审核员大概率**体验不到**；用户要等我们人工处理（可能数小时）；<br>用户量上来后不可持续；**且临时密码的传递通道仍是明文邮件**（反而是第三方邮箱） |

### 方案 C —— **只做「修改密码」（零依赖，但不解决忘记）**

- 已登录 → 设置 → 修改密码（旧密码 + 新密码）
- ✅ 零外部依赖、成本最小
- 🔴 **不解决「忘了就进不去」** —— 只补了审核清单里的第 3 项，第 2 项仍缺

### 方案 D —— **不做**

- 🔴 承担审核风险 + 保留真实产品缺陷

## 四、建议

**推荐 A，并把 C 一起做**（C 零依赖、可与 A 并行）：

| 理由 | 说明 |
|---|---|
| 1 | A 是**唯一**能让审核员体验完整流程的方案（人工方案审核员不会等） |
| 2 | A 的**一次性投入换来一个通用能力**（邮件服务）—— 将来「邮箱验证」「订阅到期提醒」「登录异常通知」都要用它，本项目**通知系统**已存在但缺发信通道 |
| 3 | **数据不出境**（腾讯云国内）—— 与已否决的「境外验单/境外广告」不同，这条干净 |
| 4 | 技术侧**零新依赖**（`reqwest` 已在）⇒ 我这边风险低 |
| 5 | C 补上「修改密码」，白哥零操作 |

⚠️ **若选 A**：白哥的三步（实名 / 域名验证 / API 密钥）**我不代劳**（涉及账号与 DNS）。
拿到密钥后我配到服务器环境变量（**不落盘到仓库**）。DNS 记录我会给**逐条对照表**。
