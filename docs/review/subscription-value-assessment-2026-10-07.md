## 二、诊断：为什么"价值不足"

### 2.1 三条根因（互相叠加）

| # | 根因 | 说明 |
|---|---|---|
| 1 | **免费层已给全量** | 2026-10-01 取消生词本上限后，免费版**没有任何数量/功能限制** |
| 2 | **订阅只多"一条"** | 且那一条（同步）**只有多设备用户才感受得到** |
| 3 | **单设备用户 = 零增量价值** | 大多数用户**只有一部手机** ⇒ 看不到任何差别 |

### 2.2 🔑 真正的问题不是"同步没用"，是"卖点写错了"

免费用户的数据**只存在本机**（未订阅时 `/api/sync/*` 返 **403**）。所以真实的价值不是
「跨设备**同步**」，而是：

> **「手机丢了 / 换新机，你的学习记录不会归零」**

⚠️ 这两句话对**单设备用户**的说服力完全不同：
- 「跨设备同步」→ 我只有一部手机，**不需要**
- 「**不会丢**」→ 我攒了 300 个词和几个月的复习进度，**丢了很心疼** ✅

📌 判据：**同一个能力，卖"机制"还是卖"后果"，转化率差一个量级。**
（设计文档里其实写对过一次 —— 「订阅正当性 = **内容流持续交付**」，
但那同样**对免费用户也成立**，所以立不住；真正独占的是「**数据资产不丢**」。）

### 2.3 ⏰ 时机判断：**现在是唯一无痛调整窗口**

🔴 **App 尚未上架 ⇒ 没有存量用户**。
免费策略现在调整**零成本**；一旦上架，收紧免费层会引发差评与「先免费后收费」的指控。
⇒ **要调整就趁现在**（这是本次评估最重要的结论之一）。

## 三、扩展建议（按「价值 ÷ 成本」排序）

> 原则：**订阅应卖「我们有持续成本、或用户有持续收益」的东西** ——
> 而不是「人为把免费功能锁起来」（后者会毁掉口碑，且我们已公开承诺免费全量）。

### 🥇 A · 云同步「重新包装 + 补体验」（**成本 ≈ 0**）

| 项 | 内容 |
|---|---|
| 改什么 | 卖点从「跨设备同步」→「**学习记录永不丢失 · 换机一键恢复**」 |
| 补什么 | ① 新机登录后**自动恢复**的显式提示（"已恢复 312 个词 / 87 天记录"）<br>② 「上次同步于 X」的状态可见<br>③ 首次订阅后的**首次恢复**要有"看得见的效果" |
| 成本 | **纯文案 + 少量 UI**（同步本身已实现）|
| 风险 | 无 |

### 🥈 B · **LLM 实时制卡归订阅**（成本有依据，**需你决策**）

现状：`/api/generate-card` **对所有人开放**，且它是**全项目唯一有真实边际成本**的对外服务。

| 层 | 免费用户 | 订阅用户 |
|---|---|---|
| 词库命中 | ✅ 直接给 | ✅ |
| 服务端**全局缓存**命中 | ✅ 给（**0 成本** —— 跨用户复用）| ✅ |
| **未命中 ⇒ 实时调 LLM** | ⏳ 提示「订阅后可用」 | ✅ 无限制 |

- 🔑 **正当性最硬**：这是唯一「我们真的在为你花钱」的服务 ⇒ 订阅 = 替你付持续成本
- 🔑 **天然分层**：成本 ∝ **唯一词数**（全局缓存），热门词免费用户也几乎总能命中 ⇒ **免费体验不受损**
- ✅ 符合产品原则：「登录态是**能力限制开关**，不是**内容可见性开关**」（实时制卡属**能力**，不是既有内容）
- ⚠️ **代价**：冷门词对免费用户会**没卡** ⇒ 需文案引导（"这个词还没人查过，订阅后可即时生成"）

> 🔗 **2026-10-07 晚补注**：本条的判据已**升级为统一规则** —— 与「任意内容制卡」合并为
> 「**命中缓存免费 · 实时生成走额度**」，因为**二者成本性质相同**（都是每次真调 LLM）。
> 详见 `product-core-expansion-2026-10-07.md` §4.3（该节原判「通用制卡零成本」已作废）。

### 🥉 C · 学习数据报告（开发量中等，纯增量）

数据**全在端侧**（`review_log` / 生词本 / FSRS 状态）⇒ 只需聚合 UI：

- 周报/月报：新增词 · 复习量 · 连续天数 · CEFR 分布变化
- 🔑 价值：**情感价值**（成就感）+ 让"坚持"看得见 ⇒ 提高留存（留存本身是订阅的前提）

### D · 其他候选（供你挑）

| 项 | 成本 | 我的看法 |
|---|---|---|
| **导出（CSV / Anki）** | 小 | ⚠️ 双刃：可能是卖点，也可能**降低留存**（导出即离开）。我**不建议**放进订阅 |
| **离线内容包**（预下载 N 篇 + 无网可读） | 中 | ✅ 真实价值，但**免费也能做**（不涉成本）⇒ 做订阅专属略牵强 |
| 深度 AI（句子讲解 / 写作批改） | **高**（每次调用都花钱）| 🟡 长期方向，但现在做**没有用户量验证**，先别上 |
| ⛔ 在线书库 | — | 已否决（NPPA + ICP 双证，个人不可得）|

## 四、对照表设计（白哥问的那件事）

### 4.1 ⚠️ 先说一个陷阱

**数据结构已经有了**：`SubscriptionLegalText.benefits`（订阅权益）+ `freeIncludes`（免费清单）。
做对照表**技术上很简单**（就是把这俩拼成两列表格）。

🔴 **但如果现在做，会"自曝其短"**：免费列 5 项 ✅、订阅列**只有 1 项** ——
对照表会**放大**「订阅不值」的观感，比现在那句模糊的话更糟。

📌 判据：**对照表是"放大器"，不是"说服器"** ——
它放大的是**权益差**。差为正则有力；差近零则**自杀**。
⇒ **先补权益（建议 A / B / C），再上对照表。**

### 4.2 如果仍要做（两个版本）

**版本一 · 现状版**（诚实但弱势）

| 功能 | 免费 | 订阅 |
|---|---|---|
| 阅读信息流全部内容 | ✅ | ✅ |
| 划词查词 | ✅ | ✅ |
| 生词本 | ✅ **无限制** | ✅ |
| 词卡朗读 · FSRS 复习 | ✅ | ✅ |
| **学习记录云端备份（换机不丢）** | — | ✅ |

**版本二 · 补完 A+B+C 后**（有说服力）

| 功能 | 免费 | 订阅 |
|---|---|---|
| 阅读 · 查词 · 生词本（无限制）· 朗读 · 复习 | ✅ | ✅ |
| **学习记录云端备份 · 换机一键恢复** | — | ✅ |
| **未收录的词 · AI 即时制卡** | — | ✅ |
| **学习周报 / 数据统计** | — | ✅ |

### 4.3 顺带修掉的一个问题（白哥指出的「没说明是订阅权益」）

现状（`subscribe_screen.dart` 257-280 行）只把权益当"一句话"展示，
**上下文里没有"这是订阅才有的"这个标签** ⇒ 用户读完不知道"我现在有没有"。
⇒ 对照表（或至少给该区块加「订阅后专享」小标题）能直接解决。
