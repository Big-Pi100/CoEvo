## 三、三个方案（都不动文案内容，只动**放哪里**）

### 方案 A：回归设计稿（**删掉多出来的那一行**）

```
✓  订阅中                        ☁✓
到期日 2026-11-20
管理或取消订阅：Apple ID 设置 → 订阅
```

- **改动**：删掉卡片里 `howToCancel()` 那一行（1 行删除）
- **好处**：3 行 vs 4 行，卡片矮 ~22pt；与设计稿逐字对齐；「取消」只出现一次
- 🔴 **代价（我上一版写错了，这里更正）**：
  **这句话在 App 里就没有了**。我核对了 `grep howToCancel`：
  - `subscribe_screen.dart:561` 是**未订阅态**的页脚（给没订阅的人看的）
  - 「我的」页**没有**这一句（只有注销提示里提到「注销不会自动取消订阅」）
  ⇒ 删掉 = 已订阅用户再也看不到「取消后仍可用到期末」这个保证。
  这对**刚点了取消**的用户是有用的一句话，不能轻易丢。
- 风险：低（技术），但**信息损失**比我上一版说的大

### 方案 B：保留 4 行，但把间距拉开分组

```
✓  订阅中                        ☁✓
到期日 2026-11-20

取消后，当前订阅期结束前仍可使用会员功能。

管理或取消订阅：Apple ID 设置 → 订阅
```

- **改动**：把 8 / 10 改成 4 / 16 / 12（块内紧、块间松）
- **好处**：文案一句不删
- **代价**：卡片更高（~4 行 + 两段间距 ≈ 多 30pt），页面本来就空，问题不大
- 风险：低

### 方案 C：卡片只留状态，说明与操作移到卡外 ⭐ 推荐

```
[卡片]  ✓  订阅中                ☁✓
        到期日 2026-11-20

取消后，当前订阅期结束前仍可使用会员功能。

管理或取消订阅：Apple ID 设置 → 订阅
恢复购买
```

- **改动**：卡片瘦成「状态 + 日期」两行；说明与两个操作都在卡外，形成「状态区 + 操作区」
- **好处**：卡片最干净，层级最清楚
- **代价**：改动最大；「管理订阅」离开卡片后，需要重新设计它与「恢复购买」的并列关系
- 风险：中

## 四、我的建议（更正版）

**C**（卡片只留状态 + 日期，说明与两个操作移到卡外）。

理由：

1. **卡片里 4 行混了三种性质**：状态（订阅中）、期限（到期日）、条款（取消后仍可用）、
   动作（去哪管理）。设计稿只有 3 行，是因为它**没有把「条款」放进卡里**。
2. 那句话**有用，不能删**（见方案 A 的代价更正）—— 所以 A 不合适。
3. 但把它和「管理订阅」堆在一起，两句都说「取消」，必然挤 —— 所以 B 只是「用间距遮掩」。
4. 移到卡外，它变成**一句独立说明**（和「未订阅态」页脚那几句同性质），
   卡片回到「状态 + 入口」的单一职责。

如果觉得 C 改动太大，那就 **B**（保留 4 行、把 8/10 调成 4/16/12）。
**我不再推荐 A** —— 它会丢一句对「刚取消的用户」有用的话。
