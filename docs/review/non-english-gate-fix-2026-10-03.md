## 一、做了什么（**5 件**，不是 3 件）

| # | 改动 | 针对的问题 |
|---|---|---|
| **A1** | 补全字符区间表：`is_letter` 加 `U+1E00–1EFF`（拉丁扩展附加）+ `U+0300–036F`（组合变音符号）+ 拉丁扩展 C/D | 🔴 **真 bug**：越南语声调字符**既不入分子也不入分母** ⇒ 被整个忽略 ⇒ 占比**虚高到 100%** ⇒ 永不触发 |
| **A2** | 新增判据：「英语功能词密度 < 8% ⇒ 非英语」 | C 判据**结构性**拦不住拉丁语系非英语（西/意/越/土拉丁占比全是 100%）|
| **A3** | 内置 **242 个**英语功能词表（闭类词，纯函数零依赖） | A2 的依据 |
| **🆕 A4** | **修正 D 判据的分母**：缩写/标识符（`CVE` `SHA512`、> 20 字母）**不计入分母** | 🔴 全量复跑**新抓到的误杀**（`id=1460`，见 §四·2）—— 计划里没有这一步，是实测逼出来的 |
| **🆕 A5** | 判据改名：`NonEnglish{latin_pct}` → `NonEnglishCharset` / `NonEnglishWords` | 「拉丁占比」**名实不符**是上轮 bug 的温床（我照名字理解为「拉丁 vs 非拉丁」，于是没发现字符被忽略）|

> **A5 的语义澄清**（这是理解整件事的关键）：
> `is_english_charset` 的字符集 = **英语文章实际会用到的**拉丁字符
> （ASCII + Latin-1 补充 + 拉丁扩展 A/B）。
> **有意排除** `U+1E00–1EFF` —— 虽然它们**是拉丁字母**，但**英语不用**（几乎只出现在越南语/少数非洲语言）。
> 📌 判据：**「是拉丁字母」与「是英语所用字符」不是同一件事** —— 判据要按**目的**分词，不是照抄 Unicode 分类。

## 四、两个实测教训（**比修复本身更重要**）

### 4.1 教训一：「已知盲区」不能靠「应该不会出现」来兜

上一轮的注释原文：> *不覆盖：…越南语扩展等 ⇒ 实测未出现 ⇒ 风险可接受*

**赌「没出现」，而它出现了。** 而且**失效模式也预判错了**：我以为是「字母偏少 ⇒ 低于 MIN_LETTERS ⇒ 放过」，实际是「**分母偏小 ⇒ 比值虚高到 100% ⇒ 连阈值都比较不上**」。

📌 **判据**：已知盲区要么**补上**，要么配一条**不依赖该盲区**的兜底判据（本轮兜底 = D 词汇判据，它只依赖词表）。

### 4.2 教训二：**比例类判据的「分母」和阈值一样重要**

这是**计划外**发现的。全量复跑立刻抓到一条误杀：

```
id=1460  LWN 转发的 Debian 安全公告（**正文是英文**）
  修正前：英语字符 100% · 功能词密度 **2.63%（43/1632）** ⇒ 被拦 ❌ 误杀
  修正后：同一篇 · 功能词密度 **14.73%（43/292）** ⇒ 保留 ✅
  ⇒ 分母 1632 里有 **1340 个**是 `CVE` / `DSA` / `SHA` 这类缩写
     （真身是几百个 `CVE-2026-80938` 编号 + 几十个包名）
```

🔑 **同一个分子（43），分母一改，结论从「非英语」翻成「英语」**。

⚠️ 而且**不能靠调阈值解决**：1460 = 2.63% 与越南语 id=2032 = 2.50% **比例交错**，
调阈值必然同时放过真非英语。**只能修分母。**

📌 **判据**：`counts_as_language_word`（缩写/超长串不进分母）**是判据的一部分**，改它必须重跑全量复跑重新标定 —— 已写进代码注释。

`it.body.as_deref().or(it.summary.as_deref())` —— `or()` 对 `Some("")` **不会** fallback 到 summary。

（记在这里是因为它是个**容易在未来被引入**的坑：哪天上游放宽了非空保证，闸门就会静默失效。）
