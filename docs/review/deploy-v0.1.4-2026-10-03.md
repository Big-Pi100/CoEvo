## 三、交付物级证据（三重对照）

🔴 **grep 二进制用 `grep -a`**（`strings` 会漏多字节，且 Rust 字面量在 `.rodata` 连续拼接，
`grep -x` 整行匹配**必然失败** —— 上一轮踩过）。

| 特征串 | 新版 | 旧版 | 性质 |
|---|---|---|---|
| `INSTR(?1,` | **2** | 0 | 🆕 差异对照 |
| `p.category = ?1` | **0** | 1 | 差异对照（旧条件**已消失**）|
| `/api/feed` | 1 | 1 | ✅ 阳性对照（证明检测器**能报 1**）|
| `非 HTML 文档` | 1 | 1 | ✅ 阳性对照 |

### 🎯 最有价值的一行是 `INSTR(?1,` = **2**

因为 `INSTR` 在源码里出现 **两次**：`items` 的 SELECT **和** `total` 的 `COUNT(*)`。
⇒ **这个「2」就是「两条 SQL 都同步改了」的直接证据。**

🔴 若只改了 `items`（漏改 `total`）⇒ 这里会是 **1**，而**功能不至于报错** ——
只是端侧 `hasMore`（`fetched < total`）**恒真** ⇒ **无限上拉**、每次白请求。
⇒ 一个数字就把「最容易漏的那处」证住了。

## 四、行为级验证：20 项全过

脚本：`scripts/trace_verify/bin/verify_interest_filter_after_deploy.py`（只读）
跑法：`ssh … "python3 -" < <脚本>`

| 组 | 断言 |
|---|---|
| 【1】单值（**向后兼容**）| 不传=990 · 空串=990 · tech=438 · science=284 · 单值互不相等 |
| 【2】🔴 多值 = 并集 | **722 == 438+284** · 顺序无关 · 三项 **890** · 去重 · 空白 · 大小写归一 |
| 【3】🔴 区分「没传」与「全非法」| 全非法 ⇒ **0**（不是 990）· `tech,xyz` == `tech` · `*` 非法 · **注入尝试 ⇒ 0 且不崩** |
| 【4】🔴 分页自洽 | 实取 **438** == total 438 · 实取 **722** == total 722 |
| 【5】返回内容确实在范围内 | 只返回 tech/science（无漏进）· 不筛时分类更多样 |

### 🔑 两个设计要点

**① 【4】分页自洽 = 同时验证两条 SQL**
「实际翻页能取到的条数 == `total`」这一条，**只有 `items` 与 `total` 用同一个条件时才成立**。
⇒ 它是「`total` 漏改」的**行为级**探测器（与第三节的 `INSTR` 计数互为独立证据）。

**② 期望值来自「当场取的单值」，不是写死的常数**
脚本先查 `total(tech)` 与 `total(science)`，再断言 `total(tech,science)` 等于两者之和。
⇒ **数据在持续抓取**（本轮就观察到 990 → 1005）也不会让断言失效。
📌 这是「**期望值必须独立于被测逻辑**」的正例：期望值来自**同一时刻的其他查询**，
   而不是「我记得它是 722」。

## 七、顺带发现（如实记录）

**② 我选的一个「阴性对照」选错了**（不影响结论，但值得说明）：
本想用 `hacker-news.fir`（HN 的 API 域名）当**阴性对照**（期望 0/0），实测是 **1/1**。
根因：HN 弃用时 seed 是 `enabled=0` **保留行**（照 Ars 先例）⇒ **URL 字符串仍在源码里**。
⇒ 🎯 这反而**侧面验证了**「HN 弃用是禁用而非删行」这个事实。
⚠️ 教训：**选阴性对照前要先确认「它真的不该出现」** —— 否则对照失效而不自知。
（阳性对照已足以证明检测器有效，故结论不受影响。）
