> ## 🔴 更正（2026-10-23 11:50，白哥指出）
>

> 根本不走 `epub_parser`（spine/nav 那套完全不适用）。

> r'^第\s*[0-9０-９一二三四五六七八九十百千零〇两]+\s*[章节回卷篇部]\s*.{0,30}$'
> ```
> 那本书只认出 4 段（前言 + 第六/七/八章）⇒ **第一到五章的标题行没匹配上**
> （多半是标题格式不规范：带全角空格、标题跨行、或用了「一、」这类写法）。
> 📌 **这是 TXT 源本身的问题，不是翻页器的 bug。**
>
> ### 正确做法：先用 **EPUB**（结构规范）验证翻页器
> 《Alice in Wonderland》那种「一章一个 xhtml」的 EPUB，
> `spine` 切章就是正确的章 —— 用它验证才不会把源文件的毛病算到阅读器头上。
> （spike 已加「点书名换书」）

> 白哥：「目录翻动 OK，**目录识别不完整**。」
> 截图证据：目录只有 4 项 —— `第 1 章（无标题）/ 第六章 寻找对话机会 / 第七章 选择你的客户 / 第八章 开始流程`，
> 而顶栏显示「第 4/4 章」。**一本书不可能真的只有 4 章却叫「第六章、第七章、第八章」。**

---

## 一、根因（已查代码，不是猜测）

`app/lib/services/ebook/epub_parser.dart` 的章节定义是：

```dart
// ⑤ 解析 OPF：metadata / manifest / spine
// spine: 有序的 idref 列表 —— 🔴 这就是章节顺序
for (final id in spineIds) { ... chapters.add(...) }
```

⇒ **「一章 = 一个 spine 文件」**。

这本书的结构是典型的 **「一个 xhtml 里用锚点/标题分多章」**：

| | 数量 | 内容 |
|---|---|---|
| `spine`（正文文件）| **4** | 第 1 个文件里塞了前几章，后 3 个文件各 1 章 |
| `nav` / `NCX`（目录）| **8+** | 「第一章 … 第八章 …」|

⇒ 结果就是你看到的：**目录只有 4 项**，标题还是「第六章/第七章/第八章」（那是文件里第一段的标题）。
第 1 项没有标题，是因为那个 xhtml 的 `<title>` 不在我们取标题的规则里。

📌 **判据：目录的「章」必须与 `nav`/`NCX` 对齐，不是与 `spine` 文件对齐。**
   导航结构是**出版方给的**；文件切分是**打包方式**，两者不是一回事。

---

## 二、三个方案

### 方案 A：按 `nav`/`NCX` 切章（**标准做法**）
- 读 EPUB 3 的 `nav.xhtml`（`epub:type="toc"`）或 EPUB 2 的 `toc.ncx`
- 每个条目有 `href="chapter1.xhtml#sec2"` ⇒ **文件 + 锚点**
- 按锚点把 xhtml 的正文切成多段，每段一章
- 优点：与出版方的目录**逐条对齐**，标题也是真实标题
- 代价：解析器要加「按锚点切 HTML」的能力；**已有书需要重新导入**才生效
- 估工：**1 天**（含 nav/NCX 双格式 + 锚点切分 + 断言）

### 方案 B：按正文里的标题标签切章（启发式）
- 在一个 spine 文件里找 `<h1>`/`<h2>`，按出现位置切
- 优点：不用解析 nav，实现快
- 代价：**标题层级不可靠**（有的书用 h1 分卷、h3 分节）；标题文字要自己猜；
  会误切（正文里的小标题也被当章）
- 估工：半天，但**长期会不停调规则**

### 方案 C：维持现状（一章 = 一个文件），只在目录里显示「文件序号」
- 成本 0，但**用户看到的目录跟书里的目录对不上** —— 阅读体验的核心缺陷

---

## 三、我建议 A

理由：
1. 这是**唯一有权威依据**的切法（出版方给的 nav 就是目录本身）
2. B 的启发式规则会一直有人报「这章怎么没了/多了」
3. 我们已经有 `epub_parser`，加一个 nav/NCX 解析 + 锚点切分是**受控的增量**，不是重写

### 代价要说清
- **已有书必须重新导入**（章节表要重建）。可以在「书架 → 某本书 → 重新导入」里做，
  也可以在下次打开时检测「章数与 nav 不符」自动提示。
- 重新导入会**丢该书的阅读进度/书签**（因为 `chapter_idx` 变了）——
  这是我在实现时必须处理的：**按 `char_offset` 迁移**（正好我们刚加了这一列）。

---

## 四、另一个必须一起定的点

切章之后，**`char_offset` 的「本章」口径也变了**（一章变小了）。
但偏移是**章内相对**的，只要「同一章的 HTML 生成规则不变」，偏移就仍然有效。
⇒ 关键是：**切章规则变了，旧进度必须按「全文偏移」重算**，不能直接沿用章内偏移。

我建议进度迁移时**用全书字符偏移**做中间量：
```
旧：chapter_idx=0, char_offset=5000
新：找到全文第 5000 个字符落在新章的哪一章 → (chapter_idx', offset')
```
