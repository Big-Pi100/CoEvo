# 「重装后自动登录一个已订阅的临时账号」— 调查（2026-10-09）

> 白哥问：**「重新安装后会自动登录一个已订阅的临时账号？」**
> 结论：**会** —— 两个独立机制叠在一起，都不是 bug 层面的意外，但**合起来的效果是错的**。
> ⚠️ **本次未改任何代码**（按项目铁律：先调查 → 报告 → 批准 → 实施）。

---

## 一、一句话回答

| 现象 | 是不是「本来就这样」 | 机制 |
|---|---|---|
| 重装后**自动登录一个匿名试用账号** | ✅ **是有意设计** | `home_screen._initAuth` 第 ③ 条：未登录 + 本机未用过试用 ⇒ 自动建号（不打扰用户）|
| 它是「**已订阅**」的 | 🔴 **不是有意设计** | `trial_handler::start` 给试用账号写了 **1 小时的 `subscription_expires`** ⇒ 服务端判 `expired=false` ⇒ 界面显示「订阅中」|

## 二、线上实证（直查 `coevo.db` + 日志，非推断）

```
users（按创建时间倒序）
  trial_4046c168      email=NULL  subscription_expires=2026-10-09T05:54:27Z  created=2026-10-09 04:54:27
  trial_1133f074      email=NULL  subscription_expires=2026-10-02T04:09:11Z  created=2026-10-02 03:09:11
  apple_145f2f189a73  mr.bigpi@…  subscription_expires=NULL
  u_b5b3a29d151f      690861018@… subscription_expires=2027-10-09          ← 昨天人工开通的测试订阅
```

`trial_4046c168` 建于 **UTC 04:54:27 = 北京 12:54**，来自手机网络 IP `223.160.174.142`。
建号后**立刻**自动跑了一整串请求（日志原样）：

```
04:54:27  trial_handler: trial/start: user_id=4046c168-…, username=trial_4046c168
04:54:27  sync_handlers:  sync_pull: uid=4046c168-… since=1970-01-01T00:00:00.000Z device=dev_dac9009…
04:54:28  routes:         avatar_get_handler / profile_handler
04:54:29  notification_handler: list_notifications
```

### 🔴 关键：这个试用账号**真的拿到了订阅权益**

`sync_pull` **执行成功**（不是 403）。而我们此前实测过：**未订阅**的账号打同一个端点返回
`403 跨设备同步是订阅权益`（Apple 号 / trial 号各一次，见
`subscription-expiry-overlay-investigation-2026-10-09.md` §六 A/B 对照）。
⇒ 试用账号在建号后的 1 小时内**确实**能跨设备同步、能传云端书架、翻译不限次。

**根因**（`backend/crates/api_server/src/trial_handler.rs:89-93`）：

```rust
// 5 分钟试用订阅（测试用）              ← 行内注释
let expires = (now + chrono::Duration::hours(1))   // ← 实际是 1 小时
```

而同一个函数的文档注释（`:37`）写着「写入 **1 天**试用订阅」——
**三处说法三个值**，实现比注释长 12 倍。服务端判据是 `subscription_expires < now`
（`routes.rs` `user_subscription_handler`）⇒ 头 1 小时 `expired=false`
⇒ 端侧 `SubscriptionStatus.active` ⇒ 「我的」页显示「**订阅中**」。

## 三、链路（端侧 4 步，全部有代码位置）

| # | 位置 | 行为 |
|---|---|---|
| 1 | `auth_provider.tryRestore` | 从 **secure storage**（Keychain / EncryptedSharedPreferences）读 token+userId |
| 2 | 同上 `else` 分支 | 读不到 ⇒ `debugPrint('本地无存储的认证信息, 清理试用标记')` + **主动清掉「已用过试用」标记** |
| 3 | `home_screen._initAuth` ③ | 未登录 + `hasUsedTrial()==false` ⇒ **`trialStart()` 自动建号并登录** |
| 4 | `trial_handler::start` | 建号时写 `subscription_expires = now + 1h` ⇒ **看起来「已订阅」** |

### 🔴 第 2 步是这次真正的放大器

那句注释（「防止 `hasUsedTrial()` 卡住流程」）的**意图**是好的，但**效果**是：
**「读不到凭据」这件事会把『本机已用过试用』抹掉** ⇒ 只要凭据读不出来（重装即可），
就**又能白嫖一次试用**。后端只有「**同 IP 每日最多 3 个**」兜着
（`trial_handler` 里的 `trial_ip_log` 检测）。

## 四、⚠️ 一个必须标为「推断」的环节：为什么「凭据读不到、但其它本地数据还在」

AndroidManifest **没有声明 `android:allowBackup`** ⇒ 取 Android 默认值 **`true`**
⇒ **Auto Backup 默认开启**，它会恢复**普通 SharedPreferences**，但恢复不了
secure storage 的 **Keystore 主密钥**（那份密钥随卸载被销毁）。
⇒ 现象正好是「**设备标识与同步游标都在、但登录凭据没有**」。

**证据**：13:14 用邮箱登录回 `b5b3a29d` 时，请求带的是
`since=2026-10-09T02:30:09.241Z`（= 今天 **10:30** 的本地游标）——
若真是「数据被清空的重装」，游标应该是 `1970-01-01`（新试用账号那次正是 1970）。

⚠️ 这一段是**推断**（服务端看不到端侧存储状态）。能区分它的事实是
「白哥是否卸载过 App」—— 若只是**覆盖安装**（同签名），则普通数据本来就不会丢。

## 五、四个发现（按严重度）

| # | 发现 | 严重度 | 说明 |
|---|---|---|---|
| 1 | **试用期写进「订阅」字段** ⇒ 所有订阅消费点把试用当订阅 | 🔴 中高 | 云同步 / 云端书架上传 / 翻译额度 都会被这 1 小时放开；且界面说「订阅中」 |
| 2 | **「已用过试用」标记会被「读不到凭据」静默清除** ⇒ 重装即可再拿试用 | 🔴 中高 | 后端只靠同 IP 每日 3 次兜底；且这**不是**本机唯一用户能绕的 |
| 3 | **到期日会显示成机器串** `2026-10-09T05:54:27Z` | 🟠 中（用户可见） | `subscriptionExpiryLabel` 只格式化**端侧**值，**后端值原样返回**（`iap_plan.dart:389`）—— 正常订阅存 `%Y-%m-%d`（10 字符），试用存 `%Y-%m-%dT%H:%M:%SZ`（20 字符）⇒ 试用账号的卡上会露出 ISO 时刻 |
| 4 | **同一事实三处说法**（1 天 / 5 分钟 / 1 小时） | 🟡 低（但危险） | 正是「注释≠实现」家族；下一次「按注释改代码」会把试用期改成 5 分钟 |

## 六、修法选项（**等你定，我不动手**）

### A. 试用期这件事（发现 1 / 4）

| 选项 | 做什么 | 代价 |
|---|---|---|
| **A1（推荐）试用不算订阅** | 建号时 `subscription_expires` 留 **NULL**；试用只表示「账号是临时的」，不表示「有订阅」 | 需改后端 + 重新部署；试用账号界面回到「免费版」（与产品原则一致：免费已全量，试用账号本来就该看到免费版 + 注册引导）|
| **A2 独立字段** | 新增 `trial_expires`（或 `trial_started_at`），**不进订阅判据** | 改 schema（本项目后端零真实用户 ⇒ 无迁移成本）；比 A1 多一步 |
| **A3 保持现状，只修说法 + UI 文案** | 代码不动，把三处注释统一为「1 小时」；界面在试用账号上显示「**试用中**」而非「订阅中」 | 最省事；但「试用 = 订阅」的语义仍混在同一个字段里，第 5 次踩的机会还在 |

⚠️ 注意 A3 仍会留下：试用账号在头 1 小时**真的**拿到付费权益（云同步等）。
如果那是有意的「体验一下」，A3 可接受；如果无意，必须 A1/A2。

### B. 「重装可再白嫖试用」（发现 2）

| 选项 | 做什么 |
|---|---|
| **B1** | `tryRestore` 读不到凭据时**不要**清「已用过试用」标记（只在**服务端明确说 token 无效**那条路径上清）|
| **B2** | 试用标记**不再只存端侧**：服务端按设备（`device_id`）记账 —— 但 `device_id` 也是端侧生成的，重装会变 ⇒ 需要 Keychain/iCloud 兜底，成本高 |
| **B3** | 接受现状（后端 IP 限 3/天兜底），只把注释写清 |

### C. 到期日显示（发现 3，**这条与 A 无关，可单独修**）

`subscriptionExpiryLabel` 对后端值也**截成日期**（或解析 ISO 后格式化），
并补断言：**两个来源都必须输出 `YYYY-MM-DD`**。
