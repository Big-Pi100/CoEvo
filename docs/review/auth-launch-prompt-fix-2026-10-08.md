# 启动登录弹窗误弹 + 退出入口找不到 —— 根因与修复（2026-10-08）

> 白哥原话：「**没有账号退出入口，另外，已登录状态还是会弹出登录弹窗**」
>
> 类型：真机 bug 修复 · 端侧（Flutter）· 后端零改动
> 状态：**已实现 + 已本地验证**（未出包、未部署）
> 相关代码：`app/lib/services/auth_session_policy.dart`（新）· `app/lib/providers/auth_provider.dart`
> · `app/lib/screens/home_screen.dart` · `app/lib/screens/profile_screen.dart`

## 一、结论先说

两条现象**同源**：**这台测试机的持久会话是一个「匿名试用账号」**。

| 现象 | 直接原因 |
|---|---|
| 已登录还弹登录弹窗 | 该账号 `email` 为 NULL ⇒ `isRegistered == false` ⇒ 旧判据「已登录但没有邮箱 ⇒ 引导注册」**每次启动都成立** |
| 找不到退出入口 | 入口**存在**但挂在「我的」页**最底部**（要滚过六组才看得见）⇒ 真机上表现为「没有这个入口」 |

⚠️ **不是**「登录态丢失」（token 有效、服务端 `valid=true`）—— 这是排查时的第一个岔路。

## 二、证据链（全部为**直查实测**，不是推断）

| 检查 | 手段 | 结果 |
|---|---|---|
| 会话属于谁 | SSH 只读查 `/opt/coevo/data/coevo.db` | 测试机恢复的 uid `1133f074-…`：`username='trial_1133f074'`、**`email` = NULL**、建于 10-02 |
| token 是否有效 | 直连 `POST 127.0.0.1:8300/api/auth/verify` | 该 uid → **`valid=True, email=None`**；另一 uid（Apple 号）→ `valid=True, email='…@foxmail.com'` |
| 页面是否走到了正常分支 | 查当日日志 | `auth_verify` 14 次几乎全是该 trial uid；`profile_handler` / `avatar_get_handler` 均被正常调用 |
| 库里有几个账号 | `SELECT * FROM users` | 仅 3 行（1 个 trial + 1 个 Apple + 1 个邮箱号） |

**因果链**：

```
users.email = NULL
  → AuthState.isRegistered = false        (auth_provider.dart:65)
  → home_screen._initAuth():
        if (isAuthenticated && !isRegistered) _showAuthDialog();   ← 旧代码
  → 每次启动弹一次登录弹窗（且永不自愈：除非用户真的去注册）
```

同时解释了为什么「我的」页看起来是**已登录**：`isAuthenticated` 为 true
（匿名试用账号**也是**已登录），副标题写着「**已登录 · 试用账号**」—— 白哥的措辞与此逐字对上。

### 📌 方法判据（新）
> **「用户说某个入口不存在」先分清「真没渲染」还是「渲染了但没找到」** ——
> 本项目最省事的鉴别方式是**直查服务端日志**：`profile_handler` 被调用
> ＝页面走到正常分支＝入口一定在 widget 树上 ⇒ 那就只剩「可发现性」一种可能。

## 三、顺带查出的三个真缺陷（1、2 已修；3 未改，待批）

1. 🔴 **`AuthClient.verifyToken` 的网络失败兜底会「抹掉」`email`**
   （`auth_client.dart:91` 返回 `{'valid': true}`，不带 email）。
   这条宽容兜底本身是对的（不该因一次网络抖动把用户登出），
   但它**改变了由该响应推导出的另一个判断**：已注册账号在启动网络抖动后
   会被判成「未注册」⇒ 凭空弹窗 + 页面上被显示成「试用账号」。
   📌 判据：**「宽容兜底」只该兜「验不了」，不该顺手把已知信息抹掉。**
   ✅ 修法：兜底时用**本地已存的登录标识**回填（见 §四②）。
2. 🟠 **「退出账号」入口可发现性差** —— 已在页尾、且与「关于」等同处一屏之下。
3. ⚠️ **`ClaimDialog` 的按钮行只有一个「登录 / 注册」，没有「关闭 / 稍后」**
   —— 自动弹出时唯一的出口是**点遮罩**（`CoDialog` 默认 `barrierDismissible: true`，
   但界面上没有任何提示）。**本次未改**（白哥只批了前两条）。

## 四、修复内容（4 处）

### ① 判据抽成**纯函数**（新文件 `services/auth_session_policy.dart`）

```
shouldPromptLoginOnLaunch({isAuthenticated, trialUsed}) => !isAuthenticated && trialUsed;
```

| isAuthenticated | trialUsed | 弹出 |
|---|---|---|
| false | **true** | ✅ **唯一该弹的组合** |
| false | false | ❌（走「新建试用账号」） |
| **true** | true | ❌ **← 本次修的正是这一格** |
| **true** | false | ❌ |

🔑 抽成纯函数的理由：输入空间只有两个布尔值 ⇒ 可以被**真值表穷举**。
在界面源码上做文本匹配锁不住分支逻辑（这项目的判据库里已记着这一族教训）。

### ② `tryRestore` 用本地登录标识兜底 email

`email = result['email'] ?? emailFromStoredLoginId(username)` ——
`_usernameKey` 存的「登录标识」自 2026-09-29 起就是邮箱。
⚠️ 判定必须**含 `@`** 才算：匿名试用账号存的是 `trial_*`，
无脑回填会把它误判成「已注册」—— 那是**反方向**的错，且更隐蔽。

### ③ `_initAuth` 只按**真实登录态**决定是否弹窗

改为三条互斥分支：已登录→**什么都不做**；未登录+用过试用→弹；未登录+没用过→建试用账号。

### ④ 「退出账号」移进「账号」组

从页尾移到「修改密码」下方（组内统一的 `_navTile` 版式，**仍有文字**）。
移动后分工更清楚：**退出**（日常、可逆）在组内一眼可见；**注销**（不可逆）留页尾。
原页尾那套 `_buildSignOutTile` 因此成为死代码，已删除。

## 五、🔴 一个必须记住的连带结论（本次差点踩）

> **自动弹窗一直是「已登录用户」唯一的登录入口。**

`ClaimDialog` 全库只有两个调用点：本页「未登录」那一行、与 `home_screen` 的**自动弹窗**。
而 App **首次启动就会自动建试用账号** ⇒ 用户几乎**永远处于已登录态**
⇒ 「未登录」那一行基本不出现 ⇒ **取消弹窗＝登录能力整条消失**。

📌 这与 `claim_dialog.dart` 文件头记着的 2026-09-29 事故是**同形**的
（当时把它当「trial 认领弹窗」删掉，连带删掉了「用已有账号登录」的唯一入口）。
🔑 判据：**删一个「入口」前，先查它是不是别的东西的唯一入口。**
**弹窗不该「自动打扰」，但入口必须「常驻」** —— 前者是骚扰，后者是能力。

✅ 处理：在「账号」组补一行「**登录 / 注册**」（**仅未完成注册的账号**显示，
点进去对已登录账号是**认领**语义 —— `trialClaim`，已有学习记录不丢）。

## 八、追加（同日 · 第二批）：账号组改为「状态行 + 下拉菜单」

> 白哥原话：「账号下第一个栏目 —— **账号登录状态**，现在**不需要修改昵称**，
> 点击**下拉**修改密码、退出账号、修改邮箱等。另外，**修改邮箱**的文字说明不合适，
> 只要——『修改邮箱』四个字就行了。」

### 形态

```
┌─────────────────────────────────────────┐
│ 🧑 昵称                        ▾        │  ← 第一行 = **账号登录状态**（点击 = 展开/收起）
│    已登录 · mr.bigpi@foxmail.com        │     副标题：状态 + 登录用的邮箱
├─────────────────────────────────────────┤  ← 以下**默认收起**
│ ↪ 登录 / 注册            （仅试用账号）  │
│ ✎ 修改昵称                              │
│ ✉ 修改邮箱                              │
│ 🔒 修改密码                             │
│ ⇥ 退出账号                              │
│ 🗑 注销账号                             │  ← 🆕 2026-10-09 追加（**最末**）
└─────────────────────────────────────────┘
```

### 五条判据（都进断言）

1. **第一行 = 状态，不是入口**：整行 `onTap` 由 `_editName` 改为切换 `_accountExpanded`。
   ⚠️ 于是 **`_editName` 失去调用点 ⇒ 改昵称会「静默消失」**（零调用方不是编译错误）
   ⇒ 必须把它**搬进下拉区**（`修改昵称`），而不是删掉。
   📌 与 `_navTile` 里那条「头像差点失去 `_uploadAvatar` 调用点」**同形，同一 widget 里第 2 次**。
2. **默认收起**（`bool _accountExpanded = false;`）：收起态信息量最大（一行说完「我是谁、登录没有」）。
   与 `InterestFilterSection` **逐参数一致**的展开语汇（`AnimatedSize` 180ms + `AnimatedRotation` 180ms）。
3. **下拉项一律只有动作名、不带说明** —— 白哥点名「修改邮箱」只要四个字；
   而「修改密码 / 退出账号 / 注销账号」的小字说明同批一并去掉（下拉是动作菜单，逐条挂说明全是噪音）。
   反向断言锁住旧文案不得复活：`title: auth.email` /「未绑定邮箱」/「登录账号 · 找回账号靠它」
   /「永久删除账号与云端数据」。
4. **邮箱信息不丢**：条目名变成动作名之后，界面上会看不到「绑的是哪个邮箱」，
   而 `ChangeEmailDialog` 里也不显示当前邮箱 ⇒ 把它放到**第一行的副标题**（超长截断）。
   ⚠️ 附带改了 `_navTile`：副标题加 `maxLines: 1 + ellipsis` ——
   可变文本进布局必须给上界，否则长邮箱会折成两行、把行高撑起来。
5. 🆕 **注销态提示不丢**：注销那条的小字说明同样被删 ⇒ 风险提示改由**二次确认弹窗**承担
   （永久删除 / 本机学习数据保留 / 不影响 Apple 订阅 三条）
   ⇒ 断言**正向锁弹窗那三条**，防「入口上省了字、弹窗里也没说」的静默降级。

### 🆕 2026-10-09 追加（第三批）：注销账号也进下拉

> 白哥原话：「**注销账号也应该放进去**。」

- **搬迁要搬净**：页尾那一小块卡（`if (auth.isAuthenticated)` 才渲染的孤立卡）**连同它的间距一起删**——
  它原先靠条件渲染才出现，而未登录时账号组本来就是单行入口 ⇒ 那是块「说不出用途的空白」。
  📌 判据：**搬走一个入口后要问「它是不是这块地方唯一的住户」** —— 是的话连容器一起撤。
- **顺序 = 安全设计**：`退出账号`（可逆）在前、`注销账号`（不可逆）在**最末** ——
  列表从上往下扫，最末一项离日常项最远 ⇒ 误触代价最小。断言直接锁这个顺序。
- **合规不变**：Apple 5.1.1(v) 只要求「**App 内**能自助注销」（禁止只留邮件/客服），
  **不禁止**要点两下才到 ⇒ 收进下拉仍满足。`verify_iap_plan` 的断言查的是
  「『我的』页里有这个入口」，**与位置无关** —— 它不会因搬迁变红，这是对的（位置不是契约）。
