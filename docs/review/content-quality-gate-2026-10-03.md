## 二、① 非英语过滤（已实施）

### 2.1 🔴 先纠正我上一轮报告里的一个**错判据**

我在调查报告里写的是「非 ASCII 字母占比」，而探针里实现成了：

```dart
if (c > 0x2000) weird++;    // 🔴 错的
```

**西里尔是 U+0400、希腊是 U+0370 —— 都小于 0x2000** ⇒ 那篇俄语**根本不会被判非拉丁**。
（这正是当时那轮统计报「乱码 0 篇」的真因。）

✅ 正确判据：**「拉丁字母」占「全部字母」的比例**。

### 2.2 正例验证暴露了问题的**真实形态**（关键转折）

| id | 拉丁占比 | 原假设「语言判据」 | 真相 |
|---|---|---|---|
| 2658 俄语 | **6.8%** | 拦下 ✅ | 真的是非英语 |
| 2041 | **92.7%** | **放过** 🔴 | ❌ **不是外语问题** |
| 2692 | **93.4%** | **放过** 🔴 | ❌ 同上 |

那两篇**九成是英文** —— 我一度以为「拦非英语就顺带拦住了乱码」。**实测否掉了**。

查它们到底是什么，看到：

```
id=2041 开头: %PDF-1\.7 %���� 4 0 obj \<\< /Filter /FlateDecode /Length 7521 \>\> stream x��
                     ↑ PDF 文件头          ↑ PDF 内部压缩流
U+FFFD 替换字符 41.85% · 控制字符 312872 个（U+001D U+0005…正是 zlib 字节）
对照正常文章: U+FFFD 0% · 控制字符 0%
```

⇒ **HN 的 `[pdf]` 帖子，我们把 PDF 二进制当文本抓进来了**。这是**另一类毛病**。

📌 判据：**「一类坏内容的判据」不一定能兜住另一类** —— 要分别验证，别想当然。

### 2.3 闸门设计：两个**独立**判据

| 判据 | 阈值 | 真实信号 |
|---|---|---|
| **A. 非英语** | 拉丁字母占全部字母 **< 0.90** | 俄语 6.8% vs 正常 ≥97% |
| **B. 编码乱码** | `U+FFFD` 占比 **> 0.05** | 乱码 41.8% vs 正常 **全部 0%** |

外加一条**保护**：字母总数 < 50 **不判**（比例在样本太小时不可靠）。
取舍：**宁可漏拦，不可误杀** —— 漏一篇短俄语文章只是偶尔看到，误杀正常文章会**静默持续丢内容**。

### 2.4 阈值实测（523 篇生产正文 · 正反例双向）

```
丢弃 3 篇（1 俄语 + 2 PDF）· 保留 520 篇
正例漏网: 无 ✅    误杀: 无 ✅
临界样本: 空 —— 正常文章拉丁占比全部 ≥97%、FFFD 全部为 0%
```

🔑 **「临界样本为空」是关键** —— 没有任何正常文章接近阈值 ⇒ 不是「勉强切过去」。

### 2.5 实现

| 文件 | 改动 |
|---|---|
| `crates/api_server/src/content_quality.rs` | 🆕 **纯函数**闸门（零 IO）+ 5 个测试 |
| `crates/api_server/src/lib.rs` | 注册模块 |
| `crates/api_server/src/content_fetch.rs` | 在 **`write_items`**（所有源的**唯一入库点**）接入 |

**为什么放 `write_items` 而不是各源解析函数里**：
守门人放在「参数化的点」上，新接一个源**自动受保护**；放各源里将来必忘
（同族教训：`unescape` 只接了一处，另一处渲染路径就漏了）。

**判据用「抓到了什么」**（`it.body` 优先，退回 summary）而不是「打算存什么」——
否则 `redistributable = 0` 的源会**绕过**闸门。

## 三、③ 禁用正文链接点击（已实施）

### 3.1 根因

`trace_markdown.dart` 里挂着：

```dart
onLinkTap: (url, _) => _openLink(url),     // → launchUrl(externalApplication)
```

⇒ 手指压到链接就**跳出 App**，而阅读页的核心交互是**长按划词查词** ⇒ 误触打断阅读。

实测正文里 **262/523 篇**含 URL（2062 个，其中 1879 个是可点链接）。

### 3.2 做法

```dart
// 链接渲染成**纯 TextSpan**（不带 recognizer）⇒ 不可点
inlineLinkBuilder: (details) => TextSpan(
  text: details.label,
  style: base,          // 与正文完全同色，无下划线
),
```

**⚠️ 为什么连「链接样式」也一起去掉**（而不只是掐掉点击）：
项目判据「**视觉元素的形态/作用域须与语义一致**」——
保留蓝色下划线但点了没反应，用户会以为**功能坏了**（比没有链接更糟）。
⇒ 看起来是普通文字，行为也是普通文字。

### 3.3 连带清理（语义残留）

禁用后 `onLinkFailed` / `_openLink` / `url_launcher` **永远不会被调用** ⇒ 一并移除：

| 位置 | 改动 |
|---|---|
| `trace_markdown.dart` | 删 `onLinkTap` / `_openLink` / `onLinkFailed` 字段 / `url_launcher` import |
| `reader_screen.dart` | 删 `onLinkFailed: (url) => _hint(context, '打不开这个链接'),` |

📌 判据：**删功能要清理语义残留** —— 留着死参数会让后续开发把旧概念加回来。

**影响面（已核实）**：「打开原文」在**阅读页顶栏**，不走这里 ⇒ **不受影响**；
其他用链接的地方（`notification_panel.dart`）各自独立 ⇒ 不受影响。

### 3.4 ⚠️ 验证的**局限**（如实说明）

**本地无法静态分析**：`flutter analyze` 与 `dart analyze` **都崩**
（已知环境限制：`AnalysisServer` 启动失败）。

所以 ③ 的验证只到：
- ✅ 人工审阅 + 符号级判据（`inlineLinkBuilder` 存在、`launchUrl`/`onLinkTap` 已无）
- ⏳ **渲染效果需 CI（`flutter analyze`）与真机目视**

## 五、🆕 本轮判据（都是踩出来的）

| # | 判据 | 触发它的事实 |
|---|---|---|
| ① | 🔴🔴 **「一类坏内容的判据」不一定兜住另一类** —— 要分别验证 | 「拦非英语」放过 PDF 乱码（它们 93% 是英文）|
| ② | 🔴🔴 **比例类判据先做正反例双向验证** —— 只测反例会得到「永不误杀」的假绿 | 一个恒 `None` 的实现也能通过反例测试 |
| ③ | 🔴 **修判据前先回查「我上一轮写的判据对不对」** —— 我写的 `>0x2000` 完全失效 | 西里尔 U+0400 < 0x2000 |
| ④ | 🔴🔴 **批量改文件的测试脚本必须 `try/finally` 恢复，且「改-跑-立刻恢复」** | 两次脚本（超时被杀 + 崩在 assert）把**源文件留在被改状态**，阈值成了 0/1.00 |
| ⑤ | 🔑 **节选 ≠ 全文** —— 用节选做「一致性断言」会因比例不同而误报 | 俄语节选 1.6% vs 完整篇 6.8%，我一度以为判据漂移 |
| ⑥ | ⚠️ **Rust 浮点格式化是 `{:.1}`，没有 C 风格的 `{:.1f}`** | `unknown format trait 'f'` |
| ⑦ | 🔑 **守门人放在「参数化的唯一入口」**，而不是各调用方 | 放各源解析里将来必忘 |
| ⑧ | 🔑 **「视觉须与语义一致」也适用于「不可点」** —— 去掉能力就要去掉暗示 | 保留下划线但不可点 = 用户以为坏了 |
