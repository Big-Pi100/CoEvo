## 一、🔑🔑 本轮最有价值的一条判据：**先定受众状态，再定它出现在哪里**

白哥第 ② 句给的是一条**内容归属判据**，不是排版意见。它直接决定「订阅权益」与
「订阅到期后」这两块出现在**哪个状态**里：

| 状态 | 渲染这两块吗 | 为什么 |
|---|---|---|
| **未订阅** | ✅ 渲染 | 正在被说服的人 —— 这两块就是给他看的 |
| **已到期**（曾订阅、现已失效） | ✅ 渲染 | 同一类受众；且「订阅到期后」正是他的处境 |
| **已订阅** | 🔴 **不渲染** | 他已经买了 —— 重复推销既占地方又零决策价值 |

📌 可复用：**任何「说服性」内容，先问「这块给谁看」，再决定它出现在哪里。**
「写得好」是第二位的事；**「写给了已经不需要被说服的人」是第一位的事**。

⇒ 落地：`_activeChildren`（已订阅态）里**没有** `_benefitsSection` / `_expirySection`
（有断言锁着：切片取 `_activeChildren` 函数体，含**前提断言**——截不到就变红）。

### 为什么把两条清单合成**一张表**

改前是两条平行清单（`benefits` 3 条 + `freeIncludes` 5 条）各自维护 ——
**同一件事有两个来源**：改一处漏一处**不报错**，只会让订阅页**少说一条权益**。
`subscription-value-assessment-2026-10-07` §四 已把对比形态定为 `功能 | 免费 | 订阅` 三列
（§4.2：**合并共同项、突出专享项**）⇒ 现在只有 `comparison` 一张表，两段由 `exclusive` 字段划分。

```
共同享有：阅读信息流全部内容 / 划词查词 / 生词本 · 无数量限制 / 词卡朗读与复习
订阅版专享：学习记录跨设备同步 / 云端书架（电子书备份） / 整段翻译（每月 10 次 → 不限次数）
```

## 四、云同步：两种形态，**一套口径**

白哥第 ③ 句要求把云同步从「贴在订阅卡上」改成「**我的里一个独立的胶囊**」。

| 形态 | 用在哪 | 为什么 |
|---|---|---|
| `SyncCloudBadge`（一枚图标） | 订阅页「已订阅」卡 | 那张卡的**主题就是订阅**，一枚紧凑图标恰好；换成带文字的胶囊会挤掉「订阅中 · 到期日」 |
| `SyncCloudChip`（独立胶囊：图标 + 文案） | 「我的」页「订阅」组 | 贴在那行订阅卡上会被读成「订阅状态的一部分」；它说的是「**云端数据走到哪了**」，是另一件事 |

- 语义归属不变（同属「订阅」组），形态变了（它现在是它自己的东西）
- 胶囊文案：`已同步 · 今天 10:32` / `正在同步…` / `同步失败` / `尚未同步`
  —— 🔑 **胶囊总有字**（空胶囊没有意义），而点击后的 `SnackBar` 在「没什么可说」时**不弹**
- 📌 判据：**形态可以随上下文不同，口径必须同源** ——
  两种形态都走同一个 `syncCloudVisual` 与同一个 `syncCloudOnTap`
  （断言用**计数**锁「`switch (s.phase)` 全库只有 1 处」）
