## 一、③ 扩白名单（已完成）

### 1.1 关键方法：**用真实解析器量「消化会不会造语法」**

发现 `gpt_markdown` 的解析器 **`plusparse` 是纯 Dart**（全部文件零 Flutter import），
官方 API `Plusparse.parse(md) -> MdDocument`。

⇒ 可以**在脚本里直接跑真实解析器**，比较：
```
parse(转义形态 `\# Head`)  vs  parse(消化形态 `# Head`)
```
的**块结构**。这比「逐字符论证」强得多 —— 机械、全量、可复跑。

### 1.2 实测结论

| 字符 | 危险位置 | 处置 |
|---|---|---|
| `_` `<` | **无**（plusparse 不支持 `_` 强调 / `<…>` autolink）| ✅ 直接消化 |
| `+` `-` `#` `*` | **仅行首**（→ 无序列表 / 标题）| ✅ 消化 + 行首保护 |
| `>` | **仅行首**（`>quote` 无空格也成引用）| ✅ 消化 + 行首保护 |
| `*`（额外）| **行内成对**（`\*\*x\*\*` → 加粗）| ✅ 消化 + 成对保护 |
| `` ` `` `~` | **连续两个**（→ 代码 / 删除线）| ⚠️ **暂不纳入**（判定复杂、残留量小）|

**顺带收窄两条过宽保护**（原按「也许危险」写，实测证明没必要）：
- `\_` 原本**无条件保留** → 实测不成强调 ⇒ 改为**可消化**
- `\#` `\+` 原本**一律保留** → 实测只有**行首**才危险 ⇒ 改为**仅行首保留**
  （原断言的理由是「消掉会变强调」，而用例 `| 4,000\+ plugins |` 其实**在表格单元格里**）

### 1.3 效果（生产 519 篇实测）

| 指标 | 扩前 | 扩后 |
|---|---|---|
| 反斜杠 | 27273 → 2377（消 91.3%）| 27273 → **1631（消 94.0%）** |
| 有残留篇数 | 77（14.8%）| **39（7.5%）** |
| 残留形态 | `\+ 383 · \_ 257 · \# 146` | **`\\ 153 · "\ " 127 · \m 125`** |

**剩余 1631 个全是「应该保留的」**：
- `\\`（LaTeX 换行 / 转义反斜杠）
- `\m` `\t` `\b` `\d` `\e` `\c` `\f`（正则 / 代码内容）
- `\(` `\)` `\{` `\}`（LaTeX 定界符 —— gpt_markdown **支持**）
- `"\ "`（行尾反斜杠 = Markdown **硬换行**）

⇒ 白哥报的形态（`\+` `\_` `\#` 类）**已清零** ✅

### 1.5 🔴 我自己犯的四次「假绿」（完整记录）

这个实验我**连续四次得出「全部安全」的错误结论**：

| 版本 | 错在哪 | 表现 |
|---|---|---|
| v1 | 用例太弱（`\* mid \*` 有空格，不构成强调）| 「全部安全」 |
| v2 | 测的是「**当前代码**会不会消化」（`+` 不在白名单 ⇒ 不动）| 「全部安全」 |
| v3 | 用例**手写时漏了反斜杠**（`r'# Head'` 本意是 `r'\# Head'`）| 「全部安全」 |
| v4 | 模板漏了「**连续两个**」形态（`\*\*bold\*\*` `\~\~del\~\~`）| 「全部安全」 |

✅ **v5 的三道防线**（已写进脚本头注释）：
1. **阳性对照** —— 先证明「不转义时确实造语法」（10 项，全过才有区分力）
2. **用例动态构造** —— `模板.replaceAll('XT', '\\$c')`，**不可能漏反斜杠**
3. **前置断言** —— 每对用例必须 `escaped != plain`，否则计入 selfCheckFail 并**警示**

📌 判据：**「无差异」是最容易假绿的结论** —— 必须先用阳性样本证明
「若真有差异，检测器会报出来」。

### 1.6 实现要点（两个坑，都是断言报红才发现的）

1. **`\#\# Head` 的串要整体跳完**再判串尾 —— 首版只看「紧邻的下一个字符」，
   而第一个 `#` 后面跟的是 `\`（第二个转义符）⇒ 漏保护 ⇒ 变 H2
2. **先定位整串起点**再判行首 —— `\#\#` 的第二个 `#` 前面是 `#`（同串的），
   不是行首 ⇒ 首版判 false ⇒ 漏保护

### 2.1 为什么有这个顺序约束（否则删了白删）

⇒ **正确顺序：先部署闸门 → 再删存量**。否则删了也会被重抓回来。

⚠️ 补充：HN 抓的是 `topstories` 前 N 条（按热度）。若那两篇 PDF 已掉出榜单，

## 四、🔴 顺带发现（既有问题，未修，请你定）

AST 对比显示 **187 篇**「消化前后结构改变」，形态是 **`ITex` / `BlockTex` 数量减少**：

```
id=553  消化前: P(T,ITex,T,ITex,T,…)  ← 大量行内 LaTeX
        消化后: P(T,ITex,T,ITex,T,…)  ← LaTeX 节点**变少**
```

⇒ **`_looksLikeLatex` 判据偏严**：部分**真 LaTeX**（如内容不含字母/`^`/`_` 的公式）
被判为「被转义的普通括号」⇒ `\(` 的反斜杠被消化 ⇒ **公式变成普通文本**。

⚠️ 这与白哥报的问题（「可见的反斜杠」）**方向相反** —— 那是「该消化的没消化」，
这是「**不该消化的被消化了**」。

**要不要修？** 两个选项：
| 选项 | 做法 | 代价 |
|---|---|---|
| **A. 放宽 `_looksLikeLatex`** | 只要 `\(…\)` 配对且内容非空 → 当 LaTeX 保留 | ⚠️ 会**漏消化** `\(66\.4%\)` 这类被转义的普通括号（白哥最初报的那类）|
| **B. 不修** | 保持现状 | 少数公式显示成文本（技术文里可见）|

📌 我倾向 **B（不修）** —— 因为 A 会把白哥**最初报的那个问题**弄回来。
但技术文里公式显示不正确也是真问题，所以**请你定**。
