## 一、C 档是什么（判据原文）

脚本判据（`audit_word_form_mappings.py` 第 247–266 行），**三个条件同时满足**：

## 二、337 条逐筛收敛 —— **真正需决策的只有 11 条**

C 档的判据用的是「反推器」给的候选，而**反推器会过度生成**。
我叠了三道**独立**筛子把它收敛：

| 筛 | 判据 | 为什么必要 |
|---|---|---|
| **S1** | `form` **本身不是词条** | 端侧**先①直查 spelling**，命中就不查 `word_form`（读 `word_query_service.dart` 确认）→ form 是词条时**映射是死数据** |
| **S2** | **真歧义**：≥2 个候选通过**正向回环**+**词性** | 反推（去后缀）天生多解；正向（加后缀）才唯一 |
| **S3** | `form` 在**真实语料**（`cefr_catalog`） | 用户真有可能划到 |

### 收敛结果

| 阶段 | 条数 | 筛掉什么 |

| S2 且**是真歧义** | **18** | 🔴 **300 条假候选**（反推器过度生成，占 **89%**） |
| **S3 且在真实语料** | **11** | 7 条（专名/罕见词） |

🎯 **337 → 11**。而且 11 条的**现状取值全部是「合法候选之一」**（没有一条取到了非法值）。

### 🔴 唯一的真错：`loses → los`

**证据**（实测）：
```
los   词条 A2 [n] zh='（西班牙语'  ipa='/lɔːs/ (Spanish); /lɒs/ (English approximation)'
      例句='In Spanish, 'los libros' means 'the books'.'
lose  词条 A2 [v] zh='失去，丢失'
```
- 端侧顺序：`loses` **不是**词条 → ①直查不中 → ②查 `word_form` → 得 `los`
- **用户查 `loses` → 拿到「（西班牙语」的卡片** ❌

🔑 **为什么 A 档没抓到它**：A 档要求「base 词性**不支持**该 rule」，
而 `los` 是 `[n]`、`plural` 接受 `{n,v}` → **词性通过了** → 落到 C 档，
**而 C 档只报「多候选」、不报「谁对」** → **这条真错被噪声淹没了**。

## 四、两个重要发现

### ① 「多候选」这个信号**两个方向都会失灵**

| 方向 | 例子 | 说明 |
|---|---|---|
| **假阳性**（报多了） | `cares` 候选含 `car` | `car` 的复数是 `cars` ≠ `cares` → **反推器过度生成**（占 C 档 89%） |
| **假阴性**（报漏了） | `evening → even` | `evening` **本身是词条**（A1 n「傍晚」）→ 端侧①直查直接命中 → **`evening→even` 是死数据，但审计把它算进 C 档** |

🔑 **反推（去后缀）天生多解；正向（加后缀）才唯一。** 只看反推候选 → 必然虚高。

### ② 当前**不会**造成「选错」（除 `loses` 外）

```
word_form 里「同 form 多 base」的行数 = 0      ← 实测
```
端侧 `analyzeForm` 已加 `ORDER BY base LIMIT 1`（确定化）。
**每个 lookup 只有一行可选** → 除上面那条真错外，不存在「在多个之间选错」的情形。

🔑 **C 档衡量的是「这个映射有多可争议」，不是「现在会出错」。**

## 七、🔴 更正：我把 `marr` / `ow` 判成「垃圾」是**错的**（2026-09-29 10:5x）

> 白哥问「所以应该除了 E 都做吗？」→ 我去核实 C 选项的两条前提，结果**两条都不成立**。

### 7.1 实测证据

| 词 | 我原判 | **实测** |
|---|---|---|
| `marr` | 「垃圾词条（释义与 `mar` 相同）」 | 🔴 **错** —— `marr` = **B2 · `[v]` · `/mɑːr/`**，释义「损坏，毁坏，糟蹋」，en=`(archaic or dialect) to damage, spoil, or impair…`，**有完整卡片**，**在真实语料** → 它是 `mar` 的**古体/方言变体**，是**合法词条** |
| `ow` | 「感叹词，不该支持 `past`」 | 🔴 **错** —— `ow` = **B2 · `[interj]`**「哎哟」· 而且 **`owed → owe` 现状本来就对**；`ow` 被 **0 个 form 指向**（`SELECT … WHERE base='ow'` → 空）→ **根本不存在这个映射问题** |

**`marred` / `marring` → `mar`** ✅ · **`owed` → `owe`** ✅ —— 端侧实测：查 `marred` 得到「损坏，破坏」（mar 的卡片）、查 `owed` 得到「欠，负债」（owe 的卡片）。**都是对的。**

### 7.2 🔴 这是「看起来像垃圾 ≠ 是垃圾」**当天第二次**重演

| # | 场景 | 我的错 | 后果 |
|---|---|---|---|
| 1 | §19 `word_form` 12,796 行 | 先定性「垃圾」，再补调查 | 差点误删（副本演练时发现混着真变形） |
| 2 | **本次 `marr` / `ow`** | **凭「释义与 mar 相同」「是感叹词」就写进报告当建议** | **报告里留了一条要执行的错误选项** |

🔑 **两次都栽在同一处**：**判据是「看起来」，不是「验证过」**。
`marr` 的释义确实与 `mar` 接近 —— 但那**正是变体词条该有的样子**（archaic form of `mar`）。
「释义相似」**不是**「垃圾」的证据，**它恰恰是变体的特征**。

### 7.3 ✅ 修正后的净结论

**C 档 11 条 → 10 条现状正确 + 1 条真错（`loses → los`）。**
「词条库里有垃圾」这个议题**在 C 档范围内不存在**。
→ 产品决策只剩 **B 一项**。
