🔴 **这与本文件自己写下的判据直接冲突**（`:413`）：

### 1.8 「重试无效」为何没有出口

- `/api/auth/verify` **能**识别失效 token（返回 `{"valid": false}`，**HTTP 恒 200**）。
- 但端侧只在**启动时**用它：`auth_provider.dart:136-169`（`tryRestore` → `token invalid on server, clearing credentials`）。
- **会话中**发生 401 ⇒ 没有任何代码去调它 ⇒ 界面永远停在「加载失败」。
- ⇒ **唯一的出路是「杀掉 App 重开」** —— 而这正是记忆里那条
  「**『静默失败 + 无出口』比报错更糟**」。

### 🔴 B. 单端登录 vs 多端（**须白哥裁决** · 后端 + 产品口径）

| 选项 | 做法 | 代价 |

| B3 | 折中：允许 N 台，超限踢**最旧** | 复杂度最高，收益有限 |

**我的建议：B1。** 理由：订阅权益就是**跨设备同步**；单端登录让该权益**在定义上不成立**。

## 6.2 🔴 B：两个**必须写进注释**的坑（都实测过）

**① 排序键必须用 `rowid`，不能用 `created_at`**
生产 `tokens.created_at` **两种格式混存**（实测）：

```
'2026-10-02 03:09:11'   ← 老行（`register` 早期写的）
'1791638643'            ← 新行（`login` 写的 Unix 秒字符串）
```
字典序里 `'2…' > '1…'` ⇒ 按 `created_at DESC` 排序会**保留全部老行**、
把**刚登录的那台**判成最旧**踢掉** ⇒ 现象是「**登录成功却立刻 401**」。
（正是本批要修的那个症状的**新版本** —— 很容易改出来。）

**② 必须先签发、后限额**：反过来的话，第 4 台登录时被删的是**已有的那 3 个之一**。

🔑 **判别性单测**：`test_token_limit_orders_by_rowid_not_created_at`
（构造「3 条老格式 + 1 条新登录」的形状 ⇒ 断言新登录那台**必须有效**）
**已证伪**：把 `rowid` 换成 `created_at` ⇒ **精确地**在该条断言上变红 ✅

⚠️ **不改**的两处（有意保留，且已在注释里写明「别顺手统一」）：
| 路径 | 行为 | 为什么保留 |
|---|---|---|
| `change_password` | 删「除当前外全部」| 凭据变更**必须**收回其他会话，否则「改密码防盗」防不住 |
| `reset_password` | 删**全部**再签发 | 忘记密码流程 ⇒ 凭据已不可信 |

📌 判据：**「同一个动作（删 token）」在不同业务语义下结论相反** —— 不能因为共用一条 SQL 就套同一策略。

## 6.3 🔴 C 的根因：类型住在**捕获层 import 不到**的文件里

`SyncUnauthorized` 被定义、被 `sync_client` 抛出，但**全仓零消费** ——
因为它住在带 Flutter 依赖的 `api/sync_client.dart`，而**捕获层** `services/sync_service.dart`
**必须是纯 Dart**（`scripts/query_verify` 要 import 它做离线断言）
⇒ **类型在层边界上静默丢失** ⇒ 401 落进通用分支 ⇒ 用户看到「同步失败」（暗示重试即可）。

**修法**：搬到 `services/sync_errors.dart`（**零 import**），`sync_client` 再 `export` 回原处
（保持既有引用不断）。

🔑 **判据**：**异常类型的定义位置必须与「能捕获它的那一层」的依赖约束相容** ——
否则它会被迫在层边界丢失，而且**不报错**（类型还在，只是没人 import 得到）。

## 6.4 D 的取舍（为什么不放 `local_meta`）

| 方案 | 结果 |
|---|---|
| 存 `local_meta` | ❌ 它**被明确排除**在 `kUserOwnedTables` 之外（它是「这份数据属于谁」的记录**本身**）⇒ **拿不到**「与数据同生命周期」 |
| **新建 `sync_cursor` 单行表** ✅ | ✅ 纳入清单 ⇒ 清数据时**随数据一起被清**，由**结构**保证 |

- 单行用 `CHECK (id = 1)` 表达 ⇒ 「写第二行」在**数据库层**就失败（比「约定只写一行」可靠）
- **迁移语义（有意）**：升级到 v11 时该表为空 ⇒ 下次同步 `since == null` ⇒ **全量重拉**
  （push/pull 幂等）；**故意不把 prefs 老游标搬过来** —— 搬过来会把脏游标带进新结构，
  而「空表」顺带**自愈**升级前就存在的空洞
- `clearSyncCursorFor` → `clearLegacySyncCursorPrefs`（只剩「清掉 v11 前遗留键」一个职责）
