## 一、为什么必须换（合规，不是性能）

上一轮我建议「阿里普惠体子集化省 21 MB」时**只算了技术收益，漏查条款**。核实后：

**阿里巴巴普惠体官方法律声明**（2.0 / 3.0 同款）：

> 「未经阿里巴巴授权，任何人不得：……2) 对阿里巴巴字体进行**修改、仿制、转换**、
> 翻译、反编译、反向工程、**拆分**、破解……」

**子集化 = 对字体文件做「拆分 / 转换 / 修改」→ 明确禁止。**

项目内早有记录（我漏查了）：

| 出处 | 原文 |
|---|---|
| `design-system-spec:778` | 「官方 3.0 法律声明的禁止事项第 ① 条含「**转换**、**拆分**」」 |
| `coevo_tokens.dart:698` | 「中文 UI。全量 24.2 MB，**不做子集化**（阿里普惠体条款禁止拆分/转换）」 |
| `ui-ux-refactor-assessment:984` | 「~~E · 阿里普惠体子集化~~ ⚠️ 条款灰区 **不建议**」 |

🔑 **「免费商用」≠「允许子集化」** —— 两个独立的授权维度，前者常被误当成后者。

## 二、许可依据（候选侧）

**Google Fonts 官方许可页**（Noto Sans SC）原文：

> "Permission is hereby granted, free of charge, to any person obtaining a copy of the
> Font Software, to **use, study, copy, merge, embed, modify, redistribute**, and sell
> modified and unmodified copies of the Font Software..."

| 维度 | OFL 1.1 |
|---|---|
| 商用 | ✅ |
| **修改 / 子集化** | ✅ **明确允许**（OFL FAQ 原文列出 "Subsetting — reduce the character set"） |
| 格式转换 | ✅ |
| 条件 | ① 附许可文本 ② 保留版权声明 ③ 🔴 **Modified Version 不得用 Reserved Font Name** |

### 2.1 🔴 保留名核实（OFL 条件 ③）

我拉了官方 `OFL.txt` 原文：

```
Copyright 2014-2021 Adobe (http://www.adobe.com/), with Reserved Font Name 'Source'
```

→ **保留名是 `Source`**（继承自 Source Han Sans 思源黑体）

| 名字 | 是否保留名 | 能否用于子集版 |
|---|---|---|
| `Source` | 🔴 **是** | ❌ 不得使用 |
| `Source Han Sans` | 🔴 含保留名 | ❌ |
| **`Noto Sans SC`** | ✅ **不是** | ✅ **可以用** |

→ **保留 `Noto Sans SC` 作为 fontFamily 是允许的**（只需附 OFL.txt + 版权声明）。

### 2.2 需要补的东西

| 项 | 做法 |
|---|---|
| OFL.txt | 放进 `app/assets/fonts/` **并声明进 pubspec**（🔴 不声明就不会进包，等于没附） |
| 版权声明 | 在 README 或「关于」页注明 Noto Sans SC (Adobe, OFL 1.1) |

## 三、实测数据

### 3.1 字体文件

| | 阿里普惠体（现状） | Noto Sans SC（候选） |
|---|---|---|
| 格式 | TTF/glyf | ✅ TTF/glyf（**不是 OTF/CFF**） |
| 字形总数 | 29,296 | **31,036**（更多） |
| cmap 码位 | — | 30,890（基本汉字区 **20,976**） |
| 可变字体 | ❌ 静态 | ✅ `wght` 100–900 |
| 源文件大小 | 24.16 MB（3 字重） | 16.95 MB（1 个 VF） |
| **子集后** | 🔴 **不能子集** | ✅ **1.24 MB / 字重（4 个 = 4.83 MB）** |

### 3.2 🔑 子集字符集 = **4,013 个码位**（从真实数据提取）

| 来源 | 汉字数 |
|---|---|
| `word.db` 全部文本字段 | **3,868** |
| `app/lib/**.dart` 源码 | 1,144 |
| **并集** | **3,873** ← 占 Noto Sans SC 全部汉字的 **13.2%** |
| + ASCII 95 + 中英标点 | **共 4,013 码位** |

⚠️ **收费项已计入**：源码里的**中文注释**也会被收进字符集（无法可靠区分注释与字符串）。
注释用字与 UI 用字高度重叠 → **多收的成本极小（几十个码位）**，
而漏收的代价是「界面上某个字变方块」→ **宁可多收**。

### 3.3 体积收益

| 项 | 大小 |
|---|---|
| 现状（阿里普惠体 3 字重） | **24.16 MB** |
| 候选（Noto Sans SC 4 字重子集） | **4.83 MB** |
| **净省** | **19.33 MB** |

🔑 这是**字重从 3 个增到 4 个**（多补一个真 `w600`）之后的结果。
若只要 3 个（400/500/700）则约 **3.63 MB**，省 20.53 MB。

## 四、🔴 本脚本的合规做法（值得记下）

**没有把字体文件内联进 HTML。**

最初想复用既有 `build_font_compare.py`（它把字体 base64 内联进 HTML，离线可看）——
但那个做法在这里**会越界**：

| | OFL 字体 | 阿里普惠体 |
|---|---|---|
| 内联进 HTML 并提交仓库 | ✅ 允许 | 🔴 **禁止**（条款禁止「上传、发布、**转载**阿里巴巴字体文件」） |
| PIL 渲染成 PNG | ✅ 允许 | ✅ **允许** |

🔑 两家条款都明确：**「用字体创建的内容」不受字体许可约束** ——
OFL 原文：「The requirement for fonts to remain under this license does
**not** apply to any document created using the Font Software」。

→ 所以改为 **PIL 截图**：两边都是位图，**零许可争议，且对比更公平**
（同一渲染器、同一字号、同一像素比）。

## 五、技术路径（若决定换）

### 5.1 改动清单

| # | 文件 | 改动 |
|---|---|---|
| 1 | `scripts/fetch_fonts.py` | ✅ **已加** `noto-sc` 条目（含真实 sha256） |
| 2 | `scripts/build_fonts.py` | 加 `noto-sc` 到 `CANDIDATES`（用 `axes: {'wght': N}`，文法与 `literata` 一致） |
| 3 | `app/assets/fonts/` | 放入 4 个子集 TTF + **`NotoSansSC-OFL.txt`** |
| 4 | `app/pubspec.yaml` | 字体声明改 4 字重 + **声明 OFL.txt 为 asset** |
| 5 | `app/lib/theme/coevo_tokens.dart` | `CoFonts.cjk = 'NotoSansSC'`（**单一出处，只改这一行**） |
| 6 | `scripts/tokens_verify/` | 断言更新：字体名 + **cmap 覆盖校验**（见 5.3） |
| 7 | `app/README` 或「关于」页 | 补版权声明（OFL 要求） |

### 5.2 🔑 一个关键实现细节：VF 默认值是 **Thin**

Noto Sans SC 的 `fvar` 轴：

```
wght: 100.0 – 900.0  (默认 100.0)      ← 🔴 默认是 Thin，不是 Regular！
```

→ **构建期必须显式 pin 每个字重**（`build_fonts.py` 的 `instances`/`axes` 机制正好支持）。
不 pin 会得到极细的字重；而 Flutter 的 `fontWeight` **不会**驱动 VF 轴
（要用 VF 得上 `FontVariation` API）→ **构建期转静态最省事**，这也是项目既有惯例。

### 5.3 断言方案

**新增断言（防「换了但没接上」）**：

| 断言 | 理由 |
|---|---|
| `CoFonts.cjk == 'NotoSansSC'` | 单一出处漂移 |
| pubspec 声明了 4 个字重（400/500/600/700） | 少一个 → 那档回退 |
| pubspec 声明了 **OFL.txt** | 不声明就不进包 → **合规条件未满足** |
| 🔴 **`word.db` 全部汉字 ⊆ 字体 cmap** | 见下 |

**⚠️ 最后一条是本次最该加的防线**：

子集化后字体**只含 4,013 码位**。将来 `word.db` 加词可能引入**新汉字**
→ **缺字 → 回退系统字体 → 那条释义变丑**，而且**没有任何报错**。

🔑 这正好命中项目已有的一条教训：「**有 fallback ≠ 视觉一致**」。
→ 用一条断言把「词库的汉字 ⊆ 字体 cmap」锁住：**词库一升级就红**，
再跑一次 `build_cjk_font_compare.py` 重新子集即可。

（同 `verify_worddb_sync` 的思路：**漂移必须能被立刻发现**。）

### 5.4 需重跑的验收

`analyze_inproc` · `tokens_verify` · `trace_verify` · `query_verify` 全套 + **真机比对三档中文渲染**。

⚠️ 字体是**视觉资产** → **必须真机肉眼过一遍**（断言保证不了字形观感）。

## 六、⏳ 需要白哥定的

### 6.1 观感（看图定夺）

对比图里两种字形的差异：

| | 阿里普惠体（现状） | Noto Sans SC（候选） |
|---|---|---|
| 风格 | 偏**几何 / 圆润**，字面较松 | 偏**方正 / 中性**，字面较紧 |
| 气质 | 有一点「设计感」 | 「工具感」更中性（大厂 App 常见） |
| 与拉丁字体搭配 | 与 `Literata`（衬线）对照明显 | 同为无衬线系，**与 UI 更统一** |

**两种都不算差，是气质取舍** → 需要白哥看实际观感。

### 6.2 三个选项

| 选项 | 收益 | 说明 |
|---|---|---|
| **A · 换 Noto Sans SC（4 字重）** | **省 19.33 MB** + 补真 w600 | 我倾向此案：合规 + 更全的字重 |
| B · 保持阿里普惠体 | 0 | 24 MB 永远减不掉；且 w600 一直是「就近取」 |
| C · 另找其他 OFL 中文字体 | 视字体 | 需要再走一轮取证 + 渲染对比（不推荐，Noto 是覆盖最全的） |

### 6.3 若选 A，还需定

- **要不要 4 个字重**（多 1.2 MB 换真 `w600`，影响 69 处 UI）
- 是否**同时**处理 3 个死依赖（`audioplayers` / `record` / KaTeX）→ 一次重构一次构建
