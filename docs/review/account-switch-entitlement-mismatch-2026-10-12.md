# 「换账号后订阅状态仍显示已订阅」调查报告

**日期**：2026-10-12 19:45
**触发**：白哥换账号（`123@qq.com`）后截图，「我的」页显示 **「订阅中 · 到期日 2026-10-13」**，
但同一张截图底部云朵胶囊写着 **「同步失败」**。
**方法**：SSH 直查生产库 + 后端/nginx 日志 + 读端侧源码（含接线链）。
**状态**：🔴 **仅调查，未改代码** —— 且本次涉及**产品语义决策**，需白哥定（见 §5）。

---

## 1. 事实（三层证据）

### ① 服务端：`123@qq.com` **没有订阅**

```
5368619a   123@qq.com    exp=None        created=1791805444   ← 今天 19:44 注册
c96e3b62   baixu100@qq.com   exp=2026-10-13T10:37:35Z      ← 真正付过钱的
```

⇒ UI 显示「订阅中」**不可能来自服务端**。

### ② UI 只能来自端侧（日期格式是铁证）

| 来源 | 呈现形式 |
|---|---|
| 服务端 `expires_at` | 原始 ISO 串 ⇒ 会显示成 `2026-10-13T10:37:35Z`（带 `T`、带 `Z`）|
| **端侧** `expiresAtUtc` | `subscriptionExpiryLabel` 里 `.toLocal()` 格式化 ⇒ 显示成 **`2026-10-13`** ✅ |

截图显示的是 **`2026-10-13`**（无时分秒）⇒ **端侧**。

### ③ 「同步失败」的真身：`403`

nginx access log（19:44 那段，反复出现）：
```
"GET /api/sync/pull?device_id=dev_e75206dd… 403   ← 6 次
```
后端 `sync_handlers.rs:520`：
```rust
return Err(AppError::Forbidden("跨设备同步是订阅权益，订阅后可开启".into()));
```
⇒ 服务端按 **`user_id`** 判订阅 ⇒ `123` 无订阅 ⇒ **403**。

---

## 2. 根因：**「订阅」被一个布尔值表达，但它其实有两层**

```
                     ┌──────────────────────────────────────┐
   端侧 IAP 权益 ──▶ │  属于 Apple ID（沙盒账号 baixu1986…）  │  ← 本机确实有这个购买
                     └──────────────────────────────────────┘
                     ┌──────────────────────────────────────┐
   服务端订阅    ──▶ │  属于我们的 user_id                   │  ← 123 没有
                     └──────────────────────────────────────┘
                              ↓  OR 成一个 bool
        subscriptionActiveNow() = 端侧.isActive || 服务端.isActive
                              ↓
        「我的」页订阅卡 → 「订阅中」        （② 端侧为真）
        云朵胶囊         → 「同步失败」      （③ 服务端 403）
```

**问题不在"哪一层错了"，而在"两层被 OR 到了一起"**：
只要**任一层**为真，UI 就认为"有全部订阅权益" ⇒ 于是
**一个不可用的能力被显示成可用**（卡片说订阅中，同步却 403）。

### 代码定位

| 环节 | 位置 | 现状 |
|---|---|---|
| 唯一判据 | `providers/iap_provider.dart` `subscriptionActiveNow()` | **端侧 OR 服务端** |
| 订阅卡片 | `screens/profile_screen.dart:1731` | 用该判据 ⇒ 显示「订阅中 · 到期日 …」 |
| 卡片到期日 | `iap_plan.dart` `subscriptionExpiryLabel()` | **端侧优先** ⇒ 显示端侧的值 |
| 云朵胶囊 | `widgets/sync_cloud_badge.dart:205` | `subscribed ? syncChipLabel(...) : syncUnsubscribedLabel()` |
| 胶囊文案 | `services/sync_status.dart:146` | `failed` 分支只为 **401** 做了特例 ⇒ 403 落到 **`'同步失败'`** |

📌 注意：`syncUnsubscribedLabel()` = **「未订阅 · 订阅后可同步」** 已经存在且正确 ——
**只是因为端侧说"已订阅"，UI 走到了另一条分支**。
⇒ 所以「同步失败」**不是新 bug**，它是**同一个根因的第二个表现**。

---

## 3. 🔴 为什么这不是「忘了复位」那么简单

项目里**已经有一条断言**管过同类事故（`verify_iap_plan.dart` 第 ⑬ 组）：

```dart
check('🔴 登出**不**碰端侧 IAP（它是 Apple ID 级，不是 App 账号级）',
    !onLogoutTail.contains('iapServiceProvider'),
    '端侧 StoreKit 权益跟 Apple ID 走 —— 换 App 账号它本来就还在，复位它会误伤付费用户');
```

⇒ **「端侧 IAP 权益跟 Apple ID 走」是 2026-10-09 的明确定案**（登出时故意不复位它）。

而今天上午我在修 B3 时，**只复位了 `_pendingReports`（积压交易），没有碰 `_snapshot`（权益快照）** ——
当时**没有违反**这条定案（甚至可以说是遵守了它）。

⇒ **所以本次的现象不是"漏了一行复位"，而是这条定案与「服务端按 user_id 判权益」之间
本来就存在的矛盾，今天被白哥的多账号测试暴露出来了。**

🔑 **判据**：**「权益」有两层（端侧/Apple ID 级、服务端/账号级）时，
不能用一个布尔值表达** —— 否则任一层为真就会把另一层的"不可用"显示成"可用"。
📌 同族已有判据：**「同一件事的口径只能一处权威」** / **「共享数据 ≠ 同判据」**。

## 4. 影响面（不止显示）

| # | 影响 | 说明 |
|---|---|---|
| 1 | 「我的」页订阅卡显示「订阅中」 | 服务端明明是 `None` —— **误导** |
| 2 | 云朵胶囊显示「同步失败」 | 应为「未订阅 · 订阅后可同步」（**文案已有，走不到**）|
| 3 | ⚠️ 其他服务端权益同样不一致 | 云端书架、翻译不限次额度都按 `user_id` 判 ⇒ 端侧说"有"、实际不可用 |
| 4 | ⚠️ 用户会反复重试 | 日志显示 19:44 内重试了 **6 次**（"失败"暗示可重试，实际是权限拒绝）|

**触发条件**：同一台设备 + **同一个 Apple ID** + 换**我们的 App 账号**。
⚠️ 生产环境真实用户几乎不会这么用；但**测试阶段（白哥反复建号）会反复遇到**。

## 5. 三个修法（**需白哥选** —— 这是产品语义决策）

### 方案 A · 分场景用不同口径（**最小、最稳**）

- **订阅卡片**（描述"你有没有订阅"）→ 用**服务端口径**；端侧只在**服务端还没记账的窗口**内兜底
- **云朵胶囊**（描述"能不能同步"）→ **必须**用服务端口径（同步本身就是服务端能力）
- ✅ 不动 ⑬ 的定案（端侧状态仍跟 Apple ID 走，只是**不拿它代表"账号级权益"**）
- ✅ 改动小（`sync_cloud_badge` 1 处 + `subscriptionActiveNow` 拆成两个口径）
- ⚠️ 代价：卡片文案要能表达"本机有购买、但当前账号没有"这种中间态

### 方案 B · 只改云朵胶囊（**最省事，但不推荐**）

- 只把 `subscribed` 从 `subscriptionActiveNow` 换成 `subscriptionProvider.isActive`
- ✅ 1 行
- 🔴 缺点：**卡片说「订阅中」、胶囊说「未订阅」** —— 同屏自相矛盾，比现在更乱

### 方案 C · 端侧权益也按 App 账号归属（**最彻底**）

- 用**交易自带的 `appAccountToken`**（今天 B1 刚加的绑定）判断"这笔交易是不是当前账号买的"；
  不是 ⇒ 端侧不算当前账号的权益
- ✅ **"订阅"只剩一个口径**（App 账号）⇒ 卡片/胶囊/服务端额度全部一致
- ✅ 用上了 B1 刚建立的绑定
- ⚠️ 代价：① **推翻 ⑬ 的定案**（"端侧跟 Apple ID 走"）② 旧交易无 token ⇒ 需兼容策略
  ③ 未登录购买无 token ⇒ 只能宽松处理

**我的建议：A 为主**（改小、不动定案、立刻消除误导）；
若白哥希望"订阅只有一种口径"，则走 **C**（更彻底，但要重写 ⑬ 那条断言）。

## 6. 附带发现（顺手记，不必单独修）

1. **⑬ 组断言只覆盖「登出」，没覆盖「换账号」** ——
   现在 `onLogout` 有复位逻辑，但**「A 账号 → B 账号」这条路径没有断言**。
   ⇒ 无论选哪个方案，都应**补一条「换账号」的断言**。
2. `syncChipLabel` 的 `failed` 分支**只为 401 做了文案**，403 落到通用「同步失败」——
   ⚠️ 这**本身不是 bug**（正常路径下 403 时 `subscribed` 应为 false，会走未订阅文案）；
   它只是**因为口径混用才被走到**。修了 §5 的方案后自动消失。
3. `sync_client.dart` **已经**把 403 正确分流成 `SyncNotSubscribed`
   （`_friendlySyncError` 也正确返回了「跨设备同步是订阅权益，订阅后可开启」）——
   这一层**没有问题**，问题在"顶层的 `subscribed` 判错了"。
