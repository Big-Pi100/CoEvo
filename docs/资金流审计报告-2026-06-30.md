# 资金流审计报告

日期：2026-06-30
范围：backend/crates/api_server/src/ 下所有涉及资金流的操作

## 审计结论

`distribution_commissions` 表已完成 **收入不可变** 改造（locked→available 除外），但仍有以下遗漏：

---

## 🔴 严重问题

### 1. 免费下单路径 — `pay_handlers.rs:158,180`

**当前行为：**
```sql
-- 全额抵扣时 INSERT 一条 status='used' 的佣金记录
INSERT INTO distribution_commissions (...) SELECT ..., 'used', ... FROM ...
-- 同时 UPDATE 原 available 记录 SET amount=0, status='cancelled'
```

**问题：** 仍在操作 `distribution_commissions` 表 INSERT status='used' + UPDATE amount=0。违反独立 INSERT 原则。

**修复方案：** 改为 INSERT INTO distribution_expenses(expense_type='subscription')

---

### 2. 免费下单原记录归零 — `pay_handlers.rs:167`

**当前行为：**
```sql
UPDATE distribution_commissions SET amount=0, status='cancelled'
WHERE id=?1 AND status='available'
```

**问题：** 直接修改了原始佣金记录的金额（设为0），违反资金流不可变原则。

**修复方案：** 只 INSERT expenses，不再修改原始记录

---

## 🟡 需要关注的统计查询

以下查询当前直接读 `distribution_commissions` 的 status 字段来统计"已打款"等指标，在 expenses 表引入后不再准确：

### 3. admin_stats — 总览指标
**文件：** `distribution_handler.rs:1162-1180`

| 旧查询 | 应改为 |
|--------|--------|
| `SUM(commissions WHERE status='available')` | `SUM(expenses WHERE status='confirmed' AND type IN ('settlement','subscription'))` |
| `SUM(commissions WHERE status='paid')` | `SUM(expenses WHERE status='paid')` |
| `SUM(withdrawals WHERE status='pending')` | `SUM(expenses WHERE status='pending' AND type='withdrawal')` |

### 4. admin_summary — 按状态汇总
**文件：** `distribution_handler.rs:1470-1484`

按 commissions 的 `locked/available/paid` 分组统计 → 应改为按 expenses 的类型和状态统计。

### 5. admin_monthly_stats — 按月统计
**文件：** `distribution_handler.rs:1536-1544`

按月统计 commissions 的 paid 金额 → 应改为按月统计 expenses。

### 6. admin_ranking — 分销员排行
**文件：** `distribution_handler.rs:1577-1587`

`SUM(dc.amount) WHERE dc.status NOT IN ('cancelled')` 计算的是总收入，没有减去支出。应改为 `SUM(dc.amount) - SUM(expenses.amount)`。

### 7. admin_team_user — 用户总佣金
**文件：** `distribution_handler.rs:1087`

同上，只算了总收入没减支出。

### 8. campaign_handler — 活动统计
**文件：** `campaign_handler.rs:562,572`

活动佣金总额和购买人数查询也使用了 commissions 表，未考虑已退回/取消的记录（但 cancelled 已排除，基本可用）。

## 🟢 可接受的操作

### 退款 — `distribution_handler.rs:1291,1392`

```sql
UPDATE distribution_commissions SET status='cancelled'
WHERE order_id=?1 AND status='locked'
```

退款时取消 **状态为 locked** 的佣金（尚未解锁可用），只改了状态没改金额。locked 的佣金尚未进入资金流，可以接受。

### locked→available 解锁 — `campaign_scheduler.rs:19`

```sql
UPDATE distribution_commissions SET status='available', unlocked_at=datetime('now')
WHERE status='locked' AND datetime(created_at,'+30 days') <= datetime('now')
```

只改了状态没改金额，是正常的解锁流程，可以接受。
