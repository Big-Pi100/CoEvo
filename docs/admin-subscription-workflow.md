# 管理后台 · 订阅审批流程设计

> 日期: 2026-05-19 · 聚焦付费权限管理

---

## 一、核心流程

```
用户联系客服 → 服务人员提交申请 → 超级管理员审批 → 自动开通/延长 → 通知用户
```

### 角色

| 角色 | 入口 | 注册要求 | 能做什么 |
|------|------|---------|---------|
| **监护者（家长）** | 独立家长入口 | 监护人声明 + 学生账号绑定 | 查看学生学习全貌 |
| **监护者（辅导老师）** | 管理后台入口 | 姓名 + 电话 + 身份证 | 查看分配学生的学习全貌 |
| **服务人员** | 管理后台入口 | 姓名 + 电话 + 身份证 | 搜索用户 + 提交订阅申请 + 可揭看手机号（写日志） |
| **超级管理员** | 管理后台入口 | `COEVO_ADMIN_KEY` | 审批 + 全部管理 + 揭看手机号（写日志） |
| **观察者** | 管理后台入口 | 由超管创建 | 只读查看 |

> 姓名和手机号默认脱敏 `张*` / `138****1234`。服务人员和超管可点击揭开。**手机号揭开写入审计日志**，姓名不记录。

---

### 账号开通流程（统一）

```
任何人注册
    │
    ├─ 从家长入口注册 → 自动角色=guardian_pending
    │   填写：监护人声明（姓名、与学生关系、知情同意）
    │
    ├─ 从管理后台入口注册 → 自动角色=pending
    │   填写：姓名、电话、身份证号
    │   选择申请角色：服务人员 / 辅导老师
    │
    ▼
提交 → 超管审批中心
    │
    ├─ 通过 → 角色激活 + 通知申请人
    └─ 拒绝 → 填写原因 + 通知申请人

### 审批后自动生效

```
通过 → 更新 user_preferences(subscription_expires)
     → 写入 audit_log
     → 服务人员可见审批结果

拒绝 → 写入 audit_log + 拒绝原因
      → 服务人员可见拒绝原因
```

## 三、数据库设计（新增部分）

```sql
-- 管理员表
CREATE TABLE admin_users (
    id TEXT PRIMARY KEY,
    username TEXT NOT NULL UNIQUE,
    password_hash TEXT NOT NULL,         -- bcrypt
    role TEXT NOT NULL,                  -- "super" | "service" | "tutor" | "observer" | "guardian"
    status TEXT NOT NULL DEFAULT 'pending',  -- "pending" | "active" | "rejected" | "disabled"
    -- 注册信息
    real_name TEXT,                      -- 真实姓名
    phone TEXT,                          -- 电话
    id_number TEXT,                      -- 身份证号（加密存储）
    -- 家长专用
    guardian_declaration TEXT,           -- 监护人声明（JSON: 姓名、与被监护人关系、知情同意）
    student_bind_id TEXT,               -- 绑定的学生 user_id
    -- 通用
    apply_reason TEXT,                   -- 申请理由
    reject_reason TEXT,                  -- 拒绝原因（审批后填写）
    registered_from TEXT,               -- "parent" | "admin"
    created_by TEXT,                     -- 创建人（审批通过时填入）
    created_at INTEGER NOT NULL,
    approved_at INTEGER
);

-- 订阅申请审批表
CREATE TABLE subscription_requests (
    id TEXT PRIMARY KEY,
    target_user_id TEXT NOT NULL,
    requested_by TEXT NOT NULL,      -- 服务人员 admin_id
    reviewed_by TEXT,                -- 超级管理员 admin_id（审批后填入）
    package TEXT NOT NULL,           -- "30d" | "365d" | "lifetime"

    status TEXT NOT NULL DEFAULT 'pending',  -- pending | approved | rejected

    requested_at INTEGER NOT NULL,

## 四、API 设计

### 管理员认证

| 方法 | 路由 | 说明 |
|------|------|------|
| POST | `/api/admin/login` | 服务人员/观察者登录 {username, password} → token |
| POST | `/api/admin/verify-key` | 超级管理员用 COEVO_ADMIN_KEY 验证 |

所有管理 API 使用 `X-Admin-Key`(超管) 或 `Authorization: Bearer <token>`(服务人员)。

### 用户管理

| 方法 | 路由 | 说明 |
|------|------|------|
| GET | `/api/admin/users?q=` | 搜索（含卡片数、复习数） |
| GET | `/api/admin/users/:id` | 用户详情 |

### 订阅申请（服务人员）

| 方法 | 路由 | 说明 | 角色 |
|------|------|------|------|
| POST | `/api/admin/subscription-requests` | 提交开通申请 | service |
| GET | `/api/admin/subscription-requests?status=pending` | 查看申请列表 | all |

### 审批（超级管理员）

| 方法 | 路由 | 说明 |
|------|------|------|
| POST | `/api/admin/subscription-requests/:id/approve` | 通过 |
| POST | `/api/admin/subscription-requests/:id/reject` | 拒绝 {reason} |
| PUT | `/api/admin/users/:id/subscription` | 直接修改（超管直达） |

### 监护者专属 API

| 方法 | 路由 | 说明 |
|------|------|------|
| GET | `/api/admin/guardian/students` | 我关注的学生列表（含概览统计） |
| GET | `/api/admin/guardian/students/:id` | 学生详情（卡片+复习+对话统计） |
| GET | `/api/admin/guardian/students/:id/cards` | 学生所有卡片（按状态分组） |
| GET | `/api/admin/guardian/students/:id/weak-points` | 薄弱点列表 |
| GET | `/api/admin/guardian/students/:id/conversations` | 完整对话流（按对话分组，全部历史） |
| GET | `/api/admin/guardian/students/:id/conversations/:convId` | 单个对话的完整消息 |

### 超级管理员 — 监护分配 API

| 方法 | 路由 | 说明 |
|------|------|------|
| POST | `/api/admin/guardian/assign` | 将学生分配给监护者（辅导老师或家长） |
| DELETE | `/api/admin/guardian/assign/:id` | 取消分配 |
| GET | `/api/admin/guardian/assignments` | 查看所有监护关系 |

### 审计

| 方法 | 路由 | 说明 |
|------|------|------|
| GET | `/api/admin/audit-log?user_id=&admin_id=&action=` | 操作日志查询 |

## 五、前端页面结构

### 入口分离

```
┌─────────────────────────────────────────────────────┐
│                                                     │
│   /admin         管理后台入口（服务人员/辅导老师）    │
│   /guardian      家长入口（独立页面）               │
│                                                     │
└─────────────────────────────────────────────────────┘
```

两个入口不同页面，不混合。

### 路由设计

```
┌── /guardian（家长入口）
│   ├─ 登录页（监护人声明确认）
│   ├─ 学生列表（仅自己的学生）
│   └─ 学生详情
│       ├─ 卡片 Tab
│       ├─ 对话 Tab（完整对话流）
│       └─ 薄弱点 Tab
│
├── /admin（管理后台入口）
│   ├─ 登录页（admin key 或账号密码）
│   ├─ 注册页（姓名+电话+身份证+申请角色+理由）
│   │
│   ├─ 状态: pending → 「申请已提交，等待审批」
│   │
│   ├─ 仪表盘（仅 active 用户可见，按角色显示不同内容）
│   │
│   ├─ 审批中心（仅超管）
│   │   ├─ 账号审批 [待审批]
│   │   ├─ 订阅审批 [待审批]
│   │   ├─ 已通过 / 已拒绝
│   │   └─ 点击查看申请人详细信息（姓名/电话/身份证/申请理由）
│   │
│   ├─ 用户管理（服务人员+超管）
│   │   └─ 搜索 → 提交订阅申请
│   │
│   ├─ 监护分配（超管）
│   │   └─ 学生 ↔ 监护者绑定
│   │
│   └─ 管理员管理（超管）
│       └─ 创建/禁用管理员
```
