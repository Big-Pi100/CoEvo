## 〇之二、🔴 完整因果链：不是「我忘了」，是**v2 本身就偏离了 v1**

追下去发现偏离有**三层**，而且我的实现是「**忠实执行了一份本身已偏离的文档**」：

| 层 | 出处 | 卡片 sections | 记忆法地位 |
|---|---|---|---|
| **L0 权威原文** | v1 §4.2 | `[root, definition, context]` | ✅ **主体（第 1 位）** |
| **L3 实施方案** | **v2 §3.3** | `[sense, collocation, family]` | 🔴 **完全丢失** —— **连 `root` 都没有** |
| 实际实现 | `data/word.db` | `[sense × 4, root]` | 🔴 排最后 |

**v2 §3.3 原文（实测摘录）**：
```json
"sections": [
  { "type": "sense", "order": 1, "pos": "v", "en": "...", "zh": "...", "example": "..." },
  { "type": "collocation", "items": [...] },
  { "type": "family", "members": [...] }
]
```
→ **`sense` 打头，且整份结构里没有 `root`**。记忆法在 v2 的卡片结构里**消失了**。

**而 v2 内部还自相矛盾**：

| 位置 | 说法 |
|---|---|
| v2 **§3.2 原则 1** | 「记忆角度：一次只能稳固建立 **1 个**『词 → 义』连接。多义项并列会导致**语义干扰**（semantic interference），降低提取强度」→ ✅ **方向正确** |
| v2 **§3.3 结构** | `[sense, collocation, family]` —— 义项打头、无记忆法 → 🔴 **与自己的原则 1 不一致** |

**我的实现同时违反了两者**：
- 违反 v1 §4.2（记忆法应排第 1）→ 记忆法被丢到第 5 位
- 违反 v2 §3.2 原则 1（应只放 1 个义项）→ 铺了 **4 个**义项

**→ 所以「我忘了最初的设计」这个描述要修正为更准确的**：
**上游文档在卡片结构上先偏离了权威原文，我在下游又忠实实现了那个偏离版本。**
两条都要修：**L3 的卡片结构按 L0 改，实现按修好的 L0 重建。**

> ✅ **对齐后的正确形状**（L0 §4.2 + L3 原则 1 的交集）：
> `[记忆法] → [definition：只 1 条] → [context：只 1 条] → [aggregate_link]`
> `definitions[1..]` 进 `card_extra` —— **这一点 L3 的 §3.2/§4.2 与 L0 §5.2 一致，可直接沿用。**

## 一、偏离清单（8 项）

### 偏离 1 🔴🔴 `section` 类型体系：v1 有 **8 种**，我只实现了 **2 种**

| v1 §4.2 / §6.2 的 type | 含义 | 我的实现 |
|---|---|---|
| `root` | 词根词缀（**记忆法 · 优先级 1**） | ✅ 有（但排最后） |
| `cognate` | 同源串记（记忆法 · 优先级 2） | 🔴 **缺** |
| `collocation` | 搭配整记（记忆法 · 优先级 3） | 🔴 **缺** |
| `etymology` | 词源故事（记忆法 · 优先级 4） | 🔴 **缺** |
| `imagery` | 联想图像（记忆法 · 优先级 5） | 🔴 **缺** |
| `definition` | 释义 | 🔴 **缺**（我合并进了 `sense`） |
| `context` | 语境原句（记忆法 · 优先级 6） | 🔴 **缺**（我把例句塞进 `sense`） |
| `aggregate_link` | 聚合页入口（§4.4） | 🔴 **缺** |
| — | — | ⚠️ `sense` 是**我自创的**，v1 里没有 |

**实测**：全库 `sections` 只有 `sense` 24,491 个 + `root` 5,484 个（= 有 `word_morpheme` 记录的词数，分母 11,523）。

### 偏离 2 🔴🔴 卡片目标反转：记忆法从「主体」变成「配料」

v1 §1.1：「每个单词的卡片在制卡时**根据记忆法优先级组合生成**」
v1 §8.2 伪代码：`for mtype in [profile.primary_type, profile.secondary_type]` → 先放记忆法 section

**我的实现**：先把 4 个词典义项铺满，词根（如果有）塞在最后。

| 我的卡 `intercept` | v1 的卡 |
|---|---|
| `sections = [sense, sense, sense, sense, root]` | `sections = [root, definition, context]` |
| 位置：词根在 **第 5 位** | 位置：词根在 **第 1 位** |
| 5 sections · 约 550 字符 | 3 sections · 约 80 字符 |

**实测 `root` 位置分布**：位置 [1] 1,715 · [2] 2,639 · [3] 939 · [4] **191** —— **`root` 从不排第一**。

### 偏离 3 🔴🔴 `word_mnemonic_profile` 是**死数据** —— 算出来了没人用

实测「`primary_code` 对应的 section 是否出现在卡里」：

| primary 记忆法 | 词数 | 卡里有该 section | 没有 |
|---|---:|---:|---:|
| `root` | 5,334 | 5,322 | 12 |
| `etymology` | **3,525** | **0** | 3,525 |
| `context` | **1,410** | **0** | 1,410 |
| `image` | **957** | **0** | 957 |
| `cognate` | **195** | **0** | 195 |
| `collocation` | **102** | **0** | 102 |

**→ 6,189 词的 `primary` 记忆法在卡里完全不存在（53.7%）。**
只有 `root` 这一类被渲染了。**表建了、数据算了、但制卡时没用。**

**最刺眼的一例**（`caution`，primary=etymology）：
```
v1 会给它： 「拉丁 cavere（当心）→ cautio（小心）→ 英语 caution」   ← 记忆法，主体
我的卡给了：[n]谨慎，小心 | [n]警告，告诫 | [v]警告，告诫              ← 三个词典义项
```
**v1 精心挑的记忆法被丢掉，换成了词典条目堆砌。**

### 偏离 4 🔴 `aggregate_link` 缺失 → 卡片无法跳到聚合页

v1 §4.4 明确卡片要带聚合页入口（`{"type":"aggregate_link","page_id":123,...}`），
§8.5 也说「单词卡加入口 section」。

**实测**：`aggregate_page` 有 **1,777 页**（etymon 1,181 + root 596），
**但 card 里没有任何 `aggregate_link`** → **用户从卡片跳不到聚合页，聚合页无法被发现。**

### 偏离 5 🔴 音频朗读清单失效（下游连带）

v1 §6.2 规定只有 `context` / `collocation` 是纯英文、需要朗读：
```
front ✅ · context ✅ · collocation ✅
definition ❌ · root ❌ · etymology ❌ · cognate ❌ · aggregate_link ❌
```

**实测**：我的例句 24,385 / 24,491（100%）都在 `sense` 里，
**type 是 `sense`，不在朗读清单内** → 按 v1 规则**一条例句都不会生成音频**。

→ v1 §6.4 估的 **例句音频 240 MB**（占总包 360 MB 的 2/3）会**全部丢失**。
**这是卡片结构错误引发的下游故障，现在还没生成音频所以没暴露。**

### 偏离 6 🟠 `root` section 缺 `text` 字段

v1 §4.2：
```json
{"type":"root", "text":"in-（不）+ cred（相信）+ -ible（能…的）", "payload":{...}}
```
**实测我的**：只有 `['type','payload']` —— **没有 `text`**。
显示文本要客户端从 `payload.parts` 现拼。功能可行，但与契约不符。

### 偏离 7 🟠 `card_extra` 语义与 v1 不同

| | v1 §5.2 | 我的实现 |
|---|---|---|
| 列 | `(id, card_id, type, content, position)` | `(id, word_id, section, ord)` |
| 装什么 | **按优先级裁剪挤出的内容**（记忆法/释义/语境按 type 归类） | **第 5 个义项起**（纯溢出） |

v1 的 `card_extra` 是「**可展开的补充内容**」（超限裁剪的产物，有 type）；
我的只是「义项溢出桶」。**语义不同。**

### 偏离 8 🟠 记忆法优先级未被使用

v1 §5.2：「**按优先级裁剪：priority 小的先保留**」
→ 意思是 `root`(1) / `cognate`(2) **最先保留**，`context`(6) 最先被裁。

**我上一轮的建议（方案 B：把 `root` 移出 `sections`）恰好是反的** ——
我提议**牺牲优先级最高的记忆法**，给词典义项腾地方。
这与 v1 的裁剪方向**完全相反**。

## 三、修复方案

### 3.0 🔴 白哥第二轮裁决（2026-09-26）—— 卡片与聚合页的职责边界

> 白哥原话：
> 「**同源串记是个聚合页面不应该直接显示在卡片上**，卡片上应该显示的是『词源故事』而点击词源故事展开同源串记聚合页；**词根词缀也是一样**。
> 卡片显示的是**当前单词的词根词缀、词源故事、释义、语境原句**。
> 而 capere 词源族和词根词缀应该**都显示单词的分拆法及释义**，而不是单纯把单词列出来，这样毫无意义。」

**① 撤回我上一版的错误**：我把「同源族」做成 chip **直接铺在卡片上** —— 这是错的。
**聚合页是聚合页，卡片是卡片**：

| | 卡片 | 聚合页 |
|---|---|---|
| 内容 | **当前这个词**的词根词缀 + 词源故事 + 释义 + 语境 | **整个族**（22 / 33 / 56 词） |
| 作用 | 记这一个词 | 建立**词与词之间**的连接 |
| 入口 | ① ② 可点击展开 | 从卡片的 ① ② 进入 |

**② 卡片 = 四段（正好等于 v1 §5.1 的 4 sections 上限）**：

```
① 词根词缀（当前词的拆解）   ← 可点击 → 词根族聚合页
② 词源故事（当前词的来源）   ← 可点击 → 词源族聚合页
③ 释义（只 1 条）
④ 语境原句（只 1 条）
```
→ **`aggregate_link` 不必单列一段**（入口内嵌在 ① ② 里），顺带解决了上一轮的「191 张超限」。

**🔴 两处必须写清的细节（2026-09-26 补充，详见 `mnemonic-layer-separation-2026-09-26.md` §3.0 / §3.5）**：

| 细节 | 说明 |
|---|---|
| **段标题随实际填入的类型变** | ① 不一定是「词根词缀」—— 不可拆词按 priority 顺延，可能填 `collocation`(3)（→「固定搭配」）或 `etymology`(4)（→「词源故事」）。v1 §4.2 示例 `[root, definition, context]` 就是这个意思 |
| **「② 词源故事」的内部 code 是 `cognate`(2) 或 `etymology`(4)** | 不是两件事 —— **显示名 vs 内部 code**。上面白哥原话里的「点击**词源故事**展开**同源串记聚合页**」正是这个映射 |
| **入口箭头只在族规模 ≥3 时显示** | 门槛来自 v1 §8.5「成员数 ≥ N（如 3）」，数据层已实施（`aggregate_page` 两类页 min 都 = 3）。⚠️ 反例 **`capture`**：它的 `capt` 词根族只有 **2 词** → 不建页 → **① 有内容但无入口**，渲染层不能默认「有拆解就有族页」 |

**③ 🔴 最重要的一条：聚合页必须显示「分拆法 + 释义」，不是「单词列表」**

| | 只列单词（我的实现） | **带分拆法（v1 §4.3 的原意）** |
|---|---|---|
| 用户看到 | `accept` · `concept` · `except` · `deception` … | `ac-（向，加强）+ cept（拿取）` → 接受<br>`con-（共同、一起）+ cept（拿、抓）` → 概念<br>`ex-（出）+ cept（拿取）` → 除…之外 |
| 感受 | **22 个不相干的词** —— 白哥说的「毫无意义」 | **一个词根 × 22 种前缀** —— 规律自己浮出来 |

**v1 §4.3 的 `gloss` 字段本来就是这个格式**（`{"word":"receive","gloss":"拿回来 → 接收"}`），
我却存成了单词自身释义（`{"word":"affair","gloss":"事件；事情"}`）—— **偏离点在这里。**

**④ 实证：分拆法可算率 100%**（数据来自 `word_morpheme`，已有）

| 词根族 | 词数 | 可分拆 |
|---|---:|---:|
| `cept` | 22 | **22（100%）** |
| `man` | 32 | **32（100%）** |
| `organ` | 15 | **15（100%）** |
| `act` / `graph` / `vers` | 23 / 23 / 19 | **均 100%** |

**⑤ 新证据：词源族能抓「词根族抓不到」的词**

`vertere`（拉丁·转）词源族 **33 词**，其中 **9 个根本不可拆**：
`vertical` · `verse` · `vertex` · `vertebra` · `versus` · `converse` · `advert` · `vs` · `conversation`

**这 9 个不属于任何词根族**（已实测：`vertical` 的词根族查询返回空），
但它们和 `convert` / `revert` / `divert` 是同一个源词的后代 —— **只有词源族能表达这层连接**。
→ **词源族的覆盖面大于词根族**，两类都做是对的。

**⑥ 我这一轮犯的错（须记录）**：**渲染界面稿时凭印象编造数据。**

我第一版界面稿写了「`vertical` 在 `vert` 词根族（19 词）」并列了 `reverse` / `diverse` / `universe` / `introvert` 作成员 ——
**实测全错**：`vertical` 不可拆、不在任何词根族；`vert` 族只有 8 词，成员是 `advertise` / `convert` / `divert` / `revert` / `invert` / `avert`。
（`reverse` / `diverse` 属 `vers` 族，19 词。）

**→ 教训：即使只是「画个稿」，每个数字也必须来自查询。** 界面稿会被当成目标看，编造的数字比没有数字更危险。

### 3.1 卡片结构重建（按 v1 §4.2 + §8.2 + 白哥裁决）

**卡片（逐词，四段）**：
```json
{
  "front": "intercept",
  "ipa": "/ˌɪntəˈsɛpt/",
  "sections": [
    {"type": "root",       "text": "inter-（在…之间）+ cept（拿取）",
                           "link": {"page_type": "root",   "key": "cept",   "size": 22},
                           "payload": {"parts": [...]}},
    {"type": "etymology",  "text": "拉丁 inter（之间）+ capere（拿取）→ 在中间拿住 → 拦截",
                           "link": {"page_type": "etymon", "key": "capere", "size": 56}},
    {"type": "definition", "text": "拦截；截获"},
    {"type": "context",    "text": "The police intercepted the stolen vehicle on the highway."}
  ]
}
```
> **`link` 是聚合页入口**，内嵌在 ① ② 里 —— 因此**不需要额外的 `aggregate_link` section**，
> 四段正好等于 v1 §5.1 的 4 sections 上限。

**聚合页（整族，每条带分拆法）**：
```json
{
  "page_type": "root",
  "front": "cept 词根族（Latin · 拿取）",
  "sections": [{
    "type": "family_list",
    "source": {"form": "cept", "language": "Latin", "meaning": "拿取"},
    "items": [
      {"word": "intercept", "breakdown": [{"form":"inter-","gloss":"在…之间"},{"form":"cept","gloss":"拿取"}],
       "zh": "拦截；截获"},
      {"word": "accept",    "breakdown": [{"form":"ac-","gloss":"向，加强"},{"form":"cept","gloss":"拿，取"}],
       "zh": "接受，收受"},
      {"word": "vertical",  "breakdown": null,
       "zh": "垂直的", "note": "整体词，不可拆 —— 同属本族"}
    ]
  }]
}
```
> 🔴 **`breakdown` 是本次修正的核心** —— 它来自 `word_morpheme`（按 `position` 排序拼出）。
> **没有 `breakdown` 就只有「22 个不相干的词」**；有它才是「一个词根 × 22 种前缀」。
> 不可拆的成员 `breakdown` 为 `null`，但要**保留在列表里**并注明。

**组合规则（按 §8.2）**：
1. 读 `word_mnemonic_profile.primary_code` → **主体记忆法 section 排第一**
   （`root` → ① `root`；`etymology`／不可拆 → ① `etymology`；`collocation` → ① `collocation`；`image` → 待定）
2. 加**另一种**记忆法 section（词根 + 词源两条并存；若词不可拆则只一条）
3. 加 `definition`（**只 1 条，取首义**，其余进 `card_extra`）
4. 加 `context`（**只留一条**，§5.2 第 4 条）
5. `apply_capacity_limit(sections, max_sections=4, max_chars=300)`
   —— **超限时按 `mnemonic_type.priority` 裁剪，priority 小的先保留**（§5.2 第 1 条）
6. 裁掉的内容进 `card_extra`（带 `type`，可展开）

## 四、方法论教训

| # | 教训 |
|---|---|
| **1** | 🔴 **权威原文必须落盘，且禁止用转述做实现依据** —— 偏离的机制性原因是「一直读二手解读」。**「我找不到原文」≠「原文不存在」≠「可以按转述做」** |
| **2** | 🔴 **约束报错时，先怀疑实现，再怀疑约束** —— 我第一反应是「约束不可用（300 字两个口径都不成立）」，实际是**我的结构错了**。顺序颠倒会得出反向结论 |
| **3** | 🔴 **「算了但没用」是最隐蔽的偏离** —— `word_mnemonic_profile` 有 11,523 行数据、`mnemonic_type` 静态表齐全，看起来「实现了」，但**制卡时没读**。**验收要看「产出是否用了它」，不是「表在不在」** |
| **4** | **偏离会向下游扩散** —— 卡片 type 错 → 音频朗读清单失效（240 MB 例句音频会丢）→ 现在没暴露是因为还没生成音频 |
| **5** | **重建 ≠ 重跑** —— 数据全在（只缺 `imagery`），修复是「重新组装」，成本约等于改一段脚本 |
| **6** | 🔴 **「罗列」不等于「建立了联系」** —— 聚合页只列单词 = 22 个不相干的词（白哥：「毫无意义」）；加上**分拆法**才成为「一个词根 × 22 种前缀」。**同一个页面的价值差，全在有没有那层结构。设计聚合类功能时先问：用户从这一屏能看到什么规律？** |
| **7** | 🔴 **即使只是「画稿」，每个数字也必须来自查询** —— 我第一版界面稿凭印象写了「`vertical` 在 `vert` 族（19 词）」，实测 `vertical` 不可拆、不在任何词根族，`vert` 族只有 8 词。**界面稿会被当成目标看，编造的数字比没有数字更危险** |
| **8** | **职责边界要显式写出来** —— 「什么在卡片、什么在聚合页」此前从未明确，我就把族的成员铺到了卡上。**边界不写，实现必然越界** |
