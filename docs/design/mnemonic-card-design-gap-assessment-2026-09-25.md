> **触发（2026-09-25 白哥）**：「你的 Phase 1 计划看起来不像完整的记忆优化，里边好像缺了很多记忆优化手段」

> 4.1 记忆法优先级（6 级 + `mnemonic_type.priority`）· 4.2 卡片内容结构（`sections` + `root` + `payload.parts`）

## 〇、结论（先看这个）

| v1 原方案 §四 | v2 现状 | 性质 |
|---|---|---|
| **§4.1 记忆法优先级** —— 6 级排序（词根词缀 > 同源串记 > 搭配整记 > 词源故事 > 联想图像 > 语境原句）+ `mnemonic_type.priority` 数据模型 | §3.1「现有数据能支撑的记忆法」—— **4 项，按「数据覆盖率」排列**（音形 100% / 语境 93.8% / 搭配 97.4% / 释义 79.4%） | 🔄 **被整体替换**（教学法优先级 → 工程数据盘点） |
| **§4.2 卡片内容结构** —— `sections` 含 `root` 类型，`payload.parts` 存词根拆分 | §3.3 卡片结构 —— 有 `sections`（`sense`/`collocation`/`family`），**但无 `root` 类型、无 `payload`/`parts`** | 🟠 **壳在、层缺** |
| **§4.3 聚合页内容结构** —— `cognate_list`（`-ceive` 词源族 4 词） | **无** | 🔴 **整块缺失** |
| **§4.4 单词卡 ↔ 聚合页关联** —— `aggregate_link`（点击跳转，**纯查询、不入复习**） | **无**（但 `family` section 借用了「挂主卡下、不单独占复习位」的**同一骨架**） | 🔴 **整块缺失**（骨架延续、对象被换） |

**一句话**：v2 保留了 v1 的**数据骨架**（`sections` 挂载、不占复习位的附属项），但**把"按记忆法组合内容"这层整体换成了"按数据可得性展示内容"**。

## 二、缺失清单（逐项对照）

### 2.1 §4.1 记忆法优先级 —— 整层被替换

**v1 的设计**（按记忆效果排序，制卡时选主 + 次记忆法组合成一页）：

| 优先级 | 记忆法 | 适用词 |
|---:|---|---|
| 1 | 词根词缀 | 可分解词 |
| 2 | 同源串记 | 有同源词群的词 |
| 3 | 搭配整记 | 固定搭配强的词 |
| 4 | 词源故事 | 外来整体词 |
| 5 | 联想图像 | 抽象词 |
| 6 | 语境原句 | 默认附加 |

**v2 的替代物**（§3.1，按**数据覆盖率**排列）：

| 记忆法 | 数据字段 | 覆盖率 |
|---|---|---|
| 音形锚定（IPA） | `pronunciation` | 100% |
| 语境锚定 | `definitions[].example` | 93.8% |
| 搭配/用法 | `related_phrases` | 97.4% |
| 释义（中英双语） | `definitions[].meaning`+`.chinese` | 79.4% |

**🔴 三处结构性错位**：

| # | 错位 | 说明 |
|---|---|---|
| 1 | **排序依据变了** | v1 问「**哪个记忆法更有效**」（教学法问题）；v2 问「**哪个数据已有**」（工程问题）。**这两个问题的答案不一样** —— 按数据可得性排，会把「词根」排到最后（数据 0%），但它恰是 v1 的 priority 1 |
| 2 | **「音形锚定」被错误升格** | v1 里发音不是「一种可选记忆法」，而是**每张卡必带的基础项**（写在 §4.2 卡片结构里）。v2 把它提为并列的 4 项之一，**于是"必备"降级成了"之一"** |
| 3 | **失去「组合」概念** | v1 是「选**主**记忆法 + **次**记忆法，组合成一页」；v2 是「列出 4 种可用素材」。**前者是策略，后者是清单** |

### 2.2 §4.2 卡片内容结构 —— 壳在、层缺

| 项 | v1 | v2 |
|---|---|---|
| 顶层 | `front` + `sections[]` | `word_id` + `front` + `ipa` + `audio` + `sections[]` + `extra[]` |
| 义项 | `{"type": "definition", "text": "难以置信的"}` | ✅ `{"type": "sense", "order": 1, "pos": "v", "en": …, "zh": …}` |
| **词根** | ✅ `{"type": "root", "text": "in-（不）+ cred（相信）+ -ible（能…的）", "payload": {"parts": [{form, type, meaning}…]}}` | ❌ **无** |
| 语境 | `{"type": "context", "text": "The story is incredible."}` | ✅（并入 `sense.example`） |
| 搭配 | — | ✅ `{"type": "collocation", "items": […]}`（**v2 新增**） |
| 词族 | — | ✅ `{"type": "family", "members": [{form, ipa}…]}`（**v2 新增，但对象是屈折形式**） |

**评价**：
- ✅ v2 在**结构工程上更完整**（有音频字段、有搭配、有 `extra` 降级义项）
- 🔴 但 **`payload.parts` 这个「结构化词根」设计丢了** —— 它不是一句文本，而是**可交互/可复用的结构化数据**（`{form, type: prefix|root|suffix, meaning}`）
- **→ v2 只能展示"词典信息"，无法生成"记忆法内容"**

### 2.3 §4.3 聚合页 —— 整块缺失

**v1 的设计**：一个独立的页面实体 `aggregate_page`，按**词源族**聚合多个词：

```json
{
  "front": "-ceive 词源族",
  "sections": [{
    "type": "cognate_list",
    "items": [
      {"word": "receive",  "gloss": "拿回来 → 接收"},
      {"word": "perceive", "gloss": "完全拿到 → 察觉"},
      {"word": "conceive", "gloss": "一起拿 → 构想"},
      {"word": "deceive",  "gloss": "拿走 → 欺骗"}
    ]
  }]
}
```

**→ v2 完全没有对应物。**

> ⚠️ **注意这里最容易混淆的地方**：v2 也有「词族聚合」（§3.2 原则 2、Phase 1 #5），**但那是「屈折聚合」**：
> `run` 为主卡，`running`/`runs`/`ran` 挂在下面 —— **目的是「减少卡片数」**。
> 而 v1 的聚合页是 **`cognate`（词源族）**：`receive`/`perceive`/`conceive`/`deceive` —— **目的是「建立记忆连接」**。
> **两者共用「词族」这个词，但对象、目的、数据来源全不同。**（详见 §3.1）

### 2.4 §4.4 聚合页关联 —— 整块缺失

**v1 的设计**：

```json
{"type": "aggregate_link", "page_id": 123, "label": "-ceive 词源族（4 个词）"}
```

**关键设计意图**：**「点击跳转到 `aggregate_page`，纯查询，不入复习。」**
→ 这是一个明确的**「复习单元 vs 参考单元」二分**：聚合页是**参考资料**，不是**待背内容**。

**v2 的对应**：`family` section（挂主卡下、`只保留 IPA 与发音，不单独占复习位`）—— **借用了同一个骨架**（不占复习位、挂主卡），**但对象从 `cognate` 换成了 `inflection`**。

> **→ 这说明 v2 是「沿着 v1 的骨架走，把内容换掉了」** —— 骨架（附属项不占复习位）保留了，**语义（词源连接）丢失了**。

## 三、三个更深的结构性问题

### 3.1 🔴「词族」被偷换了概念（最隐蔽、后果最大）

| | v2 的「词族聚合」 | v1 的「同源串记 / 聚合页」 |
|---|---|---|
| 对象 | `run` / `running` / `ran`（**同一词的屈折形式**） | `receive` / `perceive` / `conceive` / `deceive`（**不同词，共享词根**） |
| 数据来源 | `word_form` 映射表（**已有**） | 词根/词源数据（**0%**） |
| 目的 | **减少卡片数**（降复习负担） | **建立记忆连接**（利用词根迁移） |
| 记忆科学 | 形态知识（**识别**即可） | 深度加工（**语义网络**） |
| 在 v2 的位置 | §3.2 原则 2 + Phase 1 #5 | **不存在** |

**🔴 后果**：因为共用「词族」这个名字，**没人会发现另一个丢了**。
→ **这也是白哥一眼看出"缺了很多"的原因** —— 名字盖住了缺失。

### 3.2 🔴 词根被「以偏概全」地否定

v2 §3.4 的论证（L574）：

> 「原方案把词根词缀列为 priority 1。实测这是从零建设，且 **英语高频词大量是日耳曼语源单音节词（be / new / get / make / all），根本没有拉丁词根可拆**。」

**前半段成立**（高频基础词确实无拉丁词根），**但推不出后半段的结论**：

| 观察 | 适用范围 |
|---|---|
| 「be / new / get / make / all 无词根可拆」 | ✅ **仅适用于日耳曼语源高频短词** |
| 「词根词缀整体不值得做」 | ❌ **不成立** —— 拉丁/法语词源的长词**恰好最适合拆** |

**反例（v1 自己的例子就是）**：`incredible`（in- + cred + -ible）、`receive`/`perceive`/`conceive`/`deceive`（-ceive）、`transact`（trans- + act）—— **这些都在词表里**。

> **→ 这是统计口径错误：用「高频词的分布」否定了「全部词的可行性」。**
> 正确的问法应是：**「词表里有多大比例的词可拆？这些词是不是学习者最需要重点记忆的那批？」**
> （直觉上恰好成立：**可拆的多是低频长词，而低频长词正是需要记忆法辅助的那批**）

### 3.3 🔴 卡片目标从「帮助记忆」退化为「展示信息」

| | v1 | v2 |
|---|---|---|
| 卡片是什么 | **按记忆法优先级组合成的「一页记忆方案」** | **词典信息的重新排列** |
| 组织依据 | `mnemonic_type.priority`（教学法） | 数据字段存在与否（工程） |
| 主卡策略 | 主记忆法 + 次记忆法**组合** | 主卡放最高频义项 + 次义项降级 |
| 评价标准 | 「**这个内容好不好记**」 | 「**这个内容全不全、对不对**」 |

**这不是"少了功能"，是"换了目标"。**

**v2 §3.2 的 5 条原则**（一张卡=一个可提取单元 / 词族聚合 / 阅读价值排序 / 多词卡单独成组 / 发音必须排最前）**全部是结构/工程原则**，没有一条回答「**这张卡怎么帮用户记住**」。
→ 说明 v2 在改写时，**把「记忆设计」这一层整体让位给了「数据工程」**。

## 四、后果（不只是"少了个功能"）

### 4.1 🔴 Phase 1 #5 可能正在做错的东西

| 项 | 现状 |
|---|---|
| Phase 1 #5「词族聚合」 | 候选已出：`in_vocab` 配对 **1,383 条**，分组 **A 纯屈折 884 / B 有独立义 338 / C 灰区 161** |
| 这些候选是什么 | **全部是屈折形式**（`running`←`run`、`worse`←`bad`、`bore`←`bear`、`bidding`←`bid`） |
| v1 的「同源串记」是什么 | **cognate 词源族**（`-ceive` / `-cred` / `-trans`）—— **与屈折无关** |

**→ #5 做的是「屈折聚合」，不是 v1 的「词源族聚合」。两件事。**
**→ 风险：如果白哥的本意包含 v1 的聚合页，那么 #5 完成后，"词族"这个词已被占用，真正的词源族功能会更难加回来。**

**建议（待白哥定）**：
- ① **改名区分** —— 把 #5 改为「**词形聚合**（inflection）」；「**词族**」留给 v1 的 cognate 语义（避免概念再次混淆）
- ② **#5 继续做**（它本身有价值：降复习负担），但**明确它不是 v1 的聚合页**
- ③ v1 的聚合页作为**新项**评估

### 4.2 订阅权益表述含糊

v2 两处（L1285 / L1700）：「**无限生词本 · 文章 TTS 朗读**（读整篇 / 听原著）· **词根词缀/同源词群（未来）** · 云同步（未来）」

**问题**：把「词根词缀/同源词群」列为订阅权益的"未来项"，**但它在 v1 里不是"增值功能"，而是核心制卡机制**。
→ 若按 v1 设计，**免费用户也应有词根提示**（否则基础记忆体验不完整）；把它整块挂到订阅下，是**v2 降级后的连带后果**。

### 4.3 Phase 6（激励与分享）缺素材

Phase 6 的「学习成果分享（复用渲染管线 + 5 种模板）」需要一个**有说服力的成果单位**。
→ v1 的「聚合页」天然适合分享（「我掌握了 -ceive 家族的 4 个词」比「我背了 4 个词」更有感染力）。
→ v2 缺此素材。

### 4.4 数据层从未落地

已核实：`prebuilt_cards` / `prebuilt_language_cards` **无任何相关字段**；`structure_meta` 全空（且与记忆法无关）。
→ **若决定补回，需要新建数据模型 + 生成管道**（不是"改个字段"）。

## 五、补回方案

### 方案 A · 完整补回（对齐 v1 设计意图，用 v2 的工程骨架承载）

| 步骤 | 内容 | 依赖 |
|---|---|---|
| A1 | **恢复「记忆法优先级」为独立节** —— 6 级 + 明确「为何排序」；区分「教学法优先级」与「数据可得性」两个维度（不是二选一，而是**双表并列**） | 无 |
| A2 | **建 `mnemonic_type` 数据模型** —— `{priority, method, applicable_when}` | 无 |
| A3 | **扩展卡片 `sections`** —— 恢复 `root` 类型 + `payload.parts`（结构化词根拆分） | 需 A4 的数据 |
| A4 | **词根数据生成** —— 复用 `fill_card_content_llm.py` 管道（LLM 生成构词分析，规避 Etymonline 授权问题）；**先小样验证幻觉率** | LLM（key 已就绪） |
| A5 | **建 `aggregate_page` 表 + `cognate_list`** —— 词源族聚合页 | 需 A4 的词根数据（**词根相同即同族**） |
| A6 | **建 `aggregate_link`** —— 单词卡→聚合页，**纯查询、不入复习**（沿用 v1 的「复习单元 vs 参考单元」二分） | 需 A5 |
| A7 | **修正 Phase 1 #5 命名** —— 「词族聚合」→「**词形聚合**」 | 无 |

**（A5 有天然数据来源**：A4 产出的 `payload.parts` 里，`root` 相同的词自动成族 —— **不需要额外数据源**，这是 v1 设计的内在一致性。）

### 方案 B · 分步（先骨架，后数据）

先做 **A1 + A2 + A7**（纯文档与命名，零数据成本），**A3–A6 待词根数据验证后再排期**。

### 方案 C · 只评估不动

先确认白哥对 v1 这套设计的**当前态度**（仍是 priority 1，还是认可 v2 的降级）—— 再决定是否推倒 v2 的相应部分。
