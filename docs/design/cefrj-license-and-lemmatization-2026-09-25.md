## 一、CEFR-J 商用授权：✅ 明确允许

### 1.1 官方原文

来自 CEFR-J 官方下载页（`cefr-j.org/download.html`），**英文版声明**：

> The copyright of this wordlist belongs to Tono Laboratory at TUFS, but the list **can be used for both research and commercial purposes** with a proper acknowledgement of the source.

**日文版声明**（同一页，措辞更细）：

**结论：商用明确允许，条件只有一个 —— 正确引用。**

### 1.2 必须遵守的两条

**① 引用格式（官方指定，中英两版）**

英文：
```

Tokyo University of Foreign Studies. Retrieved from http://www.cefr-j.org/download.html on dd/mm/yy.
```

日文：
```
『CEFR-J Wordlist Version 1.6』 東京外国語大学投野由紀夫研究室.
（URL: XXX より◎年◎月ダウンロード）
```

**落实位置**：App 内的「开源许可 / 致谢」页面。这是标准做法，也顺便满足应用商店对第三方组件披露的要求。

**② ⚠️ 一条容易被忽略的限制**

官方免责事项第 2 条原文：

> 商用利用に関しては、**監修などを行う場合には別途相談の上、必要な経費を請求する**。

翻译：**商用利用时，如涉及「监修」（supervision / endorsement）等情形，需另行协商并收取费用。**

**含义**：免费商用的前提是**不声称对方为本产品提供监修或背书**。

| 可以做 | 不可以做 |
|---|---|
| 在产品内使用 CEFR-J 词表 | 宣传「CEFR-J 官方监修」 |
| 在致谢页引用 | 在营销材料中暗示官方背书 |
| 基于它做衍生词表 | 声称与东京外国语大学有合作关系 |

**免责事项第 4 条**（对我们有利）：

> 本語彙表を**改変して別の語彙表を作ることはかまわない**が、必ず本語彙表を適切に引用しなければならない。

→ **明确允许基于 CEFR-J 做衍生**（如把等级映射到自有体系），只要引用。

## 二、词形还原选型：✅ 自研反向生成，不用第三方库

### 2.1 Dart 生态实测（都不合适）

| 包 | 最后发布 | 状态 | 结论 |
|---|---|---|---|
| `lemmatizer` | 6 年前 | **Dart 3 incompatible + discontinued** | ❌ 不可用 |
| `lemmatizerx` | 2023-05（3 年前） | 7 likes，基于 WordNet morphy | ❌ 维护弱 + 能力有限 |
| `stemmer` 3.2.0 | 3 个月前 | 活跃，Apache-2.0 | ⚠️ **但它是 stemming 不是 lemmatization** |

**关键区分**：

```
Stemming（词干提取）    ：agreed → agre      ← 不是真词，在词表里查不到
Lemmatization（词形还原）：agreed → agree     ← 真词，能命中词表
```

我们需要的显然是后者。而唯一可用的 `stemmer` 是前者，**用了反而查不到词表**。

### 2.2 更好的思路：反向生成

**关键洞察**：

> 我们要解决的不是「通用词形还原」（难题），
> 而是「**把文章词形映射到我们词表里的 12,650 个词**」（受限问题，简单得多）。

| | 正向（通用库） | **反向（自建）** |
|---|---|---|
| 做法 | 任意词形 → 通用算法猜一个 lemma | 词表词 → 展开全部变形 → 建反查表 |
| 风险 | 猜出的 lemma **可能不在我们词表里** | 只映射到词表内的词，**准确率 100%** |
| 依赖 | 第三方库 + 可能夹带词典数据 | **零运行时依赖**（一张 SQLite 表） |
| 体积 | 库 + 词典（未知） | **34,724 条映射**，约几百 KB |
| 可控性 | 黑盒 | 规则和不规则表都可人工校对 |

### 2.3 实测结果

**规模**：

| 策略 | 生成条目 |
|---|---:|
| 旧版（flat 数据源 + 简单门控） | 35,343 |
| 无脑放行（全部规则） | 81,141 |
| **精细化门控（最终）** | **36,177**（去重后映射 **34,724**） |

**覆盖率**（四篇真实风格文本）：

| 文本 | 直接命中 | **变形还原命中** | 停用词 | 未命中 | 总覆盖 |
|---|---:|---:|---:|---:|---:|
| VOA 科技 | 62.1% | **19.0%** | 13.8% | 5.2% | 94.8% |
| BBC 教学 | 57.1% | **32.7%** | 8.2% | 2.0% | 98.0% |
| 文化评论 | 69.0% | **16.7%** | 14.3% | 0% | **100%** |
| 商业新闻 | 53.7% | **36.6%** | 7.3% | 2.4% | 97.6% |
| **平均** | | **26%** | | | **97.6%** |

> **变形还原贡献了约 26% 的词形命中** —— 这不是小数目。没有它，文章里四分之一的词会被当成「词表外词」。

**残留未命中**只有三类：

| 词 | 原因 | 处理 |
|---|---|---|
| `kilometres` | 英式拼写变体 | 词库梳理阶段补映射（已知问题） |
| `percent` | 词表缺失 | 补进词表 |
| `singapore` | **专有名词** | **本就不该计入生词**（应排除） |

### 2.4 实现要点（踩过的三个坑）

**🔴 坑 1：数据源必须用 `cefr_j_all.json`，不能用 `cefr_j_flat.json`**

- `all` 版是 list，**7,801 条，每行一个「词性 × 等级」条目**
- `flat` 版是 dict，**6,864 键，同一 headword 的多行被合并 → 只留下一个词性**
- **实测：flat 版有 851 个 key 在 all 版里对应多个词性，信息丢失**

后果实例：

| 词 | flat 版词性 | all 版全部词性 | 丢的后果 |
|---|---|---|---|
| `study` | noun | noun, **verb** | 生不出 `studied`/`studying` |
| `water` | verb | **noun**, verb | 生不出 `waters` |
| `light` | verb | **adjective**, **noun**, verb | 丢 2 个 |
| `change` | noun | noun, **verb** | 生不出 `changed` |

> 这也解释了为什么我第一轮测试时 `studied`/`adults`/`switching` 全部未命中 —— 数据源选错。

**🔴 坑 2：门控不能「无脑放行」，也不能「过度收紧」**

| 策略 | 问题 |
|---|---|
| 过度收紧（靠词性门控） | `study` 标 noun → 不生 `studied` → **漏** |
| 无脑放行（全部规则都跑） | 生成 `runed`/`studeist`/`changeing`/`helpest` 等**垃圾**（实测 10 类） |
| **精细化门控** | comp(-er/-est) 与 -ly **仅在词性含形容词时**生成；plural/past/ing **默认放行** |

**最终效果：垃圾变形 10 类 → 0 类，同时覆盖率保持 97.6%。**

**🔴 坑 3：不规则表命中时必须互斥**

- `run` 同时在规则和不规则表里 → 若两者都跑，会生成 `runed`/`runing`
- ~~**修正**：命中不规则表后直接返回，不再跑规则~~

🔄 **实现修正（2026-09-25，见 §2.5）**：**「整体互斥」会丢正确变形** ——
`run` 的复数 `runs` 是规则的，若命中不规则表就 return，`runs` 就丢了。
**正确做法：按 (lemma, 规则类别) 精确互斥** —— 不规则表只覆盖「与规则推导结果不同的类别」。

**其他细节**：

| 项 | 处理 |
|---|---|
| 长度 < 3 的词 | **跳过**规则变形（否则 `a` → `abed`/`abest`；实测词表有 117 个 ≤2 字符的词）。🔄 **必须豁免 `be`/`do`/`go`** —— 见 §2.5 |
| ~~生成的变形本身在词表里~~ → **🔄 已推翻** | ~~不建立映射（保留独立语义）~~ —— 见 §2.5，**改为无条件生成 + `in_vocab` 标记** |
| 含撇号/连字符的词 | 跳过（`don't`、`well-known`） |
| 不规则动词/名词表 | 手工维护约 150 条（覆盖最高频的），其余靠规则 |

## 二·补 实现的六处修正（2026-09-25 实测发现）

> 依据：`scripts/build_word_form.py`（本方案的落地实现）＋ 实测验证。
> **本节记录的是「文档原规则 → 实测问题 → 修正」，因为其中两条规则被推翻了。**

### 🔴 修正 1：`form` 在词表里时应**建立映射**，而非跳过

**文档原规则**：「生成的变形本身在词表里 → 不建立映射（保留其独立语义）」

**实测问题**：`run` / `running` / `ran` / `better` / `made` / `went` / `written` **全都在词表里**
→ 按原规则实现后，**14 个关键测试词里有 7 个无法还原**（`running`/`ran`/`better`/`made`/`went`/`held`/`written`）。

**根因**：词表里存在 **838 条「屈折重复立卡」**（§2.2 已记载）——
`running` 既作为独立卡片存在、**又是 `run` 的屈折形式**。
文档原文举的例子 `building` 确实有独立语义（建筑物），但 `running`/`ran`/`better` 不是。

**原规则与 §2.2 的目标直接冲突**：
| | 说法 |
|---|---|
| §2.2 | 「把文章词形映射到**我们词表里的**词」 |
| §2.4 | 「变形在词表里就**不映射**」 |

两者在「屈折重复立卡」场景下**不能同时成立**。

**修正**：
```
无条件建立映射，另加 in_vocab 标记（1 = 该 form 在词表里另有独立卡片）
→ 交由 Phase 1 #5（词族聚合）决定：哪些 form 保留独立语义（如 building）、哪些合并到 lemma
```
这样 **#1 独立可用、#5 有决策依据**，两条规则不再冲突。

### 🔴 修正 2：长度门控必须豁免 `be` / `do` / `go`

**实测问题**：`go` / `be` / `do` 都是 **2 字母**，被「长度 < 3 跳过」整体过滤
→ **英语最高频的 12 个词形全部消失**：`went` / `going` / `goes` / `gone` / `was` / `were` / `being` / `been` / `did` / `does` / `doing` / `done`。

**根因**：长度门控的目的是避免 `a` → `abed` 这类垃圾，但**误伤了真实的高频短动词**。
⚠️ 其中 `be` 还叠加了第二层误伤 —— 它同时被「污染短词检测（长度 ≤2）」判为污染词，
**两层过滤都要豁免**才生效。

**修正**：`SHORT_BUT_REAL = {'be', 'do', 'go'}`，长度门控与污染检测均豁免。

### 🔴 修正 3：按 (lemma, 规则类别) 精确互斥

**文档原规则**：「命中不规则表后直接返回，不再跑规则」（整体互斥）

**问题**：`run` 的**复数 `runs` 是规则的**，整体互斥会让它丢失。

**修正**：不规则表只列「与规则推导结果不同的类别」，其余类别照常走规则。
例：`run` → 不规则表给 `past=ran`、`ing=running`，**`plural` 未列 → 走规则得 `runs` ✅**

### 🔴 修正 4：不规则表的值需支持多形式

`be` 的过去式有 **`was` 和 `were` 两个**，单值结构存不下（实测初版只生成了 `were`，`was` 缺失）。
修正：值类型改为 `str | list[str]`。

### 📊 实测产出对比

| 项 | 文档 §2.3 | **本实现（2026-09-25）** |
|---|---:|---:|
| 映射条数 | 34,724 | **39,334** |
| 其中 form 在词表内 | — | **1,387**（交 #5 决策） |
| 目标词表 | 12,650 | **12,791**（实测 `subject='english' AND card_type='vocabulary'`） |
| 垃圾变形 | 0 类 | **0 类** ✅ |
| 长词误加 `-er/-est` | — | **0** ✅ |
| 三连字母 | — | **0** ✅ |
| 覆盖率（四篇测样） | 97.6% | **99.5%**（100/100/100/98.1） |

> **条数比文档多 4,610（+13%）的原因**：① 目标词表多 141 词 ② 无条件生成（含 1,387 条 form 在词表内的）
> ③ 部分规则细节差异。**覆盖率更高，说明多出的部分是有价值的还原，不是垃圾。**

**唯一未命中**：`percent`（词表缺失）—— 与文档 §2.3 记录一致，属「补进词表」处理范围。

**⑤ 🔴 `_IRREGULAR_FORMS` 的自指 bug（2026-09-25 实现后自查发现）**

上一轮为「不规则形式不应再作为 base」引入的排除集合，实现有误：

```python
_IRREGULAR_FORMS = {所有不规则表的值}
#   其中 run 的过去分词就是 run 本身 → 'run' 被加进集合
...
if lemma in _IRREGULAR_FORMS: continue      # ← run 被整条跳过
```

**后果**：`run` / `cut` / `put` / `set` / `let` / `hit` / `read` / `cost` / `shut`
等**「过去分词与原形同形」的高频动词全部被跳过** →
`running` / `ran` / `cutting` / `putting` / `hitting` / `reading` 在映射表中 **0 条记录**。

**修法**（一行）：`_IRREGULAR_FORMS -= set(IRREGULAR)` —— 剔除「本身也是 lemma」的形式。
修复后 `running → run` / `ran → run` / `cutting → cut` 等全部命中（映射 39,334 → **39,392**，清洗后重跑为 **36,856**）。

**⚠️ 为什么上一轮"验证通过"却漏了**：验证用例只覆盖了 `be` / `do` / `go` ——
它们的过去分词**不与原形同形**（been / done / gone），恰好绕过了这个 bug。
**→ 教训：验证用例必须专门覆盖「边界形态」** ——
**同形变化**（run-ran-run）、**零变化**（cut-cut-cut）这类"看起来不会出问题"的词，
正是阈值/集合类判据最容易误伤的地方。

**⑥ 已知缺口：现在时形态未覆盖**

`is` / `are` / `am` / `has` **无法还原**（映射表无记录）——
`IRREGULAR` 表只列了 past / past_participle / ing，**未列现在时**。

**影响**：`is` / `are` / `has` 是英语最高频词，划词划到它们**查不到** `be` / `have`。

**是否补上属产品判断**（非纯技术）—— 与 4.3 的「兼类词」是同一类问题：
**一个词形既是独立词条、又是别的词的变形**。要定的是：
划到 `is` 时，显示 `be` 的卡片，还是 `is` 自己的卡片（`is` 同为国标词表内词条）？

## 三、⚠️ 自我纠正：我此前的一个估计错了

**上一份文档我说：不做词形还原，生词数会「虚高 20–40%」。**

**实测约 7%。** 用 216 词的文本测：

```
未还原计数: 107
已还原计数: 100
虚高:        7 个词 ≈ 7.0%
```

重复的组：`build/building`、`city/cities`、`company/companies`、`farm/farming/farms`、`produce/produces`、`use/uses`

**为什么估计偏高**：我按「词形重复的潜在数量」推，没考虑**真实短文本里同一词根的变形重复本来就少**。误差 ∝ 同词根变形在文中重复次数 —— 100–200 词的短文本重复很少，一本 5 万字的书才会显著累积。

**这个纠正对优先级的影响**：

| 场景 | 词形还原的必要性 |
|---|---|
| **划词查词** | 🔴 **硬需求** —— 用户划 `received` 必须命中 `receive`，错一个就是硬伤 |
| **「N 个生词」标识** | 🟡 **锦上添花** —— 误差 7%，且方向是偏高（让用户觉得稍难一点，不是灾难） |

**但这不改变结论** —— 因为两者共用同一张表，而划词查词是核心交互。**做划词查词的顺带就把生词数算准了。**

## 四、词表噪声的真实构成（🔄 2026-09-25 实测修正）

> 🔴 **本节原写「76 个污染短词」+「501 条专有名词（其中 pos 含 proper noun 196 条）」，实测后原判据全部不成立。**
> 根因：用的是**粗粒度阈值**（长度 ≤2、无元音）。实测证明这两条都会严重误伤。
>
> **新的实测方法**（`scripts/classify_vocab_noise.py`）：改用**可验证特征** ——
> 最有效的一条是**从 `definitions` 的措辞反推性质**（见 4.2）。

### 4.1 原判据为什么不成立（三条实测反例）

| 原判据 | 实测问题 | 反例 |
|---|---|---|
| **长度 ≤2 → 污染**（115 个，其中 76 个"suspect"） | 词表里 ≤2 字符**确实有 115 个**，但绝大多数是合法词 | `a` `an` `be` `by` `do` `go` `he` `at` `up` `us` `we` `me` `my` `no` `of` `on` `or` `so` `to` |
| **无元音 → 污染** | 🔴 **判据无效** —— **y 是半元音，可独立成音节** | `by` `cry` `dry` `fly` `gym` `gyp` `hymn` `myth` `my` `why` `spy` `try` `wry` 全部"无元音"且全是合法词 |
| **`pos == 'proper noun'` → 专有名词** | 只是**精确匹配**的口径，严重低估 | 实测 `pos` **含** `proper` 的是 **445 条**；196 只是恰好等于 `proper noun` 的那部分 |

**另外**：原列出的 76 个"污染词"里，`hi` `ow` `uh` `um` `ye` `eh` `aw` 是**感叹词**、`re` `co` `de` `un` `il` 是**前缀**、`lb` `mg` `cm` `ft` `mph` 是**常用单位缩写** —— 它们是真实语言单位，只是不该作为"可查词条"。

### 4.2 ✅ 可靠判据：从 `definitions` 措辞反推（本轮最大发现）

**`definitions` 字段会直接写明词的性质**，实测样例：

| 词 | definitions 原文 | 性质 |
|---|---|---|
| `abe` | "a **nickname for** Abraham, especially Abraham Lincoln." | 人名 |
| `ada` | "a **female given name**." | 人名 |
| `nam` | "(informal, chiefly US) **short for** Vietnam" | 地名简称 |
| `baltimore` | "a major **city in the state of** Maryland, USA. **a surname.**" | 地名 + 姓氏 |
| `zg` | "**(abbreviation)** zero gravity" | 缩写 |
| `ace` | "a playing card with a single pip" | ✅ **合法词** |
| `elm` | "a tall, deciduous tree of the genus Ulmus" | ✅ **合法词** |

**→ 这比「长度/元音」可靠得多**，而且能直接区分「合法词」与「人名/地名」——
`ace` `apt` `elm` `eta` `ivy` `zen` `lad` 都不在 CEFR-J 里（它只覆盖词库 52%），
若用"不在 CEFR-J"筛，这些词会被全部误标。

### 4.3 🔴 一个必须区分的形态：**兼类词**（本轮新增）

**不能因为「有一条释义是人名」就整条删掉。** 实测反例：

| 词 | 释义构成 | 正确处理 |
|---|---|---|
| `billy` | 人名 + **警棍** + **公羊** | ✅ **保留** |
| `benjamin` | 人名 + **百元美钞** | ✅ **保留** |
| `bel` | **贝尔（声强单位）** + 贝尔（人名） | ✅ **保留** |
| `abe` | 仅 "nickname for Abraham" | ❌ 删除 |

**判据**：按**义项**逐条判断（`definitions` 是数组），
**全部义项皆专有 → 删**；**部分专有 → 保留（可选降级掉人名义项）**。

实测：纯专有 352 条、**兼类 280 条**。若不区分，会把 280 个正常词误删。

### 4.4 实测分类结果（12,791 条词表）

| 类别 | 数量 | 处理 |
|---|---:|---|
| ① 撇号残留碎片（`'m` / `'re` / `'s`） | 3 | 🔴 删 |
| ② 纯垃圾（`bbb`，三连字母） | 1 | 🔴 删 |
| ③ **专有名词**（pos 标记） | 445 | 🔴 删 |
| ④ **纯专有**（释义判定，pos 漏标） | 352 | 🔴 删 |
| ⑤ 化学元素符号（`yb` 镱 / `yc` / `yf`） | 3 | 🔴 删 |
| **小计·建议删** | **804** | |
| ⑥ 缩写（字母串：`tv` `nbc` `mph` `cm`） | 109 | 🟠 待确认 |
| ⑦ 多词短语（`according to` / `credit card`） | 142 | 🟠 待确认 |
| ⑧ 生僻短词（`(archaic)` / `(obsolete)`） | 27 | 🟠 待确认 |
| ⑨ **释义串位**（`happy`←`a` / `white`←`i` / `tape`←`tap`） | 33 | 📝 重生成释义（见 4.4.1） |

> **「污染短词 76 个」这个数字不成立** —— 该口径下的词多为缩写/功能词/前缀。

### 4.4.1 🔴 释义串位：比预想严重得多（本轮实测）

上一条记的是「多词短语释义串位」，实测发现**单字母/双字母短词也在批量覆盖后续词** ——
生成时似乎按**词条首段**取释义，导致「同释义被多词共享」：

| 受害词（合法词！） | 被谁的释义覆盖 |
|---|---|
| `happy` / `white` | `a` / `i` |
| `meet` | `me` |
| `tape` | `tap` |
| `bullet` / `bulletin` / `bully` | `bull` |
| `logo` | `log` |
| `hysterical` | `hys` |
| `ministries` / `mink` / `minneapolis` | `min` |
| `transact` | `tr` |
| `consideration` | `consider` |
| `tropical` | `tropic` |
| `shall` | `hall` |
| `humphrey` | `hr` |
| `air conditioning` | `air force` |
| `capital letter` | `cap` |
| `chewing gum` | `chew` |
| `bank account` | `ban` |

**实测 33 条**（另有 60 条同类现象落在多词短语等其他类里）。

**判据**：两个不同词条的 `definitions` 文本**完全相同**，且余部不是屈折后缀（排除 `ad`/`ads` 这类）。

**🔴 正确处理：这些是合法词，绝不能删**（`happy`/`white`/`meet`/`tape` 是高频词！）——
**应重新生成释义**（归 #8）。若不识别这个形态，会误删一批高频词。

### 4.5 🐛 顺带发现：多词短语的释义串位（独立数据 bug）

实测 142 条多词短语中，**释义取错了词**：

| 词条 | 实际释义 | 应该是谁的 |
|---|---|---|
| `air conditioning` | "the branch of a nation's armed forces..." | ← **air force** 的 |
| `capital letter` | "a type of soft flat hat with a peak" | ← **cap** 的 |
| `chewing gum` | "to bite and grind food with the teeth" | ← **chew** 的 |
| `bank account` | "to officially forbid or prohibit something" | ← **ban** 的 |
| `carbon dioxide` | "...poisonous gas (**CO**)" | 化学式应为 CO₂ |

**根因推测**：生成时按**词条首词**查了释义（`air` → air force），未按整条短语查。
**→ 这是内容生成缺陷，不是词表噪声**，需单独修（归 Phase 1 #8）。
