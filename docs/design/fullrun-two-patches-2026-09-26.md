## 一、① 中间节点补跑（`scripts/run_intermediate.py`）

### 背景

`derived_from` 有 12.3% 指向**词表外**的词（`attuned → attune`，attune 不在词表）。
这些「中间节点」自己没有 LLM 记录 → 它的 base 未知 → **链在它这里断掉** → `anchor` 算不出。

### 做法

- 把中间节点**当普通词再问一次 LLM**（同一契约 `coevo_wordlib_contract.py`）
- 输出到**独立目录** `intermediate/results.jsonl` —— **不与词表词混存**
  （混存会让 `build_chains.py` 把中间节点当词表词 → 错误地建卡）
- 支持**多轮迭代**：补跑 → 重跑链 → 若仍有新 pending 再跑一轮

### 结果（1,000 词批次，两轮）

| 指标 | 补跑前 | 补跑后 |
|---|---:|---:|
| 待补跑 pending | 96 | **0** ✅ |
| 链断（anchor 为空） | 96 | **36** |
| 有 anchor 的映射 | — | **32,207 / 32,243 = 99.89%** |
| 成本 | — | **¥0.54**（101 条） |

**多跳链生效样例**（补跑才可能出现）：
```
unhesitatingly → unhesitating → hesitate     (depth=2)
maximizing     → maximize     → maximum      (depth=2)
resuspended    → resuspend    → suspend      (depth=2)
schematically  → schematic    → schema       (depth=2)
```

### 🔴 同时暴露一个新问题（见 §三.A）

补跑出来的中间节点，**101/101 = 100% 被 LLM 判「值得独立成卡」**
—— 而它们**全都不在现网词表** → **词表有遗漏**。

## 二、② 搭配解析（`scripts/parse_related_phrases.py`）

### 🔴 此前连错两轮，真相是「两种格式并存而解析器只支持一种」

| 格式 | 样例 | 占比 |
|---|---|---:|
| **A 共享尾部括号** | `let it be, be that as it may, be yourself（顺其自然，尽管如此，做你自己）` | **65.3%** |
| **B 每段自带括号** | `blue sky（蓝天）, out of the blue（出乎意料）` | **27.4%** |
| F 无中文（仅英文短语） | `thank you, thank (someone) for` | 5.8% |

### 关键实现点（三个踩坑）

| # | 坑 | 修法 |
|---|---|---|
| 1 | **嵌套括号**：`apron strings（厨房围裙，围裙带（喻依赖））` | **配对法**从段尾回溯取最外层括号（正则会在内层停住 → 中文被截断成 `喻依赖`） |
| 2 | **中文项分隔符用错**：`；` 是**项内**补充不是项间（`未经雕琢的钻石；璞玉` 是一项） | 中文项间**只认 `，`/`,`** → MISMATCH 从 1,188 → **7** |
| 3 | 尾注 `[注：…]` 混入释义 | 解析前剥离 |

### 结果（全库 11,689 行非空）

| 项 | 数值 |
|---|---|
| 短语条目 | **25,399**（23,384 有中文） |
| 格式 A（含前缀配对 97） | 7,726 |
| 格式 B | 3,280 |
| 🔴 无法配（中文数 > 英文段） | **7 条 = 0.1%** ← 记清单人工判 |
| **旧解析器会错位的行** | **3,809 = 32.6%** 🔴 |

**旧解析的错位比此前审计的 14.1% 更严重** —— 不只释义错位，在格式 B 上**整条短语丢失**：

```
原文: blue sky（蓝天）, out of the blue（出乎意料）
旧:   [('blue sky', '蓝天）')]                    ← 只 1 段，中文带残留「）」，第 2 个短语**丢了**
新:   [('blue sky','蓝天'), ('out of the blue','出乎意料')]  ✅
```

### 落库脚本已加开关

```bash

# 可选：合并现网解析结果（LLM 未给的补进来，中文优先 LLM）
```

## 三、三个新发现

### 🔴 A. 词表有遗漏（须白哥定）

**事实链**：
1. 中间节点补跑 101 条 → **100% 判 `is_own_entry=true`**
2. 且 **101/101 不在现网词表**
3. 它们是别的词的 `base`（`belch`←belched · `accrue`←accrued · `alienate`←alienated）

**代表性遗漏词**（都是常用基础词）：
```
belch · accrue · alienate · adjourn · barricade · conserve · distill · dwindle
frown · impede · maximize · perforate · prudent · reconstruct · scrutinize
appease · broil · clod · glib · leer · pelt · subdue · tusk · wiggle
```

**推断**：现网 11,917 词表**不是完整的基础词表** → 至少漏 101 个（1,000 词批次口径）→ **外推 ≈1,200 个**。

**影响**：
- 用户划到 `belched` → base `belch` 不在词表 → 若 `belched` 自己也不建卡 → **查不到任何卡**
- 词源族/词根族**缺中间节点** → 聚合页成员不全

**两个选项（待定）**：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A 补录**（我建议） | 把「LLM 判 is_own_entry=true 且不在词表」的中间节点**补进词表**（新词条，走同一套流程） | 全量 LLM 从 11,917 → **≈13,100**（+¥6.5 / +5 min）；**好处**：链断归零、词表更完整、复习卡不缺 |
| **B 不补录** | 维持现词表，链断走「L2 降级卡」兜底 | 零额外成本；但 **≈390 条**划词要走降级路径 |

> ⚠️ 补录会改变词表规模，**属设计决策，未擅自执行**。

### 🟠 B. 搭配两个数据源互补（须白哥定）

同一批 958 个词逐词对照：

| 指标 | 数值 |
|---|---:|
| LLM 搭配总数 | 2,536 |
| ✅ 两者重合 | 829（**33%**） |
| 🔵 LLM 独有 | 1,707（**67%**） |
| 🟠 现网独有 | 1,306 |

**样例（各有胜负）**：
| 词 | LLM 独有 | 现网独有 | 评价 |
|---|---|---|---|
| `agent` | `free agent` · `real estate agent` | `chemical agent` · `travel agent` | 各有真实高频项 |
| `acquiesce` | `acquiesce in something` | `acquiesce in/ to`（含空格错误） | LLM 更规整 |
| `apologize` | `apologize for something` | `apologize for` | 现网更简洁 |

**→ 互补性强，合并最优**（开关已备好）。**默认仍只用 LLM**，等白哥定。

> 💡 **反例**：覆盖缺口只有 8 个词，全是**人名**（`daer`/`faget`/`pam`/`ronnie`…）
> —— LLM 正确地不给搭配，现网却给了（`alsop-en-le-deal` 是地名）→ **LLM 判断更对**。

## 六、附：两处核实（一处澄清、一处待定）

### ✅ `card_extra` 只有 50 条 —— 核实为**正确**，不是缺口

落库逻辑是「**前 4 个义项进 `card.content.sections`，第 5 个起进 `card_extra`**」。
实测 1,000 词批次义项分布：

| 义项数 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 词数 | 315 | 398 | 190 | 60 | 27 | 8 | 1 | 1 |

→ 义项 >4 的 37 个词，超出部分共 **27×1 + 8×2 + 1×3 + 1×4 = 50** —— 与落库行数**完全吻合** ✅

（全库口径：义项 >4 的占 **4.6%**（544/11,917））

### 🟠 待澄清：`sections` 会出现 5 个，可能超「一页容量上限」

当前逻辑：
```
sections = 前 4 个 sense section
         + 1 个 root section（若 analyzable）   ← 最多 5 个
```

**「一页容量上限」是 v1 评审 §十 明确「不要动」的 10 条之一**，但**具体上限值文档未落盘**。
若上限 = 4，则可拆词应只放 **3 个 sense + 1 个 root**（第 4 个义项进 extra）。

**另**：`etymology` 按 P1-9 的新解法**不占 sections 位**（只存 `word.etymology_text`），当前实现一致 ✅。

**→ 待白哥定上限值（4 还是 5），再统一 sense/root 的分配规则。**
