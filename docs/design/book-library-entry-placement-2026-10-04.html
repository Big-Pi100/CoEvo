三种落法对比
按「与白哥那句原话的贴合度」「改动量」「对既有结构的影响」三轴对比。
方案 与「标题平级」贴合度 改动量 对既有结构的影响 风险
A · 标题级双 Tab
✅ 已定案		 最高 —— 书库就是第二个平级标题，视觉与语义都成立 中 —— 标题栏改双 Tab；书库由顶层路由改为 /home 子视图 与既有先例一致（「收藏清单」也是 /home 子视图，保留 tabbar） 需处理「阅读 tab 已选中时再点阅读」的复位语义（既有机制已能覆盖）
B · 底部第 4 个 tab 低 —— 是 nav 级平级，不是标题级 小 —— 加一个 branch + 一个 tab 项 底部导航由 3 变 4，每项变窄；与「书库是阅读的一部分」的产品直觉相悖 tab 拥挤；白哥原话未见此意
C · 标题行右侧文字链 中 —— 入口确实落在标题这一行 最小 —— 只改标题栏，不动路由 标题栏右侧变两个入口，主次不分 小屏 / 大字体下可能换行；「书库」被读成次要入口
🔑 一条判据（沿用既有）：「它是不是 tab 的内容」—— 若是，走页内子视图（保留 tabbar）； 否则走顶层路由。按方案 A，书库 = 「阅读」这个 tab 的第二页 ⇒ 与「收藏清单」同类， 归 /home 子路由即可（/home/books），转场与手势自动继承。
🔑 标题级下划线的三档风险：朱砂短线（accent）在「墨」档对比最好； 「格」档底色纯白 + 灰调，3px 线要够粗才不糊；「夜」档 accent 变亮（#DB7E6B）， 需确认在 #0B0D12 上不刺眼 —— 请在上面切三档各看一眼。 若下划线不合适，可退化为「只靠字色 + 字重」（选中 ink / 未选中 ink3），我再出一版。
命名：平级双标题下，「我的书库」4 字会与「今日精选」4 字并排显得长， 建议标题用「书库」2 字（页内文案仍可写「我的书库」）。这条也请一并定。
⚠️ 本设计稿尚未处理：阅读页 /books/:id 的返回目标（现在返回到 /books）； 改成子视图后应确认「从书里退出」回到的是书库 tab 还是信息流 —— 定方案后我一起收口。
🔴 连带工作（进群引导的必做项）：群二维码弹层现在是 about_screen.dart 里的私有方法 _showGroupQrcodeDialog。 书库空态要复用它 ⇒ 必须抽成公共组件，否则同一个弹层会有两份实现 —— 下次改标题或换图，两处会静默走偏（这正是当初把 HeaderChip 抽出来的同一条判据）。
⇒ 实现时的动作：抽到（如）widgets/group_qrcode_dialog.dart， about_screen 改为调用它（保留唯一实现）。
🔴 文案不能把群说成「资源群」（群方案 §3.1 定的）： 群定位是「教方法 + 陪读 + 答疑」，群规明令禁传电子书文件。 所以引导文案只能落在「一起找 / 教你怎么找」，不能写「进群领书 / 拿资源 / 免费下载」—— 那既吸引错的人，也与群规自相矛盾。
⏳ 顺带发现（需你定是否一并处理）：about_screen.dart:334 有一条注释写着 「线上该图当前不存在（2026-10-04 实测 /api/public/qrcode 返回 text/plain）」—— 我刚刚实测：HTTP 200 · image/jpeg · 134551 B，图已经传上去了，该注释已过时。
⇒ 建议一并更正（属「注释与现状不符」，会把后来人引向错误方向）。
