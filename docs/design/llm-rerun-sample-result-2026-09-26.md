# LLM 全库重跑 · 抽样验证结果

- 日期：2026-09-26
- 触发（白哥）：「**组 C / 18 条这些都是规则分析的残留，根本没有意义…… 你规则分析的遗漏怎么搞？不还是要 LLM 跑，最重要的是根本不知道哪些错了，哪些漏了，判断遗漏本身还是靠规则，还是不靠谱。**」

## 〇、先回答「规则的遗漏怎么办」

**答案：规则的遗漏不可能靠规则解决 —— 因为它们没有共同特征。这正是「遗漏」的定义。**

抽样给出了**可量化的证据**：

| 规则分组（1383 条候选） | 规则结论 | LLM 抽样判定 | 规则错在哪 |
|---|---|---|---|
| **A 纯屈折**（884 条） | 建议合并 | 41 条样本中 **7 条应保留**（17%） | 🔴 **误合** —— `lyrics`(歌词) · `coordinates`(坐标) · `sanctions`(制裁) · `reins`(缰绳) · `precisely` · `probably` · `sworn` |
| **B 有独立义**（338 条） | 建议保留 | 15 条样本中 **3 条应合并**（20%） | 🔴 **误留** —— `terrified`←terrify · `torn`←tear · `studded`←stud |
| **C 灰区**（161 条） | 需人工判 | 4 条样本 2:2 | 灰区本身就是规则无能的表现 |

**→ 折算全量：约 150 条会被规则误合、约 68 条被误留 ≈ 218 条错判。**

**关键**：这 218 条**没有共同模式** —— `lyrics` 和 `pianists` 都是复数、都是 `-s` 结尾，规则无法区分。**继续加规则只会引入新的误伤**（这正是 Phase 1 清洗时「76 个污染短词」口径被推翻的原因）。

**LLM 全量重跑把问题性质改变了**：

| | 规则法 | LLM 全量重跑 |
|---|---|---|
| 覆盖面 | 只在你写规则处找 | **100%（逐词都跑）** |
| 「遗漏」 | **无法自证**（判断遗漏又要一条规则 → 循环） | 变成「判错」→ **可统计** |
| 质量度量 | 无参照 | **自洽性 + 人工盲评**（有分母） |

## 二、抽样结果

### 2.1 🔑 抽样立刻抓到一个致命契约缺陷（这就是抽样的价值）

**第一轮抽样：219 个词素全部没有 `form` 字段**（只有 `type`/`meaning`/`origin`）。

- **根因**：**我的 prompt 契约写错了** —— 示例里 `parts` 给的是空数组 `[]`，规则段落只描述了 `type/meaning/origin`，**漏写了 `form`**
- **后果（如果直接全量跑）**：`word_root.form` 全空 → **`cognate_group` 无法派生 → 聚合页全废**，11,917 词全部返工
- **修正后**：`form` 齐全度 **226/226 = 100%**

> **→ 这直接证明了「先抽样再全量」的必要性。** 契约缺陷在全量跑完之前无法被发现。

### 2.2 契约合规性（字段齐全度 —— 不是判对错）

| 项 | 结果 |
|---|---|
| 词素 `parts` 总数 | 226 |
| **缺 `form`** | **0 ✅** |
| 缺 `meaning` / `type` / `origin` | 0 / 0 / 0 |
| `analyzable=true` 但 `parts` 空 | 0 |
| `analyzable=false` 但有 `parts` | 0 |

**→ 契约 100% 合规。**

### 2.3 两轮自洽性（不用规则判质量）

| 指标 | 一致率 | 含义 |
|---|---|---|
| `entry.is_own_entry` | **99.4%** | 归一化判定极稳 |
| `morphology.analyzable` | **97.5%** | 可拆性判定稳 |
| 词素拆分 `parts` | **95.6%** | 边界判定**有 4.4% 抖动** |
| `mnemonic.primary` | 89.4% | 记忆法主次是主观选择，抖动最大（可接受） |
| **三项任一不一致** | **5.0%（8/160）** | 🔴 **这就是「必查清单」** |

**→ 5% 的静默分歧率**：全量 11,917 词中预计约 **600 词**会落在不一致区间，**只对这 600 词跑第二轮**即可，不必全量跑两轮（省一半成本）。

### 2.4 内容质量分布

| 项 | 结果 | 评价 |
|---|---|---|
| 可拆率（`analyzable`） | **52.5%**（84/160） | 对照：规则法 32.0% · 上次 LLM 抽样 45.3% |
| 独立词条率（`is_own_entry`） | **68.8%**（110/160） | S1 随机样本为主，故高 |
| 低置信（<0.6） | **2/160** | 极低，置信度校准良好 |
| `etymology` 非空 | 82.5% | v1 设计「只对外来整体词」—— 比例吻合 |
| `collocations` 非空 | 97.5% | ✅ |
| `mnemonic.rationale` 非空 | 99.4% | ✅ |
| `entry.reason` 非空 | 100% | ✅ |

**记忆法主次分布**（对照 v1 六级）：`root` 91（57%）· `etymology` 23 · `context` 22 · `image` 10 · `cognate` 9 · `collocation` 5
→ **词根确实是主力**（与「可拆率 52.5%」一致），v1 把它列 priority 1 有数据支撑。

### 2.5 🔴 真实错误（人工识别，不是规则筛的）

| 问题 | 实例 | 性质 |
|---|---|---|
| **词素边界错** | `forbidden` → `for- + bid + den`（第二轮） | 🔴 **真错** —— `-en` 才是后缀（forbid+den 是把 `d` 归错） |
| **同词两轮边界不同** | `importantly`：`import+ant+ly` vs `im+port+ant+ly` | 🟠 语义都不算错，但**不稳定** |
| 词素 `form` 未标注拼写调整 | `sun + -y → sunny`（y 双写）· `use + -ed → used`（去 e）· `heavy + -ly → heavily`（y→i） | 🟡 拼接还原率 76.2%，**但 20 条「拼不上」几乎全是拼写规则，不是幻觉** |

> `forbidden` 这条很典型：**它是「幻觉」而非「不知道」** —— 模型自信地给了一个不存在的后缀。

### 2.6 🆕 抽样对照暴露的规则硬错误（`base_form` vs `lemma`）

**触发**：白哥问「`"lemma": "prompt"` 和 `"base_form": "prompt"`，字段含义上有什么不同？」

**核实**：把抽样中判 `is_own_entry` 的词与 `word_form.lemma` 逐条对照 ——

| 指标 | 结果 |
|---|---|
| 判 `false` 的词，`base_form` == `word_form.lemma` | **43/44 = 97.7%** |
| 判 `true` 的词，`word_form` 里**仍有一条指向别处的映射** | 🔴 **22 条分叉** |

**分叉样例 —— 全是规则错、LLM 对**：

| 词形 | 规则说 | LLM 说 | 规则错在哪 |
|---|---|---|---|
| `owner` | `own`（**comparative**） | `owner` 独立 | `owner`（所有者）根本不是 `own` 的比较级 |
| `besides` | `beside`（**plural**） | `besides` 独立 | `besides` 是介词/副词，不是复数 |
| `genetics` | `genetic`（**plural**） | `genetics` 独立 | `genetics` 是单数学科名 |
| `sanctions` | `sanction`（plural） | `sanctions` 独立 | 制裁义已词汇化 |
| `lyrics` | `lyric`（plural） | `lyrics` 独立 | 歌词义已词汇化 |
| `analyses` | `analyse`（英式） | `analysis` | 拼写体系混用 |

**→ 这三条硬错误（`owner`/`besides`/`genetics`）都"匹配到了规则"，所以规则认为自己是对的 —— 又一次实证「规则判断不了自己的遗漏」。**

#### 🔴 顺带定位到一个成类的规则缺陷：`-er` 规则把施事名词误判成比较级

`in_vocab=1 且 form≠lemma` 共 **1,383 条**，`rule` 分布：`past` 384 · `plural` 377 · `adverb` 294 · `ing` 271 · `past_participle` 31 · **`comparative` 15** · `superlative` 7 · `present` 4。

把 `comparative`/`superlative` **26 条全列出**后发现成类错误：

| 类型 | 条目 | 判定 |
|---|---|---|
| ✅ 真比较级 | `worse`/`worst`→bad · `better`/`best`→good · `further`/`furthest`→far · `later`/`latest`→late · `less`/`least`→little · `lower`→low · `elder`/`eldest`→old | 正确 |
| 🔴 **施事名词被当比较级** | **`leader`→lead · `liver`→live · `offer`→off · `owner`→own** | **完全错** —— `-er` 在这里是「施事/物」后缀，不是比较级 |
| 🟠 已词汇化的独立义 | `cleaner`（清洁剂）· `cooler`（冷却器）· `lighter`（打火机） | 应独立成条 |
| 🟡 重复映射 | `better`/`best` 同时指向 `good` **和** `well` | 需去重 |

**→ 结论：`comparative` 26 条里，约 4 条明确错 + 3 条有争议 ≈ 错误率 15–27%。**
**→ 这类错误规则**永远**发现不了** —— 它匹配到了 `-er`，规则认为自己对。


**设计后果**（已写入 `word-db-schema-frozen` §1.1/§1.2）：
1. 🔴 **`word` 表去掉 `lemma` 字段**，改 `UNIQUE(spelling)` —— 独立词条的 `lemma ≡ spelling`，字段冗余**且会引诱把冲突卡塞进 `word` 表**
2. ✅ `is_own_entry=true` 时，`word_form` 的旧映射**直接删除**（✅ 白哥已批）→ `owner→own` 这类错误**无需单独维护黑名单**

### 2.7 抽样文件的字段来源分层（白哥问「哪些是规则的，哪些是 LLM 的」）

**四层，已逐字段核实**：

| 层 | 字段 | 来源 | 实测核实 | 进库？ |
|---|---|---|---|---|
| **L0 输入 · 存量数据** | `word` | DB `prebuilt_cards.front`（人工整理词表） | — | ✅ 迁移 |
| | `level` | DB `prebuilt_language_cards.level`（CEFR-J 外部标注） | **40/40 与 DB 一致** | ✅ 迁移 |
| | `form_def` | DB `definitions`（现网释义） | **57/60 前缀命中** | ✅ 迁移 |
| **L1 抽样框 · 规则** | `lemma` | `word_form.json` ← `build_word_form.py` | **60/60 与 `word_form.lemma` 一致** | ❌ **不进库** |
| | `rule_group` | `word_family_candidates.json` ← `build_variants_and_families.py`（A/B/C） | — | ❌ **不进库** |
| **L2 机械标注** | `group`（S1/S2） | 脚本常量 | — | ❌ |
| | `in_tok` / `out_tok` / `ok` / `_meta` | API 返回 + 脚本统计 | — | ❌ |
| **L3 LLM 产出** | `r1.data.*` / `r2.data.*` | deepseek-flash | 回显校验 **160/160 一致** | ✅ **唯一进库源** |

#### 🔴 关键：同一行里有两个「基础形式」字段，来源不同、语义重叠

| JSON 路径 | 来源 | 值（`owner` 例） |
|---|---|---|
| `items[].lemma` | **规则** | `own`（🔴 错） |
| `r1.data.entry.base_form` | **LLM** | `owner`（✅ 对） |

**→ 这正是白哥前一条问题的由来** —— 命名不一致（`lemma` vs `base_form`）遮蔽了「两者回答不同问题」。
**→ 落库时只有 L3 进库，L1 的字段必须丢弃**，否则会把规则的错误（`owner→own`）带进 `word` 表。

#### ⚠️ 必须交代的偏差：S2 的抽样框本身是规则的产物

| 组 | 抽样框 | 受规则污染？ | 结论可外推到 |
|---|---|---|---|
| **S1**（100 词） | 全词表按 DB `level` 分层随机 | ✅ **无** | **全词表 11,917** |
| **S2**（60 词） | `word_family_candidates.json` 的 **1,383 条** | 🔴 **有** | **仅**这 1,383 条 |

**→ S2 的「35% 判独立」只在「规则认为可疑的 1,383 条」内成立，不能外推到全词表。**
**→ 这不影响结论**（冲突卡本来就是这 1,383 条，正是要判的对象），但**要避免误读**。

**→ L1 字段在抽样文件里的唯一作用是「对照物」** —— 用来暴露规则的错，**不是数据源**。

## 三、全量重跑的成本与时间（重新核算，推翻旧估）
