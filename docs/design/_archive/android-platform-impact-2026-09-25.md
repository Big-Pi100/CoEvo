# Android 平台影响评估（白哥第 1 条提问引出的新面）

- 日期：2026-09-25
- 起因：白哥问「Apple 登录可以，安卓版，国内不能用谷歌账号呢？」

| # | 发现 | 严重度 |
|---|---|---|

## 二、🔴 三条新增的强制资质

### 2.1 软件著作权登记（软著）—— Android 强制，iOS 不需要

| 项 | 实测（多方来源一致） |
|---|---|
| 是否强制 | **Android 全渠道强制**（华为 / 小米 / OPPO / vivo / 应用宝），**苹果不强制** |
| 周期 | **普通 40–60 个工作日（1.5–3 个月）**；加急 30–40 工作日（额外费用） |
| 硬性规则 | **软著著作权人 = 营业执照主体 = 开发者账号主体**；APP 名称 / 软著登记名称 / 桌面显示名称**必须一字不差** |
| 无软著的后果 | **直接驳回提审，无例外** |

> **这是整个上架流程里最长的一环**，必须先启动。多个来源都强调「软著必须是资质办理中最早启动的环节」。

### 2.2 APP 备案（工信部移动互联网应用程序备案）

**🔴 这是一个非常容易搞混的点：**

| 项 | 网站备案（已完成） | **APP 备案（未做）** |
|---|---|---|
| 备案对象 | 域名 + 服务器 IP | **应用包名 + 签名** |
| 备案号形态 | `粤ICP备2026xxxxxx号-1` | **`粤ICP备2026xxxxxx号-2`**（独立编号） |
| 审核重点 | 资质（营业执照、域名证书、核验照片） | **行为**（隐私政策 / 权限声明 / SDK 清单） |
| 周期 | 15–20 工作日 | **约 20 个工作日**（总局 5–25 个工作日） |
| 是否通用 | — | ❌ **不等同** —— 网站备案完成 ≠ APP 备案完成 |

**依据**：《工业和信息化部关于开展移动互联网应用程序备案工作的通知》+《反电信网络诈骗法》第二十三条 → **未完成 APP 备案，商店拒绝收录，手机纯净模式拦截安装**。

**材料**：主体信息、APP 名称与包名、**公钥与 MD5**、隐私政策、**权限调用说明、SDK 名单**。

> ⚠️ **APP 备案必须关联已备案的域名** —— 我们的 `keyievolution.fun` 已备案，这个前置条件满足 ✅
> ⚠️ **APP 名称必须与安装后桌面显示名一致** —— 定名时要一次定好

### 2.3 增值电信业务经营许可证（ICP 许可）—— 明确命中

之前主方案写的是「有广告+会员属经营性，**建议向备案服务商确认**」。现在有明确依据：

> 「如果 APP 通过**会员付费**、有偿信息服务、**广告分成**等方式盈利，属于**经营性互联网信息服务**，就**必须办理**《增值电信业务经营许可证—信息服务业务》」

| 项 | 要求 |
|---|---|
| 适用条件 | **会员付费 ✅ + 广告 ✅** → 两条都命中 |
| 申请主体 | **内资公司**（外资/合资受限） |
| 注册资本 | **一般不低于 100 万元**（省内经营） |
| 周期 | **40–60 个工作日** |
| 其他 | 需场地、人员社保等条件 |

> **所以这条从「建议确认」升级为「必须办理」**。它和软著一样是长周期项（40–60 工作日）。

## 三、⏱️ 时间线倒推（关键路径）

假设目标上线日为 **T**：

```
T-120 天 ──┬─ 启动软著申请（普通件 40–60 工作日）      ← 最长路径，必须先动
           ├─ 启动 ICP 经营许可申请（40–60 工作日）
           └─ 确认营业执照经营范围覆盖「软件开发/信息技术服务」
T-90  天 ──┼─ 提交 APP 备案（需先有包名 + 签名 + 隐私政策）
           └─ 微信开放平台企业认证（300 元/年）+ 创建移动应用
T-60  天 ──┼─ 各安卓商店开发者账号注册 + 企业认证（各约 300 元）
           └─ 编写隐私政策独立网页（含 SDK 清单 / 权限说明 / 注销通道）
T-30  天 ──┼─ 拿到软著 → 各安卓市场提交上架
           └─ iOS App Store 提审（iOS 不需要软著，可更早）
T     日 ──┴─ 上线 → **30 日内完成公安联网备案**
```

**两个可并行的策略**：
1. **iOS 不受软著阻塞** → **iOS 先行**，Android 跟在后面（详见 §五）
2. 软著 / ICP 许可 / APP 备案 / 各商店账号 —— **并行推进**，别串行

## 四、登录方案（回答白哥的问题）

### 4.1 现状实测

| 项 | 结果 |
|---|---|
| 现有登录实现 | `auth.rs` 的 `register` / `login`，**只有 username + password** |
| 第三方登录 SDK | 🔴 **一个都没有**（无 `sign_in_with_apple`、无 `fluwx`、无 `google_sign_in`） |
| 微信相关代码 | 只有**支付二维码**（`pay_screen.dart`），**没有微信登录** |
| Flutter 平台目录 | `android/` ✅ `ios/` ✅ 都已存在（虽然一直只构建 web） |

**所以两种登录都是从零集成。**

### 4.2 「国内 Android 不能用 Google 账号」—— 确认，且不止 Google

| 登录方式 | iOS | Android（国内） | 备注 |
|---|---|---|---|
| **Google 账号** | ⚠️ 可用但不推荐 | ❌ **完全不可用** | 国内无 GMS |
| **微信登录** | ✅ | ✅ | **国内 Android 的主流选择** |
| **Sign in with Apple** | ✅ 原生 | ⚠️ 可跑网页流程，体验一般 | iOS 上必须提供（见 4.4） |
| **邮箱 + 密码** | ✅ | ✅ | 跨平台通用，零依赖 |
| 手机号 + 验证码 | ✅ | ✅ | 短信成本 + 模板审核 + 运营商报备 |
| QQ 登录 | ✅ | ✅ | 腾讯系，用户群偏年轻 |

### 4.3 我的建议方案

| 平台 | 主登录 | 兜底 |
|---|---|---|
| **iOS** | **Sign in with Apple** | 邮箱 + 密码 |
| **Android（国内）** | **微信登录** | 邮箱 + 密码 |

**为什么不做手机号**：
- 短信服务有真实成本（约 ¥0.04/条）+ 模板审核 + 运营商报备
- 英语学习**不是实名强制场景**（不像 UGC / 金融 / 直播）
- 微信登录已经覆盖了「不想记密码」的用户群

**为什么微信登录是 Android 的最优解**：
- 国内 Android 用户的登录习惯就是「一键微信」
- 我们有支付需求（会员），微信开放平台账号可同时支撑登录与支付

### 4.4 ⚠️ 微信登录的依赖条件（比想象中多）

| # | 依赖 | 说明 |
|---|---|---|
| 1 | **企业认证的开放平台账号** | **300 元/年**；**个人账号无法申请 App 微信登录能力** |
| 2 | **创建「移动应用」**（与现有 Web 应用是不同类目） | 需填：**Android 包名 + 应用签名 MD5**、iOS Bundle ID + Universal Links |
| 3 | 审核周期 | **1–7 个工作日**（复杂情况更长） |
| 4 | **🔴 要先有 Android 签名** | 签名来自 keystore → **必须先定包名 + 生成 keystore + 打包 APK** |
| 5 | 官网 | 需与开放平台主体一致（我们已有 `keyievolution.fun` ✅） |

> **⚠️ 鸡生蛋问题**：微信登录需要 Android 签名，而签名来自 keystore；**包名 + 签名一旦提交审核通过就不能随意改**，否则要重新走审核。
> **所以必须先把 Android 包名定下来** —— 这是现在就能做的决策。

**建议包名**：`fun.keyievolution.coevo`（与域名反向，主体清晰）

**Apple 规则 4.8**：iOS 上提供微信登录 → **必须同时提供 Sign in with Apple** ✅（我们计划做，所以合规）

### 4.5 落地顺序建议

```
① 现在：定 Android 包名 → 生成 keystore（永久有效，务必妥善备份）
② 打包 Android APK → 用 keytool 取 MD5 签名
③ 微信开放平台：企业认证 → 创建移动应用（填包名+签名+Bundle ID）→ 提交审核（1-7 天）
④ 集成 SDK：iOS 用 sign_in_with_apple，跨平台用 fluwx（微信）
⑤ 后端补：Apple 身份校验（identityToken）+ 微信 code2session
```

**但注意**：按已定方案，**Phase 4 端侧 MVP 完全不需要账号体系**（匿名可用）→ 上面这些**不阻塞开发**，可以并行办资质。

## 五、💡 建议策略：iOS 先行

**关键洞察：iOS 不需要软著，Android 需要。软著要 1.5–3 个月。**

| | iOS（中国区 App Store） | Android（国内各商店） |
|---|---|---|
| 软著 | ❌ 不需要 | 🔴 **强制** |
| APP 备案 | ✅ 需要 | ✅ 需要 |
| ICP 经营许可 | 🟢 订阅制下暂不需要（收费主体是 Apple） | 🟠 需确认（安卓商店普遍要求） |
| 隐私政策网页 | ✅ 需要 | ✅ 需要 |
| **最短上线路径** | **较短**（无软著阻塞） | **多 1.5–3 个月** |

**建议**：

1. **立即启动软著 + ICP 经营许可**（这两个都是 40–60 工作日，现在不动，Android 上线就往后推两个月）

（白哥已明确「上架中国区域」→ 海外区不做，**AdMob 不需要**，广告 SDK 用**穿山甲 / 优量汇**。这反而简化了一项。）

## 六、技术面新增

### 6.1 消息推送（国内 Android 无 FCM）

| 平台 | 方案 |
|---|---|
| **iOS** | APNs（统一、简单） |
| **Android（国内）** | 🔴 **FCM 不可用** → 需要**厂商通道**（华为 HMS / 小米 / OPPO / vivo / 荣耀）或**聚合 SDK**（极光 / 个推 / 腾讯 TPNS / 阿里云移动推送） |

**推送对我们的意义**：**复习提醒**（FSRS 到期通知）是核心留存手段。

| 选项 | 到达率 | 成本 |
|---|---|---|
| 各厂商 SDK 直连 | 99%+ | 免费，但需逐个申请配置（工作量大） |
| **聚合 SDK（推荐）** | 90–98% | 按量计费，约 **0.5–2 元/万条** |

**建议**：**第一期不做推送**（端侧 MVP 无账号、无服务端）；推送到 Phase 7 或之后，届时用聚合 SDK。

### 6.2 其他 Android 特有项

| 项 | 说明 |
|---|---|
| **targetSdkVersion** | 华为要求 ≥ 30（新版本要求更高，需上线前核实） |
| **包体积** | 我们 App 本体约 139 MB（代码 65 + 词库 50 + 字体 24）；**各商店限制不同，需核实** |
| **应用图标** | 1024×1024 PNG，各商店要求一致 |
| **应用截图** | 至少 3–5 张，建议准备 16:9 与 18:9 两套尺寸 |
| **鸿蒙** | 2026 年华为新增 HarmonyOS 应用备案要求（**独立通道**，与 Android 备案分开） |
| **权限声明** | APP 备案要求**权限调用说明与代码一致** —— 不能声明了不用，也不能用了不声明 |

## 七、两项已核实的判断（本轮更新）

### 7.1 ✅ 「教育类」不适用 —— 已核实，非待确认

**原为「待确认：教育类资质」**，白哥已核实：**我们的定位是学习工具，不是教育服务**，不落入「教育」前置审批范围。

| 原担心的教育类要求 | 结论 |
|---|---|
| 教育培训类目经营范围 | ❌ 不需要 |
| 网络安全等级保护三级 | ❌ 不需要 |
| 专职内容审核人员 ≥ 3 名 | ❌ 不需要 |
| 教师资质 / 预收费存管 | ❌ 不适用 |

> 已从 §一 结论摘要与本文档的「待确认」清单中移除。

### 7.2 ✅ 「生成式 AI 服务备案」不适用 —— 已核实，非待确认

**原为「需核实」**：我们用 LLM 生成词卡内容（词库外生词兜底）→ 是否触发生成式 AI 服务备案？

**白哥在办理 ICP 备案时已被官方纠正：不属于 AI 服务。** 我们的形态是「预先批量生成内容 + 离线分发」，**不是面向用户提供生成式 AI 交互服务**。

> 已从本文档移除该待确认项。

### 7.3 🔴 但软著这条**新增了一个更严重的风险**（本轮新发现）

**2026-03-15 中国版权保护中心新规**，签章页要求经办人**手抄承诺**：

> 「确认软件为独立开发、**未使用 AI 开发编写代码 / 撰写文档 / 生成申请材料**」

并配套**失信惩戒**：违规者列入版权登记失信名单 + 纳入个人征信 + 承担法律责任。审核同时从「形式审查」转向**实质性审查**。

**这条直接影响 CoEvo**（本项目代码大量在 AI 辅助下成稿），且**不是我能在技术上解决的**——详见 `docs/operations/qualification-startup-2026-09-25.md` §二.2，那里列了三条可行方向与各自代价。

> ⚠️ **在拿到官方明确口径前不要提交软著申请。** 后果是征信记录，不是材料被退回。
