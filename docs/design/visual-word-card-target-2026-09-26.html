🔴 为什么「到期时间」是整个复习页的骨架
FSRS 的产出只有一个东西：这张卡下次什么时候该复习。
所以：
· 排序 = 按到期时间升序（默认「记忆曲线」档）
· 分组 = 「今天该复习 / 之后」（也是按到期时间切的）
· 「23 个今天该看」 = 到期时间 ≤ 今天的卡片数
· 卡片按钮上的「下次 X 天」 = 按下之后到期时间会变成什么

→ 四处用的是同一个数。把「到期时间」藏起来，四处就都失去了依据。
三档排序（ui-ux §6.2）：记忆曲线（默认，按到期时间）· 最近（最近加入或复习）· A–Z。
⚠️ 「熟练度三点」直接映射 FSRS 三态，与阅读界面的痕迹共用定义 —— 一致的心智模型。
窗口里能看到「下次 X 天」的 4 个位置
① 列表项右侧 —— 「已到期 / 2 小时 / 4 天 / 3.5 个月」
② 顶部计数 —— 「23 个今天该看」
③ 分组标题 —— 「今天该复习 / 之后」
④ 卡片按钮 —— 「忘了 10 分钟 / 困难 21 天 / 记得 1.5 个月 / 熟练 3.5 个月」
🔑 ④ 是本次唯一需要「预测」的地方：提交之前就要知道四个分支各自的结果。 端侧 FSRS 的 reviewCard() 不改原卡（内部先 copyWith）→ 对四个评分各调一次即可预览，无需额外的预测 API。

03渲染规则 · 库级只说「可以」，渲染层决定顺序

制卡时不该分「主要/次要」，该问「可不可以」。 库级逐类独立记录可否；优先级是渲染层的事 —— 从槽位①开始按 1→6 找第一个可用的，继续找填②。 这样改渲染规则不用动数据。
→ 卡片上也不出现「主要记忆法」这类标注 —— 主次是判断，不是可核验的事实；标签会把它固化成读者以为的事实。

04点击 ① 展开：词根族聚合页

这是本次最重要的修正。聚合页里每一条都带分拆法 —— 一眼看出「同一个 cept（拿取）配合不同前缀就产生完全不同的含义」。 只列单词是没意义的：那是「22 个不相干的词」；带分拆法才是「一个词根 × 22 种前缀」。
数据实测：分拆法可算率 100%（cept 22/22 · man 32/32 · organ 15/15 …），来自 word_morpheme。

05点击 ② 展开：词源族聚合页

09验收清单 · 用这个界面校文档

以后任何文档改动、任何实现，都在这四张卡 + 两个聚合页 + 复习列表上过一遍 —— 一眼能看出不对的，就是偏离。

  • 🔴 四个评分按钮各显示「下次 X 天」，且数字由端侧 FSRS 实时预览得出（不是写死的文案）。白哥 2026-09-26 定：「要『下次 X 天』——而且在复习界面不是按 FSRS 排序的吗，没有时间怎么排序」。实现要点：端侧 reviewCard() 不改原卡 → 对四个评分各调一次即可预览
  • 🔴 复习列表项显示「下次到期时间」，因为默认排序（记忆曲线）的依据就是它。依据 v1 §10.2「复习队列排序 —— 综合考虑 FSRS 到期时间…」+ ui-ux §6.2「列表项 = 单词 + IPA + 中文释义 + 熟练度三点 + 下次到期时间」。v6 新增 02 节
  • 评分按钮中文为「忘了 / 困难 / 记得 / 熟练」（`Good` 不译「一般」），英文副标题保留（`again/hard/good/easy`）。白哥 2026-09-26 定：译名改「记得」；英文「留着」（可在按钮上直接显示间隔后，英文仍作为对齐 Anki 习惯的辅助）
  • 🔴 库级只回答「可不可以」，不回答「哪个是主要记忆法」 —— 不存在 `primary_code`/`secondary_codes`。当前实现：`word_mnemonic_profile` 把渲染决策固化成了库字段 → 改优先级要重跑全库
  • 🔴 卡片上不出现「主要记忆法」这类主次标注 —— 显示层只呈现内容，不呈现判断。判断会随渲染规则变化，而标签会让读者把它当成事实读。v3 已删掉 3 处（`主要记忆法` ×2 + `主要` ×1）；v4 把「①记忆法／②次记忆法」改为「①记忆法一／②记忆法二」
  • 🔴 顺序由渲染层现算：按 priority 1→6 找第一个「可以」的填槽位①，继续找填②。当前实现：实测 `image` 组 99.5% 满足 collocation、`context` 组 97.9% —— 本该先命中 3，判定却没按顺序
  • 「可以」= 素材存在 且过质量门槛（`collocation` 是「固定搭配强」而非「有搭配」；`cognate` 是「与英语词成词群」且族规模 ≥3）。当前口径：`collocation` 有任意搭配 = 99.3% → 会盖过词源；`cognate` 若不加 ≥3 门槛则有 5,127 词，其中 2,139 个只有 1–2 词族 → 入口点进去只有自己
  • 卡片只有四段：① 记忆法一 ② 记忆法二 ③ 释义 ④ 语境原句（①② 是顺序位，不是主次位）。当前实现：`sense`×4 + root，共 5 段
  • 记忆法（槽位①）排在最前，但字号不超过释义。权重靠强调色 + 凹陷底色 + 拆分结构建立，不靠字号 —— 记忆法是线索、释义是答案。v5 已把 `.mnem-main` 17.5px → 15.5px（原比释义 16px 还大）。当前实现：root 在位置 1–4 都出现过，从不保证第一
  • 字号层级：单词 32 > 释义 16.5 > 记忆法 15.5 > 语境 14.5 > 括号注释 13.5 > 英文释义 13 > 词源说明 12.5 > 段标签 11。🔑 内容层最大的字号应落在释义（要记的答案），不是记忆法（线索）
  • 卡片上没有同源族／词根族的成员列表 —— 那是聚合页的内容。我上一版把它做成 chip 铺在卡上，是错的
  • 槽位①② 都可点击展开聚合页，入口标出族规模（「词根族 22 词」）。当前实现：card 里没有任何聚合入口，1,777 页不可达
  • 🔴 ② 不重复 ① 已经说过的东西 —— 只在有增量（历史路径／语义演变）时显示。实测：可拆词里 ② 的义项与 ① 重复的占 78.3%（其中 65.0% 逐字重复）—— 如 disappear 的 ② 完全等于 ①
  • 🔴 聚合页每一条都带「分拆法 + 释义」，共享词根用强调色标出。当前实现：{"word":"affair","gloss":"事件；事情"} —— 只列单词 + 词典释义，没有分拆，等于 22 个不相干的词
  • 聚合页里不可拆的成员也要显示，注明「整体词，同属 X 族」。实测 vertere 族 33 词里 9 个不可拆（vertical／verse／vertex…），词根族抓不到
  • 释义只有一条；其余义项进 card_extra 可展开。当前实现：卡面最多铺 4 个义项
  • 槽位① 无内容时直接渲染 ③④ 两段，不留空段 —— 实测 116 词。已核查：这 116 词的 ③ 释义与 ④ 例句 100% 完整（见 `no-mnemonic-116-words-audit-2026-09-26.md`）；其中 41 条为词组／缩写／专名，天然不适用记忆法。当前实现：6,189 词（53.7%）的记忆法在卡里不存在
  • 例句的 section type 是 context（能被朗读清单命中）。当前实现：例句塞在 `sense` 里 → 240 MB 例句音频会全丢
  • 槽位①② 的段标题随实际填入的类型变（「词根词缀」/「固定搭配」/「词源故事」），不是固定标签。v1 §4.2 示例就是 [root, definition, context]。⚠️ 按 priority 顺序，不可拆词的槽位① 也可能落在 collocation(3)，不能默认写「词根词缀」
  • 槽位② 的显示名是「词源故事」，内部 code 可能是 cognate(2) 或 etymology(4) —— 同一段的两个名字，不是两件事。「同源串记」本身是聚合页，不铺在卡片上；卡片 ② 显示当前词的词源故事文本，点击才展开
  • 聚合入口的箭头只在族规模 ≥3 时显示，且①② 各自独立判断。门槛来自 v1 §8.5「成员数 ≥ N（如 3）」，数据层已实施（aggregate_page min=3 正好是 3）。⚠️ 反例：capture 的 capt 词根族只有 2 词 → ① 有内容但无入口；而它的 ② 词源故事有入口（capere 族 56 词）→ 不能默认「有拆解就有族页」，也不能「一个没有就以为都没有」
  • 不可拆词（vertical／laser）不摆空段，槽位①② 按 priority 顺序往后取（不可拆 → 无 cognate → 试 collocation(3) → 再试 etymology(4)）。实测「不可拆+有词源」占槽位① 的 51.4% —— 这是词源故事的主力场景。⚠️ 注意此处必须按顺序，不能直接跳到 4
  • 四段结构 = v1 §5.1 的「4 sections」上限，天然吻合；聚合入口内嵌在 ①②里，无需单列一段。顺带解决了上一轮的「191 张超限」问题
