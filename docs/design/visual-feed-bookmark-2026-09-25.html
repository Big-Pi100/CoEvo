卡片减法：去掉数字，加回一件事

你的三条改动让卡片回到最必要的形态。去掉「N 个生词」和「已读/未读」之后，卡片上只剩四个元素：分类·时长 / 标题 / 摘要 / 收藏。

有个意外收获：去掉数字反而让「痕迹」更突出 —— 之前卡片上有个「6 个生词」的数字，阅读界面里的痕迹反而像它的补充说明；现在数字没了，痕迹成了唯一的进度表达，也更符合我们已经定下的视觉签名。

02
去掉数字之后，卡片的表达力反而更强
这是你这三条改动里我最没预料到的收获。
数字会和「痕迹」抢角色。之前卡片上有「6 个生词」，阅读界面里有痕迹 —— 两者都在表达「这篇有多难 / 我掌握了多少」，用户需要判断该信哪个。

去掉数字之后，痕迹成了唯一的进度表达：你在文章里看到的淡色词，就是你和这篇文章的关系。一个概念，一个表达 —— 这比两个数字更清晰，也更符合我们定的视觉签名。

顺带：不用再建那套 CEFR 分级计数和用户级缓存了（cefr_band_counts / user_article_stats 两张字段设计作废），实现成本降一截。
原设计（已作废）

卡片上「N 个生词」

需要：分词 → 词形还原 → 词表比对 → 三档口径（按 CEFR / 按词表 / 按掌握度）→ 入库预计算 + 用户级缓存。

为的是让用户预判难度。但预判难度这件事，痕迹已经做了。

现在

只有痕迹 + 收藏

痕迹在阅读界面里自然呈现（无需额外计算 —— 它本来就要标）；收藏是一个布尔状态。

卡片更安静，实现更简单，概念更统一。

03
收藏的四个设计决定
都是为了让「重读」这件事变得容易。

① 入口在信息流标题栏，不新增 tab

收藏是信息流的一个视图，不是独立的一级入口。所以导航维持 3 tab 不变，信息流本身也还是一整条流 —— 只是标题栏右侧多了个「收藏 N」的入口（N 是收藏数）。

② 收藏清单复用同一套卡片

不做新的列表样式。同一套卡片组件，只是数据源筛选过。开发成本几乎为零，用户也不需要学新的界面。

③ 两处都能收藏

信息流卡片右上角（扫的时候收藏）+ 阅读界面顶部栏（读的时候收藏）。「读到一半觉得好」是最常见的收藏时机，不能要求用户退出再收藏。

④ ⚠️ 收藏 ≠ 已读标记

收藏是用户主动的意图（「我还要再读」），不是系统状态。所以不自动收藏、不预置、不根据阅读时长推断 —— 保持它的语义纯净。

关于「再读」的一个额外想法（供你判断）
既然收藏的目的是重读，那要不要给用户一个「该重读了」的提示？比如收藏超过 30 天且没再打开过的，在收藏清单里轻轻标一下。
我的建议是先不做。理由：「痕迹变淡」本身已经在邀请用户重读旧文（这是上一轮定下的机制）；再加一层系统催prompt会让收藏变成一个待办清单，压力就来了。收藏应该是没有压力的书签。
留到有真实用户数据后再看 —— 如果数据显示收藏夹在「只进不出」（收藏了但从不重读），那时再加提示才有依据。
04
数据层：极简
收藏是整个方案里最轻的功能。
端侧（user.db）
CREATE TABLE bookmark (
  content_id   INTEGER PRIMARY KEY,      -- 一篇文章只收藏一次
  bookmarked_at TEXT DEFAULT (datetime('now')),
  pending_push INTEGER DEFAULT 1
);
CREATE INDEX idx_bm_time ON bookmark (bookmarked_at DESC);
服务端（PostgreSQL）
CREATE TABLE bookmark (
  user_id       BIGINT REFERENCES app_user(id),
  content_id    BIGINT NOT NULL,
  bookmarked_at TIMESTAMPTZ DEFAULT now(),
  PRIMARY KEY (user_id, content_id)
);
设计要点：
① content_id 直接当主键 —— 收藏没有数量、顺序、分类的需求，不需要额外 id 和排序字段
② 时间戳 DESC 排序（最近收藏的在前），符合「我刚存了什么」的直觉
③ 跟着已有的同步机制走（pending_push + 增量 pull/push），不需要新接口
④ 取消收藏 = DELETE。因为收藏是可再生的用户意图，不是学习数据 —— 与「生词本不能硬删」不同
⑤ 收藏数不需要单独存，SELECT COUNT(*) 即可（单用户量级极小）
本轮改动汇总
  • 去掉「N 个生词」统计 → 连同 CEFR 分级计数、用户级缓存两张字段设计一并作废
  • 去掉「已读 / 未读」标签 → 位置腾给收藏
  • 新增 收藏：卡片右上角 + 阅读界面顶部栏两个入口；收藏清单复用同一套卡片；数据层一张表
  • 意外收获：去掉数字后，「痕迹」成为唯一的进度表达 —— 一个概念一个表达
  • 导航不变：仍是 3 tab，收藏是信息流的一个视图而非新入口
