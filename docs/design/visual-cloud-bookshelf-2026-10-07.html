CoEvo · 书架上云

换机以后，书还在

用户为订阅付费，买的就是「东西在云上、换机不丢」。所以书架的正文要真的上云 —— 换机登录后书架全在，点开就能读。

🔑 但这件事会造出一个现有书架没有的状态：一本书可能在本地、可能只在云端、可能正在传。 本稿要解决的就是把这三个状态表达清楚，而且不让用户觉得"我的书不在我手上"。

存什么

存原始文件，不是解析结果

直接存导入的 .epub / .txt —— 它本身就是压缩包，体积最小；换机后下载下来用端侧已有解析器重解析， 不需要服务端理解书籍结构。

怎么下

点开才下，不自动全下

书架有 20 本，换机时全自动下载 = 白耗流量和时间。⇒ 列表先显示书， 点开某本才下它（带进度）。

配额

订阅 2 GB

成本实测只占订阅收入 0.12%（sync-scope-extension §4.2）， 所以配额给得宽松；免费层不提供云端书架。

合规措辞

只说「存储空间」

🔴 私人云存储 ≠ 在线书库（分界是「是否向公众提供」）。UI 文案只能写 「云端存储」，不能写「这里有书可以看」。

〇核心：一本书有三种本地性

现有书架只有一种状态（书在本地）。上云之后必须区分三态，而且三态的表达要一眼分得开 —— 🔑 用图标形状区分（云 / 箭头），不靠颜色深浅（颜色只有朱砂一个强调色，压不住三态）。

✅ 本地有
默认态 · 不加任何标记
  • 点开：直接进阅读页
  • 视觉：什么都不加 —— 默认态不该有装饰
  • 云端：可能已备份、也可能没（不区分，见下）
☁️ 只有云端
换机后 / 删过本地
  • 点开：先下载（转圈 + 进度），完成即进阅读页
  • 视觉：书名下一枚 云图标 + 「云端」
  • 🔑 文案只说「云端」，不说「不在本地」（后者读作"你丢了它"）
⏳ 正在传
刚导入 / 刚点开
  • 上传中：导入后后台跑，不阻塞导入完成
  • 下载中：点开后跑
  • 视觉：卡片底部一条 3px 进度（不占额外高度）

3规格

🔴 2026-10-07 实现时的两处修正（本稿原写的内容已按实测更新）：

① 「存哪」由 COS 改为 本地盘 —— 原稿的否决理由是「VPS 只有 40 GB 且外网流量贵」， 但实测：df -h 显示 31 GB 可用（40G 用 6.8G，现有数据 106 MB） ⇒ 按 1 MB/本可存 3 万本，磁盘根本不是瓶颈。
带宽才是真实约束，也已实测：下行 652 KB/s · 上行 1291 KB/s ⇒ 单本 1 MB 下载 ≈ 1.5 s（完全可用）；换机全量 50 MB ≈ 77 s（一次性动作 + 进度条，可接受）。
⇒ 选本地盘的理由变成：零配置（不需要开通云服务 + 密钥 + 签名 + CORS，当天即可端到端跑通） + 现零用户、无带宽竞争。代价是大文件慢，留给「用户量上来后」再切。
✅ 已抽象成 BlobStore trait ⇒ 切 COS 只需新增一个 impl，端点与配额逻辑一行不改。

② ext 不进表 —— 文件格式是端侧知识（它有 book 表）， 下载时以 ?ext=epub 传参即可。存进表会多一个「需要保持一致的字段」， 而它并不承载跨设备信息。
项决定
存什么原始文件（.epub / .txt）—— 不存解析后的章节。 epub 本身是 zip ⇒ 体积最小；换机后复用端侧解析器（epub_parser.dart）
存哪本地盘（data/book_blobs/{user_id}/{content_hash}.{ext}， 见上方修正 ①）。生产路径 /opt/coevo/data/book_blobs/。 🔑 抽象为 book_storage::BlobStore ⇒ 换 COS 只换 impl
对象键{user_id}/{content_hash}.{ext} —— 用 content_hash（已有 v2 指纹）⇒ 同书重复导入天然幂等。 ⚠️ content_hash 必须校验为十六进制（路径安全，见修正 ②与实现说明）
去重🔴 不跨用户去重（按 user_id 隔离）。 跨用户去重会泄露「有别人也上传了这本书」⇒ 隐私问题
上传时机导入完成后后台上传 —— 不阻塞导入、不阻塞阅读
下载时机点开「云端」书时按需下载；不自动全下
配额订阅 2 GB · 免费层不提供云端书架（403，与现有同步一致）。 🔑 用量 = SUM(blob_size) WHERE deleted=0 ⇒ 删了书空间立即可用 （即使云端文件因删除失败而残留，也不会占用用户的配额）
凭证无需凭证（本地盘形态）。切 COS 时后端签发预签名 URL，密钥不落客户端
删除删书 ⇒ 同时删云端文件（blob_size 归零，配额退还）。 ⚠️ 删除端点不依赖扩展名（扫目录匹配 {hash}.*）—— 否则端侧传错格式就删不掉，配额被永久占用
书单同步元数据（书名/作者/指纹/章节数）走现有 sync 通道（sync_book 表）； 文件走独立端点（大、二进制）
🔴 鉴权分级上传＝登录 + 订阅（消耗配额）；
下载 / 删除＝只需登录 —— 订阅到期后用户必须仍能取回和删除自己已存的书。 📌 判据：「付费买的是存储，不是访问权」—— 限制入口可以，限制出口不行
🔴 措辞约束（写进本稿，因为 UI 就是文案的落点）：
✅ 可以说：「云端存储 · 换机不丢」「已备份到云端」「从云端取回」
❌ 不能说：「云端书库」「这里可以找到书」「分享给朋友」「看看别人在读什么」
📌 分界线是「是否向公众提供」（见 sync-scope-extension §4.3）—— UI 文案一旦往"内容提供者"那边靠，法律性质就变了。

4边界与取舍

项决定 / 取舍
本地有 + 已备份不显示任何标记。若显示"已备份"勾，几乎每本书都有 ⇒ 噪声
本地有但未备份也不显示（免费用户全部如此；订阅用户的会很快自动补上）。 ⚠️ 只有空间不足导致失败时才显式标出（§2 第三屏）
删本地 vs 删云端「删书」= 两边都删（并集同步下软删 + 删云端对象）。 ⚠️ 若以后要"只删本地腾空间"，那是一个新动作，不叫"删书"
下载失败明确提示 + 可重试（不静默 —— 本项目的主敌）
流量一次换机下载全部约 20–60 MB（20–50 本）⇒ 可提示"仅 Wi-Fi 下载"作为后续选项

✅ 实现状态（2026-10-07 · 后端已落地）

落点内容
🆕 book_storage.rs 对象存储抽象（trait BlobStore）+ 本地盘实现 + 配额判定。 🔴 三层路径穿越防御（字符白名单 / 前缀校验 / 拒绝元字符）—— content_hash 只允许十六进制 ⇒ 拼不出 .. 与分隔符
🆕 book_blob_handler.rs 三个端点 + 记账 + DefaultBodyLimit 放大到 33 MB。 🔑 上传分块读 + 边读边限（不用 field.bytes() —— 那会把整个 body 读进内存）； 下载用 try_unfold 手写流（项目没有 tokio-util，拉不动 ReaderStream）
🆕 sync_book 表（schema.rs） 书单元数据 + 🔴 blob_size（服务端权威字段）。 它的关键约束：blob_size 绝不出现在 push 的 DO UPDATE SET 里 —— 否则一台离线旧设备推一次书单就能把「云端有」标回「没有」， 而文件明明还在（用户以为备份丢了）
同步端点（sync_handlers.rs） books 加入 push / pull（照 bookmarks 模式）； 新增 authorize_login_only（token 解析仍只有一处实现）
路由（routes.rs） .merge(blob_routes(...)) —— 用 merge 而非 route， 因为这几个端点带自己的 state
✅ 本机验证（cargo test -p api_server --offline）： 8 项存储层断言全过 —— 含 4 类路径穿越载荷（../../etc/passwd · ..%2f · /etc/passwd · NUL 字节）、配额边界（恰好填满允许 / 超 1 字节拒绝 / 饱和加法不溢出）、真文件系统往返、删除不依赖扩展名、用户隔离。
🔑 另有 5 项记账断言（用量排除已删书 · 记账推进 received_at · 已删书拒绝上传 · push 不改 blob_size · 路由表可构造）。

⏳ 还没做（如实标注）

  • 端侧全部：书单 push/pull 接线 · 上传队列 · 三态 UI · 配额显示 · 下载后接解析器
  • ⚠️ 孤儿文件清理：端侧删书是「推 deleted=1」+「调 DELETE 端点」两个动作， 后者失败会残留文件。配额已排除 deleted=1 ⇒ 用户不受影响， 但残留文件需要定期清理任务（未做）
  • ⚠️ 并发窗口：两个并发上传可能同时通过配额检查 ⇒ 轻微超额。 不是安全漏洞（只能超额自己的配额），且端侧上传是串行队列。 若将来改并发上传，此处要加锁
  • 📌 切 COS：只差一个 BlobStore impl（约 150 行），端点与配额一行不改
