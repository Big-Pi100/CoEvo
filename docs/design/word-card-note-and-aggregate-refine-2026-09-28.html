三句话结论
①「段内说明」= 库里已有的 word_mnemonic_profile.rationale —— 11,523 词 100% 有值，但🔴 不能全量显示：与卡上两段的中位重合率 64%， 近半数词会「同一句话说两遍」→ 建议按主槽位类型选择性显示（见 §1.4）。

一、「段内说明」是什么 —— 锚点里的两种用法

锚点 visual-word-card-target 里有一个类 .mnem-note， 它在两处被用到，但用法不同：

用例段内说明放什么有没有「主体」
disorganized ②词源故事 词源链：organon（希腊·工具／器官）→ 拉丁 organizare → 古法语 organiser → 英语 organize → disorganized 无 —— 它就是这一段的正文
（锚点用 inline 把 margin/padding/border 全置零，说明它没打算做「分隔」）
laser ①词源故事 说明：五个词的首字母拼成的缩写 → 激光器。整体造词，没有词根可拆 —— 词源就是最好的记忆法。 有 —— 上面是 .mnem-main（缩写展开），下面是 .mnem-note
（这时虚线才起作用：段内主次）

🔑 所以「段内说明」= 一个记忆法段里、主体之外的那一层补充： 它解释「为什么这词要这么记」，而不是再讲一遍词源。

1.2 🔴 但不能直接显示 —— 它会和卡上已有的段「说两遍」

root 的 rationale 写的就是「怎么拆」—— apostol(使徒)+ic(…的) → 使徒的， 而 ① 词根词缀段显示的正是这个拆分。

→ 🔑 「段内说明」在这 957 个词上不是「锦上添花」，而是补上一个缺口。

1.5 两个待定的细节

Q-note-1 · 贴在哪里？
① 贴主槽位对应的那段（context→贴 ④；image→贴 ①）—— 语义最准，但位置随词而变（用户不知道去哪看）
② 统一贴记忆法组末尾（①② 之后、组的最下方）—— 位置固定，但 context 类 的解释与上面两段记忆法离得有点远
样张里用的是 ①（alsop 贴 ④、cocky 贴 ①）。
Q-note-2 · 加不加标签？
样张里加了 记忆法 / 联想图像 的小字前缀。 锚点原文没有这个前缀（就是一句小字 + 虚线）。
· 加 → 明确「这行是什么」，但重复了段头标签的信息
· 不加 → 更像锚点、更轻

🔑 所有样张里的字段（音标 / 释义 / 例句 / 词源链 / 分拆法 / 段入口 / rationale） 都逐条取自真库，未做美化 —— 包括「该段有没有 entry」这类看不到但决定界面的细节 （上一稿就因为「没核实就写」把 pos 画错，这次逐项核对过）。

三、聚合页条目「点进词库」—— 通路已具备，形态要你定

3.1 现状：不可点，而且是「看起来能点但点不动」

aggregate_page_screen.dart 的注释写着：「成员不可点」—— 理由是「设计稿没定义点成员去哪」。
⚠️ 但实现用的是 Clay（凸起），而本项目已定： 粘土 = 可交互的物件，凸起却没有 onTap = 静默无效（禁忌）。
→ 你说的「不好看」与「应该能点」，其实是同一个问题的两半。

3.2 技术通路：已有，且是「干净」的（不会污染生词本）

需要的东西现状
按拼写/词 id 查一个词的完整卡片✅ WordQueryService.lookup() / cardById()
一个「看词条」的界面✅ LookupSheet.show()（查词浮层：音标 / 词性 / 释义 / 例句）
会不会顺手把词加进生词本？✅ 不会 —— lookup() 是纯查询； 写库（_writeBackLookup）是阅读器显式调用的。
从聚合页点开 = 只查不着痕迹。这是对的： 「我点开看看」不是「我在读文章时划了个词」。
会不会套娃（聚合页→词条→再进聚合页→…）？✅ 目前不会 —— 浮层里没有 ①② 入口

3.3 链路：这是 v1 设计过的双向关系的一半

v1 与既有实现里已有这一条：
复习卡 ①/② → 聚合页 →（返回）→ 复习卡　✅ 已实现
而 lookup_sheet.dart 的文档里还提到 v1 的另一条：
查词浮层 → 聚合页 → 回到浮层　⏳ 未实现（浮层里无 ①② 入口）

→ 你现在要的，是把反方向补上：聚合页 → 点成员 → 词条
🔑 补上以后，三条边就闭环了：卡片 ⇄ 聚合页 ⇄ 词条。
