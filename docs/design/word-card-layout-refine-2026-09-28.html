一、先说「乱」在哪 —— 三处，都能指到具体 CSS

对照 L1 锚点 visual-word-card-target-2026-09-26.html 的卡片 CSS， 发现实现里漏掉了三条「建立层级」的规则，只靠间距硬撑。 间距又都是逐个手写的魔数，没有体系 —— 两者叠加就是「糊在一起、又说不清哪不对」。

#设计稿规格（L1 锚点原文）当前实现后果
1 .w-head 有 text-align:center + padding-bottom:15px + border-bottom:1px solid var(--line) 左对齐、无分隔线 词头没成为「头」—— 和下面的段落黏在一起
2 .mnem 有 background:var(--sunken) + border-radius:16px + padding:14px + 两个 inset 纯文字，无底块 🔴 ① ② 是全卡唯一「有底色的段」（spec §5.2 明文）—— 少了它，记忆法与释义的类别差异消失，四段变成四条并排文字
3 段间 14 / 15 / 16；段内 8；标签下 4；紧凑 3 18 / 16 / 12 / 8 / 7 / 6 / 11（逐处手写） 段间 18 与段内 16 只差 2px → 层级读不出来（层级要靠倍数差，不是 2px）
4 .spk = 26×26 圆形、background:card、外阴影（凸起） 裸图标 18px 音标旁一个「飘着的」图标，没有可点的物理暗示
关键认识：设计稿建立层级靠的是「容器 + 分隔」，不是靠「排得松一点」。 .w-head 的下边线把「词头」独立出来；.mnem 的凹陷底块把「记忆法（线索）」 与「释义/语境（答案）」分成两类；.mnem-note 的虚线再把段内主次分开。
——这样即使字号只差 1px，用户也一眼看得出这是什么、那是什么。

为什么不是「字号没排对」

字号层级是对的（spec §5.2 那条铁律已经落地）：单词 32 > 释义 16.5 > 记忆法 15.5 > 语境 14.5 > 注释 13.5 > 标签 11 —— 实测代码与规格逐项一致（tokens 验收有断言）。 问题不在字号，在容器与间距。

对照能看到的三点变化

  • 词头成了「头」：居中 + 下边线 → 它是这张卡的主题，不再与内容混在一起
  • 两类内容分开了：①② 有凹陷底（线索），③④ 留白（答案）—— spec §5.2 说「① ② 独占 sunken —— 全卡唯一有底色的段」，正是这个作用
  • 节奏出来了：段间 14/15 明显大于段内 8 与标签下 4 → 眼睛能数出「这是三段」

三、要请你定的四处

Q1 · 词头要不要居中？
设计稿 CSS 是 text-align:center（当时按「卡片像词条」的思路）。
· 居中：更像词典词条，词头独立、仪式感强；但单词很长时（如 disorganized 之上还有更长的）居中会让左右参差
· 保持左对齐：与下面段落左边缘一条线到底，更「文档」；但词头就不会显得是「头」
我倾向居中（照锚点），除非你觉得长词会难看。
Q2 · ①② 的凹陷底块要不要？（这是变化最大的一处）
· 要：spec §5.2 明文规定，且「线索 vs 答案」的分类立刻可见
· 不要：整卡更「平」，像一篇文章 —— 但四段就真的只能靠字号/颜色区分了
我倾向要。若你觉得凹块「太重」，可以改成只有左侧色条（更轻，但锚点没这么写）。
Q3 · ③ 释义这一段的「词性」要不要显示？
数据里有 pos: [adj]，当前实现没渲染。
· 显示（如建议稿里释义后面的小字 adj）：多一条判别信息，中文释义歧义时有用
· 不显示：更干净
数据已有，只是没用。你定要不要。
Q4 · 语境原句的左边框颜色？
设计稿 .ctx 用 --accent-bright（■ #C4533A）， 实现里用的是 --line（■ #EFE9DE， 浅到几乎看不见）。
我倾向照锚点改成 accentBright —— 现在那条竖线基本看不到，等于白设。
