## 〇、三条基础规则

任何组件设计前先问这三句，答案就唯一了：

| # | 规则 | 含义 |
|---|---|---|
| 1 | **内容平面 / 交互粘土 / 输入凹陷** | 文字永不动；有体积的只可能是可点的东西 |
| 2 | **阅读界面零粘土** | 沉浸来自「什么都没有」，不是来自「很好看」 |
| 3 | **痕迹随熟练度淡去** | 视觉签名；学习的终点是痕迹的消失 |

这三条覆盖了 90% 的决策场景。剩下 10% 交给下面的 token 表。

## 一、视觉签名：痕迹

产品的独有行为链是 `读文章 → 划线查词 → 进复习队列 → 从陌生变成「我的」`。这条链在页面上留下痕迹，而痕迹会**随熟练度淡去**。

| 态 | 条件 | 视觉强度 |
|---|---|---|
| 刚查过 | `reps = 0` | 最明显 |
| 复习中 | `reps 1–2` | 中等 |
| 已掌握 | `reps ≥ 3 且 lapses = 0` | 几乎不可见（比周围文字暖一点点） |

**语法跟着主题走**（这是三档主题最重要的差异，不是配色）：

| 主题 | 痕迹语法 | 为什么它才是对的 |
|---|---|---|
| 墨 | 底色浸染 | 暖底 + 淡朱砂，最接近真实纸张的铅笔印 |
| 格 | 下划线 | 纯白底上底色浸染几乎看不见，线才是对的 |
| 夜 | 光（熟练度 = 亮度） | 深底上「加亮」比「加色」更自然 |

实现上**仍是同一段代码**，只是 token 不同。

### 1.1 痕迹完整 token（每态 5 个）

**别只给 `bg` 三个值就开工** —— 三态各自需要一组「背景 / 边框 / 前景 / 内边距 / 圆角」。少了 `-p` 和 `-r`，痕迹块的留白会随字号漂移。

| token | 墨 | 格 | 夜 |
|---|---|---|---|
| `--tk-n-bg` 刚查过底 | `rgba(180,67,44,.15)` | `transparent` | `transparent` |
| `--tk-n-bd` 边框 | `none` | `2.5px solid var(--accent-bright)` | `none` |
| `--tk-n-fg` 文字 | `inherit` | `inherit` | `#FFD9B8` |
| `--tk-n-p` 内边距 | `1px 3px` | `0 0 1px 0` | `1px 3px` |
| `--tk-n-r` 圆角 | `3px` | `0` | `3px` |
| `--tk-m-bg` 复习中 | `rgba(180,67,44,.075)` | `transparent` | `transparent` |
| `--tk-m-bd` | `none` | `1.5px solid rgba(0,192,139,.42)` | `none` |
| `--tk-m-fg` | `inherit` | `inherit` | `#DEDCD7` |
| `--tk-m-p` / `--tk-m-r` | `1px 3px` / `3px` | `0 0 1px 0` / `0` | `1px 3px` / `3px` |
| `--tk-d-bg` 已掌握 | `rgba(180,67,44,.026)` | `transparent` | `transparent` |
| `--tk-d-bd` | `none` | `1px dashed rgba(10,10,10,.16)` | `none` |
| `--tk-d-fg` | `inherit` | `inherit` | `#8E939F` |
| `--tk-d-p` / `--tk-d-r` | `1px 3px` / `3px` | `0 0 1px 0` / `0` | `1px 3px` / `3px` |

**读法**：墨用**背景透明度递减**（.15 → .075 → .026）；格用**线宽递减**（2.5px 实线 → 1.5px 半透明 → 1px 虚线）；夜用**亮度递减**（`#FFD9B8` → `#DEDCD7` → `#8E939F`）。

> 深色（夜）的两态用**不同灰阶**而不是不同亮度（`#FFD9B8` 暖 → `#8E939F` 冷）—— 单降亮度在深底上会读成「脏」。

> **界面上不放痕迹开关**（遵守「阅读界面保持单纯」）。开关在阅读设置面板内，默认开启。

## 二、主题系统：三档底色

三档对应**三种使用场景**，不是三种审美 —— 所以三档全做、用户可切换，不是三选一。

```dart
enum ReadingTheme { ink, grid, night }
// 「跟随系统」是开关，不是第四个主题：
//   浅色 → 用户选的浅色主题（ink 或 grid）
//   深色 → night
// 持久化只需 ReadingTheme + followSystem 两个字段
```

**默认：墨 + 跟随系统**（白天暖纸，日落自动切深墨）。日落自动切换建议顺带做，成本很低（`MediaQuery.platformBrightness` 已够用）。

#### 2.1.0 🔴 三档文字对比度（**含 `--ink3`**）—— 2026-09-26 补，修掉一处不达标

§八 一直声称「文字对比度**全部达标（含 `--ink3` 弱文字）**」，但**从未给出阈值、也从未实测过 `ink3`**。
补测后发现问题：

| 档 | `ink` ↔ `read`（≥4.5） | `ink2` ↔ `read`（≥4.5） | **`ink3` ↔ `read`**（≥3.0） |
|---|---:|---:|---:|
| 墨 | 15.12 ✅ | 5.34 ✅ | **2.94 ❌** ← 原 `#9A917F` |
| 格 | 19.80 ✅ | 6.90 ✅ | 3.45 ✅ |
| 夜 | 15.18 ✅ | 6.90 ✅ | 3.87 ✅ |

**修后复测（墨档 `ink3` = `#988F7C`）→ 3.02 ✅**

> ⚠️ 上表数值由 `scripts/tokens_verify/` 用 WCAG 公式实算（可复跑）。
> 🔑 **别凭估算写对比度** —— 本表初稿我按印象填了 13.83 / 7.54 / 3.36 等一串数字，
> **全部与实算不符**，而当时已经标了「（实测）」。**标「实测」就必须真的跑脚本。**

**阈值口径**：`ink`/`ink2` 按正文 **≥4.5:1**（WCAG AA）；`ink3` 是**辅助/弱文字**，按 **≥3.0:1**。

**修法（2026-09-26 白哥定）**：墨档 `--ink3` 由 `#9A917F` → **`#988F7C`**
—— **保持色相 40° 与饱和 11.8% 不变，只降 1% 明度**，对比度 **2.941 → 3.020** ✅。
改动量极小（ΔL = 1%），暖沙纸感不受影响。

⚠️ **「格」的页面底从 `#F2F2F2` 压深到 `#EDEEF0`** —— 因为它的卡面是纯白，若页面底也近白，粘土卡片就只能靠外阴影区分，层次太弱。

**两个强调色的分工（重要，别混用）**：

| token | 用途 | 为什么不能混 |
|---|---|---|
| `--accent` | **实心填充**（选中态按钮、书签已收藏、进度环） | 上面要压 `--accent-ink` 字 → 必须够深（浅底档 ≥4.5:1） |
| `--accent-bright` | **细线与描边**（痕迹下划线、聚焦边框、图标描边） | 它不作背景、不承载文字 → 只需 vs 底色 ≥3:1 |
| 🆕 `--accent-out` | **彩色元素的外阴影** | 见 §3.3 —— 粘土规则要求「外阴影染元素自身色相」，而 `--cl-out` 是主题级（中性色元素用），彩色元素须单独覆盖 |

> **✅ 已采纳方案甲（统一色相）修复**，见 §2.1.2 / §2.1.3。

**① 品牌一致性：三档强调色曾跨 154°，没有任何共享色相**（已修）

修复前实测三档强调色与品牌色（朱砂 10°）的色相差：

| 档 | 页面底色相 | 修复前强调色 | 色相 | 与品牌色相差 |
|----|----|----|----|----|
| **墨** | 42°（暖米） | `#B4432C` | **10°** | **0°** ← 就是品牌色 |
| **格** | 220°（冷灰） | ~~`#00A87A`~~ | ~~164°~~ | ~~154°~~（接近对比色） |
| **夜** | 223°（冷黑） | ~~`#FF8A45`~~ | ~~22°~~ | ~~12°~~ |

**→ 原状态：三档色相跨 10°→164°→22°（跨越色环 42%），品牌色只等于其中一档。**

**② 格档强调色两处对比度不达标**（已修）

| 检查项 | 修复前 | 要求 | 修复后 |
|---|---:|---|---:|
| 底 ↔ 强调色 | **2.63** ❌ | ≥3:1 | **4.79** ✅ |
| 强调色压字 | **3.05** ❌ | ≥4.5:1 | **5.56** ✅ |

**→ 格档原是三档中唯一双不达标的一档** —— 不是偏好问题，是可访问性缺陷。
**根因**：`#00A87A` 青绿明度 33%、饱和 100% —— 太亮压不住白字，又和纯白底区分不够。
**✅ 修复后**：换用与墨档共用的 `#B4432C`，两项均达标且余裕充足。

#### 2.1.2 方案甲（✅ 已采纳 2026-09-25）

**方案甲 · 统一色相**（三档共用朱砂色相，只变明度）

| 档 | `--accent` | 说明 | 底↔accent | accent↔ink |
|---|---|---:|---:|---:|
| 墨 | `#B4432C` | **不变**（零改造） | 4.76 ✅ | 5.56 ✅ |
| 格 | `#B4432C` | **与墨共用**（两者底色明度接近 92% / 94%） | 4.79 ✅ | 5.56 ✅ |
| 夜 | `#DB7E6B` | 深底版（亮朱砂） | 6.67 ✅ | 6.00 ✅ |

**采纳理由**：

| 收益 | 说明 |
|---|---|
| ✅ **品牌色 = 唯一主色相** | 三档都能看到品牌色，不再只是图标色 |
| ✅ **token 从 3 值降为 2 值** | 浅底版 + 深底版，维护成本降 1/3 |
| ✅ **顺带修掉格档双不达标** | 可访问性缺陷一并解决 |
| ⚠️ 代价 | 格档失去「冷色」性格（原青绿代表精密/科技感）—— 由底色冷灰 + 等宽音标承担 |

**曾被评估但未采纳的方案乙 · 保留三色相**
只修格档的青绿值（重新算至达标），但**品牌一致性问题不解决** —— 品牌色仍只等于墨档。

#### 2.1.3 ✅ 生效结论：品牌色 = 应用内主色相

**方案甲带来一个结构性变化**：

| | 修复前 | **修复后** |
|---|---|---|
| 品牌色的角色 | **仅对外触点**（图标/启动页/分享图）—— 应用内看不到 | **应用内主色相** + 对外触点 |
| 品牌色与主题色的关系 | 品牌色只等于「墨」档的主题色 | **品牌色 = 三档共用的色相**，只是明度不同 |
| 「品牌触点用固定色、应用内用主题色，两者可以不同」 | ⚠️ 成立但导致品牌渗透弱 | **该说法不再适用** —— 品牌色即主题色系 |

**→ 品牌色结论（并入方案甲后确认）**：**朱砂 `#B4432C`**

五层依据（前几轮逐层补全）：

| 层 | 约束 | 指向 |
|---|---|---|
| ① **材质匹配**（最硬） | 「墨」主题粘土阴影 `--cl-out` 是**暖褐 33°** → 强调色须同色域；朱砂 10°（差 23°）**同色系** | 朱砂 |
| ② 对比度 | 品牌色要承载文字 → 朱砂白字 **5.56 ✅**；青绿 3.1 ❌、暖橙 2.3 ❌ | 朱砂 |
| ③ 材质固有色 | 标准陶土色 8–11° / 63–66%；朱砂 **10° / 61%** 正落其中 | 朱砂 |
| ④ **三档一致性**（方案甲新增） | 朱砂与三档底色均达标，可作唯一主色相 | 朱砂 |
| ⑤ 品类惯例 | 学习类多蓝绿（⚠️ 但绑定「扁平材质」；claymorphism 规范反推荐暖粉彩） | 避开青绿 |

**关键事实：统一色相不会让三档变得「一样」** —— 三档的性格主要由以下承担，**全部保留**：

| 保留项 | 三档差异 |
|---|---|
| 底色色相 | 暖米 42° / 冷灰 220° / 深黑 223° |
| 底色明度 | 92% / 94% / **6%** |
| 文字三档 | `#24211C` / `#0A0A0A` / `#EDEBE6` |
| 行高 | 1.82 / 1.74 / 1.84 |
| 字体 | 格档独有**等宽音标** |
| 粘土参数 | 暖褐 / 冷灰 / 无彩 |

**→ 强调色从「性格变量」变为「品牌常量」，视觉区分度的损失有限。**


### 2.2 品牌身份靠什么（🔄 2026-09-25 已随方案甲重写）

**方案甲采纳后，品牌签名的构成变了** —— **配色重新成为品牌的一部分**：

| 随主题变 | 跨主题稳定（品牌在这） |
|---|---|
| 底色（暖米/冷灰/深黑）· 文字三档 · 痕迹语法 · 粘土参数 · 行高圆角 · 强调色**明度** | **品牌色相**（朱砂 10°，三档共用）· **字体组合**（Literata + Charis SIL + Inter）· **粘土质感** · **「痕迹」这个概念** · **内容平面/交互粘土/输入凹陷** |

> **🔑 关键变化**：强调色的**色相**从「随主题变」移到了「跨主题稳定」栏 ——
> 变的只是**明度**（浅底用 `#B4432C`、深底用 `#DB7E6B`）。
> **品牌色 = 应用内主色相**，不再是「只出现在图标里」。

#### 一次论证修正（值得记下）

**原论证**：「粘土是跨底色的质感语言 → 品牌签名从『一种配色』变成『一种材质 + 一套字体 + 一个行为概念』」

这个论证**本身没错**（粘土确实跨底色稳定），**但它跳过了「配色是否也该参与品牌」这个选择** ——
把它当成了「配色不必参与」的理由。

**白哥的质疑指出**：与其说配色可以不参与，不如说**多档主题的配色本来就该是同色相的不同呈现**。

**→ 修正后的结论**：品牌签名 = **色相 + 材质 + 字体 + 行为概念**，四者并列。
配色不参与品牌**不是必然，是选择** —— 而在这个项目里，选「参与」更好（品牌渗透 + 降低 token 复杂度）。

#### 品牌色结论：朱砂 `#B4432C` ✅

暖色在 App Store 缩略图尺寸下比冷色醒目；中文语境的「印记」联想正好呼应「痕迹」；
且**是三档共用的唯一色相**（墨/格 `#B4432C`、夜 `#DB7E6B`）。

> 🔄 **原说法「品牌触点用固定色、应用内用主题色 —— 两者可以不同」已不适用**。
> 方案甲下，**品牌色即主题色系** —— 三档共用同一色相，只是明度按底色适配。

## 三、粘土质感

### 3.1 与 Neumorphism 的关键区别

| | Neumorphism | Claymorphism |
|---|---|---|
| 阴影 | 2 个外阴影 | **2 个内阴影 + 1 个外阴影** |
| 填充色 | **必须等于背景色** | **任意色，与背景无关** |
| 对比度上限 | 低（设计性缺陷 → 这是它死掉的真正原因） | **高（填充色自己控制）** |

### 3.2 三层公式（顺序不能改）

```css
box-shadow:
  6px 8px 16px        var(--cl-out),      /* ① 外阴影 · 浮起 */
  inset -5px -5px 12px var(--cl-shade),   /* ② 内暗 · 体积 */
  inset 4px 4px 10px   var(--cl-light);   /* ③ 内亮 · 充气 */
```

三个决定成败的细节：

1. **外阴影要染元素自身的色相** —— 用中性灰/黑会让粘土「发脏」
2. **两个 inset 必须反向**，且与全站光方向一致（**统一左上光**）
3. **内亮要比内暗更亮、更透明** —— 完全对称的一对会读成塑料

**逐层作用**（`visual-clay-spec` 页可勾选开关实测）：少内亮 → 只是个带阴影的圆角方块；少内暗 → 变纸片。

### 3.3 三档主题的粘土 token

| token | 墨 | 格 | 夜 |
|---|---|---|---|
| `--cl-out` 外阴影（**中性色元素**） | `rgba(150,125,95,.24)` | `rgba(110,115,125,.22)` | `rgba(0,0,0,.55)` |
| `--cl-shade` 内暗 | `rgba(186,166,138,.55)` | `rgba(158,158,158,.46)` | `rgba(0,0,0,.42)` |
| `--cl-light` 内亮 | `rgba(255,255,255,1)` | `rgba(255,255,255,1)` | `rgba(255,255,255,.062)` |
| 🆕 `--accent-out` 外阴影（**彩色元素**） | `rgba(180,67,44,.40)` | `rgba(180,67,44,.40)` | `rgba(219,126,107,.40)` |
| `--cl-radius` 圆角 | `26px` | **`14px`** ⚠️ | `24px` |
| 粘土强度 | 完整 | 中等（参数降 md 档） | 完整但内亮受限 |

> **粘土参数是主题 token 的一部分，不是全局常量** —— 这正是「三档主题 × 粘土」不冲突的原因：它们本来就是同一张表里的不同字段。

#### 3.3.1 🆕 `--accent-out`：补一个缺失的 token（2026-09-25 发现）

**§3.2 已有一条规则**：「**外阴影要染元素自身的色相** —— 用中性灰/黑会让粘土『发脏』」

**但 token 表原本只有主题级 `--cl-out`（墨 暖褐 / 格 冷灰 / 夜 无彩）** ——
它是**中性色元素**（卡片、白底按钮）的外阴影。

**→ 规则与 token 不匹配**：强调色元素（朱砂按钮、选中态）无法「染自身色相」——
若强行用主题级 `--cl-out`，在「格」档会出现 **冷灰阴影配暖朱砂填充**（色相冲突 155°），正是规则要避免的「发脏」。

**修法**：新增 `--accent-out`，值取强调色的染色版本（同色相、透明度 .40）：

| 档 | `--accent` | `--accent-out` |
|---|---|---|
| 墨 / 格 | `#B4432C` | `rgba(180,67,44,.40)` |
| 夜 | `#DB7E6B` | `rgba(219,126,107,.40)` |

**用法**：彩色元素（`background: var(--accent)`）的外阴影用 `var(--accent-out)`；
中性色元素继续用 `var(--cl-out)`。**内阴影两者共用（`--cl-shade` / `--cl-light`）。**

#### 3.3.2 🆕 `clayFill`：粘土元素的填充色（2026-09-26 补齐定义）

**§7.2 示例与 §7.3 token 结构一直在用 `clayFill`，但 §2.1 / §3.3 的表从未给它值** ——
属规格缺口（实现时只能自己猜）。现补齐：

| 档 | `clayFill` | 来源 |
|---|---|---|
| 墨 | `#FFFFFF` | = `--card` |
| 格 | `#FFFFFF` | = `--card` |
| 夜 | `#1C1F27` | = `--card` |

**🔑 结论：`clayFill` = 卡面色（`--card`），不另设值。**

| 为什么不另设 | 说明 |
|---|---|
| §3.1 已定 | claymorphism 的填充色「**任意色，与背景无关**」（这是它与 Neumorphism 的关键区别）→ 用卡面色完全成立 |
| §7.2 示例语义 | 粘土元素的例子就是「卡片、白底按钮」—— 它们本来就该是卡面色 |
| 少一个 token | 二者同值却分设字段，会制造「改了 `card` 忘了改 `clayFill`」的漂移风险 |

⚠️ **例外（将来若需要）**：若某档出现「粘土元素需要**比卡面更亮**以强化浮起感」的需求，
再把它拆成独立值 —— 但**现在不需要**，`--card` 的三档值已经满足层次（墨/格纯白、夜 `#1C1F27`）。

> **代码落点**：`CoEvoTokens.clayFill` 定义为 `=> card`（**getter 而非字段** ——
> 这样它**不可能**与 `card` 不一致）。

> **方案甲的额外收益**：统一色相后，`--accent-out` 也只需 **2 个值**（墨/格共用），
> 且墨档的 `rgba(180,67,44,.40)` 与主题级 `rgba(150,125,95,.24)` 同色系（暖色），**天然协调**。
### 3.4 ⚠️ 必须处理的冲突：圆角承载不了内阴影

校验三档参数时发现的问题，**这是「格 + 粘土」的真实代价**：

「格」的原设计圆角是 **8px**（Swiss 网格、硬朗、工具感），但粘土的内阴影是 `inset -5px -5px 12px` ——
影响范围从边缘算起约 **17px**，远超 8px 圆角能承载的尺度。

**几何关系是硬约束**（经验规则）：`圆角半径 ≥ inset 偏移 × 3`

| 圆角 R | 可用的 inset 上限 | 粘土强度 |
|---:|---|---|
| 8px | 偏移 ≤2px、模糊 ≤6px | 弱（几乎平） |
| 12px | 偏移 ≤3px、模糊 ≤8px | 中弱 |
| **14px** | **偏移 3px、模糊 8px** | **中（「格」采用）** |
| 20px | 偏移 4px、模糊 10px | 中强 |
| 24–26px | 偏移 5px、模糊 12px | 强（「墨」「夜」采用） |

圆角不够时，内阴影会绕过圆角形成**「月牙状」伪影**，边缘看起来发脏 —— 比不做粘土更难看。

**「格」的三个选项**（`visual-clay-spec` §03 有并排实测）：

| 选项 | 做法 | 评价 |
|---|---|---|
| A | 保持 8px + 参数压到极弱 | ❌ 几何不成立，边缘发脏 |
| **B** | **圆角 8px → 14px + 参数降 md 档** | ✅ **推荐** —— 仍是三档里最「精确」的（更小圆角、更紧阴影、独有的等宽音标） |
| C | 圆角提到 24px + 完整参数 | 🟠 可接受，但与「墨」的差别缩小 |

> **B 已写入 token 表（`--cl-radius: 14px`），如无异议按此执行。**

### 3.5 尺寸阶梯（最容易实现时漏掉的一环）

26px 圆角 + 8px 阴影偏移放在 180px 卡片上成立，放在 26px 高的药丸上会糊成一团。**阴影参数必须随元素尺寸缩放**：

| 档 | 高度 | 外阴影 | 内暗 | 内亮 | 圆角 |
|---|---|---|---|---|---|
| **sm** | 24–40px | `2px 3px 5px` | `inset -2px -2px 5px` | `inset 2px 2px 4px` | `--cl-radius × 50%` ⚠️ |
| **md** | 40–72px | `4px 5px 10px` | `inset -3px -3px 8px` | `inset 3px 3px 7px` | `--cl-radius × 55%` ⚠️ |
| **lg** | 100px+ | `6px 8px 16px` | `inset -5px -5px 12px` | `inset 4px 4px 10px` | `--cl-radius` |

#### 3.5.1 🔴 「格」档的圆角**不参与缩放**（2026-09-26 白哥定）

**上表的圆角系数与「格」档相乘会撞上 §3.4 的几何硬约束**：

| | §3.4 定义 | §3.5 系数 | 相乘结果 | 约束（圆角 ≥ 偏移 × 3） |
|---|---|---|---|---|
| 墨 | `--cl-radius: 26px` | ×0.55 | **14.3px** | ≥ 9 ✅ |
| 夜 | `--cl-radius: 24px` | ×0.55 | **13.2px** | ≥ 9 ✅ |
| **格** | **`--cl-radius: 14px`** | ×0.55 | 🔴 **7.7px** | ≥ 9 ❌ **不成立** |

🔑 **根因**：`0.50 / 0.55` 这两个系数**显然是为「墨 26 / 夜 24」整定的** ——
`26×0.55≈14.3`、`24×0.55≈13.2`，**都落在 14px 附近**。
而「**格」的 14px 本身就是那个目标值**（§3.4 的 B 方案就是「把 8px 提到 14px」），
**再去乘系数等于重复缩放了一次。**

**→ 修正规则（已采纳）**：

> **三档主题的 `radiusFactor` 只对「基准圆角明显大于目标值」的档有意义。**
> **「格」档基准圆角 = 14px = 目标值 → 系数全取 `1.0`（不缩放）。**

| 档 | `radiusFactor`（sm / md / lg） |
|---|---|
| 墨 | 0.50 / 0.55 / 1.0 |
| **格** | **1.0 / 1.0 / 1.0** ⚠️ |
| 夜 | 0.50 / 0.55 / 1.0 |

**代码落点**：`ClayTokens.scaleRadius`（「格」档为 `false`）——
比在数据里写三个 `1.0` 更能表达「这是语义上的例外，不是数值巧合」。

> ⚠️ 上表 `⚠️` 标记即指此条；**阴影参数（外阴影/内暗/内亮）三档仍按尺寸阶梯缩放，只有圆角例外。**

**两个硬规则**：
- 高度 **< 24px** 的元素：**完全去掉 inset**，只留外阴影（没空间表现高光）
- 圆角随尺寸缩小，不要所有元素都用同一个半径

### 3.6 凹陷（输入类）：两个 inset 方向互换

**最容易写错的一处。** 凸起时左上受光亮、右下受光暗；凹陷时正好相反：

```css
/* 凸起 */
inset -3px -3px 8px var(--cl-shade),   /* 右下内暗 */
inset  3px  3px 7px var(--cl-light);   /* 左上内亮 */

/* 凹陷（搜索框、可输入字段）*/
inset  3px  3px 8px var(--cl-shade),   /* 左上变暗 */
inset -3px -3px 6px var(--cl-light);   /* 右下受光 */
```

### 3.7 四态

粘土的物理直觉让状态表达非常直接 —— **不需要换颜色或加边框**：

| 态 | 做法 | 视觉读法 |
|---|---|---|
| 默认 | 三层齐全 | 浮起 |
| **按下** | 换成凹陷公式 + `scale(.97)` | 它真的被压下去了 |
| **选中** | 保持凸起 + 强调色填充 + **外阴影用 `var(--accent-out)`** | 选中＝激活，不是按下 |
| **禁用** | **抽掉内亮**，外阴影减半 + `opacity .5` | 它瘪了 |

### 3.8 动效（粘土感的一半）

| 动效 | 参数 |
|---|---|
| 按下 | `scale(.97)`，90ms `ease-out` |
| 松手回弹 | `Curves.elasticOut`，320ms |
| 主题切换 | 280ms `cubic-bezier(.4,0,.2,1)`（背景/文字/阴影/圆角同过渡） |

**这是 Flutter 的原生强项，几乎零成本。缺了动效，粘土只是个圆角卡片。**

### 3.9 深色模式的取舍（如实说明）

| | 浅色 | 深色 |
|---|---|---|
| 内高光 | `rgba(255,255,255,1)` | **必须压到 `.05–.07`**（采用 `.062`） |
| 结果 | 膨胀感完整 | **体积感减弱约一半** |
| 原因 | 亮部高光是粘土的核心机制 | 白高光在深底上变成「发光」而非「膨胀」 |

**不是不能做，是做不到浅色那么好。** 这是 claymorphism 的公认弱点，不是实现问题。

### 3.10 🎨 配色规则：强调色必须与粘土的阴影色域同源（2026-09-25 新增）

> **本节产出的原因**：白哥提出「品牌色需要和粘土风格匹配」——
> 此前选色只算了**对比度**与**品类惯例**，**漏了材质匹配这一层**。补上后发现它是**更硬的技术约束**。

**为什么材质匹配比品类惯例更硬**：粘土是**全站基础质感**（每个界面都有），强调色是**最高频出现的颜色**。
两者色相若冲突 → **每个界面都在冷暖打架**，无法靠别处弥补。
而「用户预期学习类=蓝绿」属于**归类信号**，可由 App 名 / 副标题 / 图标形态 / 商店分类弥补。

#### 3.10.1 技术约束：阴影色相决定了强调色的可选范围

第 3.2 节已有一条规则：**「外阴影要染元素自身的色相，用中性灰/黑会让粘土发脏」**。
反过来读，它同时约束了强调色 —— 因为强调色元素的阴影要染它自己的色相：

| 主题 | `--cl-out`（中性色元素用） | `--cl-shade` | 色相 |
|---|---|---|---|
| **墨** | `rgba(150,125,95,.24)` | `rgba(186,166,138,.55)` | 🟠 **暖褐 ~33° / 暖米 ~40°** |
| **格** | `rgba(110,115,125,.22)` | `rgba(158,158,158,.46)` | 🔵 冷灰 ~215° / 中性灰 |
| **夜** | `rgba(0,0,0,.55)` | `rgba(0,0,0,.42)` | ⚫ 无彩 |

**推论**：
- 强调色色相落在**该主题阴影的色域**内 → 阴影体系天然一致，**零适配**
- 强调色为**对比色相**（相差 150°+）→ 需专门处理

> 🔄 **2026-09-25 更新：第二条推论的解法已明确 —— 不是「重算一套主题阴影」，而是新增 `--accent-out`。**
> 见 §3.3.1：**彩色元素用 `var(--accent-out)`（染强调色相），中性色元素用 `var(--cl-out)`（主题级）**。
> 这样两个变量各自独立，**主题阴影不受强调色色相影响** —— 原先「必须重算一套」的代价被消除了。
>
> **这正是采纳方案甲（统一色相）后的额外收益**：`--accent-out` 只需 2 个值（墨/格共用 + 夜），
> 且朱砂色相与「墨」主题的暖褐阴影天然同源，零适配。

**实测各候选与「墨」主题阴影（暖褐 33°）的色相差**：

| 候选 | 色相 | 与暖褐差 | 判定 |
|---|---|---|---|
| **朱砂 `#B4432C`** | **10°** | **23°** | 🟢 **同色系** |
| 暖橙 `#FF8A45` | 22° | 11° | 🟢 同色系 |
| 青绿 `#00A87A` | 164° | **131°** | 🟠 需另配冷阴影 |
| 黛蓝 `#4A6B8A` | 210° | **177°** | 🔴 **近对比色**，冲突最大 |
| 墨黑 `#2C2C2A` | 无彩 | — | 🟡 服从阴影，自身不贡献色相 |

#### 3.10.2 明度约束：与「承载白字」的冲突，以及双色阶解法

**外部 claymorphism 规范**（多来源一致）指出：
> 「Drop shadows become ineffective on **darker variations**, so foregrounds and backgrounds stay in the **lighter pastel range**」——
> 即**明度不能过低**，否则阴影失效。

**但品牌色/强调色要承载白字**（按钮文字、图标白色标记）→ **需要够深**（WCAG AA ≥ 4.5:1）。

**这两条要求直接冲突。** 项目现有的**双 token 结构恰好处理了它**：

| token | 角色 | 明度要求 | 项目现值（墨） |
|---|---|---|---|
| `--accent` | **实心填充**（选中态按钮、已收藏、进度环） | **够深**（压白字） | `#B4432C` 朱砂 ✅ 白字 5.6:1 |
| `--accent-bright` | **细线与描边**（痕迹下划线、聚焦框、图标描边） | **可更亮** | `#C4533A` |

> **所以品牌色应取「深的那一阶」（`--accent`）** —— 因为品牌触点（图标 / 启动页 / 分享图）需要承载文字与白色标记。

#### 3.10.3 一个打破「品类惯例」顾虑的发现

多方 claymorphism 规范**推荐的强调色恰恰是暖色**：

| 来源 | 推荐主色 |
|---|---|
| daisyUI claymorphism 主题 | 「use the brightest **peach**, lilac, or sky clay hue for `primary`」—— **桃色排第一** |
| Superdesign claymorphism 配方 | 主强调色 `#4f46e5` 蓝紫 + **次强调色暖珊瑚 `#f97066`** |
| 通用 claymorphism 色板 | 珊瑚 / 暖琥珀 / 软粉 / **暖陶** 均为标配 |

且 daisyUI 明确指出 claymorphism **「Best suited to Education, onboarding, creative tools」**。

> **🔑 结论：「学习类 = 蓝绿」是「扁平材质世界」的惯例。**
> 多邻国的荧光绿 `#58CC02` 属扁平语系 —— 它**太亮、太轻**，放进粘土会压不住体积感。
> **换材质则惯例随之改变**：粘土 + 教育 的惯例是**暖粉彩 / 陶色**。

#### 3.10.4 附带结论：陶土色就是「粘土」这个材质的固有色

**材质的物理原型色往往就是最匹配的颜色** —— 比在色环上挑更可靠。

实测标准陶土色（terracotta）的色值（**统一用 HSL 口径**，非 HSV）：

| 名称 | 色值 | H | S | L |
|---|---|---|---|---|
| Terra Cotta | `#B35642` | 11° | 46% | 48% |
| Terra Cotta (CMYK) | `#B84F3E` | 8° | 50% | 48% |
| Pantone 16-1526 TCX | `#D38377` | 8° | 51% | 65% |
| **朱砂（项目现值）** | **`#B4432C`** | **10°** | **61%** | **44%** |

> ⚠️ **口径提醒**：网上查到的 terracotta 常给出 HSV 饱和度（如 `#B84F3E` 的 HSV S=66%），
> 与 HSL 饱和度（50%）**不是同一个量**。本表统一用 **HSL**（`colorsys.rgb_to_hls`），
> 全案比色时请保持同一口径，否则会出现「同一色值两组饱和」的假性不一致。

**朱砂落在陶土色域**（色相 10° 在 8–11° 区间内；饱和 61% 略高于参照值，明度 44% 更低 = 更沉的陶土）。
→ 选它 = **品牌色与材质同源**，而非「在色环上随便挑一个红」。

#### 3.10.5 暖色域内的三个合规方案（2026-09-25 实测）

> ✅ **结论已定**：方案甲（§2.1.2）采纳后，**品牌色取方案 A · 朱砂 `#B4432C`**（明度 44%）——
> 原因是它同时满足「三档共用」与「余裕充足」（白字 5.56，非贴边值）。
> 方案 B / C 保留在此作为**备选记录**（若将来要把品牌色调亮，C 是唯一可行路径）。

**🔴 先纠正一处错误**：曾提出「桃陶 `#C4643F`（明度 51%）」「暖琥珀 `#B8763A`」两档作为备选 ——
**实测白字对比度 4.01 / 3.69，均不达标**。
原因：误以为「对比度只看明度」。**实测发现色相也影响** —— 黄橙段（29°）天生更亮，同样明度下对比度反而更低。

**白字方案的明度上限（色相 10° 实测）**：

| 明度 | 色值 | 白字比 | 判定 |
|---:|---|---:|---|
| 44% | `#B5432C` | 5.52 | ✅ |
| 48% | `#C54930` | **4.81** | ✅ **上限** |
| 50% | `#CD4C32` | 4.49 | ❌ |

**→ 想更亮，必须改用深色字**（这正是 claymorphism 规范说「bright pastels + **dark readable text**」的原因）。

**三个达标方案**（均在陶土色域 8–11°，均配亮阶用于描边）：

| 方案 | 主色 | 亮阶 | 压字色 | 对比度 | 气质 |
|---|---|---|---|---|---|
| **A · 朱砂**（现行） | `#B4432C` | `#CF644E` | 白字 | **5.56** ✅ | 最沉 · 陶印 |
| **B · 陶土 CMYK** | `#B84F3E` | `#C9776A` | 白字 | **4.97** ✅ | 标准 terracotta |
| **C · Pantone 陶土** | `#D38377` | `#E0A79C` | 深棕 `#3A1F16` | **5.25** ✅ | 最柔 · 最近粘土规范 |

**三者的真实差异**：

| 维度 | A | B | C |
|---|---|---|---|
| 明度 | 44%（最深） | 48% | **65%（最亮）** |
| 饱和 | **61%**（最艳） | 50% | 51% |

### 4.1 三层组合

| 用途 | 字体 | 授权 | 体积（子集后） |
|---|---|---|---|
| 英文阅读正文 | **Literata** | SIL OFL 1.1 | 400+700 = 126.6 KB |
| **IPA 音标** | **Charis SIL** | SIL OFL 1.1 | 400+700 = 109.0 KB |

| 界面/数字 | Inter | SIL OFL 1.1 | 随 Flutter 或子集 |

**英文双字体合计 235.6 KB。**

#### 4.1.1 🔴 接入方式（2026-09-26 修正为 A′ · **不能用「整段 fallback 链」**）

**❌ 原写法（已作废）**：

```dart
// ⛔ 错：把 fallback 链挂在整段样式上 → 逐字符回退 → 音标「一条音标两种字体」
TextStyle(fontFamily: 'Literata', fontFamilyFallback: ['CharisSIL'])
```

**✅ A′ 写法（两层）**：

```dart
// ① 正文 / 例句 / 释义等「以拉丁字母为主」的文字
//    fallback 只为兜住「词源说明里偶尔内嵌的音标」（实测仅 2.0% 的卡）
TextStyle(fontFamily: CoFonts.latinSerif, fontFamilyFallback: [CoFonts.ipaSerif])

// ② 🔴 IPA 音标 —— 独立元素，**直接指定 IPA 字体，不挂 fallback 链**
//    理由：Literata 缺 18 个 IPA 码位 → 若走 fallback 会让同一条音标混杂两种字体
TextStyle(fontFamily: CoFonts.ipaSerif)
```

**为什么必须这样（实测依据）**：

| | 做法 | 结果 |
|---|---|---|
| ❌ | fallback 链挂**整段样式** → 逐字符回退 | 🔴 **10,823 / 11,523 = 93.9%** 的音标「一条音标两种字体」 |
| ✅ | 音标**元素级显式指定** | ✅ 整条一致（残留 2.0% 在词源正文内嵌的音标，无法避免） |

`absurd` `/əbˈsɜːd/` → 原写法下 `ɜː` 来自 Charis、其余来自 Literata：
同一条音标内**笔画粗细 / x-height / 黑色浓度跳变**。

**可行性依据**：IPA 集中出现的位置 —— **`card.content.ipa` 字段 11,477 张卡**（独立元素 ✅）、
`etymology.text` 227 / `definition.en` 4 / `context.text` 1（正文内嵌，共 2.0%）。

> 📄 完整实测与对照：`font-candidates-assessment-2026-09-26.md` §四之二 ·
> 可视化 `font-candidates-2026-09-26.html`（「机制对比」节）

#### 4.1.2 🔑 字体选择已在 2026-09-26 复核（结论：**不变**）

候选实测（**133 码位逐字符**，含从 11,523 张卡真实提取的 **30 个 IPA 字符**）：

| 字体 | IPA 覆盖 | 静态字重 | 结论 |
|---|---|---|---|
| **Literata** | **12/30**（缺 18） | ⚠️ 仅可变 | ✅ 仍作正文 —— 缺的正是 Charis 所长 |
| **Charis SIL** | ✅ **30/30** | ✅ 有 | ✅ 仍作 IPA |
| Andika / Gentium / Noto Serif | ✅ 30/30 | 前两者有 | 备选（未采用） |

**可达性**：`cdn.jsdelivr.net/gh/google/fonts@main/<path>`（唯一可用通道）·
取源与子集脚本见 `scripts/fetch_fonts.py` / `scripts/build_fonts.py`。

### 4.2 🔴 Literata 不能显示 IPA（已实测）

fontTools 解 cmap：Literata 完整字体的 IPA Extensions 覆盖只有 **3/96**，缺 `ɪ ʊ ʃ ʒ ː ʌ ɔ ɜ ɒ ɛ ɹ`。

对照我们的数据：`ɪ` 出现 **9,892 次**、`ː` 4,340 次 → **11,585 / 12,839 张卡（90.2%）** 的音标会回退到系统字体。

> ⚠️ 上表是**清洗前口径**（12,839 张卡）。2026-09-26 按清洗后库（11,523 张）复核：
> 缺 18 个 IPA 码位、**93.9% 的卡会出现逐字符回退** → 见 §4.1.1。

> **方法论教训**：`latin-ext` 的 `unicode-range` 声明是 `U+0100-02BA`，**表面上包含整个 IPA 区间**，但文件里实际只有 3 个 IPA 字形。**unicode-range 是粗粒度声明，不代表字形存在 —— 必须解 cmap 才能确认。**

### 4.3 ⚠️ @fontsource 分包同样骗人（本轮新发现）

修复原型页时发现：**Charis SIL 的 @fontsource 分包（latin / latin-ext）只有 22/32 覆盖**，缺的正是最关键的：

| 缺的字符 | 后果 |
|---|---|
| `ˈ` U+02C8 重音符 | **每个音标都有** —— `/ˈvɜːtɪkl/` |
| `ː` U+02D0 长音符 | 极常用 |
| `θ` U+03B8 | `think`、`thought` 必备 |
| `ˌ` `ʰ` `ʳ` `ˑ` `͡` 等 | 部分词条 |

**但根因与 Literata 完全不同，必须分清**：

| | Literata | Charis SIL |
|---|---|---|
| 完整字体 | **3/96** | **32/32** ✅ |
| @fontsource 分包 | 0–3/96 | 22/32 |
| 根因 | **字体设计上就没有 IPA** | **分发方式问题（子集太窄）** |
| 解法 | 换字体 / 用 fallback 链 | **自建子集**（字体本身没问题） |

**对实现的影响**：Flutter 侧不能直接用 `@fontsource` 的现成文件，**必须自建子集** ——
字符集 = ASCII 可打印 95 + 常用标点 8 + IPA 32 = **131 个码位**，实测每款字体子集后仅 **18–38 KB**。

**对设计文档的影响**：6 个原型页的 IPA 之前**全部在静默回退**，视觉验收无效。
已修复 —— 生成 5 款本地子集（`docs/design/fonts/`，共 148.9 KB，全部 32/32 覆盖），
并用 `@font-face` 的 `src` fallback 链加了 CDN 兜底（防 `file://` 下的 CORS 限制）。

### 4.4 中文字体：保留全量，不做子集化

`app/assets/fonts/` 3 权重共 **24.2 MB**。实测子集化能把 24.2 MB 压到约 4.9 MB（GB2312 6763 字 + UI 文案），**但不做**：

阿里普惠体 3.0 官方法律声明的禁止事项第 ① 条含「**转换**、**拆分**」——
子集化正落在里面。**为一份免费给你的字体省 19 MB，不值得把使用推到条款解释的灰区。**

> 已顺带清理：6 个未被打包的权重（Thin/Light/SemiBold/ExtraBold/Heavy/Black），
> 仓库存量 61.1 MB → 24.2 MB，全部在 git 跟踪中可恢复。

### 5.2 复习卡片的字号层级（2026-09-26 新增）

**为什么现在才补**：设计系统此前**没有定义卡片的字号层级** ——
结果实现时**凭空选了 `mnem-main: 17.5px`，比释义 16px 还大**。
白哥 2026-09-26 指出「① 词根词缀其实在字体上也不用那么大」→ 补本节固化。

**🔑 设计原则：线索不压过答案**
卡片上**内容层最大的字号必须落在「释义」**（要记住的答案），
**不是「记忆法」**（帮助记住的线索）。
记忆法的视觉权重靠三样东西建立，**与字号无关**：

| 手段 | 说明 |
|---|---|
| **强调色** | 词素用 `--accent`（朱砂），中文注释用 `--ink3` |
| **凹陷底色** | ① ② 独占 `--sunken` 凹陷块 —— **全卡唯一有底色的段** |
| **拆分结构** | `dis-（不）+ organ（器官）+ -ized（使…化）` 而不是一整句 |
| （+）**唯一可点击** | 只有 ① ② 有 `›` 箭头，交互暗示「这里能展开」 |

**层级表（378px 逻辑宽，即 iPhone 1x）**：

| 元素 | 字号 | 字体 | 说明 |
|---|---:|---|---|
| 单词 `w-word` | **32** | Literata | — |
| **释义 `def-txt`** | **16.5** | Inter 500 | 🔑 **内容层最大 —— 答案** |
| **记忆法主体 `mnem-main`** | **15.5** | Literata | 🔑 **≤ 释义** |
| 语境 `ctx-txt` | 14.5 | Literata | — |
| 记忆法括号注释 `gl` | 13.5 | Literata | 与主体比 **0.87** |
| 英文释义 `def-en` | 13 | Literata | — |
| 词源说明 `mnem-note` | 12.5 | Inter | — |
| IPA `w-ipa` | 15 | Charis SIL | — |
| 段标签 `lab` / `mnem-tag` | 11 | Inter | 字距 `.05em` |

**派生规则（移动端按比例缩）**：
- 划词浮层 / 紧凑卡：**整体 ×0.9**（单词 25 · 释义 15 · 记忆法 14）
  → **记忆法（14）仍 < 释义（15）**，关系不能反转
- 词源故事这类**整句**用 `14.5px / line-height 1.75`（句子长，行高要松）

**⚠️ 两个易犯的错**：
1. **把解释性段落做成大字号** —— 长句放大字只增加阅读负担，不增加权重
2. **用字号当权重** —— 权重该由**色彩 + 底色 + 结构**承担；字号只承担**层级**

## 七、Flutter 实现映射

### 7.1 🔴 原生缺口

Flutter 的 `BoxShadow` **不支持 `inset`**，而粘土的核心恰恰是两个 inset。

实测现成方案：`flutter_inset_box_shadow` 最新版发布于 **2022-04，已 4 年未更新**，
且要求 `hide BoxDecoration, BoxShadow` 替换整个类型（侵入性高）。**不建议引入。**

### 7.2 渐进式落地，零第三方依赖

**第一步：零依赖方案（约 80% 效果）**

```dart
BoxDecoration(
  color: t.clayFill,
  borderRadius: BorderRadius.circular(r),
  // ① 外阴影（原生支持）
  boxShadow: [BoxShadow(offset: const Offset(6, 8), blurRadius: 16, color: t.clOut)],
)
// ②③ 内阴影用前景渐变模拟：左上亮 → 右下暗
foregroundDecoration: BoxDecoration(
  borderRadius: BorderRadius.circular(r),
  gradient: LinearGradient(
    begin: Alignment.topLeft, end: Alignment.bottomRight,
    colors: [t.clLight, t.clLight.withOpacity(0), t.clShade.withOpacity(0), t.clShade],
    stops: const [0, .42, .58, 1],
  ),
)
```

> 局限：linear gradient 在圆角处会出现色带感（圆角几何不是线性的）—— 所以说「约 80%」。

**第二步：若视觉不够，写 `ClayDecoration` CustomPainter（约 150–200 行）**
做法与 Chromium 相同 —— 画一个巨大矩形，用圆角矩形 `Path.combine` 挖空，
再对结果 `MaskFilter.blur`，最后平移向边缘方向。可 100% 还原 inset。

### 7.3 token 结构

```dart
/// per-theme：随主题变
class CoEvoTokens {
  final CoRgba read, accent, clayFill;
  final CoRgba clOut, clShade, clLight;   // 粘土三参数（每主题一组）
  final double clayRadius, readLineHeight;
  final TraceTokens trace;                // 浸染 / 下划线 / 光
}

/// 🔑 全局：**不随主题变**（§2.2「字体组合」属「跨主题稳定」栏）
/// → 所以它是**独立常量类**，不进 CoEvoTokens
abstract final class CoFonts {
  static const String latinSerif = 'Literata';   // 英文阅读正文
  static const String ipaSerif   = 'CharisSIL';   // 🔴 IPA 音标 —— 元素级指定，见 §4.1.1
  static const String cjk        = 'AlibabaPuHuiTi';
  static const List<String> latinFallback = [ipaSerif];
}

ThemeData buildTheme(CoEvoTokens t) => ThemeData(...);
// 不要写 3 个手写的 ThemeData
```

> ✅ **已实现（2026-09-27）**：`app/lib/theme/theme_builder.dart` —— `buildTheme` 是**全库唯一**
> 产出 `ThemeData` 的地方（接线验收会拦住第二个），且文件内**零硬编码颜色**（全部经 `_c(token)`）。
> 旧 4 套手写主题（`app_theme.dart` 436 行）已删除；间距常量迁到独立文件 `co_spacing.dart`（`CoSpacing.*`）。
> 复盘见 `plan-and-progress-2026-09-26.md` §3.15。

> 🔴 **`ipaSerif` 只能用在「音标元素」上，不得当作 `latinFallback` 之外的通配回退** ——
> 见 §4.1.1：整段挂 fallback 链会让 93.9% 的音标「一条音标两种字体」。

### 7.4 工程量

**约 1 周**（ClayDecoration 组件 + token 扩展 + 三主题接入），放在 Step 2 设计系统阶段。
