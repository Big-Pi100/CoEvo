设计说明 · 什么变、什么不变、为什么

项现状改后为什么
外壳 Material AppBar（19px/w500 + 阴影） 自绘顶栏：23px / w600 / letterSpacing −0.345px / t.ink，padding LTRB(18,2,18,14) 与信息流 / 复习页 逐字一致 —— 这是「风格不符」最直观的一处
容器 半透明 Container（radius 16） 粘土凸起 Clay（圆角随档位 26 / 14 / 24） 其余页面已统一用 Clay；半透明容器在「格」档几乎看不见边界
分区 卡片直堆，无分组 分组 + 分组标题（账号 / 内容偏好 / 订阅 / 其他） 照复习页语汇；把「偶尔看」与「经常点」分开
间距 各处手写值混用 CoSpacing：页边 16 · 组间 16 · 组内 13/15 · 底部 tabBarClearance=100 现役页全走这套 token
底部 最后一项易被 tab bar 压住 滚动容器 padding-bottom:100 _ShellScaffold 开了 extendBody:true
顶栏副标题 无 「白哥 · 免费版」12px t.ink3 与收藏页副标题同规格；顺带让订阅状态在首屏可见
不变的部分：三条 tab、配色（朱砂 #B4432C）、三档主题语义、成就/统计的数据来源 （端侧 user.db）、订阅与支付的既有流程 —— 这一版只动「怎么排」，不动「有什么」。

待你决策的 3 件

这 3 件不是设计偏好问题，而是「依赖尚未就绪」—— 我需要你的判断才能定方案范围。

事项冲突点两个选项
朗读设置
依赖未就绪		 §6.3 定「移到阅读界面内」（查词浮层长按发音按钮 + 阅读设置面板）。 但 reader_screen.dart:59 注释明说「面板本身（字号/行高/主题/痕迹开关/语速） 是独立一批，不在骨架内」→ 面板还没做。 甲：先留在「我的」页（现状位置），等阅读面板做好再搬 —— 本次只清理不搬家
乙：本次一并做阅读面板（范围变大，含划词浮层改动）
主题风格
依赖未就绪		 同上（§6.3 把「阅读主题」也划进阅读面板）。⚠️ 但产品的三档 是全局主题（影响所有页面）， 不只是阅读底色 —— 搬进阅读面板后，用户不读书时想改主题就找不到入口。 甲：留在「我的」（它是全局设置，放这里语义更对）
乙：按 §6.3 搬进阅读面板（两处入口也可）
成就区 / 统计区
口径待统一		 §4.2 说「连续天数 / 里程碑 并入「我的」页顶部」+「统计不设独立页」； 但 §6.1 写的是「顶部：统计区 + 分享入口」，而代码里放的是 AchievementSection 组件（含成就列表）。两者不是一回事。 甲：顶部只放统计 + 分享（连续天数/掌握词数），成就列表留在 /achievements
乙：按现组件保留成就列表在顶部（页面更长）
另外发现（不是设计问题，是 bug）：个人页有 4 处 context.push 指向 未注册的路由 —— /skipped · /earnings · /team · /withdraw， 会落到路由表的 /:unknown。这是「点了没反应 / 跳到奇怪页面」的直接原因。 其中 /skipped（旧产品功能）与 3 个分销路由随本次清理一并消失， 所以修这个 bug 不需要额外工作。
判断建议：先切到夜档看一遍 —— 粘土在深底上的「内亮」会被压到 .062， 三档里最容易显脏。/ 再看「改后」的分组标题是否够/太多（现在是 4 组）。
落地成本：只动 profile_screen.dart 一个文件（实测 1,120 行 → 预计 500 行左右）， 删 5 个旧版分区 + 换外壳与容器写法；新增「兴趣筛选」「关于」两项需要新做（各约 1 个页面/组件）。 不改任何 provider、后端接口、路由注册。
