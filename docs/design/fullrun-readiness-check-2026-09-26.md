## 四、⚠️ 设计缺口（2 项，需白哥定）

### 4.1 🔴 词缀表的「先有鸡还是先有蛋」

**白哥的方案**：「分解后的词缀**优先在词缀表中选择释义**，如果没有也不强行匹配，允许增加」

**→ 但 `affix` 表现在是空的，而它的数据只能从 LLM 跑出来。**

**问题推演**：

```
第 1 个词遇到 "-ed / 过去式"     → 表空 → 新增一行
第 2 个词遇到 "-ed / 过去分词"   → sense 不同 → 不命中 → 又新增
第 3 个词遇到 "-ed / 过去式/过去分词" → 又不同 → 又新增
...
→ 🔴 词缀表膨胀成「每词一行」，失去共享意义
```

**实测风险规模**：抽样 210 条中，`-ed` 出现 **19 次、8 种表述** —— 若直接落库会新增 **8 行**（正是要避免的）。

**✅ 解法（3 选项）**：

| 选项 | 做法 | 成本 | 评价 |
|---|---|---|---|
| **A**（推荐） | **落库前先做一次词缀归一化** —— 用 LLM 对「所有出现过的词缀表述」做同义聚类，生成 canonical sense + `aliases` | **¥0.5–1**（只需几百条输入） | ✅ 一次投入，全库受益 |
| **B** | 人工先建 300 个常用词缀表 | 人工 1–2 天 | 准，但慢；且会漏掉实际出现的表述 |
| **C** | 不做归一化，接受膨胀 | ¥0 | 🔴 词缀表失去意义，等于没建 |

**⚠️ 这个必须全量前定** —— 因为它决定**落库脚本怎么写**。

### 4.2 🟠 `entry_type` 是否需要细分 `subtype`

| 现状 | 影响 |
|---|---|
| `proper` 一个值涵盖「地理实体 + 人名 + 名人」 | 🟠 白哥已定全部保留，**不细分也能上线** |
| 但人名/名人的 **`cefr_level` 标错 125 条**（`chen` 标 A1） | 细分后才能自动「排除人名做难度统计」 |

## 九、🔴 实施过程中**新发现**的漏洞（2026-09-26，写脚本时实测）

> 动手实施 §五 的补齐项时，又发现 3 个此前没看到的问题。**其中 1 个规模很大（15.4%）。**

### 9.1 🔴🔴 `word_form.json` 含 **5,692 条双重变形垃圾（15.4%）**

**实测**：
```
abandoneds     ← abandoned   rule=plural
abandoneded    ← abandoned   rule=past
abandoneding   ← abandoned   rule=ing
aberrationsed  ← aberrations rule=past
aberrationsing ← aberrations rule=ing
abidinging     ← abiding     rule=ing
```

**根因**：旧 `build_word_form.py` 对**已经是变形的词**（`abandoned`/`aberrations`/`abiding`）
**又展开了「复数/过去/ing」** → 生成 `abandoneds` / `abandoneded` / `abandoneding`。

**影响**：
| 影响面 | 说明 |
|---|---|
| 数据体积 | 多占 **15.4%** |
| 查词路由 | 命中不存在的词形（虽极罕见） |
| 链式计算 | 制造**假链断**（`crammeds` → `crammed`，而 `crammed` 不建卡） |

**✅ 已修**：链式计算加过滤 —— 判据「form 的 base 自己也有 base」→ 是「变形的变形」→ 丢弃。
**实测过滤掉 3,980 条**（抽样路径下）。

> ⚠️ **这是就绪检查时没发现的漏洞** —— 因为当时只「读代码」，没「跑数据」。
> **印证：只有真跑一遍才知道有没有坑。**

### 9.2 🔴 `anchor` 必须对**新词表**算，不是旧词表

**踩坑**：一开始对旧词表（11,917）算 anchor →
`carefully`（LLM 判 `is_own_entry=false`，**将不建卡**）会错误地**把自己当 anchor**。

**✅ 已修**：先用 `is_own_entry` 过滤出新词表，再算 anchor。
**修正后链断从 7 → 27 条**（多出的全是垃圾双重变形，**正确行为** —— 宁可暴露链断，不要路由到不存在的卡）。

### 9.3 🔴 `action`（映射去留）的判据必须是 LLM 的 `is_own_entry`，不是旧库 `in_vocab`

**踩坑**：一开始用旧库 `in_vocab=1` 做判据 → **误删了 10 条必需的路由**：

| 词 | LLM `is_own_entry` | 被误判 | 后果 |
|---|---|---|---|
| `carefully` | **false**（不建卡） | drop 🔴 | **划词 `carefully` 无卡可跳** |
| `appropriately` | **false** | drop 🔴 | 同上 |

**✅ 已修**：`drop` 仅在 **`is_own_entry=true` 且 `relation=derivation`** 时生效。
**修正后 drop 从 37 → 27 条**（剔除了误判的 10 条）。
