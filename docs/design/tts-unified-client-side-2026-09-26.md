| # | 决策 | 原文依据 |
|---|---|---|
| 1 | **词卡朗读也走 `flutter_tts`**（不再走腾讯云） | 「文章朗读和词卡都是」 |

### 1.1 🔴 我上一轮的建议错在哪

上一轮（`on-demand-generation-server-side-2026-09-26.md` §3.3）我建议 **「词卡走服务端腾讯云 TTS」**，理由是：
> 「既然生成已放服务端，顺便用同一音色生成音频 —— 这是唯一能真正统一音色的路。」

**两处错误**：

| # | 我的错误 | 实情 |
|---|---|---|
| ① | 把「音色统一」默默替换成了**跨用户/跨设备统一**，并以此否掉了 `flutter_tts` | 白哥的诉求自始就是**同一用户听到的声音前后一致**（不要「单词一个音、例句另一个音」）。**我用一个更强的、他没要求的约束去否掉他的方案** |
| ② | 3.2 节把「iOS 增强音色需手动下载」列为`flutter_tts` 的**否决理由**（「若不干预，用户听到的是质量最差的那档」） | 这是**一个可管理的 UX 问题，不是一个架构约束** —— 应对方式只需「默认挑最优可用音色 + 提供选择入口」，成本极低（见 §六） |

> 🔑 **通用教训：把用户的诉求「升级」成一个更强的约束，再拿新约束否掉用户的方案，是隐蔽的偷换。**
> 正确做法是**先回问「你要的统一，是跟谁统一？」** —— 一句话就能澄清，我却直接按更强的版本论证了。

## 三、🔴 为何「全量端侧」在本产品成立（不是妥协，是更优解）

上一轮我把「音色统一」当成不可让步的目标，于是推出「必须服务端生成音频」。
**换回白哥的口径（用户内一致）后，端侧方案反而是全面占优的**：

| 维度 | 服务端腾讯云（原建议） | **全量端侧 `flutter_tts`（现行）** |
|---|---|---|
| 音色一致性（用户内） | ✅ 一致 | ✅ **一致**（同一设备同一 `voice` 实例） |
| 音色一致性（跨设备） | ✅ 一致 | ⚠️ 不一致 —— **但这不是诉求** |
| 一次性成本 | ¥48.7 | **¥0** |
| 边际成本（新词） | ¥0.0034/卡 | **¥0** |
| App 体积 | +290 MB | **+0** |
| 离线可用 | 需先下载语音包 | ✅ **系统 TTS 本身离线**（`AVSpeechSynthesizer` 本地合成） |
| 首字延迟 | 需下载该卡音频 | ✅ **无下载、无 IO、即时** |
| 服务端依赖 | 需 `/api/tts/speak` + 腾讯云可用性 | ✅ **零依赖** |
| 隐私 | 文本出端（TTS 请求） | ✅ **不出端** |
| 音质 | 🟢 稳定（精品音色） | ⚠️ **取决于用户装了哪档音色**（见 §六） |
| 合规面 | 长文本出境 | ✅ 缩小 |

> 🔑 **结论：唯一让服务端方案胜出的维度是「跨设备统一」，而这个维度不是需求。**
> 去掉它之后，端侧在**成本、体积、延迟、离线、隐私、依赖**六个维度全面占优。

## 六、🔴 iOS 系统 TTS 的现实约束与应对（不是否决理由，是工程项）

### 6.1 约束（查证结论，仍然成立）

| 层级 | 体积 | 质量 | 获取方式 |
|---|---|---|---|
| **Compact**（默认） | 几十 KB | 🔴 「sounds like a robot」 | 内置 |
| Enhanced | 100–150 MB | 🟢 好 | 🔴 用户手动下载 |
| Premium / Siri 语音 | 300–700 MB | 🟢 最自然 | 🔴 用户手动下载 |

**三条硬约束**：① 默认只有 Compact（机器人音）② 增强语音需用户手动装，App 无法自动装 ③ 跨设备音色必然不同。

### 6.1.1 ✅ 实测澄清：「怎么识别音色档位」有官方字段，不用猜

上一轮我把「增强音色需手动下载」当成`flutter_tts` 的否决理由，却又说不清**怎么在代码里识别档位**。
实测 flutter_tts 源码后明确了（**这是可依赖的官方字段，不是启发式猜测**）：

| 事实 | 依据 |
|---|---|
| iOS 侧**返回 `quality` 字段**，取值 `"default"` / `"enhanced"` / `"premium"` | `flutter_tts-4.2.5/ios/Classes/SwiftFlutterTtsPlugin.swift:344`（`voiceDict["quality"] = voice.quality.stringValue`） |
| 🔴 **`getVoices()` 返回时不做质量排序**（按系统顺序） | 同文件 337–357 行 |
| 质量升级逻辑只在 `setVoice()` 内：按 `name`+`locale` 匹配后取最高质量 | 同文件 372–405 行（`iOS 16.0+` 支持 premium，否则 enhanced） |
| 音色对象另含 `name` / `locale` / `gender` / `identifier` | 同文件 342–348 行 |

> 🔑 **推论**：识别档位**不需要靠名字里有没有 "(Enhanced)"**（那只是常见显示名，不是契约）。
> 直接用 `quality` 字段排序即可 —— **「官方字段 > 名字启发式」**。
> ⚠️ Android / Web 无 `quality` 字段 → 代码中按 `default` 处理，**不降级**。

### 6.2 应对（按优先级，成本极低）

| # | 措施 | 说明 | 工作量 | 状态 |
|---|---|---|---|---|
| 1 | 🔴 **默认挑「最优可用音色」** | 按 iOS 官方 `quality` 字段取最高档（premium > enhanced > default） | 小 | ✅ **已实施**（见 §6.1.1） |
| 2 | **「我的」页提供音色选择 + 试听** | ⚠️ **原表述有误，已更正** —— 本地分支**本来就有**本地试听（选音色时自动读），但读**中文**、不跟语速、无显式按钮。**腾讯云分支的试听应保持服务端**（试听=验证选项，不能用别的引擎代读）→ 详见 §9.3 | 小 | 🟠 **待定夺** |
| 3 | 🟠 可选：检测到只有 Compact 时，提示「可在系统设置下载更好音色」 | 白哥说「手动下载就手动下载」→ **不做强引导**，仅作为**非阻塞提示** | 小 | 🟠 未做 |
| 4 | 🔴 **同一张卡内锁定同一个 `voice` 实例** | ⚠️ **原表述有误，已更正** —— 界面稿是**逐元素喇叭**（点哪个读哪个），不是整卡连读；要求变为「**voice 只在 `init()`/用户选择时 set 一次，逐次点击朗读不得重新 `setVoice`**」→ 详见 §9.3 | 小 | 🟠 未做 |

> 🔑 **判断标准**：诉求是「**同一用户前后一致**」→ 只要 ④ 做到，且 ① 保证用户听到的不是机器人音，就**完全达成诉求**。
> ③ 是加分项，不是必需项。

### 9.5 🔴 修复：`_pickBestVoice()` 兜底不再返回非目标语言音色（2026-09-26 白哥批准）

#### 缺陷

```dart
// 修复前（③ 兜底）
return voices.first;   // ⚠️ 取「系统全部音色」列表的第一个
```

`getVoices` 返回的是**系统安装的全部音色**（含 `zh-CN` / `ja-JP` / `fr-FR` / `de-DE` …）。
当 `lang` 在前两级都匹配不到时（例如用户指定了系统没装的英语变体），兜底会**返回列表首个** ——
而列表首个很可能是**设备语言对应的音色**（中文设备 → 中文音色）→ 出现「**用中文音色念英文**」。

#### 修复

```dart
// 修复后（③ 兜底）
return null;   // → 调用方走 `_tts.setLanguage(lang)`，由 iOS 选该语言默认音色
```

调用方（`_speakWithNative`）**本就能正确处理 `null`**（已有 `if (best != null) … else setLanguage(lang)`），
故本次只需改返回值 + 顺带简化调用处（原先「`_availableVoices.isNotEmpty`」外层判断与 `_pickBestVoice` 内部的空检查**重复**，且两个 `else` 分支**完全相同**）：

```dart
// 简化后（等价，去掉重复判断）
if (_selectedVoice != null) {
  await _tts.setVoice(...);
} else {
  final best = _pickBestVoice(lang);
  if (best != null) {
    await _tts.setVoice(...);
  } else {
    await _tts.setLanguage(lang);   // ← 交系统按语言选
  }
}
```

> 🔑 **`setLanguage` 比"猜一个音色"更可靠**：`setLanguage` 由 iOS 自己挑选该语言的默认音色，
> 而「从列表挑首个」是我们**替系统做决定**且**信息不足**（只有一个列表，不知道哪个是设备默认）。
> 🔑 **通用规则：拿不准时交给系统默认，比用启发式猜一个"看起来像"的更安全。**

#### 🟠 顺带指出一个**未改**的相关问题（供白哥决定）

设置页的**音色下拉列表列出了全部系统音色**（`profile_screen.dart:621` 直接用 `tts.availableVoices`）——
对英语学习 App 来说，列表里会混入中日韩法等大量无关音色，**选择成本高**。
- 建议：**按语言过滤**（只列 `en-*`），或至少**把英语音色排在最前**。
- ⚠️ **本次未改**：属 UI 改进而非缺陷修复，且超出本次批准范围。
