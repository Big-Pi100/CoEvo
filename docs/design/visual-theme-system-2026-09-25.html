03
那品牌身份靠什么？
这是「三档都能切」之后唯一需要认真回答的新问题。

随主题变 token 不同，代码相同

  • 底色 / 纸色 / 卡片色
  • 文字三档（主 / 次 / 弱）
  • 强调色（朱砂 / 青绿 / 暖橙）
  • 痕迹语法（浸染 / 下划线 / 光）
  • 粘土的三个阴影参数
  • 行高（1.82 / 1.74 / 1.84）与圆角

跨主题稳定 品牌身份在这里

  • 字体组合 —— Literata + Charis SIL + Inter，永不变
  • 粘土质感 —— 三种底色都成立，反而是最稳的签名
  • 「痕迹」这个概念 —— 「学过的词在变淡」这个行为不变
  • 内容平面 / 交互粘土 / 输入凹陷 的三分原则
  • 信息架构、交互方式、文案语气
  • 品牌色 —— 图标 / 启动页 / 分享图用固定色
一个反直觉的结论：粘土在这里帮了大忙。三套底色配三套强调色，本来会让品牌形象散掉。但粘土是跨底色的质感语言 —— 无论用户选哪个主题，界面的「手感」完全一致。所以品牌签名从「一种配色」变成了「一种材质 + 一套字体 + 一个行为概念」，这比单一配色更耐得住主题切换。
04
品牌基准
主题可以切，但对外形象需要一个固定锚点。
CCOEVO

建议：品牌色 = 朱砂 #B4432C，默认主题 = 墨 + 跟随系统

为什么是朱砂：它是默认主题「墨」的强调色，同时是暖色 —— 在 App Store 列表页的缩略图尺寸下，暖色图标比冷色更容易被注意到。而且朱砂在中文语境里有「印记」的联想，与「痕迹」这个概念天然呼应。

品牌触点用固定色（App 图标、启动页、官网、分享图、商店截图），应用内用主题色。两者可以不同 —— 就像 Slack 的图标固定，但可以切浅色 / 深色主题。

默认「墨 + 跟随系统」：白天打开是暖纸，日落后自动切深墨。用户不动设置也能得到合适的体验；想换的人随时能换。

05
技术实现：现有架构只差一步
项目里已经有主题切换的骨架（theme_provider.dart + 4 套 ThemeData），需要的是重新组织。
现状 → 目标
// 现状：一维，且混了「风格」和「明暗」两个概念
enum AppThemeMode { system, light, dark, duolingo }

// 目标：把「底色氛围」独立成主题族
enum ReadingTheme { ink, grid, night }   // 三档底色
// 「跟随系统」不再是主题之一，而是一个开关：
//   浅色 → 用户选的浅色主题（ink 或 grid）
//   深色 → night

// 主题由一组 token 生成，而不是四个手写的 ThemeData
class CoEvoTokens {
  final Color read;         // 阅读区底色
  final Color accent;       // 主题强调色
  final TraceStyle trace;    // 痕迹语法（浸染 / 下划线 / 光）
  final ClaySpec clay;       // 粘土三参数
  final double readLineHeight;
}

ThemeData buildTheme(CoEvoTokens t) => ThemeData(...);

// 持久化：ReadingTheme + followSystem 两个字段就够
额外工作量不大，但验证工作是真的。三套主题意味着三倍的视觉验证：文字对比度、痕迹三态在不同字号下的可读性、粘土深度、IPA 音标显示、深色下长时间阅读的舒适度。建议把「三主题验收」列为一个独立里程碑，而不是散在各功能里做。

还有一点值得做：跟随系统 + 日落自动切换。阅读类 App 的常见特性，成本很低（MediaQuery.platformBrightness 已够用），但体验提升明显。
这一版改了什么
  • 底色从「三选一」变成「主题族」 —— 三档都保留，用户自己选；默认「墨 + 跟随系统」
  • 痕迹语法跟随主题切换 —— 每档底色用最适合自己的语法，实现上仍是同一段代码（token 不同），切换有过渡动画
  • 框架维持两层 —— 底色氛围（三档主题）× 质感语言（平面 / 粘土），互相独立
  • 品牌身份重新定位 —— 从「一种配色」变成「材质 + 字体 + 行为概念」，因此不受主题切换影响
