## 四、重设计方案

### 结构（按 §6.1 定稿 + 现役视觉语言）

```
我的                            ← 自绘顶栏（23px/w600/−0.345），副标题「白哥 · 免费版」
├ 顶部统计卡（Clay 大卡）        ← **只放统计**：连续天数 + 掌握词数 + 「分享我的学习记录」
│                                 （成就列表**移出**，「查看全部成就 ›」跳 /achievements）
├ 账号                          ← 🆕 两态（见 §六）：未登录 / 已登录（昵称 + 绑定邮箱）
├ 内容偏好                       ← 🆕 兴趣筛选（§6.3 定「留在我的页」）
├ 订阅                          ← 订阅状态 / 管理订阅 · **恢复购买** / 历史订单
├ 其他                          ← 主题风格（留）· 朗读设置（留，等阅读面板）· 联系工作人员 · 🆕 关于
└ 退出账号                      ← 🆕 页尾独立项（带文字，危险色，二次确认）
```

> 🔑 **决策 1、2 的落地**：主题风格与朗读设置**仍在「其他」组内**（本次不搬家）。
> 它们现在还是**唯一**入口 —— 阅读面板没做之前搬走 = 用户没地方调（§七）。
> ⚠️ 原「账号」组只有「改昵称」一项 → 决策 4 后扩成**完整账号区块**（含登录态、绑定邮箱、退出）。

### 与现状的差异（逐项）

| 项 | 改动 | 依据 |
|---|---|---|
| 外壳 | `AppBar` → **自绘顶栏**（与信息流/复习页逐字一致） | 现役页统一写法 |
| 容器 | `Container` → **`Clay`** | 同上 |
| 分区 | 直堆 → **分组 + 分组标题** | 复习页语汇 |
| 间距 | 手写值 → **`CoSpacing`** token | 现役页统一 |
| 底部 | 补 `tabBarClearance = 100` | `_ShellScaffold` 开了 `extendBody:true` |
| 删 | 推广二维码 · 推广统计 · 真实姓名 · 手机号 · 跳过概念 · trial 弹窗 | §4.2 / `:456` / `:457` / `:386` / `:391` |
| 加 | 兴趣筛选 · 关于 · 恢复购买（显式一行） | §6.1 |
| 调 | 成就区 → 「统计区 + 分享入口」 | §4.2 / `:396` |

### 三档主题都成立

原型里三档（墨/格/夜）**用真实 token 值**（照 `coevo_tokens.dart` 实测），可实时切换验证。
⚠️ **夜档最容易出问题** —— 粘土「内亮」在深底被压到 `rgba(255,255,255,.062)`，
所以**务必切到夜档看一遍**再定。

## 六、🆕 新增需求：账号区块（登录 / 退出 + 绑定邮箱）

### 6.1 规格依据（09-25 已定，不是我发明的）

`docs/design/english-app-implementation-plan-v2-2026-09-25.md` **§10.1.1** 原文：

> **模式：匿名可用 → 需要同步或购买时引导注册。**
>
> | 平台 | 主登录 | 兜底 |
> |---|---|---|
> | **iOS（现在只有 iOS）** | **Sign in with Apple** | 邮箱 + 密码 |
>
> **不做手机号**：短信有真实成本（约 ¥0.04/条）+ 模板审核 + 运营商报备；英语学习**不是实名强制场景**。

### 6.2 实测现状（🔴 缺口比预期大 —— 用户说得对）

| 项 | 实测现状 | 结论 |
|---|---|---|
| 端侧**登录 UI** | **完全没有**（无 `/login` 路由、无 `LoginScreen` 文件） | 🔴 **缺** |
| 端侧登录方式 | `auth_client` 5 方法 = `register`/`login`/`verifyToken`/`trialStart`/`trialClaim` → **username + password** | 🟠 与规格不符（规格要 Apple 主登录） |
| **Apple 登录** | 🔴 **无**（全库无 `sign_in_with_apple` 依赖、0 命中） | 🔴 **缺** |
| **邮箱** | 🔴 **端侧无**；后端 `users` 表**无 `email` 列**；全后端 `email` **0 命中** | 🔴 **缺**（是**新增**，不是复用）—— 与 `implementation-plan` §10.1「email 全后端 0 命中」一致 |
| 匿名试用 | ✅ `home_screen` 启动时自动 `trialStart` 建 `trial_*` 账号 | ✅ 已有 |
| **退出登录** | 🟠 **有**，但只是 `AppBar` 里一个 logout **图标**（`profile_screen.dart:416`，无文字、无确认、无账号信息） | 🟠 **需重做** |
| 账号信息展示 | 有 `username` + **`real_name`（实名）** + `phone` | 🟠 实名本次删；缺邮箱 |

### 6.3 账号区块设计

**① 未登录（匿名试用）**
```
账号
 ┌───────────────────────────────
 │ 👤  未登录                    ›
 │     登录后可跨设备同步 · 找回订阅
 └───────────────────────────────
        ↓ 点击 → 登录页（新增页面）
```

**② 登录页（🆕 新页面）**
```
        ← 返回
      登录 / 注册
 ┌─────────────────────────┐
 │      用 Apple 继续        │   ← 主登录（sign_in_with_apple）
 └─────────────────────────┘
            ── 或 ──
   邮箱  ┌─────────────────┐
         └─────────────────┘
   密码  ┌─────────────────┐
         └─────────────────┘
           [ 登录 ]  [ 注册 ]
```

**③ 已登录**
```
账号
 ┌───────────────────────────────
 │ 👤  白哥                      ›   ← 点击改昵称
 │     已登录 · 试用账号          │
 ├───────────────────────────────
 │ ✉️  绑定邮箱                  ›   ← 未绑时；已绑则显示邮箱
 │     用于找回账号 · 跨设备同步
 └───────────────────────────────
```

**④ 退出账号（页尾独立项）**
```
 ┌───────────────────────────────
 │          退出账号              │   ← 二次确认；文字按钮，危险色
 └───────────────────────────────
```
🔑 从 `AppBar` **图标**移到页尾**带文字**的独立项 —— Apple 审核红线要求「账号**注销**通道」在隐私政策与 App 内可见，藏在图标里不合格。

> 🔴 **「退出账号」≠「注销账号」**：**退出** = 清本地凭证（本次做）；**注销** = **删服务端账号**（Apple 审核指南 5.1.1(v) 要求 App 内可发起删号）→ 需后端接口，见 §6.4。

### 6.5 ✅ 白哥定：**本次只做 UI 骨架**

> 「账号区块是否只做 UI」→ **是**（只做 UI）

**本次落地范围**（`profile_screen.dart` 内）：

| # | 内容 | 数据来源 |
|---|---|---|
| 1 | **未登录 / 已登录两态** | ✅ 已有（`authProvider.isAuthenticated`） |
| 2 | 已登录：昵称 + 「已登录 · 试用账号」副标题 | ✅ 已有（`isTrialAccount(username)`） |
| 3 | **「绑定邮箱」入口**（占位，点了提示「即将开放」） | 🆕 **纯 UI**，不接后端 |
| 4 | **「退出账号」页尾独立项**（带文字 + 二次确认） | ✅ 已有 capability（`authProvider.logout()`） |
| 5 | 🔔 **通知入口保留**（右上角） | ✅ 已有，见 §6.6 |

**不在本次范围**（拆成独立一批，见 §6.4）：

### 6.6 ✅ 白哥定：**通知入口保留**

> 「**右上角**的通知按钮保留，保留发给用户通知的接口」

**现状实测**：

| 层 | 现状 |
|---|---|
| 端侧入口 | `profile_screen.dart:406` 在 `AppBar.actions` —— **`Badge` + `IconButton(Icons.notifications_outlined)`** |
| 端侧页面 | `pages/user/distribution/notification_panel.dart`（`/notifications` 路由） |

✅ **结论：接口与页面都保留，只是「外壳」要换** —— 因为新版是**自绘顶栏**（没有 `AppBar` 了），
`Badge + IconButton` 无处可放。

```dart
HeaderChip(
  icon: Icons.notifications_none,
  label: '通知',
  count: unreadCount,          // 0 时传 null → 不显示计数

```
参数取自 `widgets/header_chip.dart` **实测值**：圆角 13 · `padding 7/12` · 图标 13 且 `gap 6`
· label 11.5/w600 · count 10.5/`opacity .7` · 前景 `accent` · 凹陷态底 `sunken`。
✅ 原型已按此复刻（渲染级校验：`.chip` **82.7px** · 无溢出 · 无折行）。

> 🔴 **一处语义残留待清**：`notification_panel.dart` 放在 `pages/user/distribution/`（**分销**目录）下，
> 而分销已定「不做」。它**正在被现役引用**（`app.dart:22` + `profile_screen.dart:30`）→
> **不能随手删**，但**建议搬到 `screens/`**（`pages/user/**` 是分销留下的目录结构）。

## 七、🆕 顶部统计加「阅读篇数」（白哥 2026-09-29）

### 7.1 ✅ 原型已改（三列）

顶部统计卡从两列 → **三列**（连续天数 / 掌握词数 / **阅读篇数**），三个数字**都左对齐、各占 1/3**。

🔑 **为什么要改 `text-align:right`**：两列时「掌握词数」靠右对得很齐；三列后
每列仅 **70.3px**，若仍靠右，「阅读篇数」会紧贴边界 → 改为全部左对齐（实测渲染级校验通过）。

| 项 | 值（实测） |
|---|---|
| `.hero .stats` 内容宽 | 235px |
| 每列宽 | **70.3px**（`(235 − 12×2) / 3`） |
| 三列数字是否同行 | ✅（6 个 `.n` 的 `top` 全等） |

### 7.3 ✅ 白哥定：口径 = **乙（读完的文章数）**

> 「乙　读完的文章数（滚到底 / 停留 ≥ 阈值）」

**「读完」判定**（落地规则 · 待实现）：

| 项 | 规则 | 理由 |
|---|---|---|
| **主判据** | **滚到底**（`extentAfter <= 阈值`，如 24px） | 客观、可测；「读完」的直觉定义 |
| **防误判** | 短文章一屏就到底 → 进场即算「读完」 | ⚠️ 需加**最小停留**（如 ≥ 3s）——否则「点开就退」也算 |
| **防漏判** | 停留够久但没滚（长文只读前半） | 不加兜底：**「读完」就该是读完**，不想给它注水 |
| **去重键** | `article_id` **去重**（读两次算 1 篇） | 与「掌握词数」语义一致（唯一计数） |

**⚠️ 实现前需先解决**（3 条，都在 `reader_screen.dart`）：

1. 🔴 **正文是 mock**（`data/mock_articles.dart`，**只有 3 篇**）→ 真实 feed 在 **Phase 3**。
   现在做，「篇数」上限就是 3 —— **功能可先落，但数字要等真 feed 才有意义**
2. 🔴 `reader_screen.dart` 现在是 `SingleChildScrollView`，**要加滚动监听**判断「到底」——
   属**新交互逻辑**（不是加个字段）
3. 🔴 `user.db` 要**新建表 + 走迁移**（现 `kUserDbVersion = 3` → 4）：
   ```sql
   CREATE TABLE IF NOT EXISTS article_read (
     article_id   INTEGER PRIMARY KEY,   -- 去重即主键（同 bookmark 的思路）
     first_read_at TEXT NOT NULL,        -- 首次读完（UTC ISO8601 带 Z · 本库硬约束 1）
     read_count    INTEGER NOT NULL DEFAULT 1  -- 读了几遍（保留，供将来「重读」用）

   ```
   ⚠️ 遵循本库既有约束：**UTC ISO8601 带 `Z`**（`datetime('now')` 不行）·
   **不写 `PRAGMA`**（见 `user_db_schema.sql` 文件头）· 是否加 `pending_push`（参与同步？）**待定**

**决策理由（白哥选乙而非甲/丙）**：
- 不是甲（打开过）→ 甲**易注水**（点进去看一眼就算），激励性弱

## 十、🔴 原型页的布局 Bug 与修法（白哥真机打开后发现）

**白哥反馈**：「预览页面就已经有很多错误了 —— 顶部统计卡的『掌握词数』已经在区域外了，底部的『退出账号』四个字是竖排」。

**均属实。** 我交付时 `check-prototype.js` **全绿**，但那是**源码级**校验 —— 它只看字符串，
看不见「语法完全正确的 CSS 造成的布局错」。三个 bug 的根因是**同一类**：

| # | 现象 | 根因（都是合法 CSS） | 实测证据 |
|---|---|---|---|
| ① | **掌握词数被挤出区域** | `.hero .row2` 里左侧 div **漏写 `flex:1`** → 按内容宽（圆点 220px）+ gap 26 = 246px，超过容器可用宽 → 右侧被挤出 | `.row2` **`scrollWidth 298 > clientWidth 235`，溢出 63px** |
| ② | **「退出账号」竖排** | `<span class="tx" style="flex:0">` —— `flex:0` = `flex:0 1 **0%**`（flex-basis 为 0）+ `.tx{min-width:0}` → **宽度坍缩** → 每字换行 | 该元素 **`w=0.0` h=80.0**（4 字 × 20px 逐字） |
| ③ | **「兴趣筛选」胶囊也竖排**（白哥未提，我自查发现） | 胶囊组写在 `.item .tx` **内部** → `.item .tx span{display:block}`（优先级 **0,2,1**）盖掉 `.pills{display:flex}`（**0,1,0**）→ 每个胶囊独占一行 | `.pills` 高 **138px**（5 个胶囊各一行） |

### 修法（都是「改结构/优先级」，不是加 hack）

| # | 修法 |
|---|---|
| ① | 新增 `.hero .stats{display:flex}` + `.stat{flex:1 1 0;min-width:0}`（**两个数字各占一半**）；圆点移出 ── 不再依赖某一列的宽度 |
| ② | 改用独立类 `.danger-tx`（**不再借 `.tx`** —— 它有 `flex:1`，本来就不适合装居中文本） |
| ③ | 把胶囊组**移出 `.tx`**，与 `.item` 平级（左缩进 `padding-left:45px` = item 15 + 图标 19 + 间距 11 对上） |

### 🔑 教训：源码级校验看不见布局错 → 补「渲染级校验」

我原以为「脚本全绿 + 我肉眼看过截图」就够了 —— **不够**。这次的三个 bug，脚本全绿、截图上我也没看出来
（手机框 `height:668px` + `overflow:hidden`，**超出部分被裁掉了，截图里根本看不到**）。

→ 已把方法固化成 skill `design-prototype-page` 的新工具 **`scripts/measure-render.html`**：
用 headless Chrome 量**真实几何**（`getBoundingClientRect` / `scrollWidth`），抓四类错：
① 横向溢出 ② 宽度坍缩（竖排）③ 样式作用域覆盖 ④ 并排元素不同行。

**双向受控实验**（用我**实际交付过的坏版本** `0194b75` 跑）：

| | ① 溢出 | ② 竖排 | ④ 同行 |
|---|---|---|---|
| 坏版本 `0194b75` | 🔴 `.row2` **+63px** | 🔴 「退出账号」**w=0 h=80** | 🔴 不同行 |
| 修好后 | ✅ 无 | ✅ 无 | ✅ 同行 |

另固化了三条判据：**「没检查」≠「通过」**（选择器 0 命中必须报 ⚠️）·
**判据要减掉 padding**（否则按钮被误报成折行）·
**已知有意的溢出要显式声明并附理由**（不为报告好看而放宽判据）。
