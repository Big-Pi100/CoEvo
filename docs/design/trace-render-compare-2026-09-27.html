痕迹渲染对照：三档 × 两态 × 三字号

🔴 2026-09-27 更新：白哥定「已掌握就应该不标识」—— 本页已从「三态」改为「两态 + 已掌握不标识」。

这条修正了 spec 的一处内部矛盾：原则写「学习的终点是痕迹的消失」， 值表却写「已掌握 = 几乎不可见（比周围文字暖一点点）」—— 一个说消失、一个说还留一点点。 现在按原则统一：已掌握的字回到普通文字，与「从没查过」在视觉上完全一致。

往下第 ① 节看两态是否分得清，第 ③ 节回答「墨档的圆角值不值得上自绘」。

① 三档 × 两态 × 三字号（spec §八 的验收项）
spec 原文：「痕迹两态在 15px / 18px / 24px 三档字号下都可辨」。
每行两个痕迹词：刚查过（reps=0）· 复习中（reps 1–2）。 其余词都是「已掌握或从没查过」—— 它们应该与普通文字毫无差别。

请重点看三件事：
  • 两态在 15px 下还分得清吗？（这是最小字号，也是最先失守的一档）
  • 夜档两态分得清吗？ —— ⚠️ 实测两态亮度几乎相同（.743 vs .716）， 区分完全靠「暖度」（暖奶油 vs 中性灰）。这是三档里最可能出问题的一处。
  • 「traditional」这个词看着像没标记过吗？ 它就该是普通文字 —— 已掌握的词与从没查过的词，在视觉上完全一致。
② 「已掌握 = 不标识」的验证
同一句话，左边标了「已掌握」、右边没标 —— 两行应该一模一样。 如果看得出差别，就说明「不标识」没做到。
标记为「已掌握」
The city grows vegetables indoors.
从没查过（无标记）
The city grows vegetables indoors.
为什么不能「把颜色调到全透明」？
透明确实看不见颜色，但 padding: 1px 3px 还在 —— 它会撑开字距，于是被标记过的字与普通字间距不同，用户看得出来「这里有东西」。 那仍然是标识，只是更难解释。

所以实现上用 null（没有痕迹）而不是「一个看不见的痕迹」： TraceTokens.forReps() 对已掌握返回 null，调用方跳过该标记。

顺带的收益：若已掌握还留一点暖色，痕迹就同时背了两个表达 （「这里我查过」+「这个我掌握了」），违反设计稿的「一个概念，一个表达」。 掌握度要看就去复习页 —— 痕迹只表达「我和这篇文章的关系」。
③ 对照：墨档「设计稿写法」vs「Flutter 可实现」
同一个句子、同一个背景色。唯一差别是圆角与 padding —— 刻意只用同一个 CSS 引擎画， 这样差异只反映这一件事，不会被别的因素干扰。
设计稿写法圆角 3px + padding 1px 3px
The city grows vegetables indoors, using liquid instead of soil.
Flutter 可实现矩形 + 无 padding
The city grows vegetables indoors, using liquid instead of soil.
怎么读这组对照：左边是有圆角的（设计稿），右边是 Flutter 能画出来的（矩形、背景紧贴字形）。
要判断的就一件事：这个差异，在你眼里是「可以接受」还是「一眼就觉得糙」？
  • 能接受 → 保持现实现（TextStyle.background），偏差按已知问题记录
  • 不能接受 → 为墨档单独上自绘（TextPainter.getBoxesForSelection() 拿矩形 → 自己画 RRect），代价是要自己处理断行/对齐
⚠️ 右边能看出「没有 padding」—— 背景紧贴字形，比左边「闷」一些。

三档的「读法」各有一条递减规则（这是三档最重要的差异，不是配色）： 墨 = 背景透明度递减（.15 → .075）· 格 = 线宽递减（2.5 → 1.5px）· 夜 = 暖度递减（暖奶油 → 中性灰）。

⚠️ 夜档原本写的是「亮度递减」——已修正。那个说法在三态下成立（靠「已掌握」把亮度拉到 .291）； 只剩两态时，实测亮度仅 .743 → .716（几乎无差）， 实际区分靠的是暖度/彩度。→ 若真机觉得夜档两态难辨，这里就是首要怀疑点。
