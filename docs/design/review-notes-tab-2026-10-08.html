「复习」tab：双段结构（复习 ｜ 笔记）

2026-10-08 · 白哥定案：「把我的划线移动到复习页面，名称改为笔记，与复习同级，就像阅读页面有今日精选和书架」

一、要解决的问题

维度改前改后
形态 「我的划线」是顶层路由 /highlights，从「我的」页 push 进去（带返回按钮、不带 tabbar） 「笔记」是「复习」tab 内的一段，与「复习」平级标题（同「今日精选 ｜ 书架」）
名称 我的划线（实现视角：我们存的是高亮区间） 笔记（用户视角：他做的事是「记笔记」）
入口数 2 个（「我的」页的列表项 + 路由） 1 个（复习 tab 的标题行）—— 同一份数据只留一个入口
🔑 措辞理由：描述用户的动作，不描述我们的存储。技术标识（表名 highlight / 文件名 / 路由参数）不改 —— 那只影响内部。

三、实现要点（都已落地 · 带断言）

要点说明
与阅读 tab 同构 段定义 review_section.dart（零依赖 · 可断言）+ 容器 review_tab_screen.dart。 标题 23px / w600 / 字距 -1.5%、下划线 3px、段间距 16px —— 与阅读 tab 逐值相同，否则切 tab 时标题会横移。
用 IndexedStack 两段都留在树上 ⇒ 切换瞬时，且滚动位置与筛选状态都保留。 用 if (section == …) 会在切走时销毁另一段（回来时重置）。
顺序 = 「复习」在前 与阅读 tab 同一规则：默认段写在最前 —— 点进这个 tab 想做的事就是复习。
删掉旧入口 顶层路由 /highlights 与「我的」页那个列表项都删了。 理由：两个入口指向同一份数据会让栈行为分叉（生词本那次踩过）。
「返回」按钮不需要了 判据没变（用户必须有出口），变的是层级：现在是 tab 内视图，出口 = 切 tab / 点底部 tabbar —— 与「阅读」tab 的书架段一样。
暂停要二次确认（2026-10-08 补） 白哥真机反馈「很容易误点」。它是一个单击动作，而后果（那张卡从复习列表里消失） 在当前界面上看不见，恢复入口在另一个 tab。
⇒ 判据：「后果不可见 + 恢复路径远」的动作才加确认 —— 给每个动作都加确认等于每步多一次点击。
外壳用全应用唯一的 CoDialog；按钮顺序按 iOS 惯例（取消在左 / 暂停在右）。
文案与事后提示同一处权威（review_pause.dart 的 pauseConfirmBody / pausedMessage），且按卡片类型分两套（生词 = 再次查词 · 划线 = 「笔记」页）。

四、有意没做 / 待你定

项说明
标题行右侧动作 阅读 tab 右侧有动作（收藏 N / 导入），本容器暂时空着：复习段的筛选/搜索/排序是三件东西、 且状态都在页面内部。若要加，建议加 「到期 N」药丸（一屏信息量最大）。
两段的顺序 现为 复习 ｜ 笔记。若你希望「笔记」在前，改一处（review_section.dart 的声明顺序）即可 —— 断言会跟着验证。
「笔记」是否再收口 现在它 = 原来的「我的划线」（文章 + 书的划线）。若将来「注记/感悟」也要进来，建议仍在这段内用筛选区分，而不是再加一段。
