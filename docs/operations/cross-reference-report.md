# 两份文档交叉对比分析报告

> 对比对象:

> 目的: 发现两份文档间的覆盖盲区、矛盾点和改进机会

## 2. 发现的问题

### 2.1 架构文档缺少的节点

| 缺失内容 | 用户旅程中有 | 影响 |
|:---------|:------------|:-----|
| **历史对话续接路径** | 3c 完整描述续接逻辑、续接失败场景、旧 domain 残留风险 | 诊断时不知道"续接不成功"该查哪里 |
| **个人设置流程** | 8 描述 profile 读取/修改/加密存储 | 架构中无 Flow G（user_preferences）的显式节点 |
| **对话生命周期（删除/恢复）** | **两篇都未覆盖** | 不知道软删除/物理删除的完整链路 |

### 2.2 用户旅程缺少的校验点

| 旅程 | 缺少的检查 | 建议补充 |
|:-----|:-----------|:---------|
| 1/2(K12入学) | 预置卡导入后的 domain 一致性检查 | 确认 card.domain == plan.domain 的前缀 |
| 3a(自由对话) | CP2 创建 plan 后的 domain 格式检查 | 确认 domain 不是 UUID（应为 readable name）|
| 3c(历史对话) | 续接后 plan 状态确认 | 确认 task_status 未被 k12/init 误删 |
| 4(CP1制卡) | 制卡后 review tab 可见性验证 | 确认新卡片出现在正确的 tab 中 |
| 6(复习) | tab 数量与预期一致 | 确认 UUID tab 已被前端过滤 |

### 2.3 两份文档间的矛盾

| 主题 | 架构文档说 | 用户旅程文档说 | 判断 |
|:-----|:-----------|:--------------|:-----|
| CP1 触发条件 | 3.2 节："仅当会话关联 plan 时" | 3a 旅程："CP1: extract_domain='' → 跳过" | ✅ 一致 |
| plan_updated 送达 | 2.2 节："8种消息，plan_updated 通过 mpsc channel" | 5 旅程："mpsc channel → plan_updated WS" | ✅ 一致 |
| Domain 匹配 | 4.3 节 "三模式" 含 UUID 过滤说明 | 6 旅程无 UUID 过滤说明 | **架构已更新，旅程文档未同步** |
| 自由对话 domain | 无显式说明 | 3a 旅程隐含 domain="" | ⚠️ 架构应补充自由对话的 domain 处理 |

## 4. 建议的修复顺序

```
立即 → G16: 实现 build_plan_context 注入 task 预置卡 fronts
         (唯一 P0，影响 CP1 去重质量)
         ↓
今天 → D1: 架构文档 2.x 拆分为 free/structured/reading 三个子模式
       D2: 架构文档 8.x 补充 FAQ 式诊断解答

         ↓

       D5: 旅程文档补充个人设置加密链路

```

## 5. 结论

两份文档**整体一致**，不存在根本性的矛盾。8 条用户旅程覆盖了 6 个架构节点的全部路径。主要改进方向是：

1. **架构文档对"自由对话"的描述不够精细**——被归类在"热路径"下的单一描述中，实际上自由对话的 plan 创建、CP1 触发、domain 处理与结构化对话完全不同
2. **旅程文档缺少 UUID tab 过滤的同步更新**——今天的 B1 修复改了前端 review_screen，但旅程文档的域匹配表没有更新
3. **G16 是唯一真正的未实现改进**——其余差距要么是文档描述不精确，要么是设计如此
