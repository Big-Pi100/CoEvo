## 5. 🔴【你做 → 我做】支付验证（IAP）—— 上架前必须打通

> **现状实测**（21:39 SSH 直查）：服务器 `/opt/coevo/.env` **10 个键，`IAP_*` 零个**  
> ⇒ `/api/iap/verify` 走到第 2 步就返回 **503**（「IAP 服务端未配置」）。
>
> ⚠️ **后果要说清**：用户在 App 里付费后，**端侧权益照样解锁**（StoreKit 是权威），  
> 但**后端对不上账** —— 订阅状态不落到账号上 ⇒ **换设备 / 重装后权益丢失**。  
> ⇒ 这是**上架前必须闭环**的一项，不是可选项。

### 5.1 支付验证是怎么走的（读懂它就知道要准备什么）

**`POST /api/iap/verify`**（body：`user_id` + `transaction_id`）：

| 步 | 做什么                                                  | 卡住会怎样                      |
| - | ---------------------------------------------------- | -------------------------- |
| 1 | 鉴权（**必须已登录**）                                        | 401                        |
| 2 | **读配置**（4 个 `IAP_*` 变量）                              | 🔴 **缺 ⇒ 503**（**当前就是这里**） |
| 3 | 调 **Apple App Store Server API** 查这笔交易               | 查不到 ⇒ 502                  |
| 4 | 校验 **bundle / product / environment** 三项             | 不符 ⇒ 422                   |
| 5 | 记账（`iap_transactions` + `payment_orders`）            | 500                        |
| 6 | 写订阅到期日（🔴 **直接用 Apple 的 `expiresDate`**，不是本地「加 N 天」） | 500                        |

⇒ 成功返回 `{isActive, expiresAt, productId, originalTransactionId}`。

### 5.2 【你做】App Store Connect 里要做的

**入口在哪**（🔴 **不在 Apps 列表页加** —— 订阅是 **App 级资源**，必须先进到 App 里）：

```
appstoreconnect.apple.com/apps  →「我的 App」→  **点进「记忆之书」这个 App**
  └─ 左侧边栏「订阅」
       └─ ①「自动续期订阅」区的「订阅群组」→ 点「创建」   ← 这一步建的是**群组**，不是产品
```

> 🔑 **这页上那个「创建」按钮建的是「订阅群组」** —— 所有订阅**必须挂在某个群组下**  
> ⇒ 顺序永远是「**先群组、后产品**」。群组还决定「互斥」：用户同时只能订阅同一群组里的一个。  
> 📌 页面上自己也写着：「上传二进制文件且提交首个订阅以供审核后，即可使用下表**提交**其他订阅」

### 9.6 🔴 一个必须先定的判断：会不会被当成「教育类」？

这比备案本身更要紧 —— 因为**教育类备案个人主体办不了**（见下）。

**判据**（《教育移动互联网应用程序备案管理办法》第二条 + 北京市教委官方解读）：

> 教育移动应用 = **以教职工、学生、家长为主要用户**，以教育、学习为主要应用场景，服务于**学校教学与管理、学生学习与生活、家校互动**。
>
> 官方给的对照例子：🔑 **「通用类的互联网工具不属于，如『有道词典』；但专用类的工具属于，如『有道少儿词典』」**

**套到我们身上**：

| 维度   | 我们                                 | 结论  |
| ---- | ---------------------------------- | --- |
| 主要用户 | **成人**自主学习者（不是教职工 / 学生 / 家长）       | 不构成 |
| 应用场景 | 个人阅读 + 查词，**不服务学校教学**              | 不构成 |
| 工具属性 | 面向所有人的**通用阅读 / 查词工具**（等同「有道词典」那一类） | 不构成 |

⇒ **倾向：不属于教育移动应用备案范围。**

**有利证据**（不是推断，是已发生的事实）：

- ✅ 你办**网站 ICP 备案**时，官方口径已认可我们不是 AI 服务；本地文档 `qualification-startup` 里「**教育类需前置审批**」那条也**已按你的判断删除**（定位是「**学习工具**」而非教育 / 培训服务）

**但风险要说清**：

| 若被认定 ⇒              | 后果                                                                             |
| ------------------- | ------------------------------------------------------------------------------ |
| 需办「**教育移动应用提供者备案**」 | 🔴 该办法第十条列举的提供者只有 **教育行政部门 / 学校 / 企业 / 社会组织** —— **不含个人** ⇒ **个人主体办不了**，必须企业主体 |
| 兜底                  | 拿到企业主体之前，理论上不能上线                                                               |

**规避（低成本，建议照做）**：

| # | 做法                                                    |
| - | ----------------------------------------------------- |
| 1 | App Store 品类**不要选「教育」**（选「参考」/「图书」之类；品类在 ASC 里可改）     |
| 2 | 商店描述避免「**培训 / 课程 / 教学 / 提分**」字样，用「**阅读工具 / 查词 / 记忆**」 |
| 3 | 不做 K12 定位、不面向学校推广、不接家校场景                              |
| 4 | 备案备注如实且克制：**英语阅读工具 · 面向成人自主学习 · 无课程与培训内容**            |

> ⚠️ 这是我基于官方判据的**判断**，不是保证。真被教育局巡查认定，只有企业主体一条路。  
> 但按上面 4 条做，命中概率很低。

### 9.7 顺带两条

- **经营性**：App 有订阅，但收费走 **Apple IAP**（收费主体是 Apple，即国务院令 810 号定义的「平台企业」，且 Apple 已代扣 6% 增值税）⇒ 个人主体**暂不需** ICP 经营许可证。⚠️ 转正阈值（月流水 ≥ ¥5,000）要更严格执行。
- **公安联网备案**：已有（粤公网安备 44060602003333 号）。⚠️ 腾讯云明确「**APP 备案不支持生成公安联网备案数据码**」⇒ 上架后 30 日内 App 要**单独**去公安备案。

### 9.8 备案表里那两项 SDK 怎么填（已实测核实）

**为什么是「不使用」——证据（实测，不是推断）**：

**① 实际打进包的原生库**（读 IPA 的 `Frameworks/` 列表，比读 `pubspec.yaml` 可靠）：

**② 二进制扫描**（Runner 主二进制，21 个商业 SDK 关键字）：

> 「如 SDK 功能类型选择后，**找不到对应的 SDK 厂商**，该 SDK 功能类型就无需选择，
