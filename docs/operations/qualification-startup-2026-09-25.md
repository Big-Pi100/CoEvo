## 一、无 Mac 的 iOS 开发闭环（今天就能搭）

### 1.1 为什么可行

**关键前提：Flutter 工程里 90%+ 是 Dart 代码，跨平台完全一致。** iOS 构建只是最后一步「打包 + 签名 + 上传」，这一步可以完全外包给云端的真 Mac。

```
你的 Windows                         云端真 Mac                你的 iPhone
─────────────                       ─────────────             ─────────────
写 Dart 代码          ──push──▶      Codemagic
   │                                （macOS M2）
   ├─ Android 模拟器/真机 快速验证      │  flutter build ipa
   └─ Chrome 跑 UI                  │  自动签名（API Key）
                                    │  上传 App Store Connect
                                    ▼
                                 TestFlight ──────────────▶ 装了测试版
                                 （App Store 自动处理）        真机验收

                          偶发需要：MacinCloud 远程 Mac（按小时）
                          —— 用于调试 iOS 专属问题 / Xcode 工程
```

### 1.2 成本（全部是实价，已核实）

| 项 | 方案 | 费用 | 说明 |
|---|---|---|---|
| **CI 构建** | **Codemagic 免费档** | **¥0** | **500 macOS M2 分钟/月**，每月重置，单次构建上限 120 分钟，1 并行构建，30 天制品保留 |
| CI 超量 | Codemagic Pay-as-you-go | **$0.095/分钟**（M2） | 超出 500 分钟后按分钟计 |
| **远程 Mac（备用）** | **MacinCloud PAYG** | **$1/小时 或 $4/天** | 用于调试 iOS 专属问题；含 Xcode / Transporter / Android Studio |
| 远程 Mac（常驻，可选） | MacinCloud Managed | $25/月起 | 共享 Mac，无 root |
| **Apple 开发者账号** | Apple Developer Program | **$99/年**（约 ¥700） | 企业账号需 DUNS |
| **邓白氏编码 DUNS** | 苹果专属通道 | **￥0** | 免费；约 5 个工作日 + 2 个工作日同步 |
| 真人 Mac（不推荐） | 二手 Mac mini M1 | ¥2,500+ | 只在你有大量 iOS 专属调试需求时才值 |

**500 分钟够用吗？** 一次 iOS 构建约 10–20 分钟 → **每月可构建 25–50 次**。开发期完全够；上线后每版本 2–3 次。

> ⚠️ **不要用 AWS EC2 Mac**：按秒计费但**最低分配 24 小时**，一次 30 分钟的构建实际账单 $25.99（mac2.metal $1.083/hr × 24）。这是经典陷阱。

### 1.3 必须提前知道的三个限制（诚实说明）

| # | 限制 | 影响 | 缓解 |
|---|---|---|---|
| 1 | **无法把热重载跑到 iPhone 上** | 改一行代码就能看效果的那种快感，iOS 上没有 | 日常迭代用 Android 模拟器 / Chrome（Dart 代码行为一致）；iOS 只做**阶段性验收** |
| 2 | **迭代循环变成 15–30 分钟一轮** | 构建 + 上传 + Apple 处理 + TestFlight 更新 | 把「需要上真机才能发现的问题」集中起来一次验，别一个一个改 |
| 3 | **`ios/` 目录的工程文件改起来不便** | `Info.plist` / entitlements / Podfile 改错就要重建 | ✅ **Capabilities（IAP、推送、后台音频）在 Apple Developer 网页端开启**（Windows 浏览器即可）；entitlements 通过 Codemagic 的 `project.pbxproj` 配置管理 |

### 1.4 搭建顺序（今天可做前三步）

1. **注册 Apple Developer Program** → 决定主体（个人 / 公司，见 §六 Q1）
2. **注册 Codemagic**（可用 GitHub 账号登录），连接仓库
3. **在 App Store Connect 建 App ID + 勾选 Capabilities**（In-App Purchase 必须在这里开，否则构建会报 `provisioning profile doesn't include the com.apple.developer.in-app-payments entitlement`）
4. **建 Codemagic 的 App Store Connect API Key**（Users and Access → Integrations，权限选 **App Manager**）
5. **写 `codemagic.yaml`**，跑通第一版 IPA → TestFlight
6. iPhone 装 TestFlight → 装到自己的手机

> 第 4 步的 API Key **只能下载一次**，务必保存好。

## 二、软件著作权（软著）

### 2.1 结论先行

| 项 | 结论 |
|---|---|
| **App Store 需要软著吗** | ❌ **不强制** —— 但提交可降低版权类驳回风险 |
| **Android 商店需要吗** | ✅ **全渠道强制**（华为/小米/OPPO/vivo/应用宝），无软著直接驳回提审 |
| **办理渠道** | 中国版权保护中心 `ccopyright.com.cn`（国家版权局认定的**唯一**软件登记机构） |
| **官费** | **¥0** —— 自 2017 年起普通软著登记官费取消；仅变更登记（¥150/件次）、合同登记（¥100/次）收费 |
| **法定周期** | 自受理日起 **60 日内**审查完成 |
| **实际周期** | 约 **30–60 个工作日**（受理 + 审查 + 公告 3 天 + 出证） |
| **证书有效期** | 终身有效，无需续展 |

**→ 所以 iOS 先行是对的：iOS 不卡软著，Android 卡。**

### 2.2 🔴 2026-03-15 新规 —— 必须先决策的一条

中国版权保护中心 2026-03-15 公告，**自发布之日起启用新版申请表，旧版不予受理**。核心变化：

| 变化 | 内容 |
|---|---|
| **功能描述字数** | 从「200 字以内」→ **不少于 500 字**（实际要求 500–1300 字），须完整说明研发背景、核心架构、功能模块、技术实现、应用场景；**严禁模板化填报** |
| **签章页新增手抄承诺** | 经办人须用**黑色中性笔亲笔抄写**指定承诺段落 + 签名 + **填写身份证号**；严禁打印、代签、涂改 |
| **⚠️ 承诺内容** | **「未使用 AI 开发编写代码、撰写文档或生成登记申请材料」** |
| **失信惩戒** | 违规者**列入版权登记失信名单 + 纳入个人/企业征信**，并承担法律责任 |
| **审核转向** | 从「形式审查」转向**实质性审查**；有报道称源代码层面会识别 AI 生成特征 |
| **四类非正常申请** | 批量突击申请 · 业务严重脱节 · 材料虚假重复 · **提交 AI 生成的模板化申报材料** |

**这条为什么必须你来判断**：

> 我**不能**替你把「项目代码的成稿方式」认定为「未使用 AI 开发编写代码」——
> 那需要你手抄并签身份证号，后果是**征信记录**，不是我能替你承担的。

**我需要你确认的是**：CoEvo 的代码在事实上是怎么成稿的？以及**这个问题我们怎么处理**。有三个方向，我列出它们的真实代价：

| 方向 | 做法 | 代价 / 风险 |
|---|---|---|
| **A · 直接问官方口径** | 打版权中心业务咨询电话 **010-61090099**，说明「人主导架构与设计、AI 辅助编码」的实际情形，问是否构成条款所指情形 | 时间成本低（一个电话），但可能得到保守答复 |
| **B · 找正规代办确认实操** | 问代办 2026-03 之后同类项目的实际通过情况 | 渠道信息更接地气；但代办有促成交易的动机，**其说法不能当作免责依据** |
| **C · 调整登记标的** | 登记一个**人工主导程度最高**的模块（如词表数据库构建脚本、FSRS 实现），而非整个 App | 需要真实的人工成稿证据；且登记范围变小 |

**我的建议：先做 A（一个电话），再决定。** 在拿到明确口径之前，**不要提交**——新规下材料被认定为「AI 生成」是列入征信的失信行为。

> ⚠️ 另有一条相关的现实约束：新规同时整治「**业务严重脱节**」（软著技术方向与企业核心业务无关）。所以登记标的应与我们真实做的业务一致，不要为了好办而挑无关的软件。

### 2.3 材料规范（拿到口径后照着备）

**① 源程序文档 —— 要求最严**

| 要求 | 具体 |
|---|---|
| 页数 | **前 30 页 + 后 30 页，共 60 页**；不足 60 页则全部提交 |
| 每页行数 | **不少于 50 行** |
| 页眉 | 标注**软件名称 + 版本号**，须与申请表**完全一致** |
| 页码 | 右上角标注 |
| 格式 | 去掉非代码空行；**不得用截图或反编译结果** |
| 内容 | 原始代码打印稿，**关键算法部分应保留**；最后一页应为软件退出部分代码 |

**② 说明文档（任选一种）**：用户手册 / 操作手册 / 设计说明书 / 使用说明书

- 篇幅建议 **10–30 页**，图文并茂
- 需体现**核心功能逻辑与独创性** —— 不能只给界面截图或基础操作流程
- 页眉同样标注软件名称 + 版本号

**③ 申请表**：新版（2026-03-15 后），功能描述 **500–1300 字**

**④ 主体证明**：企业 = 营业执照副本（加盖公章）；自然人 = 身份证正反面 + 非职务开发证明

**⑤ 签章页**：手抄承诺 + 签名 + 身份证号（**黑色中性笔**）

### 2.4 关于「加急」——需核实，不要轻信

市场信息**互相矛盾**：有说官费已取消、加急是代办行为；有说官方有 3/5/10 工作日的分档加急，报价 ¥800 / ¥1,200 / ¥1,600。

**我的处理**：**不采信任何一方，打电话问官方**（010-61090099）。因为你的 Android 上架时间线依赖它，值得花一个电话确认。

**但注意**：即使能加急，**新规下的诚信声明仍在** —— 加急只解决速度，不解决 §2.2 的问题。

### 2.5 办理流程（官方六步）

```
① 官网注册账号 → ② 实名认证（1–3 工作日）
→ ③ 在线填报 + 上传材料 → ④ 登记机构受理
→ ⑤ 审查（受理日起 60 日内）→ ⑥ 公告 3 天 → 下载电子证书（PDF）
```

**补正规则**：材料有问题会收到补正通知，须 **30 日内**补正，逾期视为撤回。

## 三、ICP 经营许可证（第二类增值电信业务 · 互联网信息服务）

### 3.1 先分清三个东西（这个最容易搞混）

| 名称 | 性质 | 对象 | 我们的状态 |
|---|---|---|---|
| **ICP 备案（非经营性）** | 行政备案 | **域名 + 服务器 IP** | ✅ **已完成** —— 粤ICP备2026061557号**-1** |
| **APP 备案（工信部）** | 行政备案 | **应用包名 + 签名** | ⏳ **未做** —— 需独立拿 **`-2`** 号 |
| **ICP 经营许可证（B25）** | **行政许可** | **经营行为** | 🟢 **暂不需要** —— 订阅路径下收费主体是 Apple（平台企业）；⚠️ **订阅制经营特征更强 → 转正阈值（月 ≥¥5,000）应更严格执行** |

> **三者不能互相替代。** 有了 `-1` 不等于有了 `-2`；有了备案不等于有了许可证。

**官方渠道**：企业注册地所在省的通信管理局，入口为**工信部政务服务平台**在线提交。**官方不收取办理费用**（代办另计）。
**法定时限**：60 个工作日；多数省份实际 **30–40 个工作日**。
**有效期**：5 年；**每年一季度需完成线上年报**；到期前 90 天办延续。

### 3.2 硬性条件逐条自查（广东口径）

> 广东的审核尺度**偏严**（会随机上门核验办公场地）。以下 7 条**一条不满足都办不下来**。

| # | 条件 | 说明 | 自查 |
|---|---|---|---|
| 1 | **主体类型** | 必须是**依法注册的内资有限责任公司 / 股份公司**。**个体工商户、分公司、工作室无申请资格** | ☐ |
| 2 | **股权** | 不得含外资。深圳作为试点可外商独资；广州/佛山/东莞等仍执行原管控 | ☐ |
| 3 | **注册资本 ≥ ¥100 万** | **认缴即可，无需实缴验资** —— 营业执照上认缴金额达标即行 | ☐ |
| 4 | **经营范围** | 营业执照须含「**第二类增值电信业务**」（或互联网信息服务、网络文化经营类目）。缺则先去市场监管局做工商变更 | ☐ |
| 5 | **3 名员工社保** | **本公司名下**、近 1 个月记录、全职在职。**法人可算其中 1 人**。不可挂靠、不可第三方代缴、不可异地。岗位建议：技术负责人 / 运营负责人 / 信息安全负责人 | ☐ |
| 6 | **域名 + 服务器** | 域名持有人**与申请公司一致**、已完成 **ICP 备案**（主体一致）、剩余有效期 **≥6 个月**；服务器必须**在中国大陆境内**（建议省内），提供托管协议。**境外/香港服务器一律不认** | ☐ |
| 7 | **真实办公场地** | 不认虚拟地址 / 集群注册 / 挂靠 / 住宅。需租赁合同 + 使用证明 + 实景照片，**可能上门或视频核验** | ☐ |
| 8 | 信用记录 | 法人、股东、主要管理人员近 3 年无电信业务违规 / 行政处罚 / 严重失信 | ☐ |

### 3.3 ⚠️ 一个容易被忽略的前置条件

**申请时对应的网站/平台必须能正常访问，且体现经营性特征。**

- 空白网站、半成品、内容杂乱 → **直接不通过**
- 页面须有：**用户服务条款 + 隐私政策 + 免责声明 + 联系方式**，底部**预留许可证公示位置**
- 最好具备**用户注册 + 付费/会员功能**（体现经营性）

**→ 这个顺序要注意**：不是「先拿证再上线」，而是「**先有一个合规可访问的站，才能申请证**」。
好消息是我们的 landing（keyievolution.fun）+ Web 版已经在跑，**底子在**；缺的是**条款页 + 许可证公示位**。

| 5 | 互联网信息服务业务发展和实施计划 | 业务模式、目标用户、收费方式、3 年规划 |
| 6 | 依法经营承诺书 | — |
| 7 | 内容审核与应急处置方案 | 我们有结构化交互，需说明机制 |
