### 1.3 结论：代办的说法被推翻

| 代办文章的说法 | 实证结果 |
|---|---|
| 「个人账号**仅纯离线免费工具**」 | ❌ 反例：`时间规划局` ¥3 付费 + 6 个内购项 |
| 「个人账号**禁止**：带用户注册、评论、付费、**广告**、社区、资讯功能」 | ❌ 反例：三个 App 的年龄分级均标注「包含广告」 |
| 「社交、电商、付费、UGC、直播…**只允许企业账号上架，个人账号直接拒审**」 | ❌ 同上 |
| 「个人账号**无法使用苹果支付(IAP)**」 | ❌ 反例：`时间规划局` 有包月/包年/永久三种 IAP |

**判定**：这批说法与 Apple 官方审核指南矛盾（2.5.18 专门规范 App 内广告，**不区分账号类型**），且**自我矛盾**（既说个人能上架、又说个人不能用 IAP）。来源（代办）有**推销企业账号与企业认证服务**的商业动机。

**→ Apple 侧确认无阻塞。**

### 1.4 一个连带观察（对隐私政策任务有影响）

`时间规划局`（515K+ 评价量级的产品）的隐私政策**极其简陋**：

- 用的是 2020 年的通用模板，**没有列明第三方 SDK 清单**
- 政策开头写「本应用不会向任何无关第三方提供、出售、出租、分享或交易您的个人信息」
- 但它的 App 隐私标签明确写「标识符用于追踪」→ **实际有广告 SDK**

**这不符合 Apple 的隐私政策要求，但它照样上架了**（说明该 App 是早期上架、或审核未深究）。

**对我们的启示**：**不要把「别人这么写也能过」当作合规标准。** 我们的隐私政策应按规范写（列明广告 SDK + 收集的设备标识符），这对后续备案也有利（备案会核查隐私政策与 SDK 名单是否一致）。

## 二、APP 备案操作指引（iOS 专用）

### 2.1 🔴 关键差异：iOS 填 SHA-1，不是 MD5

**这是本次调查最实用的发现。** 华为开发者联盟官方文档 + 多个来源一致：

| 平台 | 需填写字段 |
|---|---|
| Android / 鸿蒙 | 软件包名称 · **公钥** · 证书 **MD5** 指纹 · 服务器域名 |
| **iOS** | **Bundle ID** · **公钥** · 证书 **SHA-1** 指纹 · 服务器域名 |

**我们只做 iOS → 只填后一行。**

**⚠️ 易踩坑点**（多个来源强调）：公钥与 SHA-1 必须来自 **Apple Distribution 证书**，**不能填 Development 证书的**。

**怎么拿到**：在 macOS 钥匙串访问里生成 CSR → Apple Developer 后台创建 Apple Distribution 证书并上传 CSR → 下载双击装回钥匙串 → 从证书里解析出公钥与 SHA-1 指纹。

> ⚠️ **这对我们是个实际问题**：白哥没有 Mac，而这个解析步骤通常在 macOS 钥匙串里完成。
> **待解决**：确认 Codemagic 的构件里能否直接导出所需信息，或在 Windows 上用 OpenSSL 从 `.cer`/`.p12` 解析（技术上可行，需实测）。

### 2.2 材料清单（个人主体）

| # | 材料 | 我们的状态 |
|---|---|---|
| 1 | **主体**：身份证 · 手机号 · 邮箱 · 手持身份证照片 | ⏳ 待准备 |
| 2 | **APP 基础**：名称 · Bundle ID · 版本号 · 功能简介 · 图标 · **3–5 张核心界面截图** | ⏳ 需先做出界面 |
| 3 | **iOS 技术信息**：公钥 · 证书 SHA-1 指纹 | ⏳ 见 2.1 的待解决项 |
| 4 | **后台服务域名**（必须已完成 ICP 备案） | ✅ 已有 `keyievolution.fun`（粤ICP备2026061557号-1） |
| 5 | **隐私政策**（含更新日期、完整条款） | ⏳ 待写 |
| 6 | **《APP 备案承诺书》** | ⏳ 接入商平台有模板 |

**接入商选择**：**服务器在哪家就在哪家备案** → 我们的 VPS 是**腾讯云** → **在腾讯云备案系统提交**。

### 2.3 流程与周期

```
腾讯云备案系统 → 选「APP 备案」
  → 填主体信息（上传证件）
  → 填 APP 信息（名称 / Bundle ID / 功能分类 / 公钥 / SHA-1 / 域名）
  → 上传隐私政策 + 承诺书 + 截图
  → 人脸识别 + 短信核验
  → 接入商初审（1–3 天）
  → 管局审核（7–20 个工作日）
  → 获得备案号 → 填入 App Store Connect
```

**总周期：约 7–25 个工作日。**

**前置顺序**（多个来源一致的建议）：
```
① 搭好官网 + 隐私政策页 + 支持页（部署在已备案域名上）
        ↓
② 做 APP 备案
        ↓
③ App Store Connect 提交（填备案号 + 隐私政策 URL + 支持 URL）
```

> **消息来源**：App Store Connect 提交时要求填写「支持 URL」和「隐私政策 URL」，**这两个页面部署在国区服务器上，对应域名必须已备案**。我们域名已备案，只需搭页面。

### 2.4 ⚠️ 需要修正我之前的一个建议

**我在 `ad-monetization` §8.4 写的是**：
> 「备案时如实描述 App 做什么，**不写「无广告/无付费功能」这类承诺性表述**」

**这个建议需要修正。** 依据（一篇个人开发者实操文，与其他来源的做法一致）：

> 如果你是个人开发者，备注说明一定要写得**极其克制**，明确这是个人生活记录类应用，强调**无注册登录、无信息发布、无交易收费、无广告、无在线咨询**，数据主要保存在本机。这种表述更符合个人工具类 APP 的定位，**能大幅降低被误判成平台型、经营性或行业服务的概率**。一旦 APP 涉及商业行为，那就必须用公司主体来备案。

**为什么我原来的建议不够好** —— 我把「如实陈述」和「承诺」混为一谈了：

| | 性质 | 是否合理 |
|---|---|---|
| App **确实无广告**时写「无广告」 | **如实陈述** | ✅ 合理，且能显著提高通过率 |
| App **已有广告**时写「无广告」 | **虚假申报** | ❌ 绝对不行 |

**真正关键的不是「写不写」，而是「备案时 App 是否确实无广告」。**

**→ 修正后的正确策略**：

```
① 先做「无广告、无付费」的免费版
② 备案说明如实写：个人工具类应用 · 无广告 · 无交易收费 · 数据存本机
   ↑ 此时这每一句都是真的
③ 备案通过 → 上架免费版
④ 上架稳定后（可选）再加广告
   ↑ 此时属「备案信息未及时更新」而非「申报造假」—— 性质轻一档
```

**这个顺序同时满足两个目标**：备案阶段如实且通过率高；加广告阶段风险性质最轻。

> 📄 **待同步**：`_archive/ad-monetization-and-flutter-assessment-2026-09-25.md` §8.4 做法 1 需要按此修正。

### 2.5 常见驳回原因（避坑）

| 原因 | 注意 |
|---|---|
| **通信地址不详细** | 必须写到门牌号，不能只写「XX市XX区」 |
| **域名漏填** | App 用到的**所有**后台服务域名都要填，少填一个就可能被打回 |
| **公钥/SHA-1 取错证书** | 必须是 Distribution 证书，不能是 Development |
| **隐私政策不完整** | 需含权限用途、第三方 SDK 清单、数据存储、账号注销通道 |
| **手机号非本人实名** | 后续短信核验会卡住 |
| **错过初审电话** | 提交后次日 9 点前后保持电话畅通，别设勿扰模式 |

## 三、聚合广告平台 SDK 实测调查

### 3.1 三条接入路径（技术上都能走通，代价不同）

| 路径 | 做法 | 关键限制 |
|---|---|---|
| **A · 聚合平台官方 Flutter SDK** | 直接 `pub add`（如 `deepadx_sdk`、`ad_suyi_flutter_sdk`） | ⚠️ **有官方 Flutter SDK 的平台，尚未确认是否接受个人** |

**芒果联盟**（官网 FAQ 原文）：

> **支持哪些开发框架？** 聚合广告平台支持微信小程序、快应用、基于 ios 和 android 框架开发的各类 app（包括且不限于基于安卓原生框架或基于 **uniapp、apicloud、flutter、纯h5网页、cocos creator、unity** 等）
>
> **对接媒体有无门槛？** 聚合广告平台目前对接**无任何门槛。无日活要求，支持公司及个人开发者。无软著，未上架均可支持。**
>
> **合作模式？** 广告收益 **1-9 分成**（平台 1 成 / 客户 9 成）；日收益不足 2000 元/天，结款周期为自然月；超 2000 元/天，**7 天**

> **在当前国内的移动应用市场中，个人 APP 接入广告联盟面临一定限制。主流的如穿山甲、优量汇、百青藤等广告联盟通常要求企业资质。因此，个人开发者更多需依靠国外的广告联盟或第三方聚合广告平台来实现 APP 流量的广告变现。**

**技术细节未公开** —— 官网产品页只有营销内容，**SDK 文档与 Flutter 接入方式需注册/联系客服获取**。

**可压缩**：只做 3 种广告形态（**开屏 + 插屏 + 激励视频**，够用了）→ **约 1–2 周**。

> **好消息**：`deepadx_sdk` 与 `ad_suyi_flutter_sdk` 的**源码是公开的**（pub.dev / gitee），
> 它们就是「如何为聚合广告 SDK 写 Flutter 桥接」的**现成参考实现** —— 即使最终用的是别的平台，这套代码结构可以直接照搬。**这大幅降低了路径 B 的不确定性。**

### 3.6 ⚠️ 风险提示（这个行业鱼龙混杂）

| 风险 | 证据 / 应对 |
|---|---|
| **仿冒诈骗** | 芒果联盟官网挂着《关于不法分子冒充芒果联盟官网从事违法活动的**严正声明**》→ 说明冒名诈骗在这一行很常见 |
| **营销数字无法验证** | 「3 万+ 合作 APP」「3 亿+ 日活」「6 亿+ 日曝光」「收益增长 20%-100%」—— **均无法验证** |
| **主体真实性** | 芒果互动传媒（深圳）｜硕果=玖腾科技 —— 需自行查工商信息（成立时间、注册资本、社保人数） |
| **结算风险** | 账期越长风险越大 → **优先选 7 天/日结**；芒果联盟写「超 2000 元/天 → 7 天结」 |
| **数据不透明** | 必须索取「**原始广告平台子账号**」—— 能在穿山甲/优量汇官方后台看到自己的数据，是"不偷量"的硬证据 |

### 3.7 需要实际联系平台确认的 6 个问题（建议照此逐条问）

```
① 你们是否有 Flutter SDK？还是只提供 Android/iOS 原生 SDK？
   → 若有：pub.dev 包名？最新版本？谁维护？
   → 若无：需要我自己封装吗？有没有参考实现或技术支持？

② 是否支持个人开发者（自然人）？
   → 要求什么材料？（身份证 / 银行账户 / 软著 / 上架证明）
   → 是否要求先上架？未上架能否开通？

③ 广告位 ID 由谁提供？
   → 是我自己注册穿山甲/优量汇账号，还是你们用公司资质开子账号？
   → 能否给我「原始广告平台子账号」（能看官方后台数据）？

④ 结算条款的书面版本？
   → 分成比例 / 结算周期 / 起结金额 / 对私对公 / 个税代扣方式
   → 是否有合同？条款能否写明？

⑤ 技术支持的响应方式？（有 Flutter 接入问题找谁）

⑥ 你们的主体公司全称？可否提供营业执照？
```

> **第 ③ 条是最关键的** —— 如果平台愿意提供「原始子账号」，说明它是**上游官方服务商**（合法路径，绕开「穿山甲不接个人」的限制）；
> 如果只给一个自建后台，则无法验证数据真实性，也不清楚它用什么身份对接上游。
